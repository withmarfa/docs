# Site code

The code of the docs site and the status page. The root `AGENTS.md` still applies.

## Agent surfaces

- `src/lib/docs-tools.ts` is the one implementation of docs search, page fetch (whole, or one section by heading) and the topic list. The MCP server (`src/lib/mcp/`), the JSON addresses (`src/lib/docs-api.ts`) and the site's search box (`/api/search`) all call it. Change behavior there, never in one caller.
- `src/lib/mcp/server.test.ts` checks the MCP server against the MCP specification. Add a case there before changing anything a client can see. `src/lib/mcp/stdio.ts` only forwards to the HTTP endpoint, so it cannot differ from it.
- The MCP tools in `src/lib/mcp/tools.ts` are registered in a fixed order, which is the order `tools/list` returns them in. `docs_search` and `docs_list_topics` declare an `outputSchema` and return `structuredContent` that conforms to it, with the same JSON in the text block; `docs_fetch` returns Markdown. The server's `instructions` live there too. A change to a tool's name, input or result updates the instructions, the tool descriptions and `content/docs/(reference)/docs-for-agents.mdx` together.
- The `marfa docs` command in withmarfa/marfa reads `/api/docs/search`, `/api/docs/topics` and the `.md` copies. A change to their shapes or status codes needs a matching change there.
- `/` is the landing page, `(start)/index.mdx`, rendered by the page route `src/routes/$.tsx` with an empty splat; there is no `index.tsx` route and no redirect. Its Markdown copy is `/index.md`. Prerender starts at `/`, and its filter in `vite.config.ts` drops `/version.json`, `/mcp` and `/api/`, because a prerendered Worker route answers from a frozen file.
- `source.config.ts` decides what each component becomes in the Markdown copy that `.md`, `llms-full.txt`, a page address that asks for Markdown and the docs tools serve (`STYLE.md`, "Components"). The `Changelog` component draws `src/generated/changelog.json`, and `source.config.ts` writes the same releases into the copy through `changelogMarkdown` in `src/lib/changelog.ts`, and into the search index through `remarkChangelogIndex` (the page's MDX holds no release text to index). The route in `src/routes/$.tsx` adds each release to "On this page", because a component draws those headings. `ApiMap` works the same way: it draws `openapi.json`, and `source.config.ts` writes the same map into the copy through `apiMapMarkdown` in `src/lib/api-map.ts`.
- `llms-full.txt` holds the written pages: `inLlmsFull` in `src/lib/source.ts` leaves out the generated operation pages and the changelog, and the opening of `llms.txt` (`src/lib/docs-map.ts`) says so and says where they are. Change the three together.

## Worker entry

- `src/server.ts` is the Worker's one entry (`main` in `wrangler.jsonc`). It runs the stages in `src/lib/worker.ts`, then the router. A new request-level behavior is a stage, one line in `createWorkerHandler`, with a case in `src/lib/worker.test.ts`. The order is counting, rate limit, trailing slash, Markdown negotiation, static files: counting runs outermost so it sees the final response, and it sends nothing for a `429`. A stage with its own logic sits in its own module (`agent-reads.ts`, `rate-limit.ts`) and the handler only wires it, taking what it needs from `createWorkerHandler`'s options, so a test runs it with a fake `fetch` and a fake limiter.
- Prerendered pages are static files, and a static file answers before any Worker runs. `run_worker_first` in `wrangler.jsonc` runs the Worker first for every address except the hashed files in `/assets/` and the icons, and the `staticAssets` stage hands the request to the files itself. Without it a page address never sees its `Accept` header. A page slug must not be `assets` (`content/AGENTS.md`).
- **One address per page, without a trailing slash.** Prerender writes each page as `<path>/index.html`, and `html_handling: "drop-trailing-slash"` in `wrangler.jsonc` makes the files answer it at `<path>` with `200`. The `trailingSlash` stage answers a read of any other path that ends in a slash with `301` to the path without it, keeping the query; `/` keeps its slash and a write passes through. Internal links never carry a slash, so none of them meets a redirect.
- **Search engines and link previews.** Every page has a canonical link and `og:url` at `https://docs.marfa.so` (`canonicalUrl` in `src/lib/canonical.ts`) and its own `og:title` and `og:description` (`src/lib/page-head.ts`). The root route sets the rest of the share card: `og:site_name`, `og:type`, the image `public/og.png` (1200 by 630) and `twitter:card`. `/sitemap.xml` lists every page, the API reference included, from the page source, and prerender writes it. `/robots.txt` is a route, not a file in `public/`, which the status page shares; it allows every crawler, AI crawlers included. No title or description may hold an em or en dash (`content-lint.test.ts`).
- A page address whose `Accept` ranks `text/markdown` above `text/html`, or at the same rank when it names `text/markdown` first, answers the page's Markdown copy, and every answer for a page address carries `Vary: Accept`. `src/lib/accept.ts` decides the ranking. The `.md` route and the negotiated answer both build their response with `markdownResponse`, so the two cannot differ.
- `pnpm dev` renders every page through the router, because nothing is prerendered there, so it cannot show the file lookup or `run_worker_first`. Check a change to either with `pnpm build` and `pnpm exec vite preview`, which runs the built Worker as it deploys.

## Analytics

- Both Workers send page views and unhandled errors to one PostHog project from the browser, and the docs Worker also sends one count for each request to an agent address, and nothing else. `src/lib/analytics.ts` sets every browser option: autocapture, session replay, surveys, heatmaps, feature flags and all storage stay off, so neither site needs a consent banner.
- **Agent reads are counts only.** `src/lib/agent-reads.ts` is a stage of the docs Worker. It posts one `agent_read` event to PostHog's capture endpoint for each request to `/mcp`, `/api/docs/*`, a `.md` copy (by path or by `Accept`), `/llms.txt`, `/llms-full.txt` and `/docs-map.md`, with `ctx.waitUntil`, so the response never waits for it and a failed send is dropped. It sends nothing for a request the rate limit refused with `429`, and a per-address limiter of its own (`DOCS_COUNT_LIMITER`) bounds the events one address can cause: over it the request is still served and no event is sent. The limiter's key is the address and stays in Cloudflare's memory. A limiter that fails, or a request with no address while the limiter is bound, sends nothing too, because the limit is a ceiling on cost. It has no SDK and no dependency: a plain `fetch` to `/i/v0/e/` on the host `src/lib/analytics.ts` names. The event holds `$process_person_profile: false`, `$geoip_disable: true`, a fresh random `distinct_id`, and `site`, `surface`, `method` (`GET`, `HEAD`, `POST` or `DELETE`, else `other`), `status`, a `client` class from a closed list (never the `User-Agent`), and where they apply a page `path` (only a path that is a page), `via`, `mcp_method` and `mcp_tool` (closed lists; anything else is `other`) and the `hits` of a search. It never holds an IP address, a cookie, a query, a page's text, the raw `User-Agent` or any other header. A new property is a decision about what the site learns about its readers: add it to the allowed list in `agent-reads.test.ts` on purpose. A build without `MARFA_POSTHOG_KEY` sends nothing, and so does a test or a local run without a fake `fetch`. The status Worker never imports the module.
- Only `src/components/analytics.tsx` imports `posthog-js` as a value, by dynamic import after hydration, so the SDK never sits on the critical path. A type-only import is fine. Error components report through `reportError` in `src/lib/analytics.ts`.
- After changing analytics, build both targets and check that no SDK code is in either client entry chunk and that a separate chunk carries it.
- A build without `MARFA_POSTHOG_KEY` is a working state: it loads nothing and reports nowhere.

## Rate limit

- `/mcp`, `/api/docs/search` and the site's search box, `/api/search`, need no credential, so `src/lib/rate-limit.ts` limits each client by its address (`CF-Connecting-IP`) with Cloudflare's Workers rate limiting binding, declared as `ratelimits` in `wrangler.jsonc`: `DOCS_MCP_LIMITER` (120 requests a minute), `DOCS_SEARCH_LIMITER` (60), `DOCS_SITE_SEARCH_LIMITER` (300, for `/api/search`) and `DOCS_COUNT_LIMITER` (600, which bounds counting, above). That config is where the limits are set. Cloudflare keeps the key in memory and nothing here stores it or sends it to PostHog. The counts are per Cloudflare location and approximate, which suits a guard against a flood. Cloudflare advises against an address as a key because users can share one, and a service that calls for many people from one address shares the limit, so the numbers stay well above what an honest agent does. The search box's limit is set above what typing reaches: its dialog waits 100 milliseconds after a keystroke and caches each query, so a person sends a few searches a minute.
- A client over its limit gets `429` with `Retry-After: 60`. `/api/docs/search` and `/api/search` answer `{ "error": "rate_limited", "message": ... }` like the JSON address's other errors (the site's dialog treats any non-`200` as an error and keeps showing what it had), and `/mcp` answers a JSON-RPC error with no id, as the SDK answers its other refusals, with the CORS headers a browser client needs. `marfa docs` reports a `429` as `docs_unreachable`, exit code 3. `RATE_LIMIT_PERIOD_SECONDS` and the `period` in `wrangler.jsonc` are one number, and `wrangler-config.test.ts` checks it. Each limiter has its own `namespace_id` (`5701` to `5704`), unique in the Cloudflare account.
- The stage is skipped for a limiter that is not bound, as in a test, and fails open for a request with no client address or a limiter that throws. Local `vite preview` simulates the bindings. `/api/search` is limited but never counted as an agent read. `.md` copies, `llms.txt` and the other addresses have no request limit; their counting is bounded by `DOCS_COUNT_LIMITER`.

## Status page

- `src/status/` reads the store that a separate checker writes, and never writes to it. It is not prerendered, because it answers from the store at request time.
- The status build has no `@/` alias. Code under `src/status/`, and any shared module it imports, such as `src/components/analytics.tsx` and `src/lib/analytics.ts`, uses relative imports.

## Focus

- **The ring shows only after Tab, never after a click.** A browser matches `:focus-visible` on an element the reader clicked as soon as any key is pressed, such as an arrow to scroll, so `:focus-visible` alone draws a stray box. `PointerFocus` in `src/components/pointer-focus.tsx`, mounted in both root routes, sets `data-input` on the `html` element: `pointer` on `pointerdown`, `keyboard` on Tab or Shift+Tab. Arrow keys, space and typing change nothing. Before either, there is no value and the ring may show.
- **One rule draws it.** The "Pointer and focus" section of `src/styles/app.css` draws a 2px ring in half-strength foreground at offset 2px, and switches it off under `html[data-input='pointer']` for everything but a text field, which keeps its focus after a click. It also turns off the shadow ring that Fumadocs components add with `focus-visible:ring-2`, so only one ring is drawn. The same section gives enabled buttons, tabs, summaries and selects the pointer cursor.
- **Never add per-component `:focus` or `:focus-visible` styles, `outline: none` or `focus-visible:` ring utilities.** They fight the rule and bring back a ring after a click. A new control, scrollable region or custom widget inherits the global rule. If its box clips an outside ring (`overflow: hidden`, a scroll container), add its selector to the inset list in that section, which draws the ring at offset -2px, rather than styling it on its own.
- A script-focused target that is not in the tab order needs `tabindex="-1"`, which the global rule leaves without a ring.
- Do not hide a control with `opacity: 0` unless it shows again on focus, because its ring is hidden with it.

## Tests

- Tests sit beside the code as `*.test.ts` or `*.test.tsx`. Each content lint rule has a test that proves it fires on a bad sample; give a new rule one.
- `src/lib/page-limits.test.ts` counts each page's words against `src/lib/page-limits.json` (`STYLE.md`, "Less is clearer"). A page over its limit fails with what to do. A `pending` entry is a ceiling for a page awaiting rewrite, and the test fails on one that no longer excuses anything, so delete it when the rewrite lands.
- `src/lib/command-check.ts` holds the command check and `command-check.test.ts` runs it over every page. Its exceptions are in `src/lib/command-check-allowlist.json`, each with a reason; add one only for what is not a `marfa` command or option, and fix a page that names one that does not exist.
- `src/lib/glossary.test.ts` compares each word on the Glossary page with the `GLOSSARY.md` row `src/lib/glossary-sources.json` names for it. When it fails, read both definitions and make the page agree. Then run the test again and paste the fingerprint it gives, since a change to the page changes the fingerprint. A word with no row has a reason instead.

## Code Review Rules

- **Second implementation.** Flag docs search, fetch or topic logic outside `src/lib/docs-tools.ts`.
- **`marfa docs` broken.** Flag a change to the JSON addresses' shapes or status codes, or to the `.md` copies, without the matching change in withmarfa/marfa.
- **Protocol change untested.** Flag a change to what an MCP client sees without a case in `src/lib/mcp/server.test.ts`.
- **Worker bypassed.** Flag a change to `run_worker_first` that lets a page address answer from its file without the Worker, `Accept` read anywhere but `src/lib/worker.ts`, or a response for a page address without `Vary: Accept`.
- **Analytics grown.** Flag a value import of `posthog-js` outside `src/components/analytics.tsx`, an option that turns on capture, replay, flags or storage, or an agent-read event that gains an IP address, a cookie, a header, a query, a page's text or a value that came from a client and matched no closed list, or that is sent without `$process_person_profile: false`, awaited by the response, or from a build or test without a key.
- **Limit weakened.** Flag a change that makes the `429` on `/mcp`, `/api/docs/search` or `/api/search` differ from the shapes above, keys a limit on anything but the client's address, stores or sends that address, moves the stage behind work the limit should save, leaves a counted address with no bound on its events, or sends an event for a `429`.
- **Alias in the status build.** Flag an `@/` import that code under `src/status/` can reach.
- **Focus ring bypassed.** Flag a `:focus` or `:focus-visible` rule, `outline: none`, or a `focus-visible:` ring or outline utility on a component, a ring that shows after a pointer click, or a change to `PointerFocus` that sets `keyboard` on anything but Tab.
