`marfa` is the reference client of a Marfa instance. Every published operation is a command under its area, such as `marfa items list` for `GET /items`. The command is also a device: `marfa device` keeps a working copy of a slice of an instance, and `marfa folders` keeps a slice as files in a directory. `marfa operations` prints every published operation next to the command that reaches it.

## Install

Each [release of Marfa on GitHub](https://github.com/withmarfa/marfa/releases/latest) carries the command for macOS on Apple silicon, as `marfa-<version>-darwin-arm64.tar.gz`. The archive holds the `marfa` binary and nothing else.

Download the archive from the release page. With the GitHub CLI, `gh release download --repo withmarfa/marfa --pattern 'marfa-*-darwin-arm64.tar.gz'` downloads the same archive to the current directory.

Unpack it in the directory that holds it, such as `~/Downloads`:

```bash
tar -xzf marfa-*-darwin-arm64.tar.gz
```

Move `marfa` to a directory on your `PATH`, then check it runs:

```bash
marfa --version
```

To build it from source instead, clone [withmarfa/marfa](https://github.com/withmarfa/marfa) and run `cargo install --locked --path core/marfa-cli` in the clone.

The reference on this page is generated from the command's help on the `main` branch of withmarfa/marfa, so it can list a command that the latest release doesn't have. `marfa --help` and `marfa <command> --help` print the help of the build you have.

## Choose a server and a credential

A command that talks to a server takes the first of each that is set:

| What | First | Then | Then |
| --- | --- | --- | --- |
| Server | `--url` | `MARFA_API_URL` | The current server in the keychain |
| Credential | `--key` | `MARFA_API_KEY` | The credential the keychain holds for that server |

The keychain is the operating system's keychain. It holds one credential for each server, and keeping a credential there makes its server the current one. On macOS, `MARFA_KEYCHAIN` names a keychain file to use instead, for runs with nobody to answer a prompt.

`marfa login` signs you in to a server as its owner: it shows a code, you approve it in the browser, and the command keeps the token in the keychain. `marfa logout` ends that sign-in. To give a script or a connector its own key instead, see [Keys and permissions](/get-started/keys-and-permissions).

On the instance's own machine, running under the server's account, `--socket <path>` uses the machine's own authority through the server's private socket, with no credential and no keychain. `marfa setup status`, `marfa setup code`, `marfa setup open` and `marfa owner recover` need it.

`marfa whoami` says which server, instance and credential a command with no `--url` or `--key` would use.

## JSON output

`--json` prints the answer as JSON on stdout. A refusal is then one JSON object on stderr, with the error's `code`, its `message` and the exit code:

```bash
marfa status --json
```

```json
{"error":{"code":"no_server","message":"no server named: pass --url or set MARFA_API_URL","server":null,"retry_after_seconds":null},"exit":2}
```
