`marfa` is Marfa's command-line client. Every published operation has a command, such as `marfa items list` for `GET /items`. The command is also a device: `marfa device` keeps a working copy of a slice of an instance, and `marfa folders` keeps a slice as files in a directory. `marfa operations` prints each operation next to the command that reaches it.

## Install

Each [release of Marfa on GitHub](https://github.com/withmarfa/marfa/releases/latest) carries the command for macOS on Apple silicon, as `marfa-<version>-darwin-arm64.tar.gz`. The archive holds the `marfa` binary and nothing else.

Download the archive from the release page. With the GitHub CLI, `gh release download --repo withmarfa/marfa --pattern 'marfa-*-darwin-arm64.tar.gz'` downloads the same archive to the current directory.

Unpack it in the directory that holds it, such as `~/Downloads`:

```bash
tar -xzf marfa-*-darwin-arm64.tar.gz
```

Move `marfa` to a directory on your `PATH`, then check it runs:

```bash
marfa --version
```

To build it from source instead, clone [withmarfa/marfa](https://github.com/withmarfa/marfa) and run `cargo install --locked --path core/marfa-cli` in the clone.

The reference on this page is generated from the command's help on the `main` branch of withmarfa/marfa, so it can list a command that the latest release doesn't have. `marfa --help` and `marfa <command> --help` print the help of the build you have.

## Choose a server and a credential

A command that talks to a server uses the first server and the first credential that is set, in this order:

| What | First | Then | Then |
| --- | --- | --- | --- |
| Server | `--url` | `MARFA_API_URL` | The current server in the keychain |
| Credential | `--key` | `MARFA_API_KEY` | The credential the keychain holds for that server |

The keychain is the operating system's keychain. It holds one credential for each server. Keeping one there, with `marfa login` or `marfa keys keep`, makes that server the current server, which a command uses when nothing else names one. On macOS, `MARFA_KEYCHAIN` names a keychain file to use instead, for runs with nobody to answer a prompt.

`marfa login` signs the command in to a server as an app: it shows a code, you approve it in the browser as the owner, and the command keeps the app's access token in the keychain. The token holds only the scopes you approve, and by default it doesn't ask for `instance.read`, `instance.maintain`, `connectors.manage`, `blobs.manage` or `keys.manage`, so a command that needs one of those doesn't work with it. `marfa logout` revokes the token and forgets it. To give a script or a connector its own key instead, see [Keys and permissions](/get-started/keys-and-permissions).

On the instance's own machine, running under the server's account, `--socket <path>` uses the machine's own authority through the server's private socket, with no credential and no keychain. `marfa setup status`, `marfa setup code`, `marfa setup open` and `marfa owner recover` need it. A command whose answer streams, such as `marfa blobs download`, goes through the socket too. The socket carries no key, so a command whose operation needs one, such as `marfa export` or `marfa events`, is refused `401`, and the command says to run it without `--socket` ([`device/local-socket-needs-key`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/device.md#devicelocal-socket-needs-key)). A command given `--socket` refuses to run while `MARFA_API_URL` or `MARFA_API_KEY` is set.

`marfa whoami` asks the server a command would reach, and prints that server, its instance, and the credential the command would send and where it came from.

## JSON output

`--json` prints the answer as JSON on stdout. A refusal is then one JSON object on stderr, after any warning line. It holds the error's `code` and `message`, the server's own status and code in `server` (or `null`), `retry_after_seconds`, and the exit code in `exit`:

```bash
marfa status --json
```

```json
{"error":{"code":"no_server","message":"no server named: pass --url or set MARFA_API_URL","server":null,"retry_after_seconds":null},"exit":2}
```
