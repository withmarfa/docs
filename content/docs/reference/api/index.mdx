Everything an app, a script or a connector does with an instance goes through its HTTP API, and the CLI, the TypeScript SDK and the Swift SDK send the same requests. Each operation has a page generated from the API description, so it matches the server.

## Operations by area

The operations fall into five areas: **Data** (items and everything attached to them), **Changes** (following what happens to them), **Access** (keys, apps and the owner), **Connectors** (what the instance keeps for each connector) and the **Instance** itself. Each area holds a group for each kind of thing an operation acts on, with its operations by method and path, in the order the sidebar shows them.

## Send a request

Send each request to your instance's address, such as `http://localhost:8600` for one on your own machine. Almost every operation takes a credential in the `Authorization` header: a key, which begins `marfa_k1_`, or an app's access token, which begins `marfa_at_`. [Access](/build/access) explains both, and [Manage keys](/run/manage-keys) shows how to make a key.

A request body is JSON, sent with `Content-Type: application/json`, except [Upload a blob](/reference/api/blobs/uploadBlob), which takes a file's bytes. This request makes a file item from a picture already uploaded:

```http title="Request"
POST /items HTTP/1.1
Host: localhost:8600
Authorization: Bearer <key>
Content-Type: application/json

{ "type": "core.file", "properties": { "title": "Tide chart", "blob_ref": "sha256:2bab1df2e7e3d2614e09a7dcb7f4adbf67c96cb6efaa0f1068ca19caed5610c8", "mime_type": "image/png" } }
```

Marfa answers `201 Created` with the new item and its metadata. It adds the blob's size itself:

```json title="Response" status="201"
{
  "item": {
    "id": "01a1f14c-4290-758b-9864-b91eedc89488",
    "type": "core.file",
    "state": "active",
    "tier": "library",
    "created_at": "2026-11-19T00:54:29.264Z",
    "updated_at": "2026-11-19T00:54:29.264Z",
    "last_activity_at": "2026-11-19T00:54:29.264Z",
    "occurred_at": "2026-11-19T00:54:29.264Z",
    "source": "laptop",
    "version": 1,
    "schema_version": 0,
    "trashed_at": null,
    "read_only": false,
    "properties": {
      "blob_ref": "sha256:2bab1df2e7e3d2614e09a7dcb7f4adbf67c96cb6efaa0f1068ca19caed5610c8",
      "mime_type": "image/png",

      "size_bytes": 69
    },
    "edges": {}
  },
  "metadata": { "item_id": "01a1f14c-4290-758b-9864-b91eedc89488", "tags": [], "extensions": {} }
}
```

A refusal answers with an `error` object instead, as [Errors](/reference/errors) explains.
