An agent that builds on Marfa does better with the current pages than with what it remembers. Each way below reads only this site: **none needs an instance or a credential, or can reach anyone's data.** To work with your data, connect an agent to your instance: [Work from an agent](/use/from-an-agent).

## Connect the docs MCP server

The docs MCP server runs at `https://docs.marfa.so/mcp`, over Streamable HTTP. Add it as a remote HTTP server:

<Tabs items={["Claude Code", "Codex"]}>
<Tab value="Claude Code">

```bash
claude mcp add --transport http marfa-docs --scope project https://docs.marfa.so/mcp
```

`--scope project` writes it to the project's `.mcp.json`. Leave it out to add it for yourself, or use `--scope user` for every project.

</Tab>
<Tab value="Codex">

```bash
codex mcp add marfa-docs --url https://docs.marfa.so/mcp
```

Codex writes it to `~/.codex/config.toml`.

</Tab>
</Tabs>

The server gives three read-only tools, and tells the agent to search first, then read the page:

| Tool | Input | Answer |
| --- | --- | --- |
| `docs_search` | `query`, and an optional `limit` from 1 to 50 | The pages that match, best first, each with title, path and snippets, never a written answer |
| `docs_fetch` | `path`, such as `/quickstart`, and an optional `section` | The page as Markdown, or the part under that heading |
| `docs_list_topics` | None | Every page, with title, path and description |

`section` names a heading by its text, in any case, or by its id. A path with no page answers `not_found`, and a heading the page lacks answers `section_not_found` with the page's `headings`.

**Each IP address may make 120 requests a minute.** Over it, a client gets `429` and a `Retry-After` in seconds.

## Search from a terminal

`marfa docs` reads this site from the [CLI](/reference/cli), for an agent that runs shell commands. It refuses `--url`, `--key` and `--socket`.

```bash
marfa docs search "sync a folder" --limit 1
```

`marfa docs topics` lists every page, and `marfa docs <page>` prints one. Name a page by its path, and add `--section` with a heading to print only that part:

```bash
marfa docs cli --section "Exit codes"
```

With `--json`, each command prints JSON. It exits `1` when there's no such page or section, and `3` when the site can't be read or limits the request ([exit codes](/reference/cli#exit-codes)). `MARFA_DOCS_URL` reads another copy of the site.

## Read a page as Markdown

Add `.md` to a page's path for its Markdown copy, such as `/quickstart.md`, or ask for the page's own address with `Accept: text/markdown`. A browser gets HTML.

<Terminal>

```bash
curl -H "Accept: text/markdown" https://docs.marfa.so/quickstart
```

```text
# Quickstart (/quickstart)

Install Marfa on your Mac or Linux computer, connect an agent to it, and save and find your first file.
```

</Terminal>

Three files cover the site:

| File | What it holds |
| --- | --- |
| [`/llms.txt`](/llms.txt) | A summary, then every page as the sidebar groups them, linked to its Markdown copy |
| [`/docs-map.md`](/docs-map.md) | The same index, linked to the HTML pages |
| [`/llms-full.txt`](/llms-full.txt) | Every written page in one file, without the API operations and the changelog |

`llms.txt` links each API operation to its HTML page, since its Markdown copy holds only its title and description. The changelog's copy is [`/changelog.md`](/changelog.md).

## Search over HTTP

Two addresses answer JSON:

- **`GET /api/docs/search?q=<query>&limit=<n>`** answers `{ "hits": [...] }`, each with `title`, `url` and `snippets`. A blank `q` or a `limit` outside 1 to 50 answers `400` with `invalid_query` or `invalid_limit`. Each IP address may search 60 times a minute.
- **`GET /api/docs/topics`** answers `{ "pages": [...] }`, each with `title`, `url`, `description` and `breadcrumbs`.

## What this site sends

This site and the status page at `status.marfa.so` send counts to PostHog's EU Cloud. **Neither sets a cookie, keeps anything in the browser or builds a profile of a reader.**

- **In the browser:** page views, and errors that break a page.
- **For agents:** a count of each request to the docs MCP server, the JSON addresses, the Markdown copies and the three index files, holding its kind, method, status, path, MCP method and tool, result count and a coarse class of client such as `claude-code`, **never an IP address, a cookie, a search query, a page's text or the `User-Agent`.**

Marfa itself sends nothing until its owner sets a destination: see [Send or turn off telemetry](/run/telemetry).
