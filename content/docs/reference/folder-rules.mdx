**A file you delete can move its item to the bin, and an item that leaves the folder can remove its file.** These rules decide when.

## What a folder takes in

The `include` and `ignore` lists, gitignore patterns, say which paths a folder reads, and `ignore` wins. **A path with a part that starts with a period is read only where an `include` pattern names it.** Whatever the lists say, a folder never takes in these:

| Never taken in | Names |
| --- | --- |
| Secrets | `.env`, `.env.*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, SSH keys such as `id_ed25519`, `.netrc`, `.npmrc`, `.pgpass`, `.git-credentials` |
| Files a computer keeps | `.DS_Store`, `Thumbs.db`, `._*`, `desktop.ini` |
| Temporary files | `*.swp`, `*~`, `*.tmp`, `*.part`, `*.crdownload` |
| Symbolic links | Not followed |
| Empty files | A file item holds bytes |

The contract [lists every name](https://github.com/withmarfa/marfa/blob/main/conformance/spec/folder-documents.md#folder-documentsbuiltin-secret-names).

## What a folder does with each file

| When | What the folder does |
| --- | --- |
| A new file matches the query | Creates its item, and writes `marfa_id`, `marfa_version` and any missing `type`, `tier`, `title` and `tags` into a note |
| A new note the query doesn't hold | Creates the item and keeps the file as unmatched, unless `outside_query` is `hold` |
| A photo, PDF or other file the query doesn't hold | Sends nothing, unless a note embeds it or it's attached to one |
| An item leaves the query's types, tiers, tags, filter or `beneath` | Keeps the file as unmatched, and sends its edits. Another folder that holds the item writes its own file |
| An item leaves the query's states, moves to the bin or is purged | Removes the file at the next pull, unless it changed since Marfa wrote it |

`marfa folders unmatched --remove` takes unmatched files off the disk once you confirm, keeping any changed since the folder wrote it. **The items stay.** With `outside_query` set to `hold`, a new file the query doesn't hold waits, flagged `outside_query`, with no item, until the query holds it.

## Deleting, moving and renaming

- **You delete a file:** its item moves to the bin after a five-second grace, so a save that replaces a file isn't a delete. If another device changed the item, the file comes back.
- **You move or rename a file:** the item stays, also between two folders on one computer. Where the folder you move it into doesn't hold its item, the file stays there as unmatched and the folder it left writes its own again.
- **You rename a file to a name the folder doesn't send, or holds for a clash:** the item stays with it, flagged `carried`. A new file at the old path is held, flagged `waiting`, until the carrying file takes a name the folder sends or goes. A backup name, the file's own plus a suffix such as `.bak`, carries nothing.
- **The folder can't tell where a file went,** because another folder can't be read or several hold its bytes: the deletion waits.

**A pull never replaces or removes a file a program holds open for writing,** even to change its `marfa_` lines. It flags the file `busy` and writes it after the program closes it. On macOS, Marfa sees only your own programs.

**A save made as Marfa writes goes back at the path,** or, where the path is taken, under a numbered name flagged `kept` ([Conflicts](/use/conflicts#a-save-made-as-marfa-writes)). Where Marfa can't tell, as on a network disk, it keeps the replaced file as `.marfa-kept-<id>.tmp`, flagged `kept`, and a program's write to it goes back the same way. Unchanged, it is deleted once no program holds it, or after seven days. `marfa folders kept` lists them, and `--discard` settles them now.

## File names

A new item's file is named from its title: `/`, `\` and `:` become `-`, control characters blanks, whitespace at either end and leading periods go, and an empty name is `untitled`. A name is cut to 255 bytes, keeping its extension.

**A file item's title without an extension gets its type's,** as `Boiler receipt.pdf`, unless the type has none or is a document's, such as `.md`. The title stays, and a file already placed keeps its name. **A note new to a directory is written in the form the first directory wrote it,** held on its [`in-folder`](/catalog/edges/in-folder) edge.

**Names that differ only in case or Unicode form are one name:**

| When two items claim one name | Which keeps it |
| --- | --- |
| Neither has a file yet | The one created first. The other gets `Plan (2).md` |
| One already has its file there | That one |
| Two files on disk differ only in case | The one already bound, or else the first. The other is held, flagged `name`, until you rename it |

## Large changes

A folder holds a large addition or removal until you [confirm it](/use/fix-a-folder#a-large-addition-waits), and a confirmation lets go only of items no file carries. **Nothing moves to the bin while a removal waits.** The first sync isn't an addition, and edits go on while one waits. Set the thresholds with `--removal-threshold` and `--addition-threshold`:

| Setting | Default | Pauses when |
| --- | --- | --- |
| `removal_threshold.files` and `.fraction` | `10` and `0.25` | One pass would remove over 10 files and a quarter of the folder |
| `removal_threshold.ceiling` | `100` | One pass would remove over 100 files |
| `addition_threshold.files` and `.fraction` | `50` and `0.25` | New files of the last ten minutes exceed both. An empty folder judges by count alone |

## What it holds back

- **A write larger than the server takes in one request** is held, flagged `refused` with its size and the limit. The limit is 1 MiB unless [`max_request_bytes`](/reference/instance-settings#stored-settings) sets another, and a file at nine tenths of it gets a `size` warning.
- **The folder's directory is missing,** as on a disk that isn't connected, **or can't be read:** nothing in it moves to the bin, flagged `unreadable`.
- **A volume can't rename safely,** such as exFAT on a Mac: Marfa replaces and removes no file there, and counts its item `unwritten`.
- **A different directory stands at the folder's path:** the folder doesn't read it, and resumes when the original returns.

A push's [exit code](/reference/cli#exit-codes) says how it ended, a [rate limit](/use/fix-a-folder#the-server-asked-for-a-wait-before-more-is-sent) included. The rules are in the contract's [folder-guards](https://github.com/withmarfa/marfa/blob/main/conformance/spec/folder-guards.md), [folder-files](https://github.com/withmarfa/marfa/blob/main/conformance/spec/folder-files.md), [folder-documents](https://github.com/withmarfa/marfa/blob/main/conformance/spec/folder-documents.md) and [folder-sync](https://github.com/withmarfa/marfa/blob/main/conformance/spec/folder-sync.md) chapters.
