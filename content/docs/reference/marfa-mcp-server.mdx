Every instance serves MCP over the Streamable HTTP transport. **Each tool call is an API call made with the credential the client sent**, so the API's permissions, refusals and limits apply. To connect, see [Connect your agent](/connect-your-agent); the rules are in the contract's [MCP chapter](https://github.com/withmarfa/marfa/blob/main/conformance/spec/mcp.md).

## Endpoints

| Endpoint | Tools | For |
| --- | --- | --- |
| `/mcp` | The everyday tools | Finding, reading, saving and changing items |
| `/mcp/schema` | The everyday and schema tools | Shaping what the instance holds: types, views and sources |
| `/mcp/admin` | The everyday and admin tools | Running the instance |

Connect an agent to the **smallest endpoint it needs**. Each takes only `POST`, and sends its own `instructions`, naming only its tools.

## Sign-in and discovery

A request without a key or an app's access token as a Bearer credential gets a challenge:

```http title="Response"
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer resource_metadata="https://marfa.example.com/.well-known/oauth-protected-resource/mcp"
```

- **Protected resource metadata** is at `/.well-known/oauth-protected-resource` and the endpoint's path. Every endpoint lists the scopes `content:read`, `content:write`, `edge.*:read`, `edge.*:write` and `offline_access`. `/mcp/schema` adds `metadata.types:write`, `schema.write` and `system.view:write`, and `/mcp/admin` adds each permission an [admin tool](/reference/mcp-admin-tools) needs, so Full access shows every tool.
- **The authorization server is the instance:** its origin, such as `https://marfa.example.com`, is the issuer, and its metadata is at `/.well-known/oauth-authorization-server`.
- **The client signs in as any app does** ([OAuth](/build/connect-an-app)), with the instance's origin or an endpoint as `resource`. Its token works at the API and every endpoint.
- **A client can ask for more access.** When an app's token lacks a scope a call needs, the endpoint answers `403` with `WWW-Authenticate: Bearer error="insufficient_scope"` and the `scope` to ask for, before anything changes. A key gets a tool error instead.
- **A browser page calls an endpoint only from the instance's origin or an [approved page's](/build/connect-an-app#connect-a-web-page).** Any other `Origin` gets `403 forbidden`.

## Tools

An endpoint lists only the tools a credential can use. **A credential that may write a type gets all eight everyday tools, and a reader the four that read.** The tools `/mcp/admin` adds are on [MCP admin tools](/reference/mcp-admin-tools).

### Everyday tools

| Tool | What it does |
| --- | --- |
| `marfa_overview` | Types with counts, edge types, top tags, views and folders. With `type`, its fields and tables |
| `marfa_find` | Searches by words, or lists by type, tags, source, state, tier or dates: 20 entries, up to 50 |
| `marfa_get` | Reads up to 20 items in full, with versions and tables; `edges` adds edges, and `file_link` a file's download link for `ttl_seconds` |
| `marfa_read_rows` | Reads the rows of an item's [table](/build/tables), with a filter, a sort and totals: 50 rows, up to 1,000 |
| `marfa_create` | Creates an item, or saves a file from a web address or a chat |
| `marfa_update` | Sets or clears fields, or changes tags, edges, tier or state, such as a restore from the bin |
| `marfa_write_rows` | Puts, patches or deletes up to 200 rows, written whole or not at all |
| `marfa_delete` | Moves up to 20 items to the bin |

### Schema tools

| Tool | What it does | Offered when the credential |
| --- | --- | --- |
| `marfa_save_type` | Registers or changes a type | May register types, or holds `schema.write` |
| `marfa_save_view` | Makes or changes a saved view | Writes `system.view` |
| `marfa_move_items` | Moves every item of one type to another as a job | Writes a type |
| `marfa_bulk_save` | Creates up to 200 items, or with `mode: "upsert"` updates saved ones | Writes a type |
| `marfa_search_docs` | Says where to search these docs | Always |
| `marfa_sources` | Lists each source's name and mark | Always |
| `marfa_name_source` | Names a source: its own, one it claims, or any with `keys.manage` | Always |

### Hints

Every tool carries all four hints, so a client asks the person first only where it should:

- **Read-only and idempotent:** the listing and reading tools.
- **None of the three:** `marfa_create`, `marfa_take_backup` and `marfa_make_endpoint`.
- **Idempotent only:** `marfa_name_source` and `marfa_rename_sign_in`.
- **Destructive and idempotent:** `marfa_change_settings`.
- **Destructive:** every other tool.

`openWorldHint` marks the tools that can reach outside the instance: `marfa_create`, `marfa_manage_webhook`, `marfa_take_backup`, `marfa_maintain`, `marfa_change_settings`, `marfa_update_server` and `marfa_remove_file_copy`.

## Previews and confirmation

`marfa_delete`, `marfa_move_items` and the admin tools that remove, end, replace or restart act in two calls. **The first changes nothing** and answers a preview, naming every item it takes, with a `confirm` token. Once the person agrees, the agent sends the same arguments with the token. The admin tools' previews are on [MCP admin tools](/reference/mcp-admin-tools#previews).

- **A token is refused with `confirmation_stale`** when another credential sends it, after five minutes, or once what the preview showed changed, even unreadable items.
- **A token works once.** Sent again, `marfa_delete` answers `already_trashed`.

## Changing an item

`marfa_update` takes the `version` the agent read. **Unlike [Update an item](/reference/api/items/updateItem), it never merges a stale change**: if the item changed since, nothing is written, and `version_conflict` holds the item in `current` and, in `conflicting_fields`, each field of the call changed since. If it changes partway through, `failed_step` names the refused step and `applied` those written.

## Long answers

- `marfa_find`, `marfa_read_rows` and `marfa_trash` answer a `next_cursor` when more follows; send it back as `cursor`.
- `marfa_get` keeps each answer within **40,000 characters**. `cut` names each cut field by `id`, `field` and `next_offset`; call again with those, as `offset`, for the rest. `not_returned` names the items that didn't fit.

## Saving a file

`marfa_create` saves a file from a web address in `url`, or one attached in a chat in `file`, as a [file item](/build/files). It fetches **only from public addresses**, with no redirect, and answers a refusal `file_not_fetched` with a `reason`:

| `reason` | When |
| --- | --- |
| `not_public`, `redirect` | Not a public address, or a redirect |
| `bad_url`, `unreachable` | Not `http` or `https`, or no answer |
| `status` | An error answer, such as an expired chat link |
| `too_large`, `timeout` | Past the [settings](/run/settings) `mcp_fetch_max_bytes` (50 MiB) or `mcp_fetch_timeout_seconds` (60) |
| `busy`, `rate_limited` | Four fetches running, or 30 in `rate_limit_window_seconds`; retry after `retry_after_seconds` |
| `disabled` | `mcp_fetch_enabled` is `false` |

## Tool errors

A refused call is a tool result with `isError` set, holding one JSON object:

```json
{ "error": { "code": "version_conflict", "message": "…", "hint": "Read the item again with marfa_get…" } }
```

The `code` is an API [error code](/reference/errors#codes), or the tools' own `confirmation_stale`, `file_not_fetched` or `not_offered_over_mcp`. An argument the tool doesn't take is refused by name.

## Protocol

- **Revisions:** MCP 2026-07-28 with no `initialize` handshake, and 2025-11-25 and earlier through `initialize`, with the same tools.
- **No sessions or streams:** `subscriptions/listen` answers `-32601`. Follow changes with [events](/build/events).
- **Audit:** a tool's write is recorded with the credential, the caller's address and `"via": "mcp"`.
