An instance reads two kinds of setting. **Stored settings** live in its database and change while it runs: [Change an instance's settings](/run/settings) shows how. **Start-only settings** are environment variables the server reads when it starts.

## Stored settings

A retention of `0` keeps those records with no age limit. The version windows must not decrease from recent to daily to weekly, and a type's own version policy takes precedence over the instance's. Secret settings are set but never shown back: `marfa config get` names them in `secrets_set`.

## Enforcement levers

`enforcement` is one stored setting that holds chosen types to a stricter rule. Each lever names `types`, and `source_allowlist` and `source_filter` also name `sources`:

```bash
marfa config update --body '{"enforcement": {"strict_mode": {"types": ["core.note"]}}}'
```

| Lever | What it does | What the caller meets |
| --- | --- | --- |
| `strict_mode` | Refuses a write that names a property neither the item's type nor an ancestor declares. Without it, Marfa keeps an undeclared property and serves it back. | `400 invalid_properties`, with `details.code` set to `unknown_property`. |
| `source_allowlist` | Lets only the listed sources create items of a type. | `403 forbidden`, with `details.type`, `details.source` and `details.allowed`. |
| `source_filter` | Leaves items of a type whose source isn't listed out of listings, searches, exports, event streams and webhook deliveries. | Nothing: the item isn't there. |

`strict_mode` and `source_allowlist` hold for exactly the types they list, **not the types that inherit from them.** `source_filter` also covers the types under a listed type. **Reading an item by its ID isn't filtered.** An item with no source counts as one whose source is `unknown`.

An update that names `enforcement` replaces all three levers, and `null` removes them. A key can carry levers of its own in `enforcement_override`, each replacing the instance's for that key: [Manage keys](/use/manage-keys) shows `--enforcement-override`.

## Start-only settings

Most instances set none by hand: the install, the image and the Railway template set the ones they need. The `MARFA_TEST_` settings are for Marfa's own tests: leave them unset. A `MARFA_` name the server doesn't read only warns, and names the setting you may have meant.
