While `marfa folders watch` runs, it keeps the state of its folders in `folder-watch.json`. Any program on the computer, such as a menu bar app, can read it **without a credential, the network or a store.** [Keep folders syncing](/use/keep-folders-syncing) covers the watch.

## Where it is

The file sits beside the folder registry, `folders.json`: in `Library/Application Support/Marfa` under the home directory on macOS, and in `$XDG_DATA_HOME/marfa` or `.local/share/marfa` elsewhere. **Parse the whole file on each read:** a watch replaces it in one step.

## The shape

```json
{
  "version": 1,
  "processes": [
    {
      "pid": 72786,
      "build_version": "0.0.89",
      "started_at": "2026-11-19T00:05:50.939Z",
      "heartbeat_at": "2026-11-19T00:06:13.980Z",
      "heartbeat_interval_seconds": 5,
      "ended_at": null,
      "folders": [
        {
          "dir": "<notes-directory>",
          "folder": "01a1f11f-27d4-73fe-9429-dfc839d24eb9",
          "watching": true,
          "reason": null,
          "paused": false,
          "last_success_at": "2026-11-19T00:05:51.293Z",
          "first_sync_waiting": false,
          "problems": [],
          "pending_uploads": 0,
          "pending_downloads": 0,
          "paused_removals": 0
        }
      ]
    }
  ]
}
```

`processes` holds one entry for each watch on the computer.

| Field | Type | Description |
| --- | --- | --- |
| `pid` | `number` | The watch's process ID. |
| `build_version` | `string` | The CLI version running the watch. One that differs from the installed CLI's is an earlier build still running. |
| `started_at`, `ended_at` | `string`, `string` or `null` | When the watch started, and stopped (`null` while it runs). |
| `heartbeat_at`, `heartbeat_interval_seconds` | `string`, `number` | When the watch last wrote its entry, and how often it does: at least every `5` seconds. |
| `folders` | `object[]` | The folders the watch was asked to hold. |

Each folder holds:

| Field | Type | Description |
| --- | --- | --- |
| `dir`, `folder` | `string` | The folder's directory, and its ID. |
| `watching` | `boolean` | Whether the watch holds the folder now. A folder tried again after a failure counts after about 10 seconds. |
| `reason` | `string` or `null` | Why the folder isn't watched. `null` while it is, and before a first try. |
| `paused` | `boolean` | Whether the directory's sync is paused. Missing means `false`. |
| `last_success_at` | `string` or `null` | When a sync last finished with nothing pending and no blocking problem. |
| `first_sync_waiting` | `boolean` or `null` | Whether the first sync waits for you. |
| `problems` | `object[]` or `null` | The current problems, each a `code` with its `count`. |
| `pending_uploads`, `pending_downloads`, `paused_removals` | `number` or `null` | Files waiting to be sent, files the last pull couldn't write, and removals waiting for confirmation. |

**The last six fields are the folder's latest report to the server,** the one `marfa folders health` reads ([how a report is counted](https://github.com/withmarfa/marfa/blob/main/core/marfa-cli/FOLDER-HEALTH.md)). They keep their last values while the folder isn't watched, and are `null` until this watch has read a report: `null` in `problems` means unknown, `[]` none.

## Reasons

A watch of every folder tries an unwatched folder again, and `reason` changes with each attempt.

| `reason` | Meaning |
| --- | --- |
| `first_sync_waiting` | The first sync waits for `marfa folders confirm`. |
| `paused` | Paused with `marfa folders pause`. A running watch of one directory keeps running and records it. |
| `missing` | The directory can't be found, as on a disk that's away. |
| `handed_over` | A command such as `marfa folders confirm` holds the folder. |
| `instance_changed` | Another Marfa instance answers at the folder's address. Tried again when its key, server or settings change, or hourly. |
| `signed_out` | The sign-in ended. Watched again after `marfa login`. |
| `no_credential`, `no_keychain`, `unauthorized` | The watch has no credential it can use. |
| Another code | The error that keeps the folder out, such as `io`. |

## Problem codes

`problems` uses a closed set of codes:

| `code` | Counts |
| --- | --- |
| `conflict` | Unresolved conflicted copies. |
| `refused` | Files whose write the server refused. |
| `credential_refused`, `unavailable` | `1` when the credential is refused, or the server can't be reached or answers `403`, `429` or a `5xx`. |
| `unreadable` | Files and directories that can't be read. |
| `held_file` | Files held for another reason, such as a name clash. |
| `root_gone`, `settings_invalid` | `1` when the directory is missing, or the settings file can't be used or written. |
| `unwatched` | Directories the system's file watch can't register. |
| `paused` | `1` while paused. |

## Decide whether an entry is current

An entry is **current** when `ended_at` is `null` and `heartbeat_at` is no later than now and less than three `heartbeat_interval_seconds` before it. A folder is watched when a current entry lists it with `watching: true`.

- **A watch that's killed** can't set `ended_at`; its heartbeat ages instead. `pid` is only a hint, since IDs are reused.
- **One folder can appear in two entries:** a watch of every folder lists a folder that a watch of its directory holds as not watched.
- A watch drops other processes' entries whose heartbeat is an hour old or in the future.

When the file's lock stays held past three intervals, or the file can't be written, the watch says so once and goes on syncing while its entry ages. The rules are in the contract's [record of folder watches](https://github.com/withmarfa/marfa/blob/main/conformance/spec/folder-setup.md#the-record-of-folder-watches).
