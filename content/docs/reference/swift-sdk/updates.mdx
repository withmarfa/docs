A working copy follows its server's events **only while the app holds a stream.**

| Call | Gives | Use it for |
| --- | --- | --- |
| `LiveQuery(_:reading:)` | An `@Observable` value that rereads itself | A SwiftUI screen |
| `updates()` | `CopyUpdates`, coalesced, with the connection | An app's own read model |
| `changes()` | `AsyncStream<Change>`, every change | Logs, tests and one kind of change |
| `changes(since:most:)` | `CopyChanges`, what changed since a cursor | Rereading after a relaunch |

## Live queries

```swift
@State private var recent = LiveQuery(copy, reading: .list(ListFilters(types: ["core.file.image"])))

var body: some View {
    List(recent.value, id: \.id) { item in Text(item.title ?? "Untitled") }
}
```

`LiveQuery` is a `@MainActor` class. It reads at once, again after each update that could change its answer, and holds a stream while it lives.

| Property | Holds |
| --- | --- |
| `value` | The last successful answer, or the placeholder before one. |
| `isLoading`, `error` | Whether a read runs, and why the last failed. `value` keeps the last good answer. |
| `connection` | The copy's [connection](#the-connection). |
| `reading` | What it reads. **Assigning it starts a new read** and drops one still running. |

`refresh()` reads now. A `Reading` is a read and its placeholder: make one with `Reading(placeholder:_:)`, or use `.list(_:sort:)`, `.search(_:filters:limit:)`, `.item(_:)`, `.queue`, `.views`, `.view(_:)`, `.list(inView:limit:offset:)` or `.groups(inView:timeZone:)`. `Rows` carries a `completeness`: `.complete`, `.partial` during a hydration, or `.stale`.

## Copy updates

```swift
for await update in copy.updates() {
    switch update.reread {
    case .everything: await reloadAll()
    case .parts(let parts): await reload(parts)
    }
    show(update.connection)
}
```

**The first update asks to read everything.** Each later one names what changed since the one before, and at most one waits while the app reads. Iterate a sequence once.

A `CopyUpdate` holds `reread` (`.everything` or `.parts(Parts)`), `connection`, `fill` (a hydration's `listed` against `expected`, with `fraction`) and `lastSynced`. **A part a `Reread.Parts` doesn't name is unchanged:**

| Part | Read again |
| --- | --- |
| `rows.items`, `rows.removedItems` | Items held, and no longer held. Read with `items.get(_:includingBin:)`; one missing went to the bin. |
| `rows.edges`, `rows.removedEdges` | Edges held, and no longer held. |
| `rows.tables` | Each held table that changed, as `itemId` and `table`. |
| `queue`, `catalog` | `queue.all()`, `copy.catalog`. |
| `views` | `items.views()`, after this copy wrote a view. A view another device writes arrives in `rows.items`. |

An update carries `.everything` when more than 1,000 items, edges or tables changed, and while a hydration fills.

### The connection

| `CopyConnection` | Means | The copy |
| --- | --- | --- |
| `.connecting` | Asking the server. | Waits. |
| `.following` | The server answered. | Follows its events. |
| `.offline(error)` | **A failure that may mend itself.** | Retries after 5 seconds, doubling to 5 minutes, never before a rate limit's `retryAfterSeconds`. |
| `.stopped(error)` | An error asking again may not clear, such as `noCatalog` or `wrongServer`. | Tries a catch-up every 5 minutes. |
| `.keyRefused(error)` | **The server refused the key or sign-in.** | Waits for [`use(_:)`](/reference/swift-sdk/working-copy#give-the-copy-a-new-key-and-close-it). |
| `.needsHydration(error)` | The copy expired, changed instance or never completed a hydration. | Waits for a hydration. |
| `.local`, `.closed` | No server, or a reader; the copy was closed, the last update. | |

Only a catch-up or hydration that succeeds makes a stopped or offline copy `.following`. An error the app's own arguments caused doesn't change the connection.

## Change streams

`changes()` tells each `Change` as it happens, with an `origin` and an `itemId` or `edgeId` where one row is named.

| `Change.Origin` | Means |
| --- | --- |
| `.local(WriteKind)` | The app queued a write. |
| `.server(event:cursor:)` | The copy applied a server event. With no `itemId`, rows' `readOnly` changed. |
| `.serverUnreachable(error)`, `.serverReachable` | The follow lost the server, told once, or a request reached it again: **the held stream then drains the queue.** |
| `.queueDrained(DrainReport)`, `.queueNotDrained(error)`, `.answered(DrainVerdict)` | A drain ended, stopped, or answered a write. |
| `.saved(dataVersion:)` | The writer saved; a reader reads again. |
| `.refreshed(Refresh)` | Many rows may have changed. `Refresh` is `.hydrated`, `.unfinished`, `.caughtUp`, `.drained`, `.withdrawn`, `.forgotten`, `.pinned`, `.unpinned`, `.purged`, `.folderWritten`, `.viewWritten`, `.catalog` or `.tables`. |
| `.stopped(error)` | What fed the stream stopped. Local writes are still told. |

**A stream that stops stays stopped** until the next hydration or catch-up, or until one is asked for while none is held. Streams stop when the follow fails with an error other than the network, and when a stale copy can't refill in place.

**When the event log lets the copy's cursor go,** as while a Mac sleeps, **the copy refills over the slice it holds,** keeping every row, queued write and file, and tells `.refreshed(.hydrated)`. A failed refill is told `.unfinished` and retried after 1 second, up to 5 minutes apart.

## Read only what changed

`changes(since:most:)` answers `.named(ChangedRows, next:)`, the rows to read again and drop, or `.everything(next:)`: with no cursor, one from another store or before a type change, or when more than `most` (default 1,000) rows changed in one category. **Keep `next.rawValue` across launches,** and the cursor you passed until you have read what the answer names. It throws `hydrationIncomplete` during a hydration or while stale. A link that resolves differently only because another item changed isn't named: read `items.links(in:)` again.

The rules are in the [device chapter](https://github.com/withmarfa/marfa/blob/main/conformance/spec/device.md), and [Keep a copy in sync](/build/keep-in-sync) explains following a server.
