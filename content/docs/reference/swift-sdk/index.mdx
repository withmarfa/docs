The Swift SDK is the `marfa-swift` package. **An app built on it is a [device](/build/working-copies)**: it keeps a working copy of part of an instance, reads it offline, and sends its writes when it reaches the server. A script or a server needs no copy: use the [TypeScript SDK](/reference/typescript-sdk). [Build an app with Swift](/build/swift-app) builds one.

## Install

The SDK supports iOS 27 and macOS 27 and builds with Xcode 27 on a Mac with Apple silicon. Choose **File** > **Add Package Dependencies**, enter `https://github.com/withmarfa/marfa-swift`, set **Dependency Rule** to **Exact Version**, and enter the [latest release](https://github.com/withmarfa/marfa-swift/releases/latest). In a `Package.swift`:

```swift title="Package.swift"
.package(url: "https://github.com/withmarfa/marfa-swift", exact: "<latest release>"),
// in your target's dependencies:
.product(name: "Marfa", package: "marfa-swift"),
```

- **Update deliberately.** Until 0.1 any release can rename a call or add an enum case, so read the [release notes](https://github.com/withmarfa/marfa-swift/releases) and switch over the SDK's enums without `@unknown default`.
- **Each release carries one core,** already built, so the app needs no Rust toolchain. Its notes name the Marfa commit the core came from: update the SDK when you upgrade the instance.
- **The core is built for Apple silicon only.** In **Build Settings**, choose **All**, then set **Excluded Architectures** to `x86_64`, or a simulator build fails to link.

| Product | Holds |
| --- | --- |
| `Marfa` | The SDK. |
| `MarfaAPI` | `Client`, for [operations the copy doesn't make](#the-api-client). |
| `MarfaTypes` | The wire types. |
| `MarfaTesting` | A [fake copy](/reference/swift-sdk/errors-and-testing#test-against-a-fake-copy) and an in-memory keychain. Empty in a release build: wrap it in `#if DEBUG`. |
| `MarfaIcons`, `MarfaBrandIcons` | [Type icons](#draw-a-types-icon), and the brand marks they can name. |

## Sign in

A `Server` is an address and a credential. A working copy, [`Folders`](/reference/swift-sdk/items#folders) and `Client` each take one. **`Authorization` signs an app in with the owner's approval** and keeps the sign-in in the keychain, so the app never sees the owner's password.

```swift
import Marfa

let auth = try Authorization(
    server: serverURL,
    client: .init(
        name: "Shoebox",
        redirect: URL(string: "com.example.shoebox:/signed-in"),
        scopes: ["core.file:read", "core.file:write"]),
    service: "com.example.shoebox")

let credential: Credential
if let kept = try auth.credential() {
    credential = kept
} else {
    credential = try await auth.signIn(presentingFrom: window)
}
let server = try Server(url: serverURL, credential: credential)
let copy = try await WorkingCopy.open(store: storeURL, server: server)
```

| Make a `Server` with | For |
| --- | --- |
| `Server(url:credential:)` | A sign-in from `Authorization`. Throws `SignInError.otherServer`, `.notSignedIn`, or `.notAServer` for an address holding a user or password. |
| `Server(url:key:)` | An API key. Throws `AddressError.userInfo` for an address holding a user or password. |
| `Server.fromEnvironment()` | `MARFA_API_URL` and `MARFA_API_KEY`, or `nil` when neither is set. **Throws `Server.EnvironmentError` when only one is set,** or when the address names no server. |

`Server.description` never shows the key. Show `plainHTTPOrigin`, set for plain `http` to another machine, as a warning. **Every request names the contract the build was made for,** and a server on another contract answers `412 contract_mismatch`, which throws `contractMismatch`.

- **`redirect` is a private-use address:** a reverse domain name you control, with a path and no host, claimed in `CFBundleURLTypes`.
- **`scopes` are what the app asks for,** and `permissions:` adds [instance permissions](/catalog/permissions). **The owner may approve fewer:** check `credential.grants(_:)` before offering a control.
- **A new sign-in ends the grant it replaces,** leaving one approval among the [connected apps](/use/see-and-revoke-access). Where `Credential.replacedGrantStands` is `true`, tell the person to remove the old one.
- **The SDK reads sign-in metadata only at `/.well-known/oauth-authorization-server`,** and refuses an `issuer` or endpoint outside the instance's origin.

| `Authorization` call | Does |
| --- | --- |
| `credential()` | The kept sign-in, or `nil`. |
| `signIn(presentingFrom:prefersEphemeralWebBrowserSession:)`, `signIn(using:)` | The browser sign-in, from a window or SwiftUI's `webAuthenticationSession`. |
| `startDeviceSignIn()` | A `DeviceSignIn` for a device with no browser: show its `userCode` and `verificationURL`, then wait on its `credential()`. |
| `signOut()` | Deletes the sign-in, then revokes it. Returns `.endedAtServer`, `.nothingKept` or `.notConfirmed`. |

A sign-in throws a `SignInError`: `.canceled`, `.denied` or `.expired` for the person's choice, `.stateMismatch` or `.issuerMismatch` for an approval it didn't ask for, `.notSignedIn`, `.otherServer`, `.notAServer` or `.noRedirect` for an unusable address or keychain, `.refused`, `.unavailable` or `.unreadable` for the server's answer, and `.heldElsewhere` when another process held the keychain.

Once the server ends a sign-in, calls throw `signedOut`. [Connect an app with OAuth](/build/connect-an-app) explains the flow.

### Confirm it's you

Some acts need a sign-in from the last fifteen minutes: restoring an archive or backup, moving the sign-in address, changing `allow_private_addresses`, and changing where files and backups go.

```swift
let server = try Server(url: serverURL, credential: credential).confirming(from: { window })
```

**A server made with `confirming(from:)` or `confirming(using:)` signs the owner in again and resends the call,** one sheet at a time. Without it, or at a second challenge, the call throws `confirmationRequired`. **A key can't make these calls** and throws `appSignInRequired`.

## Calls on the server

Each is sent at once, never queued, and **throws `noConnection` offline.** A `Server` waits 20 seconds in all, then throws `network`.

| `Server` call | Does |
| --- | --- |
| `instanceDescription()` | The `name`, `version`, `instanceId`, `contract` and `features`, read without the key. |
| `health(timeout:)` | An `InstanceHealth`, needing no key: `status` and each component's. **With `instance.read`, also errors, backup detail and housekeeping.** A down instance returns `.down`. |
| `snapshots(ofItem:after:limit:)` | A page of an item's earlier versions, oldest first. |
| `sources()`, `source(_:)`, `updateSource(_:name:mark:)` | The `ItemSource`s the key can see, and a rename. |
| `itemCountsBySource(type:state:tier:filter:)`, `itemCounts(of:_:)` | Counts by source, and for up to 100 IDs. |
| `setTypeIcon(_:ofType:expecting:)` | The owner's icon for a type. Needs `schema.write` and write on the type. |
| `install(pluginBundle:expecting:timeout:)` | Installs a [plugin from its bytes](#install-a-plugin). |

**Pass `expecting:` the instance ID** when a change must reach the instance the person saw: another instance throws `instanceChanged`. A history page's `next` is `nil` only at the end: a short page can have more.

### Install a plugin

`install(pluginBundle:expecting:timeout:)` sends a bundle's bytes unchanged to [`installPlugin`](/reference/api/plugins/installPlugin). The instance records the SHA-256 of those bytes as the plugin's `fingerprint`, so bytes from a [plugins release](#read-a-plugins-release) record the digest the release lists. **The generated `installPlugin` decodes the bundle and encodes it again, and that fingerprint differs.** `timeout` defaults to 20 seconds. Pass `expecting:` as the other calls do.

It needs `schema.write`, write on each type and edge type, and `connectors.manage` when the bundle has a connector. The answer is a `PluginInstalled`, and `outcome` is `.installed`, `.updated` or `.unchanged`. [Install a plugin](/use/install-a-plugin) lists the other refusals. **`pluginInstallRefusal` names the two an app tells the owner about,** and is nil for every other error, including when the newer-server details are missing:

| Case | Means |
| --- | --- |
| `.needsNewerServer(marfa:server:)` | `.server` for `409 plugin_needs_newer_server`. `marfa` is the oldest release the plugin works with, and `server` is the release this instance runs. |
| `.carriesGuidance` | `.forbidden` for `403 forbidden` whose `details.changes` names `guidance`. An app's sign-in, or a key an app made, cannot install guidance or change it. The same plugin with the guidance left out installs. |

### Read a plugins release

`PluginRelease` reads a release the way [the command line](https://github.com/withmarfa/marfa/blob/main/conformance/spec/cli.md#plugins) does, and **sends no credential.** It is not a call on your instance: a failure throws `PluginReleaseError`, and nothing reaches the server until you install. `PluginRelease()` reads the latest release of [withmarfa/plugins](https://github.com/withmarfa/plugins). Pass `address:` for another release, the address `MARFA_PLUGINS_URL` names for the command line. An address with a user name or password, or one that is not `http` or `https` with a host and no query or fragment, is refused before any request, and that error does not contain the address.

| `PluginReleaseError` | Means |
| --- | --- |
| `addressCarriesCredentials` | The address holds a user name or password. |
| `addressUnreadable` | Not `http` or `https` with a host and no query or fragment. |
| `unreachable(address:reason:)` | The release could not be read: the connection failed, a file was missing, or it was not a release this build reads. The index must be format 1, and each bundle file `<name>.plugin.json`. |
| `digestMismatch(file:found:listed:)` | The bundle's SHA-256 is not the one the index lists. Do not install those bytes. |
| `canceled` | The read was canceled. |

`index()` returns the plugins in the release's order. Each `PluginIndexEntry` has its name, its version, the oldest Marfa it works with, and the bundle's file and SHA-256. `bundle(for:)` returns a `ReleasedPlugin` only when the bytes match: install its `bytes`. A redirect is followed up to five times, never onto an address with a user name or password, and never from `https` to `http`. `timeout` is how long one request waits for more bytes, 30 seconds unless you set it.

`PluginVersion` reads `MAJOR.MINOR.PATCH` with no leading zero, such as `PluginVersion("0.0.13")`, and compares by those numbers. Any other string gives nil. **`0.0.0` is a development build:** `isDevelopment` is true, and `takes(_:)` accepts any plugin. Any other release accepts a plugin whose oldest Marfa is the same or older.

```swift
import MarfaAPI

let release = try PluginRelease()
let listed = try await release.index()
if let tickets = listed.first(where: { $0.name == "tickets" }) {
    let bundle = try await release.bundle(for: tickets)
    _ = try await server.install(pluginBundle: bundle.bytes, expecting: instanceID)
}
```

## The API client

**`Client` from `MarfaAPI` makes the operations the working copy doesn't**, with the same `Server`. Every other operation is a method named after its operation ID. A refusal throws a `MarfaError`, so read a success from `ok`: `try await api.listAuditLog().ok.body.json`.

```swift
import MarfaAPI

let api = Client(server)
let title = Components.Schemas.FieldDefinition(_type: .string, required: true)
let entry = Components.Schemas.TypeDefinitionInput(
    fields: .init(additionalProperties: ["title": title]), id: "app.readinglist.entry")
_ = try await api.check(itemType: entry)
_ = try await api.register(itemType: entry)
```

- **Types:** `check(itemType:)`, `register(itemType:)`, `replace(itemType:with:)`, `delete(itemType:force:)`, `register(edgeType:)`, `edgeTypes()` and `delete(edgeType:force:)`.
- **A call waits 30 seconds** for the answer to start, then throws `network`. `Client(server, timeout:)` changes it.
- **A date may carry fractional seconds.** `Client` reads one with or without them.
- **A delete of a type something names** throws `server` with `type_in_use`.

### Owner operations

| Calls | Do | Needs |
| --- | --- | --- |
| `getConfig`, `updateConfig` | Read and change the [settings](/run/settings). `updateConfig` can name `X-Marfa-Instance-Id` in `headers:`. | `config.manage` |
| `check(_ AddressChange)`, `apply(_:expecting:)` | Check a [change of address](/run/address), then make exactly that change. Show the check's `consequences` first. | `config.manage` |
| `listAppGrants`, `narrowAppGrant` | List the apps the owner approved, or narrow one. To end one, see [an app's data](#an-apps-data). | `grants.manage` |
| `restoreBackup` | [Restore a backup](/run/back-up-and-restore). | `backups.manage` |
| `changePassword(from:to:)` | Replace the owner's password once the current one proves right. Ends every browser sign-in of the owner, keeps keys and apps. | `sign_ins.manage` |

The restore and address calls need a [recent sign-in](#confirm-its-you). `changePassword(from:to:)` returns a `PasswordChangeOutcome`: `.changed`, `.currentPasswordWrong`, `.newPasswordRefused`, `.notPermitted(requiredScope:)` or `.tooManyAttempts(retryAfterSeconds:)`. **A wrong current password counts as an attempt at the owner's sign-in.** A failure with no answer to read throws a `MarfaError`, and the password may or may not have changed.

### An app's data

`Client` lists and deletes what an app keeps under an `app.<vendor>` namespace. Ordinary listings leave it out. The calls are [`listAppVendorData`](/reference/api/apps/listAppVendorData), [`deleteAppVendorData`](/reference/api/apps/deleteAppVendorData), [`revokeAppGrant`](/reference/api/apps/revokeAppGrant) and [`endSignIn`](/reference/api/sign-ins-and-passkeys/endSignIn). [Manage the data an app keeps for itself](/use/manage-app-data) is the same job from the command line. A grant from `listAppGrants` names its `vendors`.

<Callout type="warn" title="Only a backup or an export brings it back">
Deletion purges the items and the types. It is not a move to the bin. Tell the owner, and pass `.ownerConfirmed` only once they agree.
</Callout>

| Call | Does |
| --- | --- |
| `appData(vendor:limit:cursor:)` | One page. Every type under the namespace, registered or held by an item, with `active`, `archived` and `trashed` counts, on every page. Items in every state, the bin included, oldest first. `limit` is 1 to 200, and 25 when you omit it. Pass `nextCursor` as `cursor`. It is `nil` on the last page. |
| `removeAppData(vendor:_:expecting:)` | Deletes the namespace's items and types, sending [`deleteAppVendorData`](/reference/api/apps/deleteAppVendorData) again until none are left. Returns an `AppDataRemoval`. |
| `disconnect(grant:revokingKeys:data:)` | Ends the app's tokens and consent. `data` defaults to `.keep`. `.remove(.ownerConfirmed)` deletes every namespace the app holds in that same write. |
| `end(signIn:revokingKeys:data:expecting:)` | Ends that sign-in at once, this client's own included. `.remove` applies only to an app. |

Listing needs `grants.manage`, or the owner's browser session. An app's sign-in lists only a namespace its app holds, and a key also needs read on the types. Deleting also needs `items.purge`. A key or an app's sign-in also needs write on the types, and `schema.write` while a type is registered there. `disconnect` needs `grants.manage`, and `end` needs `sign_ins.manage`. Removing data on either also needs `items.purge`, and `schema.write` for a key or an app's sign-in.

The first failure from `removeAppData` is thrown. That includes `forbidden` naming `items.purge`, `grants.manage` or `schema.write`, `notFound` when no app or owner holds the namespace, and `validation` when the name is not an `app.<vendor>` namespace. It also includes `server` with code `type_in_use`, when a folder, view, webhook or table column outside the namespace names one of its types, or `type_has_subtypes`, when a type outside it inherits from one. A column of one of the namespace's own types does not count. Nothing is deleted.

A failure after the server has answered, cancellation included, is not thrown. **`stoppedBy` holds it, and `isComplete` is true only when `stoppedBy` is `nil` and `remainingItems` is 0.** `removedItems` and `removedTypes` count only answers the server gave, so list the namespace to see what remains. When the server deletes no item while some remain, `stoppedBy` is `invalid` and the call returns. The namespace stays with the app or the owner that holds it. Items outside it stay, and an edge from one of them to a deleted item goes.

**`.remove` while the app holds more than 1,000 items throws `validation` with code `bulk_cap_exceeded`, and nothing ends.** Delete each of the grant's `vendors` with `removeAppData` first. `end` refuses `.remove` for a browser sign-in or a key with `validation`, and ends nothing. `revokingKeys` also revokes keys the app made, and keys those keys made, except an owner's key. `expecting:` on `removeAppData` and `end` makes another instance throw `instanceChanged`.

```swift
let page = try await api.appData(vendor: "app.readinglist")
let removal = try await api.removeAppData(vendor: page.vendor, .ownerConfirmed, expecting: instanceID)
```

### Move the items of a type

A type's ID never changes, so renaming one means registering the new type, moving the items and deleting the old type. **The move is a job on the instance**, so a call that starts it returns before the items have moved.

| Call | Does |
| --- | --- |
| `previewMove(ofType:to:properties:)` | Counts what the move would take, and writes nothing. |
| `startMove(ofType:to:properties:)` | Starts the job, merging `properties` into each item (`null` removes one). |
| `follow(moveJob:every:)` | Polls the job until it ends. |
| `cancel(moveJob:)` | Stops the job. |

**Check the job's `result` before deleting the old type:** `remaining` counts what is left, and `remainingHidden` says some are out of the credential's sight. A setting the move can't rewrite throws `type_move_blocked`. [Change, rename or delete a type](/build/change-a-type) has the sequence and its code.

## Draw a type's icon

A type's icon is an Iconify ID from one of two pinned sets, such as `lucide:book-open` or `simple-icons:github`. **`ItemType.icon` is the one the type resolves to** ([display hints](/catalog/type-definition)).

```swift
import MarfaIcons

TypeIcon(type)                   // from an ItemType
TypeIcon(id: "lucide:book-open") // from an ID
```

**Brand marks need `MarfaBrandIcons.register()`** once at launch. A `nil` or unknown ID draws a fallback. `LucideIconSet.ids` and `MarfaBrandIcons.ids` list every ID the instance accepts.

The rules are in the contract's [device](https://github.com/withmarfa/marfa/blob/main/conformance/spec/device.md), [stores](https://github.com/withmarfa/marfa/blob/main/conformance/spec/stores.md), [queue and verdicts](https://github.com/withmarfa/marfa/blob/main/conformance/spec/queue-and-verdicts.md), [keys and sign-in](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#an-apps-own-data) and [plugins](https://github.com/withmarfa/marfa/blob/main/conformance/spec/plugins.md#installing) chapters.
