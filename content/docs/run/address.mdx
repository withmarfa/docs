This page will explain the instance's address once: a private address for your own devices, a public one for Claude and ChatGPT, and how to set it for each kind of install.

## Choose how it's reached

The way you reach the instance decides which caller address the server believes, so the command asks, and sets [the address](/run/address#the-address) and the proxy setting to match.

| `--access` | Reached | Address | Proxy setting |
| --- | --- | --- | --- |
| `local` | Only from this machine. | `http://localhost` and the port. | None. |
| `tailscale` | From your tailnet, through Tailscale Serve. | This machine's `ts.net` name, served with `tailscale serve` on port 443 unless you pass `--https-port`. The tailnet needs MagicDNS and HTTPS certificates. | `TRUSTED_PROXY_CIDRS` set to the range of the instance's Docker network. |
| `cloudflare` | Through a Cloudflare Tunnel on this machine. | The `https` address you give with `--address`. | `TRUSTED_PROXY_HEADER` set to `CF-Connecting-IP`. |
| `proxy` | Through another proxy on this machine, such as Caddy or nginx. | The `https` address you give with `--address`. | `TRUSTED_PROXY_CIDRS` set to the range of the instance's Docker network. |

**To use Marfa from Claude or ChatGPT in a chat, choose `cloudflare`, or `proxy` with a public address.** Their servers connect over the internet, which a tailnet address doesn't reach. `tailscale` suits your own devices and agents on your computer, such as Claude Code. [Connect Claude and ChatGPT](/use/claude-and-chatgpt) shows the rest.

The instance gets a Docker network of its own, named for the install (`marfa-net` unless you pass `--name`), and the command reads its range from Docker. The network is made once and kept when the container is replaced, so the range stays the one the setting names. The port is 8600, or the next free one, unless you pass `--port`. It is published on the loopback address only, so only a proxy or tunnel on the same machine reaches it.

**For `cloudflare` and `proxy`, point the tunnel or proxy at `http://localhost:` and the port, on the machine that holds the folder.** The summary repeats this as **Point at**, beside the machine's name. A tunnel aimed at another port, or running on another machine, makes the address answer `502`.

For `cloudflare`, also turn off Cloudflare's Email Address Obfuscation, or the instance's pages show email addresses as `[email protected]`. [The address](/run/address#the-address) says where.

## The address

`MARFA_AUTH_BASE_URL` is the URL your devices reach the instance at. The server uses it as the OAuth issuer and in its links. **The owner can claim the instance and sign in only over `https`**, or over `http` on `localhost`, `127.0.0.1` or `[::1]`.

Devices reach the instance on your local network, from anywhere over Tailscale, or through a Cloudflare Tunnel at an address on your own domain. Claude and ChatGPT connect from their own servers and [need a public address](/run/address#give-the-instance-a-public-address).

**Behind a proxy or tunnel, tell the server which caller address to believe.** Otherwise every request seems to come from the proxy, and anyone's wrong passwords count toward one address's limit of ten in fifteen minutes, locking the owner out. [`marfa server install`](/run/address#choose-how-its-reached) sets the right one. By hand, set one of these:

- **`TRUSTED_PROXY_CIDRS`** names the proxy's address ranges. The server believes `X-Forwarded-For` from any address in them, so list only your proxy. A proxy beside a container, such as Tailscale Serve, reaches it from Docker's network, which `docker network inspect bridge --format '{{json .IPAM.Config}}'` shows. Every container there is then trusted, so run nothing there you don't control.
- **`TRUSTED_PROXY_HEADER`** names a header the platform's edge overwrites with the caller's address, for a host whose edge addresses you can't list. Set it only when nothing reaches the server except through that edge, or any client can choose its address.

**Through Cloudflare, turn off Email Address Obfuscation**, or every email address on the instance's pages shows as `[email protected]`. Turn it off under **Security** > **Settings** in the Cloudflare dashboard, or for one hostname with a Configuration Rule.

## Give the instance a public address

The chat's servers reach your instance **over the public internet**, at an `https` address. An address on your local network or your tailnet works for an agent on your own computer, as [Use Marfa with AI agents](/use/from-an-agent) shows, but not for a chat.

A Cloudflare Tunnel gives the instance a public address on your own domain without opening a port on your network. Install it that way, or run the install again to change how it's reached:

```bash
marfa server install --access cloudflare --address https://marfa.example.com
```

[Install the server](/run/address#choose-how-its-reached) covers the other choices, such as your own proxy. On a public address, anyone can reach the instance's sign-in page, but every request for your data needs a credential, and only you can approve one.

## Choose the address

Your instance's address followed by `/mcp`, such as `https://marfa.example.com/mcp`, gives the chat tools to find, read, save and change items. **Use it unless you need more.** To design types or save views from a chat, add `/mcp/schema` instead, and to check the instance's health, read its audit log or manage keys and webhooks, add `/mcp/admin`. Each address is a connector of its own in the chat app. [Endpoints](/marfa-mcp-server#endpoints) lists what each one adds.
