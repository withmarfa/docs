An instance starts at `http://localhost`, which only its own computer reaches. **Your other devices need an `https` address.** Claude in a chat needs a public one on port 443, because it connects from Anthropic's servers. ChatGPT needs a public one or [OpenAI's Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels).

| You want to reach it from | Use |
| --- | --- |
| Only the computer it runs on | `local`, the default. |
| Your own computers and phone, wherever they are | [Tailscale](#reach-it-over-tailscale), with no public address at all. |
| Anywhere, Claude included, and ChatGPT without a tunnel | [Marfa Cloud](/run/marfa-cloud), [a Cloudflare Tunnel](#give-it-a-public-address), a proxy of your own, or [Railway](/run/run-on-a-server#on-railway). |

[Connect your agent](/connect-your-agent) says what each agent needs.

## Choose how it's reached

On a computer you [installed with one command](/run/install), `--access` sets the address, how the server listens and which caller addresses it trusts. Run the install again to change it:

| `--access` | Address | What the command does |
| --- | --- | --- |
| `local` | `http://localhost` and the port. | Nothing beyond the install. |
| `tailscale` | This computer's name on your tailnet, such as `https://your-mac.<tailnet>.ts.net`. | Serves the port with `tailscale serve`, on port 443 unless you pass `--https-port`. |
| `cloudflare` | The `https` address you give with `--address`. | Trusts the `CF-Connecting-IP` header from the tunnel. |
| `proxy` | The `https` address you give with `--address`. | Trusts `X-Forwarded-For` from the proxy. |

The server listens on `127.0.0.1` only, so only a proxy or tunnel on the same computer reaches it. **For `cloudflare` and `proxy`, point the tunnel or proxy at `http://127.0.0.1:` and the port,** which the command prints as **Point at**. Aimed elsewhere, the address answers `502`.

## Reach it over Tailscale

```bash
marfa server install --access tailscale
```

The tailnet needs **MagicDNS and HTTPS certificates** turned on in the Tailscale admin console, and the app running and signed in. The address works on every device signed in to your tailnet, and nowhere else. The command doesn't use Tailscale Funnel.

## Give it a public address

A Cloudflare Tunnel gives the instance an address on your own domain without opening a port, and needs a domain on Cloudflare: [Cloudflare's guide](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/create-remote-tunnel/) has the detail.

<Steps>
<Step>

### Make the tunnel

In the Cloudflare dashboard, create a tunnel of type `cloudflared`, and run the command it gives **on the computer that runs Marfa**.

</Step>
<Step>

### Route an address to the instance

Give the tunnel a public hostname, such as `marfa.example.com`, with the service `http://127.0.0.1:8600`, or the port the install chose.

</Step>
<Step>

### Tell the install

```bash
marfa server install --access cloudflare --address https://marfa.example.com
```

</Step>
</Steps>

On a public address anyone can reach the sign-in page, but every request for your data needs a credential, and only the owner approves one. **Turn off Cloudflare's Email Address Obfuscation** for the address, or the instance's pages show email addresses as `[email protected]`: it's under **Security** > **Settings**.

## Move the address

The stored setting `sign_in_address` is where the owner signs in: every app sends you there to approve it, your passkeys belong to it, and the links the server builds start with it. **The owner signs in only over `https`,** or `http` on `localhost`. `addresses` lists every address people reach the instance at, and always holds the sign-in address. `marfa config get` shows both.

Moving the sign-in address **signs out every browser and app,** and passkeys made for the old address stop working until it moves back. Grants and keys stay. Set up the tunnel or proxy first: **the server moves the address only when the new one answers as this instance within five seconds.** The move needs [a sign-in from the last fifteen minutes](/run/sign-in-as-the-owner#confirm-its-you):

```bash
marfa login --fresh-sign-in
marfa config set sign_in_address https://marfa.example.com
```

That is refused and changes nothing, but lists what the move would do. Run the same command with `--confirm-address-change` when you're ready. Then sign in at the new address, add a passkey and connect your apps again. On the server's own computer, `marfa server install --address` moves it for you.

## Behind a proxy of your own

Every request through a proxy seems to come from the proxy, so one person's wrong passwords could lock the owner out, and the [audit log](/use/audit-log) would record the proxy as every caller's `client_ip`. Two [start-only settings](/reference/instance-settings#start-only-settings) tell the server which caller address to trust: **`MARFA_TRUSTED_PROXY_CIDRS`** names the proxy's address ranges, so list only your proxy, and **`MARFA_TRUSTED_PROXY_HEADER`** names a header the platform's edge overwrites with the caller's address, safe only when nothing reaches the server except through that edge. `marfa server install` and the Railway template set these for you.
