---
title: Keep a synced directory's unsent edits after a restore
sidebar_label: Keep folder edits after a restore
description: Move a synced directory's unsent edits onto a restored instance, which refuses to take them from the directory itself.
job: An owner restores into a new instance and keeps the edits a synced directory held but never sent.
kind: how-to
---

**A directory that held edits the old server never received can't send them to the new instance.** Its push is refused `instance_changed`, and `marfa folders remove` refuses it while edits wait ([withmarfa/marfa#3402](https://github.com/withmarfa/marfa/issues/3402) tracks this). So take the files out, and let a new directory send them. A directory with nothing unsent needs only [Fix a folder](/use/fix-a-folder#now-answers-as-another-marfa-instance).

**Before you start,** [restore the backup](/run/back-up-and-restore#restore-a-backup) and sign the CLI in to the new instance. Do the steps once for each directory.

<Steps>
<Step>

### Move the directory aside

Note the folder's ID in `marfa folders list`, then move the directory away. Never edit or copy its `.marfa` folder.

```bash
marfa folders list
mv ~/Documents/Home ~/Documents/Home.old
```

</Step>
<Step>

### Take it off the list

The path is gone, so `remove` only forgets it and deletes nothing. Name the path as `folders list` shows it.

```bash
marfa folders remove ~/Documents/Home
```

</Step>
<Step>

### Add a new directory and let it write

Add the folder again by its ID, which the restore kept. The plan should say how many files it writes into the directory and that it sends none: answer yes, then push. **The new directory must hold the folder's files before you copy anything in:** a file copied in earlier that is not a note comes back as a new item beside the old one.

```bash
marfa folders add ~/Documents/Home --folder 01a1f46f-bed0-7310-bb7c-840868eb64ac
marfa folders push ~/Documents/Home
```

</Step>
<Step>

### Copy in what changed

Copy the files you added or changed out of `Home.old`, never its `.marfa`, and push again:

```bash
cp ~/Documents/Home.old/"Packing list.md" ~/Documents/Home.old/"New idea.md" ~/Documents/Home/
marfa folders push ~/Documents/Home
```

Delete `Home.old` once `marfa folders status` shows every file in step.

</Step>
</Steps>

## What each file becomes

- **A changed note or file** updates its item.
- **A new file** becomes a new item.
- **A note whose ID the backup never held,** because the old server made it after the last backup, becomes a new item under a new ID.
- **A file you deleted** in the directory is not deleted in Marfa: its item stays until you bin it.
