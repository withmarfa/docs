An instance is yours to run, so installing, upgrading and backing it up fall to you. These pages cover that work, from the first install to an upgrade, mostly with the CLI and a browser. To write code against an instance, go to [Build](/build).

<Cards>
  <Card title="Install with the CLI" href="/run/install">Take a Mac or Linux machine with Docker to an instance ready to claim.</Card>
  <Card title="Deploy" href="/run/deploy">Run an instance you keep, with storage that survives a restart and an address your devices reach.</Card>
  <Card title="Sign in as the owner" href="/run/sign-in-as-the-owner">Sign in to the owner's pages with a password or a passkey.</Card>
  <Card title="Manage keys" href="/run/manage-keys">Give a script a key that reaches only what it needs, then narrow, rotate or revoke it.</Card>
  <Card title="Manage apps" href="/run/manage-apps">Approve what an app may reach, then narrow or disconnect it.</Card>
  <Card title="Back up and restore" href="/run/back-up-and-restore">Copy the data directory and secrets, and bring them back.</Card>
  <Card title="Upgrade" href="/run/upgrade">Move to a new build, which updates the database after copying it.</Card>
  <Card title="Sync a folder" href="/run/sync-a-folder">Keep a directory on your computer in step with your items, as Markdown files.</Card>
  <Card title="Run a connector" href="/run/run-a-connector">Build a connector, give it a key of its own, and run it once or on a schedule.</Card>
  <Card title="Troubleshooting" href="/run/troubleshooting">The cause and the fix for a problem, found by the message Marfa shows.</Card>
</Cards>

Looking something up? The [Catalog](/catalog) lists what Marfa ships, and the [Reference](/reference) covers the CLI, the MCP server and the HTTP API.
