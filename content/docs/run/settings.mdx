An instance has two kinds of settings. **Stored settings** live in its database and change while it runs, from any computer with a key that holds `config.manage`. **Start-only settings** are environment variables the server reads once, when it starts. [Instance settings](/reference/instance-settings) lists every one with its default.

## Change settings while it runs

A stored setting **takes effect at once, with no restart.** Set one by name, and return it to its default with `unset`:

<Terminal>

```bash
marfa config set trash_retention_days 30
```

```text
set trash_retention_days
```

</Terminal>

`config set` refuses a value of the wrong kind before it sends anything, and **asks for a secret with no echo,** never as an argument. `marfa config settings` lists every stored setting with its value, and names every start-only setting without one.

To change several at once, send a body. **An update changes only the settings it names,** and `null` returns one to its default:

```bash
marfa config update --body '{"trash_retention_days": 30, "name": "Family archive"}'
```

`marfa config replace` sets the whole configuration instead: **a setting you leave out returns to its default,** so read it with `marfa config get` first. A value outside its rule is refused and nothing changes. A change applies to work that starts after it, and the [audit log](/use/audit-log) records it.

## Changes that need a recent sign-in

These need [a sign-in from the last fifteen minutes](/run/sign-in-as-the-owner#confirm-its-you), from the CLI signed in with `marfa login`, or the [private socket](/run/run-on-a-server#the-private-socket) on the server's computer. A key is refused:

- **Moving `sign_in_address`:** [Give your instance an address](/run/address#move-the-address).
- **Changing where files and backups go:** `backup_path` and the `object_store_` settings, as [Back up and restore](/run/back-up-and-restore#turn-on-backups) shows.
- **Changing `allow_private_addresses`.**

## Let webhooks reach a private network

Marfa sends only to public addresses: webhooks, `heartbeat_url`, `posthog_host`, the OTLP endpoints and `object_store_endpoint`. A loopback, private or Tailscale address (`100.64.0.0/10`), or a name that leads to one, is refused `400 validation_error`. To reach a receiver on your own network, turn on `allow_private_addresses`:

```bash
marfa login --fresh-sign-in
marfa config set allow_private_addresses true
```

**Leave it off** unless something you run needs it: it lets anyone who can register a webhook make the server send to your own network.

## Set a start-only setting

On a computer you [installed with one command](/run/install), add the setting to `marfa.env` in the install folder and run `marfa server restart`. In a container, change its environment and **create the container again:** a restart keeps the old environment. On Railway, change the service's variables, which redeploys it.

If a setting is outside its rule, the server opens no port, logs one line naming every wrong setting, and exits with status `1`. [Fix a server that won't start](/run/troubleshooting/start-and-claim) shows the message.
