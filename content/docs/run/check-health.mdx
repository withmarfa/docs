## Check that all is well

**`marfa attention` is the one check to run from any machine.** With `instance.read`, it names a degraded part of the server, a job that failed, a connector or folder with a problem, a key about to expire, and backups that aren't kept or have stopped. It prints `nothing needs attention` while all is well.

Two more checks fill it in:

- **`marfa update status`** says whether a newer release is out. Read [Upgrade an instance](/run/upgrade) before you move to one.
- **`marfa server status`,** on the server's own machine, says whether the service runs and answers, with the release, the address and whether backups are kept. When the server isn't answering, it shows the end of its log.

<Terminal>

```bash
marfa attention
marfa server status
```

```text
nothing needs attention
marfa 0.0.80: running and healthy
  Runtime   native, the launchd agent so.marfa.server.marfa
  Address   http://localhost:8600
  Folder    /Users/you/marfa-server
  Owner     set up
  Login     on
```

</Terminal>

## The housekeeping jobs

An instance looks after itself on a schedule: it empties the bin, thins old versions, moves expired feed items to the bin, clears old log entries, copies and checks files, and takes backups. Each piece of that work is a housekeeping job. **What each job last did shows whether the instance is keeping up,** and running one applies a changed retention without waiting.

Listing needs `instance.read`, and running needs `instance.maintain`. The [private socket](/run/run-on-a-server#the-private-socket) needs neither.

### List the housekeeping jobs

<Terminal>

```bash
marfa housekeeping list
```

```text
name                      every  next run                  last run                            result
enrichment-sweep          30 s   2026-11-19T00:44:05.544Z  succeeded 2026-11-19T00:43:35.544Z  {"extracted":0,"skipped":0,"failed":0}
audit-cleanup             1 d    2026-11-20T00:02:52.721Z  succeeded 2026-11-19T00:02:52.721Z  {"deleted":0,"deliveries":0}
trash-purge               1 d    2026-11-20T00:02:52.692Z  succeeded 2026-11-19T00:06:27.387Z  {"deleted":0}
```

</Terminal>

`--json` gives every field [List housekeeping jobs](/reference/api/health-and-maintenance/listHousekeeping) describes.

### Read what a job did

- **`last_outcome`** is `null` until a run finishes, then `succeeded`, `failed` with the reason in `last_error`, or `held` when the job did nothing because [the clock is far ahead](#when-the-clock-jumps-ahead) or a restore holds writes.
- **`last_result`** holds the job's own counts, such as `deleted` for a cleanup, `moved` and `held` for `feed-expiry`, and `copied` and `remaining` for `blob-replicate`, with `refused` naming each store that took no copy, and why.
- **`running_since`** is when the current run started, or `null`.

A job whose `last_outcome` stays `failed`, or whose `next_run_at` is long past, is **the place to look when an instance falls behind**. A run past its deadline is `failed`. `marfa attention` names a failing job too.

### What each job does

<include cwd>src/generated/housekeeping.md</include>

Retention windows and intervals are [stored settings](/run/settings#change-settings-while-it-runs), such as `trash_retention_days`, `audit_retention_days` and `event_log_retention_days`, and a change takes effect without a restart. **A retention of `0` keeps everything** of its kind.

Four jobs are listed only when something turns them on: `heartbeat` while `heartbeat_url` is set, `blob-orphans` while `blob_cleanup_enabled` is `true`, `backup` while a [backup place](/run/back-up-and-restore#turn-on-backups) is set and `backup_interval_seconds` is above `0`, and `release-check` while `update_check_enabled` is `true`. Running a job that isn't listed is refused `404 housekeeping_job_not_found`. Other jobs stay listed when their work is off, such as `enrichment-sweep` while `enrichment_enabled` is `false`.

#### Feed expiry

`feed-expiry` acts only on a type with a `feed_days` window in its [retention policy](/catalog/type-rules#retention-policy), set on the type or taken from a parent. Once an active feed item is older than that, counted from when it was created, which a connector's later updates don't change, the job moves it to the bin, where it can be restored until `trash-purge` deletes it. **Library items, archived items and items brought back from the bin stay.**

`held` counts expired items the job left because moving one would take an item that isn't expired with it, or an edge with `cascade_on_delete` set to `block` refuses it.

### Run a housekeeping job now

Name the job as the listing shows it. **The server runs it before it answers:**

<Terminal>

```bash
marfa housekeeping run trash-purge --json
```

```json
{
  "name": "trash-purge",
  "started_at": "2026-11-19T00:43:49.074Z",
  "finished_at": "2026-11-19T00:43:49.080Z",
  "outcome": "succeeded",
  "result": {
    "deleted": 0
  },
  "error": null
}
```

</Terminal>

A run that fails still answers `200`, with `outcome` set to `failed` and the reason in `error`. A run on demand never moves the next scheduled run later. While a run of the same job is in progress, another is refused `409 housekeeping_job_running`: try again when it finishes. [Run a housekeeping job](/reference/api/health-and-maintenance/runHousekeeping) lists every answer.

### When the clock jumps ahead

**While the server's clock reads more than seven days later than the time it last trusted, the jobs that delete do nothing.** A clock set wrong would otherwise judge everything old enough to remove. Those runs are recorded as `held`, and [Health](/reference/api/health-and-maintenance/getHealth) reports the instance `degraded`, with `housekeeping.held`.

If the clock is right, as after months switched off, confirm it with `instance.maintain`:

```bash
marfa housekeeping confirm-clock
```

An agent at `/mcp/admin` uses `marfa_maintain` with `action: "confirm_clock"`. A clock that runs a day without jumping is trusted by itself.

## Empty the bin

An item stays in the bin until it's purged. `trash-purge` purges each item once it has been in the bin longer than `trash_retention_days`, 60 days by default. `marfa items bin list` shows when each becomes eligible.

<Callout type="warn" title="A purge can't be undone">It deletes the items and their history. Emptying the bin has no dry run, so list the bin first.</Callout>

Emptying it now needs `items.purge` or the private socket:

<Terminal>

```bash
marfa items bin list
marfa items bin empty --confirm PURGE
```

```text
id    type           version  binned                    deletion                                name        binned by
<id>  core.bookmark  v1       2026-11-19T00:44:24.361Z  eligible from 2027-01-18T00:44:24.361Z  Fig jam     marfa on your-mac
<id>  core.bookmark  v1       2026-11-19T00:44:24.325Z  eligible from 2027-01-18T00:44:24.325Z  Lemon tart  marfa on your-mac
retention: 60 days
2 items deleted from the bin
```

</Terminal>

**A credential empties only the types it writes.** The command purges 200 items at a time until the bin is empty, and an item that changed or left the bin meanwhile stays. If it stops partway, run it again: a repeat is safe. To purge one item, run `marfa items purge <id>`. [Empty the bin](/reference/api/trash/emptyTrash) has the HTTP form.

The rules behind this page are in the [housekeeping](https://github.com/withmarfa/marfa/blob/main/conformance/spec/housekeeping.md) chapter of the contract.
