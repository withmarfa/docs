`marfa server install` runs the server as a service of this computer: a launchd agent on a Mac, a systemd service on Linux. It makes the server's two secrets, starts it, and **prints a link that claims the instance.** You need a Mac with Apple silicon, or Linux on x86_64 or arm64.

<Steps>
<Step>

### Install the programs

Marfa is two programs of one release: the CLI, `marfa`, and the server, `marfa-server`. Install both with Homebrew, or with the script, which puts both in `~/.local/bin`:

```bash
brew install withmarfa/tap/marfa
```

`marfa` uses only the `marfa-server` beside it. [The CLI page](/reference/cli#install) gives the script and its options.

</Step>
<Step>

### Run the install

Run it as yourself, not with `sudo`. It asks how your devices reach the server: choose `local` to start with this computer alone, and [give the instance an address](/run/address) later.

<Terminal>

```bash
marfa server install --access local
```

```text
Marfa 0.0.89 is running.
  Address   http://localhost:8600
  Folder    /Users/sam/marfa-server on sams-mac
Keep a copy of /Users/sam/marfa-server/marfa.env somewhere safe, outside this folder.
Open this link to choose the owner's username and password. It works once, for five minutes; run this command again for a new one.
  http://localhost:8600/setup#handoff=…
```

</Terminal>

If the server doesn't start, `marfa server status` shows the end of its log, and [Fix a server that won't start](/run/troubleshooting/start-and-claim) explains each message.

</Step>
<Step>

### Claim the instance

Open the link and choose the owner's username and password. Until the instance has an owner, run the command again for a new link. [Sign in as the owner](/run/sign-in-as-the-owner) covers passkeys.

</Step>
<Step>

### Keep a copy of the secrets

Copy `marfa.env` to a password manager or another safe place. **It's the only copy of `MARFA_KEY_SALT`:** with another one the server starts but refuses every key and app token, and you sign in again to make new ones. A [backup](/run/back-up-and-restore) restores without it. The install also says that **no backups are kept yet**: [set them up](/run/back-up-and-restore#turn-on-backups) next.

</Step>
</Steps>

## What the install holds

Everything lives in one folder, `marfa-server` in your home directory unless `--dir` names another. Its path plus `/data/control/marfa.sock` must fit a system's socket limit, so choose a short one.

<Files>
  <Folder name="marfa-server" defaultOpen>
    <File name="marfa.env" />
    <File name=".env" />
    <Folder name="data" defaultOpen>
      <File name="marfa.db" />
      <Folder name="blobs" />
      <Folder name="control" />
      <File name="marfa.settings.key" />
    </Folder>
  </Folder>
</Files>

`marfa.env` holds the [start-only settings](/reference/instance-settings#start-only-settings), `.env` what the install commands record, `marfa.db` the database, `blobs` the bytes of your files, and `control` the private socket that [claims the instance](/run/run-on-a-server#the-private-socket). `marfa.settings.key` seals secret settings: without it the server starts and asks you to set them again.

The folder decides the port, the listening address and the data paths, so the command refuses a `marfa.env` that sets them. If a secrets manager writes `marfa.env`, add `--external-settings`: the command then only checks the file and names what's missing.

## Look after the service

**On a Mac,** the service is the launchd agent `so.marfa.server.<name>`, started at login, with its log at `~/Library/Logs/Marfa/<name>.log`. **On Linux,** it's the systemd user service `marfa-<name>.service`, started at boot, with its log in `journalctl --user -u marfa-<name>.service`. As root, it's a system service under a `marfa` account, in `/var/lib/marfa-server`. `--name` lets one computer run several installs, each with its own `--dir` and `--port`.

| Command | What it does |
| --- | --- |
| `marfa server status` | Says whether it runs and answers, its release and address, and whether it has an owner. |
| `marfa server stop`, `start`, `restart` | Stop it, start it, or read `marfa.env` again. None changes the release. |
| `marfa server upgrade` | Moves the install to the release of the `marfa` you run: [Upgrade an instance](/run/upgrade). |
| `marfa server uninstall` | Removes the service and keeps the data. `--delete-data` also removes it, after you type the install's name. |

Run `marfa server install` again with `--access`, `--address` or `--port` to change them. It changes only what isn't already as asked, and never a secret. To run a server in Docker or under your own supervisor, see [Run Marfa on Railway or a server](/run/run-on-a-server).
