---
title: Fix a command that can't find its server or key
sidebar_label: Command can't find its server
description: Find the message a marfa command shows when it can't reach its server, find its key or read its profile, and fix it.
job: Someone whose CLI command can't reach its server, find its key or read its profile finds the message and fixes it.
---

A command that talks to an instance needs a server and a credential, from its options, the environment, a profile or the keychain. [Connect to a server](/reference/cli#connect-to-a-server) gives the order the CLI follows, and [Exit codes](/reference/cli#exit-codes) says what each code means. A message not listed here says what to do in its own words.

## request to … failed: the connection was refused

Nothing answers at that address: the server isn't running, or listens on another port. The CLI exits with `3`. Start the server, and check `MARFA_API_URL` or `--url`. For an install in another folder, `marfa server status --dir <folder>` shows where it listens.

## no server named

The full message is `no server named: pass --url or --profile, or set MARFA_API_URL or MARFA_PROFILE`, and the CLI exits with `2`. Set `MARFA_API_URL` to the instance's address, such as `http://localhost:8600`, or pass `--url`. With only a key, the message is `a key from --key or MARFA_API_KEY needs its server named`, and the CLI also exits with `2`: it never sends a key to a server you didn't name.

## no credential for …

The command knows the instance but has no credential for it, and the CLI exits with `5`. Set `MARFA_API_KEY`, sign in with `marfa login`, or keep a key with `marfa keys keep`. With the keychain off, only `--key`, `MARFA_API_KEY` or a profile with a `key_command` works.

## no profile file at … or no profile named …

`--profile` or `MARFA_PROFILE` names a profile the CLI can't find, and it exits with `2`. A name is exact: `Example` is not `example`. Write a section such as `[example]` with a `url` line in the file the message names, as [Name a server with a profile](/reference/cli#name-a-server-with-a-profile) shows.

## cannot be used with … or cannot be combined with …

A profile and `--url`, `--key`, `MARFA_API_URL` or `MARFA_API_KEY` each name a server, and the CLI won't guess which you meant: it would send one server the other's key. It exits with `2` and sends nothing. Drop one of the two, or unset the variables. `--profile`, `--url` and `--key` take precedence over the variables.

## the key command of profile …

The profile's `key_command` gave the CLI no key, and the CLI exits with `5`. The message ends with the reason. **The CLI runs the program with no shell and no standard input,** so give its full path, and make it print the key alone, as one line, without asking: sign in to the secrets manager first.

## --socket cannot be combined with MARFA_API_URL, MARFA_API_KEY or MARFA_PROFILE

`--socket` acts with the computer's own authority, so it refuses to run while the environment names a server, a key or a profile. Unset all three for the command:

```bash
unset MARFA_API_URL MARFA_API_KEY MARFA_PROFILE
```

## No such file or directory

With `--socket`, nothing is at that path, and the CLI exits with `3`: the server isn't running, or its data is elsewhere. The server makes the socket at `control/marfa.sock` in its data folder when it starts. Start it, and check the path: [the private socket](/run/run-on-a-server#the-private-socket) says where it is. A path through a symbolic link, such as `/tmp` on macOS, is refused: give the path with its links resolved.
