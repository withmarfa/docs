---
title: Fix a refused key or sign-in
description: Fix a key Marfa refuses, a sign-in that fails, and a request refused for its reach or its rate.
---

Marfa checks every request's credential, then what that credential may reach. [Access](/build/access) explains both, and [Manage keys](/run/manage-keys) shows how to change what a key holds.

## 401 unauthorized: A valid credential is required

Marfa didn't accept the credential: it's missing, mistyped, revoked or expired. The CLI exits with `5`.

Send the key in full, as `Authorization: Bearer <key>`. An expired key's answer carries the time in `details.expired_at`. If the key was revoked or has expired, [make a new one](/run/manage-keys#make-a-key), or run `marfa login` again for the CLI.

## 404 item_not_found: Item not found, for an item you know exists

Your credential can't read the item's type. **Marfa answers as it does for a missing item,** so a refusal never shows what a credential can't see.

`marfa keys current` shows the maps of the key you're using, and `marfa overview` the types it reaches. Use a key that reads the type.

## 404 item_not_found: This item is in the trash

The item is in the bin, and the answer carries `"trashed": true` in `details`. A read says to ask with `state=trashed`, and a change says to restore the item first:

```bash
marfa items restore <id>
```

## 403 type_not_permitted

Your credential can't write the type. `details.grant` names the grant it lacks, and the message says whether it reads the type at all:

```json
{
  "error": {
    "code": "type_not_permitted",
    "message": "Write access to type \"core.bookmark\" denied",
    "details": { "grant": { "kind": "type", "name": "core.bookmark", "level": "write" } }
  }
}
```

A type it can't read gives `No access to type "core.task"`. Use a key that holds the grant, or [narrow a key](/run/manage-keys#narrow-a-key) to add it.

## 403 forbidden: This operation requires the permission

The message names the [permission](/catalog/permissions) the credential lacks, such as `This operation requires the audit.read permission.`, and `details.required_scope` names it too. Give the key that permission, or use one that holds it.

## 401 insufficient_user_authentication: Sign in again to perform this operation

The action, such as a restore or moving the sign-in address, needs **a sign-in from the last five minutes**, and the CLI's or app's sign-in is older. Nothing changed. Sign in again, then run the command within five minutes:

```bash
marfa login --fresh-sign-in
```

A browser that signed in too long ago gets `403 forbidden` with the same message. [Confirm it's you](/run/sign-in-as-the-owner#confirm-its-you) lists the actions that need it.

## 403 app_sign_in_required

The action needs a person, and a key has no sign-in to renew. The message is `Only a person signed in to an app, or the private local command, can do this.` Run it from the CLI signed in with `marfa login`, or through the [private socket](/run/run-on-a-server#the-private-socket).

## Too many password attempts

The owner's password was tried too often. The sign-in page says `Too many attempts. Try again in` and how long, and the API answers `429 rate_limited` with `Too many password attempts. Try again later.` and a `Retry-After`. **A passkey still signs in.**

Wait, sign in with a passkey, or [recover the owner's password](/run/sign-in-as-the-owner#recover-the-owners-password), which lifts the lock. Behind a proxy, every caller can share one address unless the server [trusts the forwarded one](/run/address#behind-a-proxy-you-set-up-yourself).

## Owner setup and sign-in require HTTPS, except on this machine

The [sign-in address](/run/address#the-address) is a plain `http` address on another machine, so the server refuses the owner's pages and passkeys with `403 forbidden`. A password or session sent that way could be read on the network.

Serve the instance over `https`, as [Choose how it's reached](/run/address#choose-how-its-reached) shows, and [move the address](/run/address#move-the-address) to it. A passkey belongs to its host name, so sign in at the same address each time.

## The sign-in code is no longer valid: run marfa login again

`marfa login` waited longer than the code lives. **A code works for 10 minutes,** and the CLI exits with `3`. In the browser, the same code reads `That code has expired. Start again on your device to get a new one.`

Run `marfa login` again, and approve the new code within 10 minutes.

## 429 rate_limited

The credential sent more requests in the current window than the instance allows, with the message `Too many requests from this credential; try again later.` The CLI exits with `3`, which means a retry can succeed.

Wait the seconds that `Retry-After` and `details.retry_after_seconds` name, then send the request again. Each key or app may make `rate_limit_requests` requests, 4,000 by default, in each `rate_limit_window_seconds`, 60 by default. Both are [stored settings](/run/settings#change-settings-while-it-runs) that change without a restart.

## 408 request_timeout on a restore or an upload

No byte of a restore or a file upload arrived for 60 seconds, so the server ended it and kept nothing of it. The CLI exits with `3`.

Send it again over a connection that stays up.
