---
title: Fix a refused key or sign-in
sidebar_label: Refused key or sign-in
description: Find the message Marfa shows when it refuses a key or a sign-in, or when a request reaches too far or too often, and fix it.
job: Someone whose key or sign-in is refused finds the message they see and fixes it.
---

Marfa checks every request's credential, then what that credential may reach: [Access](/build/access) explains both. Nothing changes when a request is refused.

## 401 unauthorized: A valid credential is required

The credential is missing, mistyped, revoked or expired, and the CLI exits with `5`. Send the key in full, as `Authorization: Bearer <key>`. For a revoked or expired key, [make a new one](/use/manage-keys), or run `marfa login` again for the CLI.

## 404 item_not_found

Either the credential can't read the item's type, and **Marfa answers as for a missing item** so a refusal never shows what a credential can't see, or the item is in the bin, and `details` says `"trashed": true`. `marfa keys current` shows what the key reaches. For an item in the bin, run `marfa items restore <id>`.

## 403 type_not_permitted

The credential can't write the type, and `details.grant` names the grant it lacks, such as `Write access to type "core.bookmark" denied`. Use a key that holds it, or [make a new key](/use/manage-keys) that does.

## 403 forbidden

If the message names a [permission](/catalog/permissions), such as `audit.read`, use a key that holds it. If `details.namespace` names one, nobody can register there that way: a `common` type comes only from a [plugin](/use/install-a-plugin), and an `app.<vendor>` someone else holds needs the owner to [give it to the app](/use/manage-app-data#give-an-apps-types-to-another-app). A key no record traced to its maker at upgrade can't do either: make a new one with your own sign-in.

## 401 insufficient_user_authentication: Sign in again to perform this operation

The action, such as a restore or moving the sign-in address, needs **a sign-in from the last fifteen minutes,** and yours is older. Sign in again, then run the command within fifteen minutes:

```bash
marfa login --fresh-sign-in
```

A key is refused `403 app_sign_in_required` instead, because it has no sign-in to renew: use the CLI signed in as the owner, or [the private socket](/run/run-on-a-server#the-private-socket). [Confirm it's you](/run/sign-in-as-the-owner#confirm-its-you) lists the actions.

## 429 rate_limited

A credential sent more requests than the instance allows, or the owner's password was tried too often (`Too many password attempts. Try again later.`). Wait the seconds `Retry-After` names: **a passkey still signs in.** Behind a proxy, every caller can share one address unless the server [trusts the forwarded one](/run/address#behind-a-proxy-of-your-own). `rate_limit_requests` and `rate_limit_window_seconds` set the request limit.

## Owner setup and sign-in require HTTPS, except on this machine

The [sign-in address](/run/address#move-the-address) is a plain `http` address on another computer, so the server refuses the owner's pages and passkeys with `403 forbidden`. Serve the instance over `https`, as [Give your instance an address](/run/address) shows, and move the address to it.

## The sign-in code is no longer valid: run marfa login again

`marfa login` waited longer than its code lives, **10 minutes,** and exits with `3`. In the browser the same code reads `That code has expired.` Run `marfa login` again and approve the new code within 10 minutes.
