title: Folders
description: Fix a folder that refuses to open, or whose store a newer CLI can't use.

A folder keeps its own working copy and its record of which file is which item. [Sync a folder](/run/sync-a-folder) sets one up.

## A folder refuses to open with unknown field search

The message names an unknown field, `search`. The folder's `system.folder` item still holds `search`, which the folder type no longer declares.

Repair the settings on the instance. Read the item and its version with `marfa items get <id>`, then send the intended `query`, without `search`, with `marfa folders change <id> --version <n> --file settings.json`. Marfa never turns `search` into `query`, and editing `.marfa/folder.yaml` alone can't remove it. [Change a folder's settings](/run/sync-a-folder#change-a-folders-settings) shows the file.

## wrong_schema on a folder's store

A newer CLI can't open a store that another build of the core made. A folder command that writes, such as `marfa folders push`, `pull`, `scan` or `watch`, then counts the writes the store holds that the server hasn't taken, and acts on the count:

- **None.** If the store also holds no answer the folder has yet to record, the command replaces the store with one of its own shape, says so on standard error, and carries on. **It changes no file and asks for no new first sync.** The new store keeps the folder's record of its files, its first sync, its server and `.marfa/folder.yaml`, and fills again from the server. The command then sends the edits and deletions you made meanwhile, takes away the files of notes that went to the bin, and keeps holding a file the server refused before. An edit to a file whose note went to the bin meanwhile is sent as a new note.
- **Some.** The command leaves the store and the files as they are. Push the folder with the build that made the store, after `marfa folders confirm` if its first sync waits, then run the newer build again.
- **Unknown.** If the count can't be read, push the folder with the earlier build, remove it with `marfa folders remove`, which leaves its files, and add it again with the newer build.

The count includes each write the server gave up on, and each refused write the folder doesn't keep against a file, such as a deletion. A push doesn't send those again. If the count stays above zero after a push, remove the folder with the build that made the store and add it again with the newer build. If the server never took a deletion, the file comes back then: delete it again.

The command also leaves the store alone when it keeps its record of files in a shape the newer build can't carry: remove the folder with the earlier build and add it again. If the store names no folder, `marfa folders add` replaces it.

`marfa folders status` only reads, so it reports the refusal with the same advice and changes nothing.
