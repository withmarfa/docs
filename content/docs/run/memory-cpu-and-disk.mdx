---
title: Choose a host
description: Choose a host with the memory, CPU and disk an instance needs, and see how much of each yours uses.
---

An instance is one small process with one database, and it needs little while it waits. **What sizes a host is the files you keep**, which take their own size on the disk, and the reading of their text, which takes memory while it runs.

## What a host needs

- **Any 64-bit machine Marfa runs on:** a Mac with Apple silicon, or Linux on x86_64 or arm64.
- **Memory for the largest file it reads.** The server reads the text of each file you upload, OCR included, and one file may use up to `enrichment_max_memory_bytes` while it does, 1 GiB by default. On a host with less to spare, lower that setting: a file that needs more is skipped and keeps no text. `enrichment_enabled` turns the reading off.
- **Disk for the database and every file,** each file's bytes kept once in the blob folder beside the database, plus room for what the server writes beside them.

## Leave room on the disk

The server keeps `disk_reserve_bytes`, 128 MiB by default, free on the volume of its data. **An upload, a restore or an export that would take the volume below it is refused** with `507 insufficient_storage`, and the instance goes on answering reads. [Health](/reference/api/health-and-maintenance/getHealth) reports the disk as degraded once less than the reserve, or 64 MiB, is free.

Leave room beyond that for what the server writes:

- **An [archive export](/run/export-and-restore)** writes temporary files on the same volume while it runs, and the reserve counts them.
- **A [backup folder](/run/back-up-and-restore)** on the same volume holds its own copy of every file, and the reserve counts it too.
- **An upgrade** copies the database beside itself before it changes it, when the new release changes the database. [Upgrade an instance](/run/upgrade) says when.

[The data directory](/run/run-on-a-server#the-data-directory) lists what else the folder holds.

## See what an instance uses

`marfa metrics` asks the instance what it holds and what its process costs. It needs a credential with `instance.read`, which the owner has:

```bash tab="CLI" tab-group="client"
marfa metrics --json
```

```http tab="HTTP"
GET /metrics
Authorization: Bearer <key>
```

Beside its counts of items, files, types, keys and webhooks, the answer holds a `process` block and a `storage` block:

```json title="Response" status="200"
{
  "uptime_seconds": 769,
  "process": {
    "version": "<release>",
    "memory_rss_bytes": 26689536,
    "memory_rss_peak_bytes": 28246016,
    "cpu_user_seconds": 0.194388,
    "cpu_system_seconds": 0.14642
  },
  "storage": {
    "database_bytes": 1056768,
    "wal_bytes": 1215432,
    "rows": { "items": 1, "versions": 0, "event_log": 2, "audit_log": 28 }
  }
}
```

| Field | What it says |
| --- | --- |
| `process.version` | The release the server runs. |
| `process.memory_rss_bytes` | The memory the process holds. |
| `process.memory_rss_peak_bytes` | The most memory the process has held since it started. Compare it with the host's memory after a large upload or import. |
| `process.cpu_user_seconds`, `process.cpu_system_seconds` | The CPU time the process has spent on its own work and in the operating system since it started. |
| `storage.database_bytes`, `storage.wal_bytes` | The size of the database file and of its write-ahead log, which is `0` when there is none. |
| `storage.rows` | The rows of the largest tables: `items`, `versions`, `event_log` and `audit_log`, counted for each request. |

**A figure the server can't read is `null`**, and the others still stand. [Get instance metrics](/reference/api/health-and-maintenance/getInstanceMetrics) has the whole answer, and `blobs.total_bytes` in it is the size of every file the instance keeps.

## Keep the database small

Old versions, the bin and the logs are what grow besides your own items and files. Their stored settings bound them: `version_max_versions` and the `version_` windows, `trash_retention_days`, `audit_retention_days` and `event_log_retention_days`. [Settings](/run/settings) lists each with its default, and [Run housekeeping](/run/housekeeping) says which job clears each.
