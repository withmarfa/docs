**An instance tells you of its own faults first, in what needs your attention.** Everything else it can send about itself is off until you set a destination, so an instance that sets none sends nothing. The CLI, connectors and apps report apart from the instance: see [what they send](/run/client-telemetry).

| To get | Set |
| --- | --- |
| Each fault, as it happens | A [webhook](/build/receive-webhooks) on `attention.raised` |
| Traces, logs and metrics over OTLP | `otel_exporter_otlp_endpoint` |
| [Errors in PostHog](/run/send-errors-to-posthog) | `posthog_host` and `posthog_project_token` |
| A heartbeat | `heartbeat_url` |

Each is a [stored setting](/run/settings#change-settings-while-it-runs), set from any computer with `config.manage` and followed from the next send, with no restart. **`telemetry_enabled` set to `false` pauses traces, logs, metrics and PostHog reports together,** and keeps every setting as it was.

## See a fault

When the server meets a fault of its own, such as a database failure, a panic or an internal error, `marfa attention` lists an entry of kind `fault`. Its reference names the kind and where, such as `internal:POST /items/{id}`, never an item, and its title counts how often. The entry goes 24 hours after the fault last happened, or at a restart.

To be told at once, subscribe a webhook to `attention.raised` with a key that holds `instance.read`. While the database fails, the server still sends a new fault's event to such a webhook, from memory. [Receive webhooks](/build/receive-webhooks) shows how.

## Send traces, logs and metrics

Marfa exports over OTLP, the OpenTelemetry protocol, to any receiver that takes it over HTTP, posting to `v1/traces`, `v1/logs` and `v1/metrics` under the address. The endpoints and headers are secrets, so `marfa config set` asks for each with no echo:

```bash
marfa config set otel_exporter_otlp_endpoint
marfa config set otel_exporter_otlp_headers
marfa config set otel_sample_ratio 0.1
```

The headers are `key=value` pairs with percent-encoded values, such as `authorization=Bearer%20<token>`. `otel_sample_ratio` is `0.05` unless you set it, and **a trace that holds an error is always exported**. The traces, logs and metrics endpoints and headers send one signal elsewhere, and an endpoint of its own needs `otel_exporter_otlp_endpoint` set too.

**The server reads no `OTEL_*` variable.** It logs a warning naming each one it finds, without its value, so a variable a hosting platform sets can't move your telemetry. Each endpoint must be public unless [`allow_private_addresses`](/run/settings#let-webhooks-reach-a-private-network) is on.

**A log record carries its message and a fixed list of fields, and a span names the route,** never the path a request used, so neither holds what you wrote, a file's name or a credential. A `GET` or `HEAD` answered `2xx` or `304` in under a second has no log record, but keeps its line in the request log on standard output.

### Metrics

Every 60 seconds, and once more when it stops, the server exports two metrics:

- **`http.server.request.duration`,** in seconds, for every request but the event stream, with `http.request.method`, `http.route`, such as `/items/{id}`, and `http.response.status_code`.
- **`process.memory.usage`,** the server's resident memory in bytes.

### Tell instances apart

**Everything an instance exports names it by `service.instance.id`**, the `instance_id` that `GET /` answers, and its release by `service.version`. `otel_resource_attributes` adds attributes of your own, replacing the server's of the same name, and `otel_service_name` sets the service name, `marfa-server` by default. The server names no environment, so mark a test instance with `deployment.environment=test`.

**A restore carries no telemetry secret.** Its answer names the settings to set again.

## Send a heartbeat

An instance can't report its own death. Set `heartbeat_url`: and the `heartbeat` [housekeeping job](/run/housekeeping) requests it with a `GET`, no body and no identity, every minute. Give it to an uptime monitor. `heartbeat_enabled` set to `false` pauses it.

**`marfa config get` never shows a secret,** only that it's set, in `secrets_set`.

The rules behind this page are in the [telemetry](https://github.com/withmarfa/marfa/blob/main/conformance/spec/instance.md#telemetry) section of the instance chapter of the contract.
