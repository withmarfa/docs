---
title: Connect Claude and ChatGPT
description: Add your instance to Claude or ChatGPT once, on the web, so you can find and save your items from a chat on the web, the desktop or your phone.
---

Claude and ChatGPT reach your instance's MCP server from their own servers, not from your device. **Add it once on the web, and it works in the same account's desktop and mobile apps**, so you can ask a chat on your phone to find a note or save a link. Each chat signs in to your instance and reaches only what you approve.

Claude calls what you add a custom connector. That is Claude's word: it has nothing to do with a Marfa [connector](/connectors), which brings in records from another service.

## Give the instance a public address

**Claude's and ChatGPT's servers must reach your instance over the public internet, at an `https` address.** A local address or a tailnet address works for an agent on your own computer, such as Claude Code, but not for these.

A Cloudflare Tunnel gives the instance a public address on your own domain without opening a port on your network. Install it that way, or run the install again to change how it's reached:

```bash
marfa server install --access cloudflare --address https://marfa.example.com
```

[Install the server](/run/install#choose-how-its-reached) covers the other choices, such as your own proxy. On a public address, anyone can reach the instance's sign-in page, but every request for your data needs a credential, and only you can approve one.

## Add it to Claude

You need a Claude plan that allows custom connectors. On a Team or Enterprise plan, an owner of the organization adds the connector first, in **Organization settings** > **Connectors**.

<Steps>
<Step>

### Add the connector

On claude.ai, open **Customize** > **Connectors**, select **+**, then **Add custom connector**. Name it `Marfa`, enter your instance's address followed by `/mcp`, such as `https://marfa.example.com/mcp`, and select **Add**.

</Step>
<Step>

### Approve it

Select **Connect**. Your instance's **Approve access** page opens. Sign in as the owner if you aren't already, then choose **Full access**, or **Choose access** to give less, such as read and edit on notes and nothing else. [Access](/access#what-the-owner-approves) describes the page.

</Step>
<Step>

### Try it

In a chat, ask Claude what it can see in Marfa. It calls `marfa_overview` and answers with the types and tags you approved.

</Step>
</Steps>

## Add it to ChatGPT

You need a ChatGPT plan that allows custom MCP servers.

<Steps>
<Step>

### Add the server

On chatgpt.com, open **Plugins**, select the plus button, then **Add custom MCP server**. Enter your instance's address followed by `/mcp`, such as `https://marfa.example.com/mcp`.

</Step>
<Step>

### Approve it

Your instance's **Approve access** page opens. Sign in as the owner if you aren't already, then choose **Full access** or **Choose access**.

</Step>
<Step>

### Try it

In a chat, ask ChatGPT what it can see in Marfa.

</Step>
</Steps>

## Save a file from a chat

**In ChatGPT, attach a file and ask it to save the file to Marfa.** ChatGPT gives the tool a link to the file, and your instance fetches it and saves it as a file item, such as a `core.file.image` for a photo. The link works for a short time, so if the save fails, attach the file again.

In either chat, you can also ask it to save a file from a public web address. The instance fetches only from public addresses, follows no redirect, and records every fetch in the [audit log](/run/audit-log). To turn fetching off, set `MARFA_MCP_FETCH_ENABLED=false`, as [Settings](/run/settings#every-environment-setting) shows.

## Choose which tools it gets

`/mcp` is the address for finding, reading, saving and changing items. To design types or save views from a chat, add `/mcp/schema` instead, and to check the instance's health, read its audit log or manage keys and webhooks, add `/mcp/admin`. Each address is a connector or server of its own in the chat app. [MCP server](/mcp-server#endpoints) lists what each one adds.

Whatever the address, **the chat asks before it deletes**: the first delete call only previews what would go, and the chat shows you before anything moves to the trash. It asks the same way before it makes a webhook, which sends events to an address outside your instance. No tool purges, exports or changes the instance's settings.

## Disconnect it

Remove the connector or server in the chat app's settings. To end the chat's access on your instance as well, disconnect it on the **Connected apps** page, or with `marfa apps disconnect`, as [Authenticate](/build/authenticate#revoke-access) describes. Its next request is refused.
