---
title: Files outside a folder's query
description: Tell whether a file whose item a folder's query doesn't hold will sync, stay as unmatched, be removed or be skipped.
---

A folder's query says which items the folder holds, but a file you add, or an edit made elsewhere, can put an item outside it. **Which part of the query the item falls outside decides what happens**: outside its types, tiers, tags or filter, the folder keeps the file; outside its states, or in the bin, the folder removes it.

## What a folder does with each file

| When | What the folder does |
| --- | --- |
| A new Markdown file has no frontmatter | Creates an item from the folder's `defaults`, then its query, and writes the frontmatter into the file |
| A new Markdown file names a type, tier or tag the query doesn't hold | Creates the item anyway, and keeps the file as unmatched |
| An edit, in the folder or elsewhere, takes an item outside the query's types, tiers, tags or filter | Keeps the file as unmatched, and still sends its edits to the item |
| An item leaves the query's states, or goes to the bin | Removes the file at the next sync, unless you changed it since Marfa wrote it |
| A new Markdown file names a state the query doesn't hold | Creates the item, then removes the file at the next sync, as for any item that leaves the query's states |
| A photo, PDF or other file whose type the query doesn't hold | Leaves it on disk and sends nothing, unless a note embeds it or it's attached to one |

[Files in a folder](/run/folder-files#how-items-appear-as-files) says how a new file takes its type, tier and title.

## Unmatched files

**An unmatched file stays in sync with its item**: the folder keeps it, sends your edits, and never removes it for falling outside the query. Another folder whose query holds the item can take the file over. To see which files are unmatched and take them away without touching their items, use `marfa folders unmatched`, as [Remove files a folder keeps but no longer holds](/run/keep-folders-running#remove-files-a-folder-keeps-but-no-longer-holds) shows.

## Many files at once

**New files have no limit.** Drop hundreds of files into a folder and it creates an item for each, without asking. Only two things wait for you:

- **The first sync** after `marfa folders add`, which [Sync a folder](/run/sync-a-folder#confirm-the-first-sync) covers.
- **A large removal,** files or items going at once, which [Confirm or undo a large removal](/run/folder-safeguards#confirm-or-undo-a-large-removal) covers.

The rules behind this page are in the [folders](https://github.com/withmarfa/marfa/blob/main/conformance/spec/folders.md) chapter of the contract, such as [`folders/unmatched-file-kept`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/folders.md#foldersunmatched-file-kept) and [`folders/binary-outside-search`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/folders.md#foldersbinary-outside-search).
