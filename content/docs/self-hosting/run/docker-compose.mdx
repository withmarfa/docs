The server repository ships a `docker-compose.yml` that brings up Postgres, runs database migrations, and starts the Marfa server with the local integration runtime enabled. It is the quickest way to run a self-host on Postgres.

<Callout type="info">
  **The stack builds the image, and the image carries its integrations.** The build
  stages exactly the set the server declares it installs, points
  `MARFA_INTEGRATIONS_ROOT` at them, and runs a verification step that fails the
  build unless exactly that set arrived, each entry in its declared shape and each
  one importable. Nothing has to be assembled to run the shipped integrations, and
  a source checkout picks up whatever its own integrations directory holds.
</Callout>

## Prerequisites

Clone the server repository and create a `.env` next to `docker-compose.yml` with two secrets:

```bash
API_KEY_SALT=$(openssl rand -hex 32)
MARFA_AUTH_SECRET=$(openssl rand -hex 32)
```

Both are required and must stay stable: rotating `API_KEY_SALT` invalidates existing API keys, and rotating `MARFA_AUTH_SECRET` invalidates existing sessions. Optionally set `POSTGRES_PASSWORD` (it defaults to `marfa` for local use).

## Start

```bash
docker compose up --build
```

Compose starts Postgres, waits for it to be ready, applies migrations, then starts the server on port 8600. Check it:

```bash
curl http://localhost:8600/health
```

## Bootstrap the instance

```bash
marfa bootstrap http://localhost:8600 <secret>
```

The secret is the one-time value the server printed to its log at startup:

```bash
docker compose logs marfa | grep "holds no credential yet"
```

Or, without the CLI:

```bash
curl -X POST http://localhost:8600/keys \
  -H "Authorization: Bearer <the secret from the log>" \
  -H 'Content-Type: application/json' \
  -d '{"label":"operator","source":"operator"}'
```

**Two credentials come back.** `key` is the operator key, which runs the instance and works in no space; `space_key.key` is bound to the space the same call provisioned and is the one to configure a client with. Both plaintexts are shown once.

From here, see the [self-hosted quickstart](/introduction/quickstart-self-hosted) for creating your first item.

## Customize

The stack runs in keys mode with no email and filesystem blobs, which suits a single-operator instance. To go further, set the relevant variables on the `server` service (see [Configuration](/self-hosting/run/configuration)):

- Email for password resets and magic links: the `MARFA_SMTP_*` variables.
- Multi-user accounts: `AUTH_MODE=hosted` plus `MARFA_AUTH_BASE_URL` and `CORS_ORIGINS`.
- S3 or R2 blob storage: `BLOB_BACKEND=s3` plus the `S3_*` variables.
- TLS: put a reverse proxy in front of the server (see [Deployment](/self-hosting/run/deployment)).
