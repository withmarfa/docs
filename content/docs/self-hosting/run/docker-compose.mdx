---
title: Docker Compose
description: Run a self-hosted Marfa with Postgres in one command.
---

The server repository ships a `docker-compose.yml` that brings up Postgres, runs database migrations, and starts the Marfa server with the local integration runtime enabled. It is the quickest way to run a self-host with Postgres, and therefore with integrations.

## Prerequisites

Clone the server repository and create a `.env` next to `docker-compose.yml` with two secrets:

```bash
API_KEY_SALT=$(openssl rand -hex 32)
MARFA_AUTH_SECRET=$(openssl rand -hex 32)
```

Both are required and must stay stable: rotating `API_KEY_SALT` invalidates existing API keys, and rotating `MARFA_AUTH_SECRET` invalidates existing sessions. Optionally set `POSTGRES_PASSWORD` (it defaults to `marfa` for local use).

## Start

```bash
docker compose up --build
```

Compose starts Postgres, waits for it to be ready, applies migrations, then starts the server on port 8600. Check it:

```bash
curl http://localhost:8600/health
```

## Bootstrap an admin key

```bash
marfa bootstrap http://localhost:8600
```

Or, without the CLI:

```bash
curl -X POST http://localhost:8600/keys \
  -H 'Content-Type: application/json' \
  -d '{"label":"admin","role":"admin","source":"bootstrap"}'
```

The plaintext key is shown once. From here, see the [self-hosted quickstart](/introduction/quickstart-self-hosted) for creating your first item.

## Customize

The stack runs in keys mode with no email and filesystem blobs, which suits a single-operator instance. To go further, set the relevant variables on the `server` service (see [Configuration](/self-hosting/run/configuration)):

- Email for password resets and magic links: the `MARFA_SMTP_*` variables.
- Multi-user accounts: `AUTH_MODE=hosted` plus `MARFA_AUTH_BASE_URL` and `CORS_ORIGINS`.
- S3 or R2 blob storage: `BLOB_BACKEND=s3` plus the `S3_*` variables.
- TLS: put a reverse proxy in front of the server (see [Deployment](/self-hosting/run/deployment)).
