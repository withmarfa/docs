Many apps write to the same items, and a device may send a write it made offline hours earlier. **Marfa keeps that safe with a version on every item.** A write names the version it read, and Marfa checks what has changed since before it applies anything.

## Optimistic concurrency

Marfa uses **optimistic concurrency control**: it takes no lock when you read an item, and checks the version when you write. The `version` does the job that an `ETag` and an `If-Match` header do in other HTTP APIs, but an item has no `ETag` and a write takes no `If-Match` header: it names the `version` it read in the request instead. **A write that the check refuses answers `409 version_conflict`, not `412 Precondition Failed`**, and carries the item as it is now.

## What the version counts

An item's `version` starts at 1 and goes up by one with each change to the item itself: its properties, its type, its tier, its `occurred_at` or its `source_id`.

**Everything else leaves the version alone**: tags, extensions, edges, and moves between active, archived and trashed. So a tag added in one app never makes another app's edit stale.

## When two apps write the same item

A write based on an older version isn't refused for that alone. Marfa compares the fields your write changes with the fields changed since the version you read. **If they don't overlap, both changes stand**, and the item moves to its next version. If they overlap, Marfa refuses your write with `409 version_conflict` and sends back the item as it is now, for you to combine.

A write can also ask Marfa to settle a collision for it, with `conflict=auto`, by the rules of the item's type. For a note, the last writer's title wins, and **both bodies are kept**: the note keeps the body it holds, and yours goes into a conflicted copy, a new note linked to the original by a `derived-from` edge, so neither writer's text is lost. A [device](/devices) sends every update with `conflict=auto`. [Write safely](/build/write-safely) shows both ways.

Say you read a note at version 3 and send a new body. If another app has since changed only the title, both changes stand. If it changed the body, your write is refused, or, with `conflict=auto`, your body goes into a conflicted copy.

## History

Each time an item's version moves, Marfa keeps a snapshot of the item as it was. The snapshots are what a stale write is compared against, and [List item versions](/api-reference/items/listItemVersions) reads them, oldest first. Each snapshot records which sign-in wrote it, such as an app, a key or a browser.

**Marfa doesn't keep every snapshot forever.** It keeps every recent one and fewer as they age. A write based on a version whose snapshot is gone can't be compared, so it's refused, and the app reads the item again.

The rules behind this page are in the [versions](https://github.com/withmarfa/marfa/blob/main/conformance/spec/versions.md) chapter of the contract.
