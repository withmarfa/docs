Every app keeps its own copy of your data, in its own shape: notes in one app, tasks in another, bookmarks in a third. So your data is **scattered** across apps, **locked in** the app that saved it, and **invisible to your other tools**.

Marfa is a shared data layer that you run yourself. It keeps your data in one place you own, as **typed items**: a note, a task or a bookmark, each with a type that says what it holds. Every app, script, agent and folder you allow works from the same data, **each with only the access you give it**. Apps become views onto your data, not places that keep it.

<Callout type="warn" title="Marfa is early">Expect breaking changes until version 1.0. The [Changelog](/changelog) lists each one.</Callout>

## How it fits together

One running Marfa is an **instance**. It belongs to one person, its owner, and holds their data in the middle. Everything else reaches it by one of five routes, and connectors join it to services you already use.

<MarfaAtAGlance />

Two routes **keep a copy on the device**, so they work offline and send their changes when they reach the instance again. An iPhone or Mac app built on the [Swift SDK](/swift-sdk) is one. A [synced folder](/run/sync-a-folder) on your Mac is the other: each note is a Markdown file that you, or an agent, edit in any app.

Three routes **call the instance directly**. Claude, ChatGPT, Claude Code and Codex connect to its [MCP server](/marfa-mcp-server). An agent that runs commands uses the [CLI](/cli), and a script you write calls the [HTTP API](/api-reference). [Connectors](/connectors) copy records from services such as Todoist and GitHub, and some carry your changes back.

Every route sends requests with a credential that reaches only what you approved, and you can revoke it at any time. [How Marfa works](/how-marfa-works) explains each part.

## What you can do with it

- **Keep your data when you change apps.** Stop using an app, and everything it saved stays in Marfa for the next one.
- **Give an agent your data.** It finds and saves your items, and reaches only the types you choose, each for reading or for reading and writing.
- **Build on data that's already there.** A reading list, a dashboard or a personal CRM starts full, because your other apps already saved what it shows.

If you know Apple's platforms, Marfa is **like iCloud, but for structured data and open to any app**. It's also **like HealthKit, but for any kind of data**: each app asks for the types it needs and sees no items of any other type.

## What Marfa isn't

- **Not for teams.** An instance belongs to one person. It holds that person's data, and other people don't collaborate in it.
- **Not hosted for you.** Your data lives on the machine you run Marfa on, and in any storage you choose to attach.
- **Not an app.** You don't need any particular app. Apps are built on Marfa, and anyone can build one.
- **Not a place to run code.** Apps, agents and connectors run outside Marfa and reach it over its API.

## Where it runs

Marfa keeps your data in one SQLite database file and a folder of files, so there's no database server to set up. Run it on your own Mac, a home server, or the ready-made template on Railway.

Your own devices reach it over your home network, or from anywhere over a private network such as Tailscale. To reach it from the internet, as Claude and ChatGPT on the web need, give it a public address on your own domain through a Cloudflare Tunnel. [Deploy](/run/deploy) covers each.

Marfa is open source under the Apache License 2.0. The rules it follows are written down in [the contract](https://github.com/withmarfa/marfa/tree/main/conformance/spec) and checked by tests.
