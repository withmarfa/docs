An agent reaches your data the way any program does: **by one route into your instance, with a credential that reaches only what you approve.** Choose the route by where the agent runs. You need an instance the agent can reach; the [Quickstart](/quickstart) starts one.

| Route | Suits | How it signs in |
| --- | --- | --- |
| The Marfa plugin | Claude Code and Codex | You sign in and approve |
| A custom connector | Claude and ChatGPT, in a chat on any device | You sign in and approve |
| The CLI | An agent that runs shell commands | A key of its own, or your sign-in |
| A synced folder | An agent that edits files | The folder's sign-in on that computer |

## Claude Code and Codex: the Marfa plugin

The Marfa plugin works in both, and holds three skills:

- **`connect`** adds your instance's MCP server and has you sign in.
- **`find-and-save`** finds and saves items without duplicating or overwriting anything.
- **`design-a-type`** drafts the smallest change when a new kind of record needs a type of its own.

The plugin installs nothing else on your computer.

Start a new session and **ask the agent to connect to Marfa.** It asks for your instance's address, adds the server, and opens your instance's approval page in your browser. Choose **Full access**, or **Choose access** to pick the types it may read or change, and select **Approve**.

To add the server without the plugin, run `claude mcp add` or `codex mcp add` with your address followed by `/mcp`, as the [Quickstart](/quickstart) does.

## Claude and ChatGPT: a custom connector

Claude and ChatGPT reach your instance from their own servers, so **your instance needs a public `https` address**, which [Give your instance an address](/run/address) sets up. You add the address once as a custom connector on the web, and Claude then reaches it from the desktop and phone apps too. [Use Marfa from Claude or ChatGPT](/use/claude-and-chatgpt) shows each app's steps.

## An agent that runs commands: the CLI

A coding agent that runs shell commands can use the [CLI](/cli), which does everything Marfa does, including what no MCP tool offers. **Give an agent that works on its own a key of its own,** holding only the types it needs, so you can tell its work from yours and revoke it alone. [Work from an agent](/use/from-an-agent#an-agent-that-runs-on-its-own) sets this up.

## An agent that edits files: a synced folder

A [synced folder](/use/sync-a-folder) keeps a directory in step with your items, **each note a Markdown file**. While the folder is watched, an agent edits the files with the tools it already has, and each change reaches your instance. The agent reaches only the items the folder holds.

## What the MCP server offers

Your instance serves MCP, the protocol agents use to call tools, at three addresses. **Add only the one the agent's work needs,** as a server of its own with its own sign-in.

| Address | Tools |
| --- | --- |
| `/mcp` | Find, read, save, change and move items to the bin, and read and write a table's rows |
| `/mcp/schema` | Those of `/mcp`, and save a type or a view, move items to another type, and save many items at once |
| `/mcp/admin` | Those of `/mcp`, and read the instance's health and the audit log, and manage keys and webhooks |

An agent lists only the tools its credential can use, so an agent that can only read sees fewer. The [Marfa MCP server](/marfa-mcp-server) page lists every tool.

## Give it these docs

An agent does better with the current docs than from memory. The [docs MCP server](/docs-mcp-server), at `https://docs.marfa.so/mcp`, searches these docs and **reaches no one's data**, so an agent that builds on Marfa often uses both servers. `marfa docs search <query>` reads the same docs from the CLI, with no instance.
