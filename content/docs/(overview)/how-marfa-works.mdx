Marfa has a small number of parts, and every page in these docs builds on them.

## The instance

An **instance** is one running Marfa server and the data it keeps. It belongs to one person, its **owner**, and everything in it is that person's. The data lives in one SQLite database file and a folder of file contents on the machine the server runs on.

**The instance is the source of truth.** Apps, devices and connectors read from it and write to it, and none of them talk to each other directly. When two of them change the same thing, the instance decides the outcome, so every copy ends up agreeing with it.

## Your data

Everything in an instance is an **item**: one note, one task, one bookmark, one photo. Each item has a **type**, such as `core.note` or `core.task`, which says what the item holds. Marfa ships types for common things, and you can register your own, as [Items and types](/items-and-types) explains.

An item's content is its **properties**, such as a note's title and body. Beside them, an item can carry **tags**, such as `favorite`, and **extensions**, where an app keeps its own data about the item.

**Edges** link one item to another: a note `about` a book, a task the `parent-of` its subtasks. [Properties, metadata and edges](/properties-metadata-and-edges) explains all four.

A **file** is an item that names its bytes, which Marfa stores once however many items use them. [Files](/files) explains how.

## Changes

Every item has a **version** that goes up each time its content changes. A write names the version it read, so Marfa can tell when someone else changed the item in between, and either combine the two changes or refuse the write.

Nothing is overwritten by accident. [Versions](/versions) explains how.

**Every change is also an event** in one log. An app follows the log to stay current, or registers a webhook so Marfa posts each change to it. [Events and webhooks](/events) covers both.

## Who can reach it

Nothing reads or writes your data without a credential, and **a credential reaches only what it was given**. A script or an agent uses a **key**. An app signs in with OAuth instead, and the owner approves what it asks for, the way you approve an app that signs in with Google.

Access is given by type. A notes app can be allowed to read and write notes and nothing else: it can't read items of any other type, or learn whether any exist. [Access](/access) explains keys, apps and permissions.

## What reaches it

Everything that uses Marfa runs outside it and reaches it over its HTTP API. The Swift SDK and the CLI embed the **core**, a Rust engine that sends their requests and can keep a working copy of the data they need. The TypeScript SDK sends its requests straight to the API.

<WhatReachesIt />

- **Apps and scripts** send requests with their credential. The [TypeScript SDK](/typescript-sdk) and the [CLI](/cli) send them for you.
- **AI agents** use the CLI or the API like any script, with a key of their own, as [Use Marfa with AI agents](/guides/ai-agents) shows.
- **Devices** keep a **working copy** of the data they need, such as an iPhone app built on the [Swift SDK](/swift-sdk). They read from the copy offline, queue their writes, and send them when they can reach the instance. A **folder** keeps a working copy as ordinary files on your computer. [Devices](/devices) explains both.
- **Connectors** are programs that bring in records from another service, such as Todoist, and can carry changes back to it, as [Connectors](/connectors) explains.

What a connector brings in lands in the **feed**, which holds records as they arrived. What a person chooses to keep is in the **library**. [Items and types](/items-and-types#library-and-feed) explains the two.
