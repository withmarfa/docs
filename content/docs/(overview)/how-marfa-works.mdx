Marfa has one center, the **instance**, which holds your data. Everything else is either part of that data or a program that reaches the instance over its HTTP API. Each part has a page of its own, linked from its section.

## The instance

An instance is one running Marfa server and the data it keeps. It belongs to one person, its **owner**, and its data lives on the machine the server runs on. [Deploy](/guides/deploy) shows how to run one.

The instance is the **source of truth**. Apps, devices and connectors read from it and write to it, and never talk to each other directly. When two of them change the same thing, the instance decides the outcome, and every copy comes into line with it.

## Your data

Everything in an instance is an **item**, such as one note, task or photo. Its **type**, such as `core.note`, says which properties it holds, and Marfa checks every write against it. [Items and types](/items-and-types) explains both.

An item's content is its **properties**. Beside them sit its tags and extensions, and **edges** link it to other items, such as a note `about` a book. [Properties, metadata and edges](/properties-metadata-and-edges) explains when to use each.

A **file** is an item that names its bytes, a **blob**, which Marfa stores once however many items name it. [Files](/files) explains how.

## Changes

Every item has a **version**, and a write names the version it read, so Marfa can tell when someone else changed the item in between. [Versions](/versions) explains what Marfa does then.

Every change is also an **event** in one log. An app follows the log to stay current, or registers a webhook so Marfa posts changes to it. [Events and webhooks](/events) covers both.

## Who can reach it

Nothing reads or writes your data without a **credential**, and a credential reaches only what it was given. A script or an agent uses a **key**. An app signs in with OAuth, which is the preferred way for an app: the owner approves what it asks for. An app may also use a key. [Access](/access) explains both.

## What reaches it

Every program that uses Marfa runs outside it and sends requests to its HTTP API. Programs differ in what sits between them and the API:

- **The Swift SDK and the CLI** embed the **core**, a Rust engine that sends their requests and can keep a working copy of the data they need. A program that keeps a working copy is a **device**: it reads offline and sends its writes when it can reach the instance, as [Devices](/devices) explains.
- **The TypeScript SDK** sends each request straight to the API, and keeps no copy.
- **AI agents** use the CLI or the API like any script, with a key of their own, as [Use Marfa with AI agents](/guides/ai-agents) shows.
- **Connectors** are programs you run that bring in records from another service, such as Todoist, as [Connectors](/connectors) explains.
