Marfa keeps one person's data in one place: notes, tasks, bookmarks, messages, events, files. You run it yourself, on your own machine or a host you choose, and every app you allow reads and writes that data in shapes they all understand. A reading app can open with every article your browser saved, and a timeline can show your notes and events whichever app wrote them.

This page explains what Marfa is and how its parts fit together. To see it working, follow the [Quickstart](/quickstart): it starts Marfa on your machine and writes your first note.

<Callout title="Before the first release">Marfa hasn't had its first release yet. These docs describe Marfa as it is on its `main` branch, and they change as it does.</Callout>

## Why Marfa exists

Building an app has never been easier, but connecting apps is still hard. Each app keeps its data in its own place, in its own shape, behind its own API: your notes in one, your tasks in another, your reading in a third. To search across them or see them on one timeline, you glue their APIs together, and the next app you build starts with an empty database.

Marfa is the layer in the middle. Your data lives in one place, and many apps read and write it. An app you write next year can show what today's apps saved, without asking any of them.

## How Marfa fits together

One running Marfa is an **instance**. It belongs to one person, its owner, and holds that person's data. The server is the software that answers for the instance over HTTP, and it is the source of truth: everything else reads from it and writes to it.

<MarfaAtAGlance />

Three kinds of program reach an instance, and all of them use the same HTTP API:

- Apps and scripts send requests with a credential: a key you give them, or an access token from signing in. A credential reaches only the types of data it was given.
- Devices keep a working copy of part of the instance, so they read without a connection and queue their writes until they can send them. An app built on the [Swift package](/swift-package) is a device, and the [CLI](/cli) can be one too. A folder of files on your Mac can be one too.
- Connectors bring records in from services you already use, such as a task manager or an RSS feed, and can carry changes back. A connector is a program you run; the server never runs one.

None of these run inside Marfa. The server stores your data and answers requests; what reads and writes it runs wherever you choose.

## Your data, in four words

Everything in an instance is an **item**: one note, one task, one bookmark. Each item has a **type**, such as `core.note`, which says what properties it carries. Marfa ships types for common things, and you can register your own. [Items and types](/items-and-types) explains both.

**Edges** connect items: a note can be `about` a book, and a task can be the `parent-of` another. A **file** is an item that points at its bytes, which Marfa stores once however many items name them. [Properties, metadata and edges](/properties-metadata-and-edges) and [Files](/files) explain these.

Access follows the type. If you have built for Apple's HealthKit, the model is familiar: an app asks to read or write each type it needs, and sees nothing else. A credential that can't read a type gets the same answer as if no item of that type existed. [Access](/access) explains keys, apps and permissions.

## What you can build

Because the data is shared, the next app you build doesn't start empty. For example:

- A reading app that opens with every article your other apps saved.
- A timeline of your notes, events, messages and photos, whichever app wrote them.
- A personal CRM on the same `core.entity.person` items your other apps use.
- A connector that brings in records from a service you already use.
- A script or an agent that works with your data through a key you give it.

## Where it runs

Marfa runs on your own computer or on a host such as Railway, which has a ready-made template. Your data lives in one SQLite database file and a folder of file contents, so there's no database server to set up. [Deploy](/guides/deploy) covers keeping an instance running.

You reach your instance over your local network, from anywhere over a private network such as Tailscale (which these docs suggest), or at a public address on your own domain through a Cloudflare Tunnel. Signing in to the instance from a browser needs HTTPS, except on the instance's own machine.

## What Marfa isn't

Marfa isn't for sharing data between people: an instance has one owner, and every app and device works with that one person's data. It isn't a hosted service that keeps your data either. Your data lives on the machine you run Marfa on, and in any storage you choose to attach. And it isn't a place where apps run: they run outside it and reach it over the API.
