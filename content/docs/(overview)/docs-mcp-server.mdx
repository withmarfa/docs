title: Docs MCP server
description: Connect an AI agent to these docs over MCP, so it searches and reads the current pages instead of working from memory.
---

The docs MCP server lets an agent search and read these docs while it works. It runs at `https://docs.marfa.so/mcp`, over the Streamable HTTP transport, and needs no credential.

<Callout title="It reads the docs, not your data">It searches docs.marfa.so and can't reach your instance. To give an agent your data, give it a key and the CLI, as [Use Marfa with AI agents](/build/ai-agents) shows.</Callout>

## Connect it

Add the server to your agent as a remote HTTP server:

<Tabs items={["Claude Code", "Codex"]}>
<Tab value="Claude Code">

Add it to a project's `.mcp.json`, so everyone who works in the project has it:

```json title=".mcp.json"
{
  "mcpServers": {
    "marfa-docs": {
      "type": "http",
      "url": "https://docs.marfa.so/mcp"
    }
  }
}
```

Or add it from a terminal. `--scope project` writes it to `.mcp.json`; leave it out to add it for yourself only:

```bash
claude mcp add --transport http marfa-docs --scope project https://docs.marfa.so/mcp
```

</Tab>
<Tab value="Codex">

Add it to `~/.codex/config.toml`, or to a trusted project's `.codex/config.toml`:

```toml title="config.toml"
[mcp_servers.marfa-docs]
url = "https://docs.marfa.so/mcp"
```

Or add it from a terminal:

```bash
codex mcp add marfa-docs --url https://docs.marfa.so/mcp
```

</Tab>
</Tabs>

## Its tools

The server gives the agent three read-only tools. When the agent connects, the server also tells it how to use them: search to find pages, then fetch the page it needs.

| Tool | Input | Answer |
| --- | --- | --- |
| `docs_search` | `query`, and an optional `limit` from 1 to 50 | The pages that match, best first, each with its title, path and snippets. It returns passages and links, never a written answer |
| `docs_fetch` | `path`, such as `/files`, and an optional `section` | The page as Markdown, or only the section under the heading `section` names |
| `docs_list_topics` | None | Every page, with its title, path and description |

`docs_search` and `docs_list_topics` return structured results that follow the output schema each tool lists. The same JSON is also in the result's text, for a client that reads only text.

To read one part of a long page, such as a single release in the [Changelog](/changelog), pass `section`. Name the heading by its text, in any case, or by its id, such as `who-may-read-a-blob`. The result is that heading and everything under it, down to the next heading of the same level or a higher one. If two headings share a text, the first one wins; use the id to choose another.

`docs_fetch` answers with an error result when it can't return what you asked for. Its `error` is `not_found` when there's no page at the path, and `section_not_found` when the page has no such heading. A `section_not_found` result lists the page's headings in `headings`, so the agent can choose one.

The server allows each IP address 120 requests a minute, counting the handshake and every tool call. The limit is per IP address, so a service that calls the server for many people from one address shares it. A client over the limit gets `429` with a `Retry-After` header that holds the seconds to wait. [Docs as Markdown](/docs-as-markdown#request-limits-and-what-the-site-counts) says what the site counts about these requests.

An agent with no MCP can read the same pages through [Docs as Markdown](/docs-as-markdown).
