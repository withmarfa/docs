---
title: Properties, metadata and edges
description: An item's data lives in four places, properties, tags, extensions and edges, and each suits a different kind of information.
---

An item's own content is its **properties**, such as a note's title and body. Beside the item sits its **metadata record**, which holds **tags** and **extensions**. And **edges** link the item to other items.

The four differ in who decides their shape and in whether writing them changes the item's version, so choosing the right one keeps an app from fighting the model.

Try each kind of write on a note below, and watch what changes:

<ItemAnatomy />

| | What it holds | Who decides its shape | Moves the item's version |
| --- | --- | --- | --- |
| Properties | The item's own content, such as `title` and `body` | The item's type | Yes |
| Tags | Labels, such as `favorite` | No one: a tag is a word | No |
| Extensions | An app's own data about the item, under a namespace | The app that writes the namespace | No |
| Edges | A typed link to another item, such as `about` | The edge type | No: an edge has its own version |

## Which to use

- **A property** when the information is part of what the item is, and every app reading the type should understand it: a task's due date, a bookmark's URL.
- **A tag** when a person groups or marks items in their own way: `favorite`, `to-read`, `work`.
- **An extension** when your app keeps something about an item that only it needs, especially on an item another app wrote: your place in an article a connector brought in.
- **An edge** when the information is a relationship to another item: a note about a book, a subtask under its task.

## Properties

Properties are an item's content, and its type declares them, as [Items and types](/items-and-types) explains. An update sends only the properties it changes, and names the version it read:

```http
PATCH /items/{id}
Content-Type: application/json

{ "version": 3, "properties": { "title": "Reading list" } }
```

The item comes back at version 4, with its other properties as they were. **Because properties are what the version counts, two apps changing the same property can't silently overwrite each other.** [Versions](/versions) explains how Marfa settles that.

## Tags and extensions

Tags and extensions live in an item's metadata record. **Writing either leaves the item's version alone**, so a tag added on one device never makes another device's edit stale. Writing them still needs write access to the item's type.

A tag is a label with no schema and no hierarchy. An item's tags are a set, and a search matches them along with the item's text:

```http
POST /items/{id}/tags
Content-Type: application/json

{ "tags": ["favorite"] }
```

An extension is a JSON object stored on an item under a namespace, such as `com.example.reader`. Whoever writes a namespace decides what goes in it, and **one app's extension stays out of another's way**: a key reads and writes only the namespaces it was given.

```http
PUT /items/{id}/extensions/com.example.reader
Content-Type: application/json

{ "position": 0.42 }
```

Only a key's extension map grants extensions, so an app that signs in with OAuth reaches none. [Access](/access) explains the maps.

## Edges

An edge is a typed, directed link from one item to another: a note `about` a book, a task the `parent-of` a subtask. It's a record of its own, with its own `id`, properties and version, so writing it leaves both items' versions as they are.

```http
POST /edges
Content-Type: application/json

{ "source_id": "<note id>", "target_id": "<book id>", "edge_type": "about" }
```

**The edge type sets the rules**: how many edges each item can hold (a task has at most one parent), which types each end can be, and what trashing an item does across the edge. Trashing a parent trashes its children, while trashing a note leaves the book it was about. Read from the other end, an edge has a reverse name: `parent-of` reads as `child-of` from the child. You can [register edge types](/api-reference/edge-types/registerEdgeType) of your own.
