---
title: Versions
description: How an item's version counts its changes, so that two apps writing the same item never silently overwrite each other.
---

Many apps write to the same instance, often to the same item, and a device may send a write it made offline hours earlier. **Marfa keeps that safe with a version on every item.** A write names the version it read, and Marfa compares it with what has changed since before it applies anything.

## What the version counts

An item's `version` starts at 1 and goes up by one with each change to the item itself: its properties, its type, its tier, its `occurred_at` or its `source_id`.

**Everything else leaves the version alone**: tags, extensions, edges, and moves between active, archived and trashed. So a tag added in one app never makes another app's edit stale.

## When two apps write the same item

A write based on an older version isn't refused for that alone. Marfa looks at which fields your write changes and which fields changed since the version you read. **If they don't overlap, both changes stand.**

<Sequence title="Two apps edit the same note">

1. You read a note at version 3, and start changing its body.
2. Meanwhile, another app changes the note's title. The note is now at version 4.
3. You send your new body, naming version 3, the version you read.
4. Only the title changed since version 3, and you changed only the body, so nothing collides. Marfa applies your body. The note is at version 5, with both changes.

</Sequence>

Had the other app changed the body too, the two changes would collide. Marfa then refuses your write with `409 version_conflict` and sends back the note as it is now, so you can combine the two and try again.

A write can also ask Marfa to settle a collision for it, by the rules of the item's type. For a note, the last writer's title wins, and **both bodies are kept**: yours goes into a conflicted copy, a new note linked to the original, so neither writer's text is lost. Devices always write this way. [Write safely](/guides/write-safely) shows both ways.

## History

Each time an item's version moves, Marfa keeps a snapshot of the item as it was. The snapshots are what a stale write is compared against, and [List item versions](/api-reference/items/listItemVersions) reads them, oldest first. Each snapshot records which sign-in wrote it, such as an app, a key or a browser.

**Marfa doesn't keep every snapshot forever.** It keeps every recent one and fewer as they age. A write based on a version whose snapshot is gone can't be compared, so it's refused, and the app reads the item again before it writes.

The rules behind this page are in the [versions](https://github.com/withmarfa/marfa/blob/main/conformance/spec/versions.md) chapter of the contract.
