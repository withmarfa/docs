Many apps write to the same items, and a device may send a write it made offline hours earlier. **Marfa keeps that safe with a version on every item.** A write names the version it read, and Marfa checks what has changed since before it applies anything.

## Optimistic concurrency

Marfa uses **optimistic concurrency control**: it takes no lock when you read an item, and checks the version when you write. The `version` does the job an ETag with `If-Match` does in other HTTP APIs, except that the write names it in the request body, as the `version` field, not in a header. **A write that fails the check answers `409 version_conflict`, not `412 Precondition Failed`**, and carries the item as it is now.

## What the version counts

An item's `version` starts at 1 and goes up by one with each change to the item itself: its properties, its type, its tier, its `occurred_at` or its `source_id`.

**Everything else leaves the version alone**: tags, extensions, edges, and moves between active, archived and trashed. So a tag added in one app never makes another app's edit stale.

## When two apps write the same item

A write based on an older version isn't refused for that alone. Marfa looks at which fields your write changes and which fields changed since the version you read. **If they don't overlap, both changes stand.**

<Sequence title="Two apps edit the same note">

1. You read a note at version 3, and start changing its body.
2. Meanwhile, another app changes the note's title. The note is now at version 4.
3. You send your new body, naming version 3, the version you read.
4. Nothing collides, because only the title changed since version 3. The note is at version 5, with both changes.

</Sequence>

Had the other app changed the body too, the changes would collide, and Marfa would refuse your write with `409 version_conflict`, sending back the note as it is now for you to combine.

A write can also ask Marfa to settle a collision for it, with `conflict=auto`, by the rules of the item's type. For a note, the last writer's title wins, and **both bodies are kept**: yours goes into a conflicted copy, a new note linked to the original by a `derived-from` edge, so neither writer's text is lost. A [device](/devices) sends every update with `conflict=auto`. [Write safely](/guides/write-safely) shows both ways.

## History

Each time an item's version moves, Marfa keeps a snapshot of the item as it was. The snapshots are what a stale write is compared against, and [List item versions](/api-reference/items/listItemVersions) reads them, oldest first. Each snapshot records which sign-in wrote it, such as an app, a key or a browser.

**Marfa doesn't keep every snapshot forever.** It keeps every recent one and fewer as they age. A write based on a version whose snapshot is gone can't be compared, so it's refused, and the app reads the item again.

The rules behind this page are in the [versions](https://github.com/withmarfa/marfa/blob/main/conformance/spec/versions.md) chapter of the contract.
