title: Docs as Markdown
description: Read these docs from a terminal, as JSON or as Markdown, with no MCP, credential or Marfa instance needed.
---

Every page has a Markdown copy, and the whole site can be searched from the CLI or over plain HTTP, so an agent can read the docs before you've set anything up. An agent that supports MCP can use the [Docs MCP server](/docs-mcp-server) instead.

## Read a page as Markdown

Add `.md` to a page's path for its Markdown, such as `/files.md`. The copy holds the page's title and path, then its text, including anything the page draws in from the reference. A path with no page answers `404`.

You can also ask for the page's own address with `Accept: text/markdown`. `/files` and `/files/` then answer the same Markdown as `/files.md`, with `Content-Type: text/markdown`.

A request that ranks HTML higher, as a browser's does, or lists `text/html` before `text/markdown` at the same rank, still gets the HTML page, and both answers carry `Vary: Accept` so a cache keeps them apart. Each HTML page also names its Markdown copy in a `<link rel="alternate" type="text/markdown">` in its head.

<Terminal>

```bash
curl -H "Accept: text/markdown" https://docs.marfa.so/overview
```

```text
# Overview (/overview)

Marfa is a shared data layer for your apps, and you run it yourself.
```

</Terminal>

Three files cover the whole site:

| File | What it holds |
| --- | --- |
| [`/llms.txt`](/llms.txt) | An index: a summary of Marfa, then every page, grouped as the sidebar groups them, each linked to its Markdown copy or, for an API operation, its reference page |
| [`/docs-map.md`](/docs-map.md) | The same index, with links to the HTML pages |
| [`/llms-full.txt`](/llms-full.txt) | The Markdown of the written pages in one file, without the API operations and the changelog |

An operation's Markdown copy holds only its title and description; its reference page holds its request and answers. The changelog, left out for its length, has its own copy at [`/changelog.md`](/changelog.md). Search finds both, and `docs_fetch` and `marfa docs <page>` read them.

## Search from a terminal

`marfa docs` reads this site from the CLI, for an agent that runs shell commands and has no MCP. It needs no instance or key, and it refuses `--url`, `--key` and `--socket`, so it can't send a credential anywhere.

<Terminal>

```bash
marfa docs search "trash an item" --limit 1
```

```text
Trash an item  /api-reference/items/deleteItem
  Moves the item, and every item a cascading edge such as `parent-of` reaches, to the trash. You can restore them until the retention window ends. Marfa then purges them.
```

</Terminal>

`marfa docs topics` lists every page, and `marfa docs <page>` prints one as Markdown. Name a page by its path, such as `files`, or by its full address. With `--json`, `search` and `topics` print the JSON the addresses below answer, and a page prints its `path`, `url` and `markdown`.

When a search finds nothing, `marfa docs search` says so, lists up to five pages whose title, path or description holds a word of the query, and ends by pointing to `marfa docs topics`, which lists every page. With `--json` it prints the empty `{ "hits": [] }` and nothing else.

To read part of a long page, add `--section` and a heading of the page, as its text in any case or as its anchor. The command prints that heading and the sections inside it, up to the next heading of the same level or a higher one:

<Terminal>

```bash
marfa docs cli --section "Use another keychain file"
```

</Terminal>

With `--json`, the page's `markdown` holds only the section, and `section` holds the heading you asked for. A heading the page doesn't have is refused with `docs_section_not_found` and exit code `1`, and the refusal lists the page's headings.

On a terminal, `marfa docs` shows a control character in a page, other than a line break or a tab, as an escape such as `\u{1b}`, so a page can't move the cursor or redraw the screen. Piped to a program, the page is printed as the site sent it.

`marfa docs` exits `1` when there's no page at the path or no such section, and `3` when the site can't be read; the CLI's [exit codes](/cli#exit-codes) list them all. To read another copy of the site, such as one you run locally, set `MARFA_DOCS_URL` to its `http` or `https` address.

## Search and list pages as JSON

For a program with neither MCP nor the CLI, two addresses answer as JSON:

- `GET /api/docs/search?q=<query>&limit=<n>` answers the same hits as the search above, as `{ "hits": [...] }`, each with its `title`, its path in `url`, and `snippets`. `q` is required, and `limit` runs from 1 to 50. A blank `q` or a `limit` out of range answers `400`, with `invalid_query` or `invalid_limit` in `error`.
- `GET /api/docs/topics` lists every page as `{ "pages": [...] }`, each with its `title`, its path in `url`, its `description` and its `breadcrumbs`.

To read a page itself, fetch its Markdown copy.

## Request limits and what the site counts

`/api/docs/search` allows each IP address 60 requests a minute, so a service that makes requests for many people from one address shares that limit. A client over the limit gets `429` with a `Retry-After` header that holds the seconds to wait, and `marfa docs` reports it as exit code `3`. The other addresses on this page have no limit.

The site counts each request to these addresses, and to the Markdown copies, `llms.txt`, `llms-full.txt` and the [Docs MCP server](/docs-mcp-server), to see which pages agents read. A count records the kind of read, the HTTP method, the status, the page path, the MCP method and tool name, the number of search results, and a coarse class of client, such as `claude-code` or `browser`. It never records an IP address, a cookie, a search query, a page's text or the client's `User-Agent`, and it creates no profile of a reader. The count is itself limited for each IP address: a request the site refuses with `429` is not counted, and a request from an address over the counting limit is answered normally but not counted.
