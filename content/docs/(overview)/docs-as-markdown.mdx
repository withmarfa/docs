Every page has a Markdown copy, and the whole site can be searched from the CLI or over plain HTTP, so an agent can read the docs before you've set anything up. An agent that supports MCP can use the [Docs MCP server](/docs-mcp-server) instead.

## Read a page as Markdown

Add `.md` to a page's path for its Markdown, such as `/files.md`. The copy holds the page's title and path, then its text, including anything the page draws in from the reference. A path with no page answers `404`.

Three files cover the whole site:

| File | What it holds |
| --- | --- |
| [`/llms.txt`](/llms.txt) | An index: a summary of Marfa, then every page, grouped as the sidebar groups them. Written pages link to their Markdown copy, and API operations to their full reference page. |
| [`/docs-map.md`](/docs-map.md) | The same index, with links to the HTML pages |
| [`/llms-full.txt`](/llms-full.txt) | Every page's Markdown in one file |

## Search from a terminal

`marfa docs` reads this site from the CLI. It needs no instance or key, and it refuses `--url`, `--key` and `--socket`, so it can't send a credential anywhere. It suits an agent that runs shell commands and has no MCP:

```bash
marfa docs search "trash an item" --limit 1
```

```text
Trash an item  /api-reference/items/deleteItem
  Moves the item, and every item a cascading edge such as `parent-of` reaches, to the trash. You can restore them until the retention window ends. Marfa then purges them.
```

`marfa docs topics` lists every page, and `marfa docs <page>` prints one as Markdown. Name a page by its path, such as `files` or `/files`, or by its full address. With `--json`, `search` and `topics` print the same JSON as the addresses below, and a page prints its `path`, `url` and `markdown`.

`marfa docs` exits `1` when there's no page at the path and `3` when the site can't be read. The CLI's [exit codes](/cli#exit-codes) list them all.

To read another copy of the site, such as one you run locally, set `MARFA_DOCS_URL` to its `http` or `https` address.

## Search and list pages as JSON

For a program with neither MCP nor the CLI, two addresses answer the same searches and lists as JSON.

`GET /api/docs/search?q=<query>&limit=<n>` searches the pages. `q` is required, and `limit` is optional, from 1 to 50:

```http
GET /api/docs/search?q=trash%20an%20item&limit=1 HTTP/1.1
Host: docs.marfa.so
```

```json
{
  "hits": [
    {
      "title": "Trash an item",
      "url": "/api-reference/items/deleteItem",
      "snippets": [
        "Moves the item, and every item a cascading edge such as `parent-of` reaches, to the trash. You can restore them until the retention window ends. Marfa then purges them."
      ]
    }
  ]
}
```

A blank `q` or a `limit` out of range answers `400`, with `invalid_query` or `invalid_limit` in `error`.

`GET /api/docs/topics` lists every page as `{ "pages": [...] }`, each with its `title`, its path in `url`, its `description` and its `breadcrumbs`. To read a page itself, fetch its Markdown copy.
