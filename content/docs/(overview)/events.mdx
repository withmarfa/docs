An app that shows your data needs to know when any app changes it. Marfa records every change as an **event** in one log, in order. An event here is a record of a change, not a `core.event` item, which holds a calendar event.

The figure shows the two ways to follow the log: your app pulls events from the event stream, or Marfa pushes them to your service as webhooks.

## The event log

Every change to an item, an edge, or an item's tags and extensions adds an event to the log; a refused write adds none. Each event has an **event type** that says what changed, such as `item.updated`, or `metadata.changed` for tags and extensions, and carries the thing as it stands after the change.

Event IDs rise with every event, so the last ID an app handled, its **cursor**, says exactly where it stopped.

A credential sees only the events about what it can read. The Catalog's [Events](/catalog/events) page lists every event type and its fields.

## The event stream

The [event stream](/api-reference/event-stream/streamEvents) is a long-lived connection your app opens. Send your cursor, and Marfa replays every event after it, tells you when you've caught up, and then sends each new event as it happens. Resume from your cursor after a break, and you get every later event **exactly once**.

If you've been away longer than the log keeps events, which [Settings](/guides/settings) sets, your app reads its data again from the start. [Keep a copy in sync](/guides/keep-in-sync) shows how to follow it and handle each way it ends. The Swift SDK and the CLI follow the stream for you.

## Webhooks

A webhook works the other way round: Marfa posts to your service. You register a URL and the event types you want, and Marfa posts each new event there, signed so your service can check it came from your instance. If your service is down or busy, Marfa retries for several hours.

A webhook has no cursor and no replay: it delivers only events written after you registered it. Deliveries can arrive **out of order**. A receiver keeps the highest event ID it has applied for each item and ignores an older one.

| Use | When |
| --- | --- |
| The event stream | An app needs every change, including what it missed while away |
| A webhook | A service reacts to changes as they happen, such as sending a message when a task is done |

[Receive webhooks](/guides/receive-webhooks) shows how to register one and check each delivery.

The rules behind this page are in the [events](https://github.com/withmarfa/marfa/blob/main/conformance/spec/events.md) and [reach](https://github.com/withmarfa/marfa/blob/main/conformance/spec/reach.md) chapters of the contract.
