---
title: Quickstart
description: Start Marfa on your own computer, claim it, make a key, and write and read your first note.
---

By the end of this page you'll have a Marfa instance running on your computer, with you as its owner and one note in it. You need two terminal windows: one for the server, one for everything else. This instance is for trying Marfa; [Deploy](/guides/deploy) covers one you keep.

**You need** macOS or Linux, with Git, [Node.js](https://nodejs.org) 22.14 or later and [pnpm](https://pnpm.io/installation). On Linux, also install [Rust](https://www.rust-lang.org/tools/install), to build the CLI, and the `acl` package, which the server uses to check who may reach its private socket.

<Steps>
<Step>

### Start the server

Clone Marfa into a short path, such as your home directory, build it, and start the server:

```bash
cd ~
git clone https://github.com/withmarfa/marfa.git
cd marfa
pnpm install
pnpm build
cd packages/server
export MARFA_AUTH_SECRET="$(openssl rand -hex 32)"
pnpm dev
```

The server listens on `http://localhost:8600` and keeps its data in `packages/server/data`. A new instance has no owner yet, so the server prints a **setup code**, in a line that reads `Claim this Marfa at /setup with setup code: …`. Keep it for the next steps, and leave the server running.

</Step>
<Step>

### Install the CLI

The CLI is the `marfa` program, Marfa's command-line tool. Open a second terminal and install it:

<Tabs items={["macOS", "Linux"]}>
<Tab value="macOS">

Download it from the terminal, as below.

<include cwd>src/generated/cli-download.md</include>

</Tab>
<Tab value="Linux">

Build it from the clone with Rust:

```bash
cd ~/marfa
cargo install --locked --path core/marfa-cli
marfa --version
```

</Tab>
</Tabs>

</Step>
<Step>

### Claim the instance

Claiming makes you the owner, once and for good: a second claim is refused.

<Tabs items={["In the terminal", "In the browser"]}>
<Tab value="In the terminal">

```bash
marfa setup claim --url http://localhost:8600 --email you@example.com
```

The CLI asks for a password for the owner, then for the setup code the server printed. Neither is shown as you type.

</Tab>
<Tab value="In the browser">

Open `http://localhost:8600/setup`, enter the setup code the server printed, and choose the owner's email and password. **Claiming signs you in**, and setup goes on from there to add a passkey, name the instance, connect something and read how it's backed up. Done opens [Home](/guides/sign-in-as-the-owner#start-from-home).

</Tab>
</Tabs>

</Step>
<Step>

### Make a key

**Programs that work with your data use a key**, the CLI included. The owner makes the first one from the instance's own computer, through the server's private socket. In the second terminal:

```bash
cd ~/marfa/packages/server
marfa --socket "$(pwd -P)/data/control/marfa.sock" keys create --label laptop --source laptop
```

The CLI prints the key, which begins `marfa_k1_`, once, on the first line. This key can do everything the owner can grant, which suits a trial. Give an app or a script a narrower one, as [Manage keys](/guides/manage-keys) shows.

Point the CLI and the examples below at your instance, with the key:

```bash
export MARFA_API_URL=http://localhost:8600
export MARFA_API_KEY=<the key>
marfa status
```

`marfa status` names the instance and shows `health ok`.

</Step>
<Step>

### Write a note

A note is an item of the type `core.note`, which requires a `body`. Create one:

```bash tab="CLI" tab-group="client"
marfa items create --type core.note \
  --prop title="Reading list" --prop body="Start with the essays." --json
```

```bash tab="HTTP"
curl -s http://localhost:8600/items \
  -H "Authorization: Bearer $MARFA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "type": "core.note", "properties": { "title": "Reading list", "body": "Start with the essays." } }'
```

```js tab="TypeScript" title="note.mjs"
// npm install @withmarfa/client
import { createClient } from "@withmarfa/client";

const marfa = createClient({
  baseUrl: process.env.MARFA_API_URL,
  credential: process.env.MARFA_API_KEY,
});

const { data, error } = await marfa.POST("/items", {
  body: {
    type: "core.note",
    properties: { title: "Reading list", body: "Start with the essays." },
  },
});
if (error) throw new Error(error.error.message);
console.log(data.item.id, data.item.version);
```

Marfa answers with the new item: an `id` it made, the properties you sent, and a `version` of 1. Copy the `id` for the next step.

```json
{
  "item": {
    "id": "01a12192-a000-76e3-b129-b55027e21dcb",
    "type": "core.note",
    "state": "active",
    "properties": { "body": "Start with the essays.", "title": "Reading list" },
    "version": 1,
    "source": "laptop"
  }
}
```

The answer has more fields than this; the Catalog's [Items](/catalog/items#fields-every-item-has) page lists them.

</Step>
<Step>

### Read it back and change it

Read the note by its `id`:

```bash tab="CLI" tab-group="client"
marfa items get <id> --json
```

```bash tab="HTTP"
curl -s http://localhost:8600/items/<id> -H "Authorization: Bearer $MARFA_API_KEY"
```

```js tab="TypeScript"
const id = "<id>";
const { data: note } = await marfa.GET("/items/{id}", { params: { path: { id } } });
```

Now change its body. **An update names the version it read**, so Marfa can tell whether someone else changed the note in between:

```bash tab="CLI" tab-group="client"
marfa items update <id> --version 1 \
  --prop body="Start with the essays, then the letters." --json
```

```bash tab="HTTP"
curl -s -X PATCH http://localhost:8600/items/<id> \
  -H "Authorization: Bearer $MARFA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "version": 1, "properties": { "body": "Start with the essays, then the letters." } }'
```

```js tab="TypeScript"
await marfa.PATCH("/items/{id}", {
  params: { path: { id } },
  body: { version: 1, properties: { body: "Start with the essays, then the letters." } },
});
```

The note comes back at version 2, with the new body and its title unchanged. Had another app changed the body since version 1, Marfa would have refused your write rather than overwrite theirs. [Versions](/versions) explains how.

</Step>
</Steps>
