---
title: Sort out a conflicted copy
description: See which edits to a note merge, which make a conflicted copy, and how to keep the version you want.
---

A note can change in two places at once: in your editor and from an agent, or on two computers that follow one folder. **Most edits meet and merge.** When two edits rewrite a note's text, Marfa keeps both: one stays in the note, and the other becomes a conflicted copy, a second file for you to sort out.

## Edits that merge

Each file names the version of the note it was written from, on its `marfa_version` line. When you save, Marfa compares your edit with what changed on your instance since that version:

- **Edits to different parts merge.** You add a tag on one computer while an agent rewrites the body on the other, and the note ends with both. Every computer's file then shows both changes.
- **A rename and an edit merge.** Rename a file on one computer and edit its body on another, and the note has the new title and the new body.
- **Two changes to the title don't make a copy.** The one that reaches your instance last is the title, and the same holds for the note's other properties, such as its language.
- **A computer that was off merges the same way.** When its watch starts again, its edits from while it was away merge or conflict by the same rules, and it receives what changed elsewhere, deletes included.

## Edits that make a conflicted copy

Only a note's text makes a copy: its body, or its `notes` property. When two edits change the same one, such as both rewriting the body, **the first to reach your instance keeps the note.** The other becomes a new note, a conflicted copy, and its file appears beside the original on every computer that follows the folder. A push or a watch reports it:

```text
conflicted update_item Trip ideas.md conflicted copy Trip ideas (2).md
```

The copy holds the edit that came second, word for word, under the same title, so its file gets a number:

```markdown title="Home/Trip ideas (2).md"
---
type: core.note
tier: library
tags:
  - conflicted-copy
  - lisbon
title: Trip ideas
derived-from:
  - "[[01a1f156-a90d-74da-a4fb-68ebfdabc90f]]"
marfa_id: 01a1f15b-2c7e-7a41-b0d3-5e8f19c2a6d4
marfa_version: 1
---
Lisbon in May. Book the hotel and the train by Friday.
```

- **It's tagged `conflicted-copy`,** beside the original's own tags, so `marfa items list --tag conflicted-copy` finds every one.
- **Its `derived-from` line** names the note it was copied from.
- **It's a note of its own,** with its own `marfa_id`, so nothing you do to it changes the original.

## Sort it out

Open both files and decide what the note should say:

1. Copy what you want to keep from `Trip ideas (2).md` into the original, `Trip ideas.md`, and save it.
2. Delete the conflicted copy's file. It moves to the bin, where you can restore it if you change your mind.

To keep the copy's version instead, paste its body over the original's, then delete the copy. **Edit the original, not the copy,** so links to the note, its tags and its history stay with it.

An agent can do the same: ask it to find notes tagged `conflicted-copy`, show you each pair, and merge them as you say.

## Make conflicts rare

- **Keep a watch running on every computer,** as [Keep folders syncing](/use/keep-folders-syncing) shows, so each edit reaches the others quickly and two edits seldom overlap.
- **Save often** in an editor that keeps a file open for a long time.
- **Have an agent read a note before it changes it.** An agent that works through the MCP server does this by itself, and its change is refused, not copied, if the note changed since it read it.
