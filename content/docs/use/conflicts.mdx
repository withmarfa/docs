title: Sort out a conflicted copy
description: See which edits to a folder merge, which make a conflicted copy, and how to resolve one.
---

This page will say what happens when two edits to one note meet, from one computer or two, and how to tell a conflicted copy apart and resolve it.

## Edit on either side

Edit a file and sync, and the edit reaches its item:

<Terminal>

```bash
marfa folders push Notes
```

```text
0 created, 1 updated, 0 renamed, 2 unchanged, 0 missing, 0 deleted, 0 skipped
the server answered 1 write(s)
1 file(s) written
```

</Terminal>

An edit is a write based on the `marfa_version` the file names. If another app changed the same note meanwhile, the instance settles the two as [Versions](/build/versions) explains: changes to different fields merge, and a collision the type can't merge leaves a conflicted copy, which appears as a second file.

A note's file name and its title stay in step. Rename the file and the new name, without its extension, becomes the title. Change the title anywhere else and the next sync renames the file, numbering the name if another file has it. The folder leaves a name alone when it can't tell whether you chose it.
