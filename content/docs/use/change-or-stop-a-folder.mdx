A folder's settings live on your instance, so **a change reaches every directory that follows the folder.** Stopping never deletes an item. The examples use the `Home` folder in `~/Documents/Home`, from [Sync a folder](/use/sync-a-folder).

## Hold only some items

Edit `.marfa/folder.yaml` in any directory that follows the folder, and the next sync sends the change. **Leave `folder` and `version` to Marfa.**

```yaml title="Home/.marfa/folder.yaml"
folder: 01a1f46f-bed0-7310-bb7c-840868eb64ac
version: 1
title: Home
query:
  types:
    - core.note
    - core.file
  filter: "tags contains \"home\""
defaults:
  tags:
    - home
ignore:
  - drafts/
```

- **`query`** says which items the folder holds: here notes and files tagged `home`.
- **`defaults`** says what a new file gets when it doesn't say, here the tag `home`.
- **`ignore`** lists the paths the folder leaves alone, in the form `.gitignore` takes.

To clear a setting, empty its value: a setting you delete from the file is refused. **While the first sync waits for you,** the file isn't read, so change the settings with `marfa folders update` instead, as the [folder type](/catalog/folder) shows with every setting.

## What a narrower or wider query does

- **Items the query now holds** are written as new files. Widening a query can write many.
- **Items that leave the query by type, tier, tag, filter or `beneath` keep their files,** which go on syncing. **An item that leaves by state loses its file** at the next pull, unless the file changed since Marfa wrote it. Nothing moves to the bin. Two directories that follow this folder on one computer each keep their own file, and when the query widens again each writes its own.
- **No folder hands a file to another folder on the computer.** Where an item moves from this folder's query into another's, this one keeps its file as unmatched and the other writes its own.

To take those files away, list them, then remove them. Their items stay as they were:

<Terminal>

```bash
marfa folders unmatched ~/Documents/Home
```

```text
1 unmatched file(s), 1 of them removable with `folders unmatched --remove`
Tram.md
```

</Terminal>

`marfa folders unmatched ~/Documents/Home --remove` asks first, and keeps a file you've changed since the folder wrote it. Use it rather than your file manager: deleting a file by hand moves its item to the bin.

## Pause a folder

Pause one directory's sync, and the others go on:

<Terminal>

```bash
marfa folders pause ~/Documents/Home
```

```text
/Users/sam/Documents/Home is paused; `folders resume` lets its sync go on
```

</Terminal>

**A pause changes no file and sends nothing,** and lasts through a restart of the watch or the computer. Meanwhile the watch skips the directory, and a push, pull or scan is refused `sync_paused`. Edit the files if you like: `marfa folders resume ~/Documents/Home` lets the sync go on, and it sends your changes and takes in what changed elsewhere. To stop a directory before you [move to a new install](/run/upgrade#move-to-a-new-install), run `marfa folders push` first: an edit not yet sent stays only on disk, and the copy you move doesn't hold it.

## Stop following in one directory

Run `marfa folders push ~/Documents/Home` first, so no edit stays only on disk, then:

<Terminal>

```bash
marfa folders remove ~/Documents/Home
```

```text
/Users/sam/Documents/Home no longer follows the folder 01a1f46f-bed0-7310-bb7c-840868eb64ac; its files stay
```

</Terminal>

**The files stay as plain files** that no longer sync, and other directories go on. `remove` is refused while edits wait to be sent, unless another Marfa instance answers at the folder's address ([Keep folder edits after a restore](/run/keep-folder-edits-after-a-restore)). Once you delete the directory, [forget it](/use/settle-a-held-delete#when-the-other-folder-is-gone). `marfa folders add` with the folder's ID follows it again: each note, and each file you haven't changed since, rejoins its item, and a file you changed comes back as a new item.

## Retire a folder everywhere

A retired folder's items stay, but no directory can sync it again, so send every edit first:

1. In each directory that follows the folder, run `marfa folders push`.
2. Run `marfa folders revoke` with the folder's ID.
3. In each directory, run `marfa folders remove` to keep its files as plain files.

A directory you miss says so at its next sync, and step 3 there ends it:

```text
marfa: the folder 01a1f46f-bed0-7310-bb7c-840868eb64ac is revoked, and a revoked folder has no settings to follow
```
