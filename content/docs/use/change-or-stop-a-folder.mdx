A folder's settings live on your instance, so **a change reaches every directory that follows the folder.** Stopping never deletes an item.

## Change what a folder holds

Edit `.marfa/folder.yaml` in any directory that follows the folder, and the next sync sends the change. **Leave `folder` and `version` to Marfa.**

```yaml title="Home/.marfa/folder.yaml"
folder: 01a1f445-dde9-7548-bdb5-6823ae8ee275
version: 2
title: Home
query:
  types:
    - core.note
    - core.file
defaults:
  tags:
    - from-folder
ignore:
  - drafts/
```

- **`query`** says which items the folder holds. Add a `filter`, such as `tags contains "lisbon"`, to hold only some, or `tier: all` to take in the feed too.
- **`defaults`** says what a new file gets when it doesn't say, here the tag `from-folder`.
- **`ignore`** lists the paths the folder leaves alone, in the form `.gitignore` takes.

The [folder type](/catalog/folder) lists every setting. To change one from the CLI instead, name the version you read, so two changes made at once don't overwrite each other:

<Terminal>

```bash
marfa folders update 01a1f445-dde9-7548-bdb5-6823ae8ee275 --version 1 --ignore 'drafts/' --defaults '{"tags":["from-folder"]}'
```

```text
version                   2
properties.defaults.tags  from-folder
properties.ignore         drafts/
```

</Terminal>

Each setting you name replaces its value whole.

## What a narrower or wider query does

- **Items the query now holds** are written as new files. Widening a query can write many.
- **Items it no longer holds keep their files,** which stop syncing. Nothing moves to the bin.

To take those files away, list them, then remove them. Their items stay as they were:

<Terminal>

```bash
marfa folders unmatched ~/Trip
```

```text
1 unmatched file(s), 1 of them removable with `folders unmatched --remove`
Questions.md
```

</Terminal>

`marfa folders unmatched ~/Trip --remove` asks first, and keeps a file you've changed since the folder wrote it. Use it rather than your file manager: deleting a file by hand moves its item to the bin.

## Stop syncing for a while

There's no pause command yet: **a folder syncs only while a watch runs.** Run `marfa folders autostart off` to stop the watch, and every folder on the computer with it. Edit the files meanwhile if you like: when you turn autostart on again, the watch sends your changes and takes in what changed elsewhere.

To stop one folder and keep the others syncing, stop following it in its directory, and add it again later.

## Stop following in one directory

<Terminal>

```bash
marfa folders remove ~/Trip
```

```text
/Users/sam/Trip is no longer a folder; its files stay
```

</Terminal>

**The files stay as plain files** that no longer sync, and other directories go on. Run `marfa folders push ~/Trip` first: `remove` is refused while edits it has found wait to be sent, but an edit it hasn't scanned yet stays only on disk. `marfa folders add` with the folder's ID follows it again, and makes no duplicates.

## Retire a folder everywhere

`marfa folders revoke <id>` retires the folder's settings for good. Its items stay, and a directory that still follows it can't sync:

```text
marfa: the folder 01a1f448-cb83-74dd-bebf-1f2b25bb796d is revoked, and a revoked folder has no settings to follow
```

Run `marfa folders remove` in each such directory to keep its files.
