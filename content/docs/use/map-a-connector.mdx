A plugin's connector brings one or more **kinds** of record. Until you save a mapping, each kind lands as its own type, in the [feed](/build/items-and-types#library-and-feed). The mapping is your choice, for each kind, of whether it comes in, which type and tier it lands as, and how each field is filled. [The connector kit](/reference/connector-kit#mapping) says how a template is rendered, how a status word is chosen, and when two kinds cannot share a type. Each command needs `connectors.manage`.

## Read the mapping

```bash
marfa plugins mapping show rss
```

Until you save one, the answer is version `0`. Each kind is on, on its own type, at tier `feed`, and each field is filled from the field of the same name, unless the plugin sets another default.

## Change a kind

Edit a JSON or YAML file. A kind or a member you leave out is stored as its default. On a kind whose `target_type` is not its own type, fields you leave out are filled from the field of the same name, where both types have it, and status overrides you leave out are empty. This puts the RSS connector's entries in the library:

```yaml title="mapping.yaml"
version: 0
kinds:
  entry:
    tier: library
```

<Terminal>

```bash
marfa plugins mapping set rss mapping.yaml
```

```text
saved the mapping of rss at version 1
```

</Terminal>

Reading it again shows that kind's tier as `library`. The picture kind, left out of the file, stays at its default.

For each kind:

- **Turn a kind off** with `enabled: false`. It writes nothing, reads nothing and carries nothing, and the items it already brought stay where they are.
- **Write a kind as another type** by setting `target_type` to a type you can write. The connector then creates and edits items of that type only under its own source. Your own items of that type are left alone.
- **A create names no tier.** Marfa gives the item the tier that kind's mapping names. Until you set one, that tier is the feed.

A field is `from` (a field of the kind's own type), `fixed` (one value for every item) or `template` (a text field only). `status_overrides` maps one of the kind's status words to one of the target type. Both are on the [kit page](/reference/connector-kit#mapping).

## When a save is refused

Marfa checks the mapping as it saves it. A mapping that doesn't fit is refused `400 validation_error`, and the answer names the path: a target type that is missing, under `system`, or not one you can write, among other faults. Send the version you read. A mapping saved since then is refused, and nothing is saved:

```text
marfa: the server refused (409 connector_mapping_stale): The mapping is at version 1. Read it again and send that version. {"version":1}
```

Read the mapping again and send that version.

## Preview a kind

To see how one kind would land, put a draft of that kind's entry in a file. Marfa checks the draft as a save would, and saves nothing:

```bash
marfa plugins mapping preview rss --kind entry --file entry.yaml --wait
```

The connector renders it on its next look, on the item `--item` names or on one it chooses. `--wait` prints the fields it filled. Without `--file`, it previews the mapping in force. **A preview lasts 10 minutes.** One the connector could not render, or did not answer in time, ends with `preview_ended`. A paused connector answers none ([the kit](/reference/connector-kit#pause-run-now-and-previews)).

## Move what it already brought

Saving a mapping changes no item. It applies to what the connector writes next. To move the items it already brought, [rewrite them](/use/rewrite-connector-records).

Removing the plugin removes the mapping. An archive carries it, and a restore keeps a mapping you saved rather than the archive's ([Move your data with an archive](/run/export-and-restore#what-a-restore-changes)).
