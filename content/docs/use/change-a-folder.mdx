---
title: Change what a folder syncs
description: Change which items a folder holds, what its new files become, and which files it leaves alone.
---

A folder's settings live on your instance, so **a change reaches every computer that follows the folder.** Change them in the folder's own settings file, or with the CLI from any computer.

## Edit the settings file

Each computer writes the folder's settings into `.marfa/folder.yaml`:

```yaml title="Home/.marfa/folder.yaml"
# This folder's settings, the system.folder it follows. An edit here is
# sent through the folder operations by `folders push`, or while watching.
folder: 01a1f165-1c9c-71f5-b4b6-e88135e8df1f
version: 2
title: Home
query:
  types:
    - core.note
    - core.file
defaults:
  tags:
    - from-folder
ignore:
  - drafts/
```

Edit the file and save it, and the next sync sends the change to your instance. **Leave `folder` and `version` to Marfa.**

- **`query`** says which items the folder holds. Add `tier: all` to take in the feed too, or a `filter` to hold only some items, such as `tags contains "lisbon"`.
- **`defaults`** says what a new file becomes when its frontmatter leaves something out, such as its type or tags. Here every new note or file is tagged `from-folder`.
- **`ignore`** lists the paths the folder leaves alone, in the form a `.gitignore` takes. Here the folder doesn't sync the `drafts` directory.

The [folder type](/catalog/folder) lists every setting, such as `full_pass_interval_seconds` and the thresholds for [large changes](/use/large-changes).

## Change it from the CLI

From any computer you're signed in on, change a setting by the folder's ID. **A change names the version it starts from,** so two changes made at once don't overwrite each other. Read the version with `marfa items get <id>`, then send the change:

<Terminal>

```bash
marfa folders update 01a1f165-1c9c-71f5-b4b6-e88135e8df1f --version 1 \
  --ignore 'drafts/' --defaults '{"tags":["from-folder"]}'
```

**Each setting you name replaces its value whole,** and settings you leave out stay as they were. To hold only the notes and files tagged `lisbon`, send the whole query:

```bash
marfa folders update <id> --version <n> \
  --query '{"types":["core.note","core.file"],"filter":"tags contains \"lisbon\""}'
```

The other computers take the change on their next sync.

## What a change to the query does

- **Items the query now holds** are written into the folder as new files on the next sync. Widening a query can write many, so check with `marfa search` or `marfa items list` first.
- **Items the query no longer holds keep their files.** The folder stops syncing them, and nothing moves to the bin. [Remove files a folder no longer holds](#remove-files-a-folder-no-longer-holds) takes the files away.
- **A new file the query wouldn't hold** is still sent, and flagged unmatched. To leave such files on disk instead, set `outside_query` to `hold`.

[List, filter and search](/build/list-filter-search) has the whole filter grammar.

## Remove files a folder no longer holds

When you narrow a query, the files of the items it drops stay on disk. List them, then remove them:

```bash
marfa folders unmatched ~/Home
marfa folders unmatched ~/Home --remove
```

`--remove` asks before it takes anything away, and keeps a file you've changed since the folder wrote it. **Use it rather than your file manager:** a file you delete by hand moves its item to the bin, while this command only takes the file out of the folder, and the item stays as it was.
