---
title: Keep folders syncing
description: Keep every folder on your computer in step with one watch that starts when you sign in, and work on a folder's files while it runs.
---

A folder you [set up](/use/sync-a-folder) stays in step only while something watches it. **One watch keeps every folder on the computer in step,** and autostart runs it each time you sign in, so no terminal stays open.

## Start the watch when you sign in

Turn on autostart once on each computer:

```bash
marfa folders autostart on
```

It starts the watch at once, in your own account, and starts it again each time you sign in. It needs no administrator: on macOS it's a launchd agent, and on Linux a systemd user unit. **It holds no key and no address:** each folder uses the sign-in the keychain keeps for its instance, the one `marfa login` made.

The watch gives way to what you're doing, so it doesn't slow your computer down, and it keeps working when every core is busy.

To see whether it's running, and which folders it holds:

```bash
marfa folders autostart status
```

`status` also says when a folder isn't being watched, and why, such as a folder whose first sync waits for you to confirm it, or one with no sign-in the watch can use.

## Watch by hand

To run the watch yourself, in a terminal, start it with no directory. It watches every folder that `marfa folders list` shows:

<Terminal>

```bash
marfa folders watch
```

```text
watching every folder /Users/sam/Library/Application Support/Marfa/folders.json lists (interrupt to stop)
/Users/sam/Notes: watching
/Users/sam/Recipes: watching
/Users/sam/Notes: 0 created, 1 updated, 0 renamed, 0 deleted; the server answered 1 write(s); 1 file(s) written
```

</Terminal>

Press Ctrl-C to stop it. To watch one folder, name its directory: `marfa folders watch ~/Notes`. Don't run a watch by hand while autostart is on: only one process can work a folder at a time.

## What the watch does

- **An edit reaches your instance within seconds,** because your computer tells the watch which files changed. A change made elsewhere, by an agent or another computer, is written into the files as quickly.
- **It reads every file every 10 minutes,** in case your computer missed a change. For a large folder that rarely changes, make that less often with the folder's `full_pass_interval_seconds`, as [Change a folder](/use/change-a-folder) shows.
- **It follows the list of folders.** A folder you add joins the watch, and one you remove leaves it, with no restart.
- **One folder that can't be watched doesn't stop the others.** The watch reports it once and tries again. A folder whose directory is on a disk that isn't connected stays listed until you remove it.
- **When the instance can't be reached,** the watch keeps your edits and sends them once it can. If the instance is limiting requests, the watch waits as long as it asks and carries on.

## Work on a folder while the watch runs

A command that works a folder, such as `marfa folders confirm`, `restore` or `push`, asks the running watch for it. The watch finishes the step it's on, lets the folder go, and takes it back when the command ends. If the watch hasn't let go within 10 seconds, the command is refused before it changes anything with `reading_handle`: run it again.

## Use a key file on a computer nobody signs in to

On a server, or a Mac that runs with nobody signed in, the keychain stays locked. **A key file replaces the keychain for the watch.** Make a key with only what the folders need, as [Manage keys](/run/manage-keys) shows, and write a file with two lines, outside every folder:

```bash title="~/.config/marfa/watch.env"
MARFA_API_URL=https://marfa.example.com
MARFA_API_KEY=marfa_k1_…
```

Make it readable by you alone, then turn autostart on with it:

```bash
chmod 600 ~/.config/marfa/watch.env
marfa folders autostart on --key-file ~/.config/marfa/watch.env
```

- **The file must be yours and closed to everyone else** (mode 600), and lie outside every folder. Otherwise the command says what's wrong and writes nothing. A file inside a folder would be sent to your instance as one of its files.
- **The key is used only for the folders on that instance.** A folder on another instance is reported as having no credential.
- **The file is read again each time the watch opens a folder,** so a new key you put in the file is the one it uses next.

`marfa folders autostart on` with no `--key-file` goes back to the keychain.

## After you upgrade the CLI

When an upgrade puts a new `marfa` at the path autostart runs, **the watch moves to it by itself.** It finishes what it's doing, ends, and the new build starts in its place. Nothing it was sending is lost. Its log names both builds:

```text
restarting for a new build: marfa 0.0.79 to 0.0.80; the watch ends once the passes under way finish, and the service manager starts /Users/sam/.local/bin/marfa
```

A new build may also replace a folder's own store under `.marfa`, keeping every edit not yet sent. A watch you started by hand keeps running the build it started with, and says so once: start it again to use the new one.

If `autostart status` says the agent is outdated, run `marfa folders autostart on` again with the same options, such as `--key-file`.

## Read the watch's log

The watch writes to `folder-watch.log` beside the list of folders, readable by you alone. **If edits stop reaching your instance, read the end of the log first.** When something stopped the watch, its last line says what and when:

```text
2026-11-19T12:00:00Z folders watch stopped by SIGTERM, sent by process 4821
```

To have the watch send error reports, set the telemetry settings in your shell before you run `autostart on`, as [What the CLI and apps send](/run/client-telemetry) lists. [Folder sync status](/folder-sync-status) describes the file another program can read to show how each folder stands.

## Remove files a folder no longer holds

When an item leaves a folder's query, such as when you narrow the query, the folder keeps its file rather than deleting it. `marfa folders unmatched ~/Notes` lists those files, and `--remove` takes them away after asking. **Use this, never your file manager:** a file you delete by hand moves its item to the bin, while this command only stops the folder holding it, and the item stays as it was.

## Stop syncing

`marfa folders autostart off` stops the watch and turns autostart off. Your folders stay as they are, and nothing syncs until you start a watch again. [Stop or remove a folder](/use/pause-or-stop-a-folder) covers taking one folder off a computer.
