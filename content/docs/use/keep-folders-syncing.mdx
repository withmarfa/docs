---
title: Keep folders syncing
description: Keep every folder on your computer in step with one watch that starts when you log in, and work on a folder while it runs.
---

A folder you [set up](/use/sync-a-folder) stays in step only while something watches it. **One watch keeps every folder on the computer in step,** and autostart runs it each time you log in, so no terminal stays open.

## Start the watch when you log in

Turn on autostart once on each computer:

```bash
marfa folders autostart on
```

It starts the watch at once, in your own account, and starts it again each time you log in. It needs no administrator: on macOS it's a launchd agent, and on Linux a systemd user unit. **It holds no key and no address:** each folder uses the sign-in the keychain keeps for its instance, the one `marfa login` made.

The watch runs at a lower priority than your apps, so it doesn't slow your computer down, but it still keeps working when every core is busy.

To see whether it's running, and which folders it holds:

```bash
marfa folders autostart status
```

`status` also says when a folder isn't being watched, and why, such as a folder whose first sync waits for you to confirm it, or one with no sign-in the watch can use.

## Watch by hand

To run the watch yourself, in a terminal, start it with no directory. It watches every folder that `marfa folders list` shows:

<Terminal>

```bash
marfa folders watch
```

```text
watching every folder /Users/sam/Library/Application Support/Marfa/folders.json lists (interrupt to stop)
/Users/sam/Home: watching
/Users/sam/Recipes: watching
/Users/sam/Home: 0 created, 1 updated, 0 renamed, 0 deleted; the server answered 1 write(s); 1 file(s) written
```

</Terminal>

Press Ctrl-C to stop it. To watch one folder, name its directory: `marfa folders watch ~/Home`. Don't run a watch by hand while autostart is on: only one process can work a folder at a time.

## What the watch does

- **An edit reaches your instance within seconds,** because your computer tells the watch which files changed. A change made elsewhere, by an agent or another computer, is written into the files as quickly.
- **It reads every file every 10 minutes,** in case your computer missed a change. For a large folder that rarely changes, make that less often with the folder's `full_pass_interval_seconds`, as [Change what a folder syncs](/use/change-a-folder) shows.
- **It follows the list of folders.** A folder you add joins the watch, and one you remove leaves it, with no restart.
- **One folder that can't be watched doesn't stop the others.** The watch reports it once and tries again. A folder whose directory is on a disk that isn't connected stays listed until you remove it.
- **When the instance can't be reached,** the watch keeps your edits and sends them once it can. If the instance is limiting requests, the watch waits as long as it asks and carries on.

## Work on a folder while the watch runs

A command that works a folder, such as `marfa folders confirm`, `restore` or `push`, asks the running watch for it. The watch finishes the step it's on, lets the folder go, and takes it back when the command ends. If the watch is slow to let go, the command changes nothing and says so: run it again.

## A computer nobody logs in to

On a server, or a Mac that runs with nobody logged in, the keychain stays locked, so the watch can't use your sign-in. Give it a key file in its place, as [Manage keys](/run/manage-keys) shows.

## After you upgrade the CLI

[Update the CLI](/cli#update-the-cli) says how to update it. On the machine that runs your instance, the newer CLI goes in a folder of its own, so the watch keeps running the server's `marfa`. Elsewhere, when an update puts a new `marfa` at the path autostart runs, **the watch moves to it by itself.** It finishes what it's doing, ends, and the new build starts in its place. Nothing it was sending is lost. Its log names both builds:

```text
restarting for a new build: marfa 0.0.79 to 0.0.80; the watch ends once the passes under way finish, and the service manager starts /Users/sam/.local/bin/marfa
```

A new build may also replace a folder's own store under `.marfa`, keeping every edit not yet sent. A watch you started by hand keeps running the build it started with, and says so once: start it again to use the new one.

If `autostart status` says the agent is outdated, run `marfa folders autostart on` again with the options you used before.

## If edits stop arriving

The watch keeps a log of what it did and why it stopped. If edits stop reaching your instance, [Folders](/run/troubleshooting/folders) in Troubleshooting says where the log is and how to read it. [Folder sync status](/folder-sync-status) describes the file another program can read to show how each folder stands.

## Stop syncing

`marfa folders autostart off` stops the watch and turns autostart off. Your folders stay as they are, and nothing syncs until you start a watch again. [Pause or stop syncing a folder](/use/pause-or-stop-a-folder) covers taking one folder off a computer.
