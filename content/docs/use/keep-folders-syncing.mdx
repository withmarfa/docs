A folder you [set up](/use/sync-a-folder) stays in step only while something watches it. **One watch keeps every folder on the computer in step,** and autostart runs it each time you log in, so no terminal stays open.

## Start the watch when you log in

Turn on autostart once on each computer:

```bash
marfa folders autostart on
```

It starts the watch at once, in your own account, and again each time you log in: a launchd agent on macOS, a systemd user unit on Linux. **It holds no key:** each folder uses the sign-in that `marfa login` keeps in your keychain. It runs at a lower priority than your apps.

`marfa folders autostart status` says whether it's running, and why any folder isn't watched, such as one whose first sync waits for you.

On a server, or a Mac that runs with nobody logged in, the keychain stays locked, so give the watch a key file instead, as [Manage keys](/run/manage-keys) shows. When you [update the CLI](/cli#update-the-cli), the watch moves to the new build by itself, and loses nothing it was sending.

## Watch by hand

To run the watch in a terminal instead, start it with no directory, and it watches every folder that `marfa folders list` shows:

<Terminal>

```bash
marfa folders watch
```

```text
watching every folder /Users/sam/Library/Application Support/Marfa/folders.json lists (interrupt to stop)
/Users/sam/Home: watching
/Users/sam/Work/Home: watching
/Users/sam/Home: 0 created, 1 updated, 0 renamed, 0 deleted; the server answered 1 write(s); 1 file(s) written
```

</Terminal>

Press Control+C to stop it. Don't run one by hand while autostart is on: one process works a folder at a time.

## What the watch does

- **An edit reaches your instance within seconds,** and a change made elsewhere is written into the files as quickly.
- **It reads every file every 10 minutes,** in case your computer missed a change.
- **It follows the list of folders,** so a folder you add or remove joins or leaves it with no restart.
- **When the instance can't be reached,** it keeps your edits and sends them later.
- **A command such as `marfa folders push`** asks the watch for the folder, and the watch takes it back when the command ends.

## When a large change waits

A folder sends a few new files or deletions without asking. **When many arrive together, it holds them and waits for you,** so a directory dropped in or moved out by mistake doesn't make or bin hundreds of items. The rest of the folder goes on syncing.

| It waits for | When a change takes |
| --- | --- |
| A large addition | More than 50 new files, and more than a quarter of the folder's files |
| A large removal | More than 10 files, and more than a quarter of the folder's files, or more than 100 files |

Here 55 scans were copied into `~/Home`:

<Terminal>

```bash
marfa folders push ~/Home
```

```text
0 created, 0 updated, 0 renamed, 4 unchanged, 0 missing, 0 deleted, 0 skipped
a large addition waits: 55 new file(s) held, not sent; `folders confirm` sends them, and deleting the files you did not mean to add cancels it; new files that arrive meanwhile join it
```

</Terminal>

- **Send them** with `marfa folders confirm ~/Home`.
- **Cancel** by deleting the files you didn't mean to add.

When the 55 files are moved out again, nothing is deleted while the removal waits:

<Terminal>

```bash
marfa folders push ~/Home
```

```text
0 created, 0 updated, 0 renamed, 4 unchanged, 55 missing, 0 deleted, 0 skipped
a large removal waits: 55 delete(s) not sent; `folders confirm` sends them, `folders restore` writes the files back
```

</Terminal>

- **Write the files back** with `marfa folders restore ~/Home`.
- **Let it go** with `marfa folders confirm ~/Home`, which moves their items to the bin.

The thresholds are the folder's `addition_threshold` and `removal_threshold`, listed with the [folder type](/catalog/folder). In a script, `marfa folders push --confirm-additions` sends every new file, however many.

## When something stops

- **To stop syncing,** see [Change or stop syncing a folder](/use/change-or-stop-a-folder).
