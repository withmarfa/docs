title: Edit notes as files
description: See what a note's file holds, how to link and attach files, and what happens when you rename, copy or rewrite a file.
---

A synced folder writes each note as a Markdown file, and reads a file you change back as an edit. You, or an agent, can work in any editor. The examples follow the `Notes` folder from [Sync a folder](/use/sync-a-folder).

## What a note's file holds

A note's file is named after its title. Here's `Trip ideas.md`:

```markdown title="Notes/Trip ideas.md"
---
type: core.note
tier: library
tags:
  - travel
title: Trip ideas
references:
  - "[[Hotel in Lisbon]]"
marfa_id: 01a1f121-6ef4-734f-978e-64d6dac60210
marfa_version: 2
---
Lisbon in April. Ask Sam about the tram. Book the train.
```

The lines between the `---` fences are the frontmatter, and the text after them is the note's body.

- **`type`, `tier`, `tags`, `state` and `occurred_at`:** the item's own fields.
- **A line named after a kind of edge,** such as `references`: a link to another item.
- **Every other line,** such as `title`: one of the note's properties.
- **`marfa_id` and `marfa_version`:** which item the file is, and the version it was written from. Leave them to Marfa.

**A new file needs no frontmatter.** Save `Ideas.md` with only a body, and it becomes a new note, titled `Ideas`. Once your instance creates it, Marfa writes the frontmatter, `marfa_id` included, into the file.

A `.txt` file is all body. **Any other file, such as a photo or a PDF, becomes a file item** if the folder's query holds files: a photo becomes a `core.file.image`, and a PDF a `core.file`.

## Rename, copy or rewrite a file

- **Rename a file** and its new name becomes the note's title. Change the title anywhere else, and the next sync renames the file.
- **Save a file without its `marfa_id` and `marfa_version` lines,** as an editor or an agent that rewrites the whole file may, and it stays the same note. Marfa writes the two lines back within seconds, and nothing is duplicated.
- **Copy a file to a new name,** such as to use a note as a template, and the copy becomes a new note with its own `marfa_id`. The original stays as it was.
- **Delete a file** and its note moves to the bin, where you can restore it. A folder asks before it deletes many at once, as [Large changes](/use/large-changes) shows.

**Two notes with the same title** are written as two files, one with a number added, such as `Plan (2).md`. The note created later gets the number, on every computer, and a file already at the plain name keeps it.

## Link to another note

Write a link in a note's body with double brackets, and it links the note to the item it names, by title or file name:

```markdown
Book the room from [[Hotel in Lisbon]], and pack from [[Packing list|the list]].
```

The text after `|` is what the note shows. `[[Packing list#Shoes]]` links to the same note, at a heading.

- **Links follow a retitled note.** When a note gets a new title, each folder rewrites the links to it on its next sync.
- **A note can link to one that doesn't exist yet.** Once the note it names is created, here or elsewhere, the link connects by itself.
- **A name that fits several items connects to none** until only one has it, such as after you rename or bin the other. Marfa never guesses.
- **A link in code** or in a comment is text, and links nothing.

`marfa folders status ~/Notes` lists each file whose links are waiting, and why.

## Attach a file to a note

**Embed a picture** in a note's body, and the picture is kept in Marfa as a file item of its own, linked to the note:

```markdown
![](photos/map.png)
```

Obsidian's form, `![[map.png]]`, works too. Every file attached to a note is written with the note, where its embed says or else beside the note, even if the folder's query doesn't hold files.

To attach a file without showing it in the body, list it on the note's `has-attachment` line:

```markdown
has-attachment:
  - "[[boarding-pass.pdf]]"
```

- **An attached file follows its note.** Move the note to another directory, and the next sync moves the file beside it. To keep a file somewhere else, embed it by its path.
- **It goes to the bin with the note,** and comes back when you restore the note.
- **Take it off the `has-attachment` line and the attachment ends,** but the file stays an item in Marfa. Taking an embed out of the body ends only the link, so the file stays attached.

## Edit on either side

**A change reaches the other side within seconds** while a [watch](/use/keep-folders-syncing) runs. Edit a file in your editor, and your instance has the change. Change the note from an agent or the CLI, and the file is rewritten. A file you're still editing is never written over: if two edits to the same part of a note meet, Marfa keeps both, as [Sort out a conflicted copy](/use/conflicts) shows.

[Folder safeguards](/folder-rules) has every rule a folder follows: how each kind of file becomes an item, how links resolve, and what a folder does with files outside its query.
