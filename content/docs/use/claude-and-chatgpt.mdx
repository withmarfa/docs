---
title: Use Marfa from Claude or ChatGPT
description: Add your instance to Claude or ChatGPT once, on the web, so you can find and save your items from a chat on the web, the desktop or your phone.
---

Claude and ChatGPT reach your instance from their own servers, not from your device, so **your instance needs a public `https` address**, which [Give your instance an address](/run/address) sets up. You add the address once on the web, and Claude then reaches your instance from its desktop and phone apps too. The chat signs in to your instance and reaches only what you approve.

Claude calls what you add a custom connector. That's Claude's word: it has nothing to do with a Marfa [connector](/use/connect-a-service), which brings in records from another service.

## Add it to Claude

Every Claude plan can add a custom connector, and the Free plan can add one. On a Team or Enterprise plan, an owner of the organization adds it first, in **Organization settings** > **Connectors**, and each member then selects **Connect** beside it in **Customize** > **Connectors**.

<Steps>
<Step>

### Add the connector

On claude.ai, open **Customize** > **Connectors**, select **+ Add**, then **Add custom connector**. Name it `Marfa`, enter your instance's address followed by `/mcp`, such as `https://marfa.example.com/mcp`, and select **Continue**. Keep the sign-in settings Claude finds, select **Continue** again, then **Add**.

</Step>
<Step>

### Approve it

Select **Connect**. Your instance's approval page opens. Sign in as the owner if you aren't already, then choose **Full access**, or **Choose access** to give less, such as read and edit on notes and nothing else, and select **Approve**.

</Step>
<Step>

### Try it

In a new chat, select **+** > **Connectors** and check that Marfa is on. Ask Claude what it can see in Marfa: it answers with the types and tags you approved.

</Step>
</Steps>

## Add it to ChatGPT

Your ChatGPT plan, and your workspace if you're in one, must allow custom MCP servers. You add the server on chatgpt.com.

<Steps>
<Step>

### Add the server

Open **Plugins**, select the plus button, then **Add custom MCP server**. Name it `Marfa`, enter your instance's address followed by `/mcp` under **Connection**, and choose OAuth for authentication. Read the warning, select **I understand and want to continue**, then **Create as a plugin**.

</Step>
<Step>

### Approve it

Your instance's approval page opens. Sign in as the owner if you aren't already, choose **Full access** or **Choose access**, and select **Approve**.

</Step>
<Step>

### Try it

In a new chat, type `@`, select Marfa, and ask what it can see in Marfa.

</Step>
</Steps>

## Save a file from a chat

In ChatGPT, **attach a file and ask it to save the file to Marfa**. ChatGPT gives Marfa a link to the file, and your instance fetches it and keeps it as a file item, such as a `core.file.image` for a photo. The link works for a short time, so if the save fails, attach the file again.

In either chat, you can also ask it to save a file from a public web address, such as a PDF on a website. Your instance fetches only public addresses, and never follows a redirect. To stop agents from having your instance fetch files, turn the setting off:

```bash
marfa config set mcp_fetch_enabled false
```

## What the chat can do

The chat reaches only the types you approved, and changes only those you let it change. **It asks before it deletes:** moving items to the bin first shows what would go, and the chat shows you before anything moves. Nothing it does deletes an item for good, exports your data or changes your instance's settings. [Work from an agent](/use/from-an-agent) has more to ask for.

## Disconnect it

Remove the connector or server in the chat app's settings. That stops the chat from calling your instance, but **the sign-in it holds still works until you end it** on your instance. Find the chat's app and revoke it:

```bash
marfa apps list
marfa apps revoke <app-id>
```

Its next request is refused, and what it saved stays. [See and cut access](/use/see-and-cut-access) covers every sign-in and key.
