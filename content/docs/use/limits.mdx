## What Marfa doesn't do

- **One person.** An instance has one owner, and holds one person's things. There are no accounts for other people, nothing shared and no teams. Every app, agent and key acts for you.
- **No hosted service.** Marfa doesn't run instances for anyone. You run your own, on your own computer or on a host you choose, such as Railway, as the [Quickstart](/quickstart) shows.
- **No pages of your data.** In a browser, your instance shows only a page that says it's running and the pages for setting it up, signing in, approving an app or the CLI, recovering your password and managing your passkeys. It never shows your files, notes or other items: you see them through an app, an agent, the CLI or a [synced folder](/use/sync-a-folder).
- **No connectors inside the server.** The server never reads another service itself. A [connector](/use/connect-a-service) is a program you run, with a key of its own.
- **One Google account for each instance.** Google connectors keep the account they first ran with, as [Create a Google Cloud project](/use/google-project) explains.

## Limits on what you store

| Limit | Value |
| --- | --- |
| A note's body, or another type's main text | 1,000,000 characters |
| Any other text field | 100,000 characters, unless its type sets its own length |
| Tags on one item | 100 |
| One tag | 128 characters |
| One write | 1 MiB, or 16 MiB for bulk operations |
| A file | No fixed size. Marfa refuses a file that would leave less than 128 MiB free on its disk |

A type can set a shorter or longer length for its own fields: its page in the [Catalog](/catalog/types) shows it.

## Limits on how you ask

| Limit | Value |
| --- | --- |
| Requests from one app or key | 4,000 a minute, and 200 a minute to the key operations |
| Items moved to the bin in one command | 20, as [Move items to the bin](/use/command-line#move-items-to-the-bin) shows |
| Items in one page of a list | 500 |
| A search | 500 characters, and at most 16 words outside quotes |
| A filter | 2,048 characters, and at most 10 conditions |
| Types or tags named in one filter | 10 types, 100 tags |

When an app or a key goes over its requests, your instance asks it to wait. A synced folder waits and carries on by itself, as [Sync a folder](/use/sync-a-folder#if-the-server-is-limiting-requests) shows.

## How long things are kept

| What | Kept for |
| --- | --- |
| An item in the bin | 60 days, then deleted for good |
| Earlier versions of an item | Every version for 30 days, one a day to 90 days, and one a week to a year, up to 500 for each item |
| The audit log | 90 days |

## Change a limit

Most of these are settings you can change, such as keeping the bin for a year:

```bash
marfa config set trash_retention_days 365
```

`marfa config settings` lists every setting with its value, its default and the values it takes. [Change an instance's settings](/run/settings) explains them. The limits on text, tags, searches and filters are fixed.
