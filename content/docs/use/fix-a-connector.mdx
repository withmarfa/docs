---
title: Fix a connector that fails
sidebar_label: Fix a connector
description: Find the message a plugin's connector shows when it does not start, stops, brings nothing, or Google refuses it, and fix it.
job: Someone whose connector fails, or whose Google sign-in is refused, finds the message they see and fixes it.
---

Start with `marfa plugins status <name>`. It says whether the connector is running, paused, or on no host. `marfa connectors list` gives its ID. `marfa connectors get <id>` lists the problems it reports now, and `marfa connectors runs <id>` lists recent runs. Find the message you see below.

## host no host

`marfa plugins status` ends with `host no host`, or install says the connector runs on no host yet. Nothing is running it. [Link a host and assign the connector](/use/run-a-plugin-connector). Marfa does not publish a program that redeems the link yet.

## Resume it, then ask it to run

`marfa plugins status` says `paused`. `marfa plugins run` is refused with `connector_paused`, and the message ends "Resume it, then ask it to run."

```bash
marfa plugins resume <name>
```

Pausing removes nothing. [Pause or run a connector](/use/pause-or-run-a-connector) is the rest of that step. A run that was already going is covered on the [kit page](/reference/connector-kit#pause-run-now-and-previews).

## The connector brings nothing

`marfa plugins settings <name>` names a required setting with no value on a `missing:` line. Set it, including any secret ([Give a connector its settings](/use/connector-settings)). A kind with `enabled: false` writes, reads and carries nothing, and leaves its items where they are ([Map a connector](/use/map-a-connector)). A connector that has not signed in to Google brings nothing from Google.

## The process exits with a code

[Exit codes](/reference/connector-kit#exit-codes) say what each code means. What to do:

- **0.** Nothing.
- **1.** Start it again after a wait.
- **2.** Fix the connector's definition or how it is started. This is not a setting.
- **3.** Have the host mint a new key: `marfa plugins assign <name> --none` revokes the key, then [assign it](/use/run-a-plugin-connector#assign-a-connector) to its host again. Assigning it to the host it already runs on keeps the old key.
- **4.** Change the connector's [settings or secrets](/use/connector-settings).

## This connector has not signed in to Google yet

The problem's key is `google:sign-in`. The connector makes no Google calls. Set the web client first ([Give a connector Google access](/use/connector-google-access)), then run `marfa plugins sign-in <name>` and open the address it prints.

## Google no longer accepts this connector's sign-in

The key is `google:reconnect`. Access was revoked, went unused for six months, was for a limited time that ended, or the Cloud project is still in Testing. Publish the project if it is in Testing ([the sign-in screen](/use/connector-google-access#publish-the-sign-in-screen)), then run `marfa plugins sign-in <name>` again. Until the token changes, the connector makes no Google calls.

## Google does not accept this connector's OAuth client

The key is `google:client`. `google_client_id` and `google_client_secret` have to be a **Web application** client in your Cloud project. Set them again, then sign in again. Until those settings change, the connector makes no Google calls.

## Google did not grant

A key that starts with `google:scope:` means a permission was left unticked. Sign in again and leave every permission ticked.

`google:account` means the token is another Google account. Sign in with the original one, or use another instance.

`google:refresh-token-changed` means Google issued a new token that the connector holds only in memory. Sign in again before it restarts.

`google:refresh-token-expires` names when access ends. Sign in again before then, and choose ongoing access.
