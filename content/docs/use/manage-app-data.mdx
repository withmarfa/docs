An app can keep data of its own in your instance, such as a reading app's list of saved pages. It sits under the app's **namespace**, a name such as `app.readinglist`, with the types the app registered there. **Your own lists and searches leave it out,** so these commands are where you see it. [Access](/build/access#an-apps-own-types) explains which apps reach it.

Any computer where the CLI is signed in with Full access can do all of this. An agent at `/mcp/admin` does the same with [`marfa_app_data`](/reference/mcp-admin-tools), which shows you a preview before it deletes anything.

## See what an app keeps

`marfa apps list` shows each app with the namespaces it holds, under `vendors`. To see one namespace's types, with how many items each holds, and then its items, the bin included:

<Terminal>

```bash
marfa apps vendors data list app.readinglist
```

```text
type                   active  archived  trashed
app.readinglist.entry  2       0         1
```

</Terminal>

## Delete it for good

<Callout type="warn" title="Only a backup brings it back">
The items are purged, not moved to the bin, and the app's types go with them. Take a backup first with `marfa backups run`.
</Callout>

<Terminal>

```bash
marfa apps vendors data delete app.readinglist --confirm PURGE
```

```text
deleted 3 items and 1 type of app.readinglist
```

</Terminal>

The command deletes every item of the namespace, in every state, 1,000 at a time, saying how many are left until none is, and then its types. What stays:

- **Your own items** that link to one of the app's items. They lose only the link.
- **Other apps' data,** and the namespace, which stays with its app.
- **The app's access and keys.** To disconnect it too, see below.

If a folder, view or webhook of yours names one of the app's types, the delete is refused with `type_in_use` and deletes nothing. Change or remove that first.

## Delete it as you disconnect the app

Disconnecting an app keeps its data unless you ask. To delete it in the same step, take a backup, then add `--remove-data --confirm PURGE` to `marfa apps revoke` or `marfa sign-ins end`:

```bash
marfa apps revoke <app-id> --remove-data --confirm PURGE
```

**An app that keeps more than 1,000 items is refused, and stays connected.** Delete its data with `marfa apps vendors data delete` first, then disconnect it. [See and revoke access](/use/see-and-revoke-access#cut-one-off) covers the rest of disconnecting.

## Give an app's types to another app

A namespace belongs to the app that registered the first type in it. An app that registers again gets a new client ID and loses its namespace, so **give it to the new ID**, from `marfa apps list`:

```bash
marfa apps vendors move app.readinglist <client-id>
```

`marfa apps vendors list` shows who holds each. Only you, or a key you made with `grants.manage`, can move one.

The rules behind this page are in the contract's [keys and sign-in chapter](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#an-apps-own-data).
