---
title: Confirm a large change in a folder
description: Decide what happens when a folder pauses a large drop of new files or a large removal, and let it go, cancel it or pass it in a script.
---

A folder sends a few new files or a few deletions without asking. **When many arrive together, it pauses them and waits for you,** so a directory dropped into the wrong folder, or moved out of it by mistake, doesn't create hundreds of items or move them to the bin. The rest of the folder goes on syncing meanwhile, and a watch says once that something waits.

| Pause | It waits when a change takes | Setting |
| --- | --- | --- |
| A large addition | More than 50 new files, and more than a quarter of the folder's files | `addition_threshold` |
| A large removal | More than 10 files, and more than a quarter of the folder's files, or more than 100 files whatever their share | `removal_threshold` |

**A change must pass both numbers to pause,** so removing 20 files from a folder of 1,000 goes ahead. A folder that holds no files yet is judged by the count alone. The first sync is never counted, since it [waits for you anyway](/use/sync-a-folder#confirm-and-sync). [Change what a folder syncs](/use/change-a-folder) changes either setting.

## A large addition

New files count toward the pause; edits and renames of files the folder holds don't. **A copy that arrives slowly counts as one drop:** new files sent in the last ten minutes count with the ones found now.

<Terminal>

```bash
marfa folders push ~/Home
```

```text
0 created, 0 updated, 0 renamed, 7 unchanged, 0 missing, 0 deleted, 0 skipped
a large addition waits: 55 new file(s) held, not sent; `folders confirm` sends them, and deleting the files you did not mean to add cancels it; new files that arrive meanwhile join it
the server answered 0 write(s)
0 file(s) written
```

</Terminal>

While it waits, the files stay on disk with no item made for them, and new files that arrive meanwhile join the drop. `marfa folders status ~/Home` lists each one as `held`.

- **Send them:** `marfa folders confirm ~/Home` makes them items at the next sync.
- **Cancel it:** delete the files you didn't mean to add. Once every waiting file is gone, the pause ends.
- **In a script:** `marfa folders push ~/Home --confirm-additions` sends every new file it finds, however many. Nobody is there to confirm, so the decision is the script's.

## A large removal

A removal pauses when many files go at once, such as a directory moved out of the folder. It also holds back when many items leave the folder elsewhere, such as when an agent moves them to the bin:

<Terminal>

```bash
marfa folders push ~/Home
```

```text
0 created, 0 updated, 0 renamed, 42 unchanged, 20 missing, 0 deleted, 0 skipped
a large removal waits: 20 delete(s) not sent; `folders confirm` sends them, `folders restore` writes the files back
the server answered 0 write(s)
0 file(s) written
```

</Terminal>

Nothing is deleted while it waits. Choose one:

- **Write the files back:** `marfa folders restore ~/Home` puts each missing file back as it was. Putting the files back yourself does the same.
- **Let it go:** `marfa folders confirm ~/Home` moves their items to the bin at the next sync, where you can restore them for as long as your instance keeps the bin.

<Terminal>

```bash
marfa folders restore ~/Home
```

```text
20 file(s) written back; 0 item(s) restored, sent at the next push
```

</Terminal>

Files attached to a note come back with the note. Before it deletes anything, `confirm` checks again: a file that moved to another folder, or whose item changed elsewhere meanwhile, isn't deleted. `restore` names any file it couldn't write back, and later syncs try again.

## See where a folder stands

`marfa folders status ~/Home` shows where every file stands, and whether an addition or a removal waits, without asking your instance. A file the folder can't read, such as a note with an unknown type, shows as `held` with the reason. [How a folder treats files](/folder-rules) has the full rules.
