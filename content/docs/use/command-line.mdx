With the `marfa` command you find, add, change and tag your items from any computer that reaches your instance. **You need the command signed in,** as the [Quickstart](/quickstart) shows, and `marfa whoami` says which instance a command reaches.

A script signs in with a [key](/use/manage-keys) instead. Add `--json` to any command for an answer a script or an agent can read. The [CLI reference](/reference/cli) lists every command, and [Fix a command that can't find its server or key](/run/troubleshooting/cli) helps when one reaches the wrong instance.

## Find items

Search every item you can reach, of every type:

<Terminal>

```bash
marfa search lisbon
```

```text
score    id                                    type           when                      title
  1.000  01a1f166-8cb0-7605-807f-d4c89178f4d1  core.bookmark  2026-11-19T01:23:12.176Z  Hotel in Lisbon
  0.824  01a1f167-35a4-75ea-8947-c51cf3a5bf4e  core.file      2026-11-19T01:23:55.427Z  Lisbon hotel booking
```

</Terminal>

- `marfa search lisbon --type core.file` finds only files.
- `marfa items list --tag lisbon` lists the newest items with that tag, and `--all` lists every one.
- `marfa items list --tier feed` lists the feed, where what arrives in volume, such as from connectors, goes.
- `marfa items get <id>` shows one item, with its version and properties.
- `marfa items link <id>` prints the item's [link](/reference/item-links), to share or open it.
- `marfa tags` lists every tag in use, with how many items carry it.

## Add items

`marfa items add` saves a file from your computer as an item of its own, and Marfa picks the type from the file, so a photo becomes a `core.file.image`. `marfa items create` makes an item that isn't a file, such as a note, with its type and properties. The [Catalog](/catalog/types) lists each type's properties.

```bash
marfa items add ~/Pictures/beach.png --title "Beach at Comporta" --tag travel
marfa items create --type core.note --prop title="Lisbon packing list" \
  --prop body="Sun hat, adapter" --tag lisbon
```

## Change an item

**A change names the version you read,** so it never quietly overwrites an edit made since, from your editor or an agent:

<Terminal>

```bash
marfa items update 01a1f167-3524-769f-bb84-884191bc60f2 --version 1 \
  --prop body="Sun hat, adapter, sandals"
```

```text
updated core.note 01a1f167-3524-769f-bb84-884191bc60f2 "Lisbon packing list" (version 2)
```

</Terminal>

If the item changed after you read it, and the two changes touch different properties, the server writes both, provided Marfa still keeps the version you read, which it thins over time; if not, the command answers `409 ancestor_unavailable` and writes nothing. **When both change the same property,** nothing is written and the command answers `409 version_conflict`, naming the property, such as `Conflicting fields: body`. Read the item again with `marfa items get`, then send your change with the new version. To keep an item that a connector brought into the feed, move it to the library with `marfa items update <id> --tier library`.

## Tag and link items

Tags are free labels, and an edge links two items and says how. This one says the note references the bookmark:

```bash
marfa items tags add 01a1f167-3524-769f-bb84-884191bc60f2 packing
marfa items tags remove 01a1f167-3524-769f-bb84-884191bc60f2 packing
marfa items tags replace 01a1f167-3524-769f-bb84-884191bc60f2 lisbon travel
marfa edges create --from-id 01a1f167-3524-769f-bb84-884191bc60f2 \
  --to-id 01a1f166-8cb0-7605-807f-d4c89178f4d1 --type references
```

`marfa items edges <id>` lists the edges leaving an item, and `marfa items backrefs <id>` the edges arriving at it.

## Move items to the bin

`marfa items trash` takes up to 20 items and moves them to the bin, **all of them or none**, with the items beneath each, such as a task's subtasks, so more than 20 can move. First see what would move. The answer ends with a digest:

<Terminal>

```bash
marfa items trash 01a1fc3c-ff24-71a6-acec-ff95fd1b51e1 01a1fc3c-ff07-70dc-94f4-246dfb5cbfe1 --dry-run
```

```text
items[0].id       01a1fc3c-ff24-71a6-acec-ff95fd1b51e1
items[0].takes    (none)
items[1].id       01a1fc3c-ff07-70dc-94f4-246dfb5cbfe1
items[1].takes    (none)
count             2
digest            6f635780026065088cef41ac9458ba815b7d6fba8083ce1fdce081eedc7bfc27
```

</Terminal>

Nothing has moved. When the list is right, run the same command with that digest in place of `--dry-run`, so nothing moves if the list has changed:

```bash
marfa items trash 01a1fc3c-ff24-71a6-acec-ff95fd1b51e1 01a1fc3c-ff07-70dc-94f4-246dfb5cbfe1 \
  --digest 6f635780026065088cef41ac9458ba815b7d6fba8083ce1fdce081eedc7bfc27
```

## Get an item back, or empty the bin

An item stays in the bin for 60 days by default, which the [settings](/run/settings) change. **Emptying the bin can't be undone:** everything in it is deleted for good, 200 items at a time, and an item that changed meanwhile stays. It needs the `items.purge` permission, which the CLI holds with Full access. An attached file's bytes can outlive its item for a while, because another item may share them.

- `marfa items bin list` shows each item with when it can be deleted for good.
- `marfa items restore <id>` brings one back as it was.
- `marfa items bin empty --confirm PURGE` empties the bin.
