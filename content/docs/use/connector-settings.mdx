A plugin's connector declares the settings it needs, and **Marfa keeps the values.** The machine that runs the connector holds none. The connector reads them at the start of each run. [The connector kit](/reference/connector-kit#settings-and-secrets) says how a missing or unusable setting stops a run. Each command needs `connectors.manage`.

## See what it needs

The RSS connector's settings look like this before anything is set:

<Terminal>

```bash
marfa plugins settings rss
```

```text
rss_feeds: secret, not set, required
rss_private_hosts: not set
rss_pictures: "addresses" (default)
missing: rss_feeds
```

</Terminal>

`missing` names each required setting with no value and no default. **A secret is never shown,** only whether it is set.

## Give settings values

```bash
marfa plugins settings rss --set rss_private_hosts=feeds.example.com --set rss_pictures=save
```

That prints `set rss_private_hosts, rss_pictures for rss`. Repeat `--set` for each setting that is not a secret. A secret named here is refused before anything is sent. Marfa checks each value against its kind. If one doesn't fit, nothing is set. Reading the settings again then shows the values, and the `missing` line is gone once every required setting is set:

```text
rss_feeds: secret, set, required
rss_private_hosts: "feeds.example.com"
rss_pictures: "save"
```

## Enter a secret

A secret is never an argument, so it stays out of your shell's history. Type it at the prompt, which doesn't echo, or send it on standard input. One final line break is dropped:

```bash
marfa plugins secret rss rss_feeds
printf '%s\n' 'https://example.com/feed.xml' | marfa plugins secret rss rss_feeds
```

That prints `set rss_feeds for rss`, and not the value. `--clear` removes a secret. A secret can't start or end with whitespace. Marfa stores a secret as short as one character. The [connector kit](/reference/connector-kit#settings-and-secrets) stops a run when a secret is shorter than 8 characters, because it cannot keep a shorter value out of its logs, and the process exits 4.

**No answer, log, audit entry, export or backup holds a secret's value.** Only the connector's own key, the one its host minted, can read it back. Your own sign-in cannot. The audit log records which settings changed.

## When a secret no longer opens

Marfa seals each secret with a key it keeps beside its database, in `marfa.settings.key`. A secret it can't open, such as after the data directory moved without that file, is listed as `secret, unreadable here: set it again`. `marfa attention` names it, such as `rss/rss_feeds`. Enter it again as above.

**An archive carries no secret.** A restore lists each one in `connector_secrets_to_set`. Settings that are not secrets come back with the archive ([Move your data with an archive](/run/export-and-restore#what-a-restore-changes)).

A newer plugin keeps a value whose setting keeps the same kind, secrecy and choices, and drops it otherwise. Removing the plugin removes every value.

The rules are in the [plugins](https://github.com/withmarfa/marfa/blob/main/conformance/spec/plugins.md#a-connectors-settings) chapter of the contract.
