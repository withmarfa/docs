Once an agent is connected, as [Connect your agent](/connect-your-agent) shows, you work with your items by asking in your own words. **The agent acts with its own credential,** so it reaches only what you approved, and the [audit log](/use/audit-log) records its changes as its own.

## Ask for what you want

- **Save a file from the web:** "Save the PDF at this address to Marfa, tagged `taxes-2026`." Your instance fetches the file itself and keeps it as a file item.
- **Find a file or a note:** "Which of my photos are tagged `garden`?" or "What did I save about Lisbon?"
- **Save what you're working on:** "Save this summary as a note, and attach the photo to it."
- **Change an item:** "Tag these three PDFs `reading`," or "Mark the boiler service task done."
- **Tidy up:** "Move the notes tagged `scratch` to the bin."

The agent starts from an overview of your instance: the types, tags and views it can reach. **If it needs access you didn't approve,** a client that supports it asks you to approve more.

## What the agent does before it changes anything

- **It reads before it writes.** An update names the version the agent read. If the item had changed before the update began, nothing is written and the agent reads it again.
- **It asks before it deletes.** Moving items to the bin (the tool `marfa_delete`) first shows what would change, and so does changing many items to another type. The agent shows you and acts only once you agree, and an agreement lasts five minutes.
- **It never deletes an item for good at `/mcp`.** What it moves to the bin waits there for you to restore. Emptying the bin (`marfa_purge`) is only at `/mcp/admin`, where each purge needs its own preview and your confirmation.

## An agent that runs on its own

An agent that runs on a schedule has nobody to approve it in a browser. **Give it a key of its own,** as [Manage keys](/use/manage-keys#make-a-key) shows, holding only what it needs, such as `--type-permission core.file.image=write --expires-in 30d`. Every item the agent creates carries the key's source, so you can tell its work from yours.

Put the key in `MARFA_API_KEY` where the agent runs and have its client send it as a header. The client reads the variable when it connects, so **the key stays out of every file:**

<Tabs items={["Claude Code", "Codex"]}>
<Tab value="Claude Code">

```bash
claude mcp add --transport http --scope user marfa https://marfa.example.com/mcp \
  --header 'Authorization: Bearer ${MARFA_API_KEY}'
```

Keep the single quotes, so your shell doesn't fill in the key.

</Tab>
<Tab value="Codex">

```bash
codex mcp add marfa --url https://marfa.example.com/mcp --bearer-token-env-var MARFA_API_KEY
```

</Tab>

## An agent that runs commands

A coding agent that runs shell commands can use the [CLI](/reference/cli), which has a command for almost every operation in the API. Approving an app is the one that needs a browser. Give it a key of its own and a [profile](/reference/cli#name-a-server-with-a-profile) whose `key_command` reads the key from your password manager:

```toml title="profiles.toml"
[agent]
url = "https://marfa.example.com"
key_command = ["op", "read", "op://Private/Marfa agent key/key"]
```

Then set `MARFA_PROFILE=agent` and `MARFA_NO_KEYCHAIN=1` where it runs. **With the keychain off, a command that names no server is refused,** so the agent reaches only the instance its profile names.

Tell it how to work in its instructions file:

```markdown title="AGENTS.md"
## Marfa

Marfa holds the files and records I keep. Use the `marfa` CLI with `--json`.

- See what the key reaches: `marfa overview --json`
- Find items: `marfa search "<words>" --json`
- Read one: `marfa items get <id> --json`
- To change one, read it first and pass its `version` to `marfa items update`.
```

[Work from the command line](/use/command-line) shows the everyday commands.

## See what an agent did

The [audit log](/use/audit-log) lists what an agent changed under its own name, and each item version it wrote names the agent as its writer. **You can cut an agent off at any time,** as [See and revoke access](/use/see-and-revoke-access) shows. Its next request is refused, and what it wrote stays.
