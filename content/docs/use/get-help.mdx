## Check the docs first

Many messages Marfa gives have a page that explains them. [Troubleshooting](/run/troubleshooting) lists them by what you see. From a terminal, search the docs without opening a browser:

```bash
marfa docs search "version conflict"
```

## Report a problem

Report something that doesn't work as it should as an issue on [withmarfa/marfa](https://github.com/withmarfa/marfa/issues/new/choose), with the **Bug report** form. It asks for:

- **What happened,** and what you expected instead.
- **The steps** that make it happen.
- **The version** of the CLI and of your instance. `marfa --version` gives the CLI's, and `marfa status` gives your instance's on its `instance` line, such as `Marfa 0.0.80`.
- **Where it ran,** such as macOS 27 or Linux in Docker.
- **The message, word for word.** Copy the whole line the CLI printed, such as `marfa: the server refused (404 item_not_found): Item not found`. With `--json`, the CLI prints the same refusal as one line of JSON, which is easier to paste whole.

Leave out anything private: keys, passwords, the contents of your notes and your instance's address. Read a log through before you paste it.

## Ask a question or share an idea

Ask in [Questions](https://github.com/orgs/withmarfa/discussions/categories/questions), and suggest something Marfa could do in [Ideas](https://github.com/orgs/withmarfa/discussions/categories/ideas).

## Report a security issue

**Never report a security issue in a public issue or discussion.** Report it privately, as the [security policy](https://github.com/withmarfa/marfa/security/policy) explains: select **Report a vulnerability** on the repository's **Security** tab, and say what you found, how to make it happen and what someone could do with it. Only the latest release gets security fixes, so check the problem is still there after you [upgrade](/run/upgrade).
