A synced folder holds two kinds of file, and you or an agent work with both in any app:

- **A file you keep as it is,** such as a PDF, a photo or a spreadsheet, holds the item's own bytes.
- **A note** is a Markdown file, whose top lines hold the item's details.

The examples follow the `Home` folder from [Sync a folder](/use/sync-a-folder).

## Add, change and delete

- **Add a file** and it becomes an item, if the folder's query holds its type. A photo becomes a picture, titled with its file name, such as `beach.png`.
- **Add a note** with only a body, such as `Ideas.md`, and it becomes a note titled `Ideas`. Marfa then writes its details at the top of the file.
- **Change a file** and the same item gets the change, as a new version.
- **Rename a file** and the item's title follows: `beach.png` renamed to `Comporta beach.png` is titled `Comporta beach.png`. Change a note's title anywhere else, and the next sync renames its file.
- **Copy a note to a new name** and the copy becomes a new note. The original stays as it was.
- **Delete a file** and its item moves to the bin, where you can restore it. A folder asks before it deletes many at once, as [Keep folders syncing](/use/keep-folders-syncing#when-a-large-change-waits) shows.

Two notes with the same title are written as two files, one with a number added, such as `Plan (2).md`.

## What a note's file holds

Here's `Ideas.md` after its first sync, tagged by the folder's [defaults](/use/change-or-stop-a-folder#change-what-a-folder-holds):

```markdown title="Home/Ideas.md"
---
type: core.note
tier: library
tags:
  - from-folder
title: Ideas
marfa_id: 01a1f447-3a34-74c3-8488-87e8f7e17a7b
marfa_version: 1
---
Try the tram.
```

- **`type`, `tier`, `tags`, `state` and `occurred_at`** are the item's own fields.
- **A line named after a kind of edge,** such as `references`, links to another item.
- **Every other line,** such as `title`, is one of the note's properties.
- **`marfa_id` and `marfa_version`** say which item the file is. Leave them to Marfa. An editor that drops them doesn't make a duplicate: Marfa writes them back.

A file you keep as it is has no such lines, so set its tags from an agent or the CLI.

## Link to another item

Write a link in a note's body with double brackets, naming another item by its title or file name:

```markdown
Book the room from [[Hotel in Lisbon]], and pack from [[Packing|the list]].
```

The text after `|` is what the note shows.

- **A link follows a retitled note:** each folder rewrites it on its next sync.
- **A link can name a note that doesn't exist yet.** It connects once the note is created.
- **A name that fits several items connects to none,** and the sync says so. Rename one of them, or name the item by its ID, as in `[[01a1f447-3a34-74c3-8488-87e8f7e17a7b]]`.

## Attach a file to a note

**Embed a picture** in a note's body, and the picture is kept as a file item of its own, attached to the note:

```markdown
![](photos/map.png)
```

Obsidian's form, `![[map.png]]`, works too. To attach a file without showing it, list it on the note's `has-attachment` line instead.

- **An attached file follows its note** to another directory, and to the bin and back.
- **Take it off the `has-attachment` line** and the attachment ends, but the file stays an item.

## When both sides change

While a [watch](/use/keep-folders-syncing) runs, a change in either place reaches the other within seconds. A file you're still editing is never written over: if two edits to a note's body meet, Marfa keeps both, as [Sort out a conflicted copy](/use/conflicts) shows.
