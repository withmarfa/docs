---
title: Work with the files in a synced folder
description: Add, change, rename and delete the files, pictures and notes in a synced folder, and link and attach them to one another.
---

A synced folder holds two kinds of file. **A file you keep as it is,** such as a PDF, a photo or a spreadsheet, is the item's own bytes. **A note** is a Markdown file, whose top lines hold the item's details. You, or an agent, work with both in any app. The examples follow the `Home` folder from [Sync a folder](/use/sync-a-folder).

## Files and pictures

**Drop a file into the folder and it becomes an item,** if the folder's query holds files. A photo becomes a `core.file.image`, and a PDF or any other file a `core.file`, titled with the file's name, such as `beach.png`.

- **Change the file,** such as by annotating a PDF or cropping a photo, and the same item gets the new bytes, as a new version.
- **Rename the file,** and the item's title follows, unless you gave the item another title: `beach.png` renamed to `Comporta beach.png` is titled `Comporta beach.png`. A title you set from an agent or the CLI leaves the file's name as it is.
- **Delete the file,** and its item moves to the bin, where you can restore it.

Tags and other details of a file item aren't in the file. Set them from an agent or the CLI, such as `marfa items tags add <id> taxes-2026`.

## What a note's file holds

A note's file is named after its title. Here's `Packing.md`, after a tag and a link were added:

```markdown title="Home/Packing.md"
---
type: core.note
tier: library
tags:
  - lisbon
title: Packing
references:
  - "[[Hotel in Lisbon]]"
marfa_id: 01a1f165-1eab-700e-b1f9-8113132d108d
marfa_version: 1
---
Passport, sun hat, adapter.
```

The lines between the `---` fences are the frontmatter, and the text after them is the note's body.

- **`type`, `tier`, `tags`, `state` and `occurred_at`:** the item's own fields.
- **A line named after a kind of edge,** such as `references`: a link to another item.
- **Every other line,** such as `title`: one of the note's properties.
- **`marfa_id` and `marfa_version`:** which item the file is, and the version it was written from. Leave them to Marfa.

**A new note needs no frontmatter.** Save `Ideas.md` with only a body, and it becomes a new note, titled `Ideas`. Once your instance creates it, Marfa writes the frontmatter, `marfa_id` included, into the file. A `.txt` file is all body.

## Rename, copy or rewrite a note

- **Rename a note's file** and its new name becomes the note's title. Change the title anywhere else, and the next sync renames the file.
- **Save a file without its `marfa_id` and `marfa_version` lines,** as an editor or an agent that rewrites the whole file may, and it stays the same note. Marfa writes the two lines back, and nothing is duplicated.
- **Copy a file to a new name,** such as to use a note as a template, and the copy becomes a new note with its own `marfa_id`. The original stays as it was.
- **Delete a file** and its note moves to the bin. A folder asks before it deletes many items at once, as [Confirm a large change in a folder](/use/large-changes) shows.

**Two notes with the same title** are written as two files, one with a number added, such as `Plan (2).md`. The note created later gets the number, on every computer, and a file already at the plain name keeps it.

## Link to another item

Write a link in a note's body with double brackets, and it links the note to the item it names, by title or file name:

```markdown
Book the room from [[Hotel in Lisbon]], and pack from [[Packing|the list]].
```

The text after `|` is what the note shows. `[[Packing#Shoes]]` links to the same note, at a heading.

- **Links follow a retitled note.** When a note gets a new title, each folder rewrites the links to it on its next sync.
- **A note can link to one that doesn't exist yet.** Once the note it names is created, here or elsewhere, the link connects by itself.
- **A name that fits several items connects to none** until only one has it, such as after you rename or bin the other. Marfa never guesses.
- **A link in code** or in a comment is text, and links nothing.

`marfa folders status ~/Home` lists each file whose links are waiting, and why.

## Attach a file to a note

**Embed a picture** in a note's body, and the picture is kept in Marfa as a file item of its own, linked to the note:

```markdown
![](photos/map.png)
```

Obsidian's form, `![[map.png]]`, works too. Every file attached to a note is written with the note, where its embed says or else beside the note, even if the folder's query doesn't hold files.

To attach a file without showing it in the body, list it on the note's `has-attachment` line:

```markdown
has-attachment:
  - "[[boarding-pass.pdf]]"
```

- **An attached file follows its note.** Move the note to another directory, and the next sync moves the file beside it. To keep a file somewhere else, embed it by its path.
- **It goes to the bin with the note,** and comes back when you restore the note.
- **Take it off the `has-attachment` line and the attachment ends,** but the file stays an item in Marfa. Taking an embed out of the body ends only the link, so the file stays attached.

## Change either side

**A change reaches the other side within seconds** while a [watch](/use/keep-folders-syncing) runs. Change a file in any app, and your instance has the change. Change the item from an agent or the CLI, and the file is rewritten. A file you're still editing is never written over: if two edits to a note's body meet, Marfa keeps both, as [Sort out a conflicted copy](/use/conflicts) shows.

[How a folder treats files](/folder-rules) has every rule a folder follows: how each kind of file becomes an item, how links resolve, and what a folder does with files outside its query.
