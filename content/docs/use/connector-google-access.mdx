Marfa does not publish a connector host yet. Installing the connectors by name, and the steps to install a host, are coming. The sign-in below is stored, and nothing runs the connector until a host is published. Install the plugin first, as [Install a plugin](/use/install-a-plugin) describes. A setting for a plugin that is not installed is refused.

A plugin's connector that signs in to Google uses **a Google Cloud project you own**. Marfa publishes none. You create a web client, give that plugin its client ID and secret, and sign in once in a browser. Marfa keeps the refresh token as one of the connector's secrets, and the connector reads it on each run. **Each plugin's connector works with one Google account.** The same plugin for a second account needs a second instance. Each plugin stores its own client and its own token. Each command needs `connectors.manage`.

<Steps>
<Step>

### Create the project

Sign in to the [Google Cloud console](https://console.cloud.google.com) with the Google account whose data you want. Go to **Menu** > **IAM & Admin** > **Create a Project**, enter a **Project name**, and select **Create**. Nothing in Marfa uses the project's name or ID.

</Step>
<Step>

### Turn on the APIs

A project can call only the APIs you turn on. The connector's Catalog page names the APIs it calls and the permissions it asks for. Google calls a permission a scope and writes it as an address.

Go to **Menu** > **APIs & Services** > **Library**, open each API, and select **Enable**. For [Google Calendar](/catalog/connectors/google-calendar), enable the **Google Calendar API**.

</Step>
<Step>

### Publish the sign-in screen

The sign-in screen is what you see when you give the connector access. Go to **Menu** > **Google Auth platform**, and select **Get started** if it is not set up yet.

1. Under **App information**, enter an **App name** and a **User support email**, then select **Next**. Don't choose a name that could be mistaken for a Google product.
2. Under **Audience**, choose **External**, then select **Next**.
3. Under **Contact information**, enter an email address, then select **Next**.
4. Under **Finish**, agree to the Google API Services User Data Policy, then select **Continue** and **Create**.
5. Go to **Audience** and select **Publish app**, then confirm. The status changes from **Testing** to **In production**.

**Publish the app.** While a project is in Testing, Google ends every sign-in after seven days, so the connector would stop each week. Once published, a sign-in lasts until you remove it or it goes unused for six months. You don't need to add yourself as a test user.

</Step>
<Step>

### Create a web client

Go to **Menu** > **Google Auth platform** > **Clients**, and select **Create client**. Set **Application type** to **Web application**. Under **Authorized redirect URIs**, add your instance's [sign-in address](/run/address#move-the-address) followed by `/connect/oauth/callback`, such as `https://river.marfa.so/connect/oauth/callback`, then select **Create**.

Google shows the whole client secret **only now**. Copy it with the client ID. The same web client can be set on every Google plugin on the instance. Each plugin still keeps its own copy, and each gets its own token when you sign that plugin in.

</Step>
<Step>

### Give the connector the client

`marfa plugins settings <name>` lists the settings. The Google plugins WithMarfa ships name the client ID `google_client_id`, the client secret `google_client_secret`, and the token `google_refresh_token`. Set the ID, then enter the secret at the prompt. A secret is never an argument ([Give a connector its settings](/use/connector-settings)):

```bash
marfa plugins settings <name> --set google_client_id=<the client ID>
marfa plugins secret <name> google_client_secret
```

</Step>
<Step>

### Sign in

```bash
marfa plugins sign-in <name> --wait
```

The command prints an address. Open it within ten minutes, choose the account, and **leave every permission ticked.** Google says it hasn't verified the app, because nobody reviewed your project. Select **Advanced**, then the link that ends in **(unsafe)**. The browser can be on any computer.

When the browser finishes, the command prints `signed in <name>`. The token is stored as that plugin's `google_refresh_token`. The connector reads it on its next run. Without `--wait`, the command prints the address and returns. A sign-in that fails, expires, or is replaced by a later start exits `1`. [Fix a connector](/use/fix-a-connector) lists what to do for each reason, and the problems the connector reports once it runs.

</Step>
</Steps>

## When access ends

Run `marfa plugins sign-in <name>` again when the connector can no longer reach Google. Publish the project first if it is still in Testing. **Moving the sign-in address,** for example onto [Marfa Cloud](/run/marfa-cloud), needs the new address followed by `/connect/oauth/callback` on the client's redirect URIs before you sign in.

A second Google plugin can use the same project. Turn on its API, set its own client ID and secret, and sign that plugin in on its own. Its token holds only the permissions it asks for.

Marfa sends Google one request, for the token, and only to finish a sign-in you started. The rules are in the plugins chapter of the contract, under [A connector's sign-in](https://github.com/withmarfa/marfa/blob/main/conformance/spec/plugins.md#a-connectors-sign-in).
