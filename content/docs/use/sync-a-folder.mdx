---
title: Sync a folder
description: Keep a directory and a set of items in step, so your files, pictures and notes are ordinary files you open in any app, and sync the same folder on a second computer.
job: Someone keeps a directory and a set of items in step, and adds the same folder in another directory, on this computer or another.
---

- **You'll build** a directory on your computer that holds your files and notes, each an ordinary file you open in any app.
- **You need** the `marfa` CLI signed in to your instance, as the [Quickstart](/quickstart) sets it up.
- **You'll have** a folder where a PDF, a photo or a note you add becomes an item, and a change on either side reaches the other.

A folder's settings, such as which items it holds, live on your instance, so **any directory, on any computer, can follow the same folder.** Nothing is written or sent until you agree to the first sync.

<Steps paged>
<Step>

### Create the folder

Make the folder on your instance. Its query says which items it holds, here every note and every file. Files include their kinds, such as pictures:

<Terminal>

```bash
marfa folders create --title Home --query '{"types":["core.note","core.file"]}'
```

```text
id                      01a1f445-dde9-7548-bdb5-6823ae8ee275
…
```

</Terminal>

**Keep the ID** on the `id` line for the next step.

</Step>
<Step>

### Add a directory

Choose the directory that follows the folder. It can be empty or hold files already, and the CLI makes it if it isn't there. Here `~/Home` holds a note, `Packing.md`, and a photo, `beach.png`:

<Terminal>

```bash
marfa folders add ~/Home --folder 01a1f445-dde9-7548-bdb5-6823ae8ee275
```

```text
the first sync of /Users/sam/Home will write and send nothing until you agree: 1 file(s) to write into the directory, 2 to send to the server
Go ahead? [y/N] y
/Users/sam/Home follows the folder 01a1f445-dde9-7548-bdb5-6823ae8ee275
the first sync is confirmed: 1 file(s) to write into the directory, 2 to send to the server; `folders push` or `folders watch` runs it
```

</Terminal>

**Check the plan before you answer.** The query decides every item the first sync writes to disk, so a folder of files writes every file you've saved. Here the one to write is the receipt from the [Quickstart](/quickstart), and the two to send become new items. Answer `n` to stop, and narrow the query as [Change or stop syncing a folder](/use/change-or-stop-a-folder) shows.

Keep the directory out of iCloud Drive, other cloud-synced folders, network storage and anything git tracks, where another program syncs the same files. `marfa folders add` warns in each case.

</Step>
<Step>

### Run the first sync

<Terminal>

```bash
marfa folders push ~/Home
```

```text
0 created, 0 updated, 0 renamed, 0 unchanged, 0 missing, 0 deleted, 0 skipped; 2 already queued by an earlier scan, so not counted as created or updated here
the server answered 6 write(s), creating 2 item(s)
2 file(s) written
```

</Terminal>

The counts are zero because `add` had already queued your two files. The push **creates two items**, and writes the receipt and `Packing.md`, which now holds the note's details at its top:

<Files>
  <Folder name="Home" defaultOpen>
    <Folder name=".marfa">
      <File name="folder.yaml" />
    </Folder>
    <File name="beach.png" />
    <File name="Boiler receipt" />
    <File name="Packing.md" />
  </Folder>
</Files>

The receipt's file is named after its title. `.marfa` holds the folder's store and settings: leave it in place.

</Step>
<Step>

### Keep it in step

`push` syncs once. To keep every folder in step while you work, turn on autostart, which runs a watch now and each time you log in:

```bash
marfa folders autostart on
```

Then change a file in any app, or drop in another photo, and the watch sends it within seconds. Change an item from an agent or the CLI, and its file is rewritten. [Keep folders syncing](/use/keep-folders-syncing) covers the watch.

</Step>
</Steps>

## Sync the folder on a second computer

Add another directory that follows the same folder, on a second computer or on this one. Each keeps its own copy of the files, and **a change in one reaches the others.**

1. **On another computer,** [install the CLI](/quickstart#install-marfa) and run `marfa login` with your instance's address. An instance installed with `local` answers only on its own machine, so [give it an address](/run/address) first.
2. **Find the folder's ID** on the `folder:` line of `.marfa/folder.yaml` in a directory that follows it. `marfa folders inventory` lists every folder's ID, without its title.

Add the new directory with that ID, and agree to the plan:

<Terminal>

```bash
marfa folders add ~/Work/Home --folder 01a1f445-dde9-7548-bdb5-6823ae8ee275
```

```text
the first sync of /Users/sam/Work/Home will write and send nothing until you agree: 3 file(s) to write into the directory, 0 to send to the server
Go ahead? [y/N] y
```

</Terminal>

Then run `marfa folders push ~/Work/Home`, which writes the three files and sends nothing.

On another computer, turn on autostart there too: each computer needs its own watch. On the same computer, the one watch already covers both directories.

- **Shared:** the folder's settings, and where each file sits. Rename or move a file in one directory, and it moves in the others.
- **Not shared:** each directory's store under `.marfa`, which sends its own edits.

When two directories rewrite a note at once, Marfa keeps both edits, as [Sort out a conflicted copy](/use/conflicts) shows. To stop one directory following the folder, see [Change or stop syncing a folder](/use/change-or-stop-a-folder).
