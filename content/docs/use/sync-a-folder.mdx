---
title: Sync a folder
description: Keep a directory on your computer and a set of items in step, so each note is a Markdown file you can edit in any app.
---

- **You'll build** a folder on your computer that follows your notes, so each note is a Markdown file you can edit in any app.
- **You need** the `marfa` CLI signed in to your instance, as the [Quickstart](/quickstart) sets it up.
- **You'll have** a directory with a file for each note, where a change on either side reaches the other.

A folder's settings, such as which items it holds, live on your instance, so a second computer can follow the same folder. Each computer keeps its own copy in its directory. **Nothing is written or sent until you confirm the first sync,** and a folder never deletes many items at once without asking, as [Folder safeguards](/folder-rules) explains.

<Steps paged>
<Step>

### Create the folder

Make the folder's settings on your instance. The query says which items the folder holds, here every note:

<Terminal>

```bash
marfa folders create --title Notes --query '{"types":["core.note"]}'
```

```text
id                      01a1f122-3490-71b4-b475-0aae177f9880
type                    system.folder
state                   active
tier                    library
created_at              2026-11-19T00:08:33.168Z
version                 1
properties.title        Notes
properties.query.types  core.note
```

</Terminal>

**Keep the ID** on the `id` line for the next step. `marfa folders inventory` lists your folders' IDs again later.

</Step>
<Step>

### Add a directory

Choose the directory on your computer that follows the folder. It can be empty or hold files already, and the CLI makes it if it isn't there:

<Terminal>

```bash
marfa folders add ~/Notes --folder 01a1f122-3490-71b4-b475-0aae177f9880
```

```text
/Users/sam/Notes follows the folder 01a1f122-3490-71b4-b475-0aae177f9880
the first sync will write and send nothing until you confirm it: 1 file(s) to write into the directory, 1 to send to the server
`marfa folders confirm ~/Notes` lets it go; `marfa folders remove ~/Notes` drops the folder and leaves the files
```

</Terminal>

Here your instance holds one note, `Trip ideas`, and the directory holds one file, `Packing.md`, which becomes a new note. Where a note's file would land on a file already there, one of the two gets a number added to its name, and **neither is written over**.

Keep the directory out of iCloud Drive, other cloud-synced folders and network storage, where two programs would sync the same files. For notes kept beside code, use a directory that git ignores, so a branch switch doesn't change its files. `marfa folders add` warns in both cases and goes on.

</Step>
<Step>

### Check the plan

**The query decides every item the folder takes in,** and the first sync writes all of them to disk. A query that names only a type holds every item of that type in the library, so a folder of `core.note` with thousands of notes writes thousands of files. `marfa folders status ~/Notes` shows the plan again, and [Change a folder](/use/change-a-folder) narrows the query by tag or tier.

</Step>
<Step>

### Confirm and sync

Confirm the first sync, then run it once:

<Terminal>

```bash
marfa folders confirm ~/Notes
marfa folders push ~/Notes
```

```text
the first sync is confirmed; `folders push` or `folders watch` runs it
0 created, 0 updated, 0 renamed, 0 unchanged, 0 missing, 0 deleted, 0 skipped; 1 already queued by an earlier scan, so not counted as created or updated here
the server answered 3 write(s), creating 1 item(s)
2 file(s) written
```

</Terminal>

The directory now holds a file for each note, and `Packing.md` is a note on your instance:

<Files>
  <Folder name="Notes" defaultOpen>
    <Folder name=".marfa">
      <File name="folder.yaml" />
    </Folder>
    <File name="Packing.md" />
    <File name="Trip ideas.md" />
  </Folder>
</Files>

The `.marfa` directory holds the folder's own store and its settings. Leave it in place.

</Step>
<Step>

### Keep it in step

`marfa folders push` syncs once. To keep every folder in step while you work, start a watch, and turn on autostart so it starts each time you sign in:

```bash
marfa folders autostart on
```

[Keep folders syncing](/use/keep-folders-syncing) covers the watch and autostart.

</Step>
<Step>

### Edit a note

Open `Trip ideas.md` in any editor, change a line and save it. Within seconds the watch sends the change, and `marfa search` finds the new words. Change the note from an agent or the CLI, and the file is rewritten to match. [Edit notes as files](/use/edit-notes-as-files) says what each file holds.

</Step>
</Steps>

## If the server is limiting requests

A first sync of a large directory sends its files in pages, so it seldom meets your instance's [rate limit](/use/limits). If it does, the push says so and how long the server asked it to wait, and sends the rest on the next push:

```text
2 write(s) not delivered, waiting for the next drain: the server is limiting requests (429) and asked for a wait of 60s
```

A running watch says `the server is limiting requests; waiting 60s`, waits, and carries on by itself. Nothing is lost while it waits.
