---
title: Sync a folder
description: Keep a directory on your computer and a set of items in step, so your files, pictures and notes are ordinary files you open in any app.
---

- **You'll build** a folder on your computer that follows your files and notes, so each is an ordinary file you open in any app.
- **You need** the `marfa` CLI signed in to your instance, as the [Quickstart](/quickstart) sets it up.
- **You'll have** a directory where a PDF, a photo or a note you add becomes an item, and a change on either side reaches the other.

A folder's settings, such as which items it holds, live on your instance, so a second computer can follow the same folder. Each computer keeps its own copy in its directory. **Nothing is written or sent until you confirm the first sync,** and a folder never deletes many items at once without asking, as [How a folder treats files](/folder-rules) explains.

<Steps paged>
<Step>

### Create the folder

Make the folder's settings on your instance. The query says which items the folder holds, here every file and every note. A query for `core.file` also takes its kinds, such as `core.file.image` for pictures:

<Terminal>

```bash
marfa folders create --title Home --query '{"types":["core.note","core.file"]}'
```

```text

type                    system.folder
state                   active
tier                    library

updated_at              2026-11-19T01:05:54.211Z

properties.query.types  core.note, core.file
```

</Terminal>

**Keep the ID** on the `id` line for the next step.

</Step>
<Step>

### Add a directory

Choose the directory on your computer that follows the folder. It can be empty or hold files already, and the CLI makes it if it isn't there:

<Terminal>

```bash
marfa folders add ~/Home --folder 01a1f156-b623-73f9-b312-a5123d7bb20f
```

```text
/Users/sam/Home follows the folder 01a1f156-b623-73f9-b312-a5123d7bb20f
the first sync will write and send nothing until you confirm it: 1 file(s) to write into the directory, 3 to send to the server
`marfa folders confirm ~/Home` lets it go; `marfa folders remove ~/Home` drops the folder and leaves the files
```

</Terminal>

Here your instance holds one note, `Trip ideas`, and the directory holds three files: a note, `Packing.md`, a photo, `beach.png`, and a PDF, `receipt.pdf`. Each of the three becomes a new item. Where an item's file would land on a file already there, one of the two gets a number added to its name, and **neither is written over**.

Keep the directory out of iCloud Drive, other cloud-synced folders and network storage, where two programs would sync the same files. For files kept beside code, use a directory that git ignores, so a branch switch doesn't change them. `marfa folders add` warns in both cases and goes on.

</Step>
<Step>

### Check the plan

**The query decides every item the folder takes in,** and the first sync writes all of them to disk. A query that names only types holds every item of those types in the library, so a folder of `core.file` writes every file you've saved. `marfa folders status ~/Home` shows the plan, file by file, and [Change what a folder syncs](/use/change-a-folder) narrows the query by tag or tier.

</Step>
<Step>

### Confirm and sync

Confirm the first sync, then run it once:

<Terminal>

```bash
marfa folders confirm ~/Home
marfa folders push ~/Home
```

```text
the first sync is confirmed; `folders push` or `folders watch` runs it
0 created, 0 updated, 0 renamed, 0 unchanged, 0 missing, 0 deleted, 0 skipped; 3 already queued by an earlier scan, so not counted as created or updated here
the server answered 9 write(s), creating 3 item(s)
2 file(s) written
```

</Terminal>

The first line of counts is all zeros because `marfa folders add` had already read your three files and queued them; the next line shows the push sending them and **creating three items**. The two files written are `Trip ideas.md`, and `Packing.md` again, now with the details Marfa keeps at its top. The directory now holds:

<Files>
  <Folder name="Home" defaultOpen>
    <Folder name=".marfa">
      <File name="folder.yaml" />
    </Folder>
    <File name="beach.png" />
    <File name="Packing.md" />
    <File name="receipt.pdf" />
    <File name="Trip ideas.md" />
  </Folder>
</Files>

On your instance, `beach.png` is a `core.file.image`, `receipt.pdf` a `core.file`, and `Packing.md` a `core.note`. The `.marfa` directory holds the folder's own store and its settings. Leave it in place.

</Step>
<Step>

### Keep it in step

`marfa folders push` syncs once. To keep every folder in step while you work, turn on autostart, which starts a watch now and again each time you log in:

```bash
marfa folders autostart on
```

[Keep folders syncing](/use/keep-folders-syncing) covers the watch and autostart.

</Step>
<Step>

### Change a file

Drop another photo or PDF into `~/Home`, or open `Trip ideas.md` in any editor, change a line and save it. Within seconds the watch sends the change, and `marfa search` finds it. Change an item from an agent or the CLI, and its file is rewritten to match. [Work with the files in a synced folder](/use/edit-notes-as-files) says what each file holds.

</Step>
</Steps>

## If the server is limiting requests

A first sync of a large directory sends its files in pages, so it seldom meets your instance's [rate limit](/use/limits). If it does, nothing is lost: the push stops sending, says how long the server asked it to wait, and leaves the rest for the next push. It ends like this:

```text
2 write(s) not delivered, waiting for the next drain: the server is limiting requests (429) and asked for a wait of 60s
```

Wait that long and run `marfa folders push` again. A running watch waits by itself and carries on.
