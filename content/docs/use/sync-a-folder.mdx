---
title: Sync a folder
description: Keep a directory on your computer and a set of items in step, so your files, pictures and notes are ordinary files you open in any app.
---

- **You'll build** a folder on your computer that follows your files and notes, so each is an ordinary file you open in any app.
- **You need** the `marfa` CLI signed in to your instance, as the [Quickstart](/quickstart) sets it up.
- **You'll have** a directory where a PDF, a photo or a note you add becomes an item, and a change on either side reaches the other.

A folder's settings, such as which items it holds, live on your instance, so a second computer can follow the same folder. Each computer keeps its own copy in its directory. **Nothing is written or sent until you confirm the first sync,** and a folder never deletes many items at once without asking, as [How a folder treats files](/folder-rules) explains.

<Steps paged>
<Step>

### Create the folder

Make the folder's settings on your instance. The query says which items the folder holds, here every file and every note. A query for `core.file` also takes its kinds, such as `core.file.image` for pictures:

<Terminal>

```bash
marfa folders create --title Home --query '{"types":["core.note","core.file"]}'
```

```text
marfa: writing to http://localhost:8600
id                      01a1f165-1c9c-71f5-b4b6-e88135e8df1f
…
```

</Terminal>

It prints the new folder item. **Keep the ID** on its `id` line for the next step.

</Step>
<Step>

### Add a directory

Choose the directory on your computer that follows the folder. It can be empty or hold files already, and the CLI makes it if it isn't there. Here `~/Home` already holds a note, `Packing.md`, and a photo, `beach.png`:

<Terminal>

```bash
marfa folders add ~/Home --folder 01a1f165-1c9c-71f5-b4b6-e88135e8df1f
```

```text
/Users/sam/Home follows the folder 01a1f165-1c9c-71f5-b4b6-e88135e8df1f
the first sync will write and send nothing until you confirm it: 1 file(s) to write into the directory, 2 to send to the server
`marfa folders confirm /Users/sam/Home` lets it go; `marfa folders remove /Users/sam/Home` drops the folder and leaves the files
```

</Terminal>

The one file to write is the receipt you saved in the [Quickstart](/quickstart). The two to send are `Packing.md` and `beach.png`, which become new items. The bookmark stays out, since the query holds only notes and files. Where an item's file would land on a file already there, one of the two gets a number added to its name, and **neither is written over**.

Keep the directory out of iCloud Drive, other cloud-synced folders and network storage, where two programs would sync the same files. For files kept beside code, use a directory that git ignores, so a branch switch doesn't change them. `marfa folders add` warns in both cases and goes on.

</Step>
<Step>

### Check the plan

**The query decides every item the folder takes in,** and the first sync writes all of them to disk. A query that names only types holds every item of those types in the library, so a folder of `core.file` writes every file you've saved. See what the first sync will send:

<Terminal>

```bash
marfa folders status ~/Home
```

```text
0 file(s) in step
Packing.md: waiting (create, placement)
beach.png: waiting (upload, create, placement)
the first sync waits for confirmation: 1 file(s) to write into the directory, 2 to send to the server
```

</Terminal>

To take in fewer items, [Change what a folder syncs](/use/change-a-folder) narrows the query by tag or tier.

</Step>
<Step>

### Confirm and sync

Confirm the first sync, then run it once:

<Terminal>

```bash
marfa folders confirm ~/Home
marfa folders push ~/Home
```

```text
the first sync is confirmed; `folders push` or `folders watch` runs it
marfa: writing to http://localhost:8600
0 created, 0 updated, 0 renamed, 0 unchanged, 0 missing, 0 deleted, 0 skipped; 2 already queued by an earlier scan, so not counted as created or updated here
the server answered 6 write(s), creating 2 item(s)
2 file(s) written
```

</Terminal>

The counts are zero because `marfa folders add` had already queued your two files, and the push sends them, **creating two items**; the two files it writes are the receipt and `Packing.md`, now with the details Marfa keeps at its top. The directory now holds:

<Files>
  <Folder name="Home" defaultOpen>
    <Folder name=".marfa">
      <File name="folder.yaml" />
    </Folder>
    <File name="beach.png" />
    <File name="Boiler receipt" />
    <File name="Packing.md" />
  </Folder>
</Files>

The receipt's file is named after its title, `Boiler receipt`, without `.pdf`. On your instance, `beach.png` is a `core.file.image` and `Packing.md` a `core.note`. The `.marfa` directory holds the folder's own store and its settings. Leave it in place.

</Step>
<Step>

### Keep it in step

`marfa folders push` syncs once. To keep every folder in step while you work, turn on autostart, which starts a watch now and again each time you log in:

```bash
marfa folders autostart on
```

[Keep folders syncing](/use/keep-folders-syncing) covers the watch and autostart.

</Step>
<Step>

### Change a file

Drop another photo or PDF into `~/Home`, or open `Packing.md` in any editor, change a line and save it. Within seconds the watch sends the change, and `marfa search` finds it. Change an item from an agent or the CLI, and its file is rewritten to match. [Work with the files in a synced folder](/use/work-with-folder-files) says what each file holds.

</Step>
</Steps>

## If the server is limiting requests

A first sync of a large directory sends its files in pages, so it seldom meets your instance's [rate limit](/use/limits). If it does, nothing is lost: the push stops sending, says how long the server asked it to wait, and leaves the rest for the next push:

<Terminal>

```bash
marfa folders push ~/Home
```

```text
marfa: writing to http://localhost:8600
6 created, 0 updated, 0 renamed, 3 unchanged, 0 missing, 0 deleted, 0 skipped
the server answered 3 write(s), creating 2 item(s); 4 more held back until the write each follows is answered
5 write(s) not delivered, waiting for the next drain: the server is limiting requests (429) and asked for a wait of 60s
the server asked for 60s before the next drain; push again after that to send the rest
could not catch up: rate limited: Too many requests from this credential; try again later.
2 file(s) written
```

</Terminal>

Wait that long and run `marfa folders push` again. A running watch waits by itself and carries on.
