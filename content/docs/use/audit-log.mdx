Your instance keeps a log of **every change, sign-in and export:** which agent saved a file, who made a key, when a setting changed, and who exported your data. Marfa writes every entry itself.

- **It records** changes to your items, types and files, sign-ins and the keys and apps behind them, settings, webhooks and connectors, exports and restores, and the jobs Marfa runs on its own.
- **It never records a read,** so it doesn't say who looked at what. A write Marfa refused and a dry run leave no entry.
- **A change that succeeded is already in the log,** and if Marfa can't write the entry, it undoes the change. No entry holds a secret, such as a key or a password.

## Read it

<Terminal>

```bash
marfa audit
```

```text
id                                    action              when                      actor
01a1f13b-d21f-7229-8845-d8d6c16e5b69  key.revoke          2026-11-19T00:36:31.895Z  marfa on your-mac
01a1f13a-805e-7533-93d8-13ec40863738  connector.register  2026-11-19T00:35:05.437Z  RSS connector
more: --cursor cLsSIhjS1hvLPAoNsBwIHAQYYMjAyNi0xMS0xOVQwMDozMToxNC4wNjdaCQGh8Tb4lnchgXqvesFMNds
```

</Terminal>

Entries come newest first, 50 at a time. When more match, the last line gives the `--cursor` that reads the next page, and `--all` reads every page.

## See who did it

The `actor` column is the name the sign-in had at the time, so renaming or revoking it later changes nothing. It shows `Marfa` for work Marfa did on its own, and `no sign-in` for an entry from before anyone signed in, such as a failed sign-in. **Add `--json` to see the actor's kind and ID:**

<Terminal>

```bash
marfa audit --resource-type item --resource-id 01a1f130-ece6-765a-9d0b-113af7fdef49 --json | jq '.data[0].actor'
```

```json
{
  "kind": "key",
  "id": "01a1f130-37fc-7184-b4a2-3fba803cf8be",
  "name": "Reading digest"
}
```

</Terminal>

`browser`, `app` and `key` are [sign-ins](/use/see-and-revoke-access). `local` is a command run on the instance's own machine, and `server` is Marfa itself.

## Filter it

| Option | Keeps the entries |
| --- | --- |
| `--kind` | Of one kind: `access`, `data`, `settings` or `housekeeping`. |
| `--action` | With this action, such as `item.create`. |
| `--resource-type` and `--resource-id` | About one kind of thing, such as `item`, or one item, key or setting by its ID. |
| `--created-after` and `--created-before` | From between two times, such as `2026-11-19T00:30:00Z`. |
| `--query` | That hold every word you give, in any order, in the action, the ID of what changed or of the key that acted, the address the request came from and the details. |

Everything one key did:

```bash
marfa audit --query 01a1f130-37fc-7184-b4a2-3fba803cf8be
```

The search doesn't read the actor's name, so search by the key's ID, which [`marfa sign-ins list`](/use/see-and-revoke-access#see-what-can-reach-your-data) shows.

## How long entries are kept

Entries are kept for **90 days,** and a daily [housekeeping job](/run/housekeeping) deletes older ones. To keep them for a year, or for ever with `0`:

```bash
marfa config set audit_retention_days 365
```

Reading the log needs the `audit.read` permission, which the CLI holds with Full access. A key can hold it alone. [The audit log](https://github.com/withmarfa/marfa/blob/main/conformance/spec/events.md#the-audit-log) in the contract lists every action.
