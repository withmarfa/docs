A **plugin** adds types that every app and agent can share, under `common` or a root of its own, such as `rss`. A type may come with guidance an agent reads. The plugin also brings the edge types those types use and, for some, a connector. Only a plugin adds a `common` type.

The latest release of [withmarfa/plugins](https://github.com/withmarfa/plugins) installs by name every plugin WithMarfa publishes, which [Plugins](/catalog/connectors) lists. **Install a connector you mean to run by name,** since only a release's bundle names the connector's code for a host. **You need** the CLI signed in to your instance, as the [Quickstart](/quickstart) leaves you.

## Install by name

<Terminal>

```bash
marfa plugins install tickets
```

```text
installed tickets 0.0.14 with 5 types
```

</Terminal>

The CLI reads the plugin from the latest release. It checks the bundle's SHA-256 against the release's `plugins.json` before sending it, and your instance fetches nothing. A bundle that doesn't match, or a release the CLI can't read, exits `3` with `plugins_unreachable` and installs nothing. `MARFA_PLUGINS_URL` names another release.

**Installing is one write:** every type and edge type goes in, or none does. Afterwards `marfa types get common.ticket` shows `provenance.plugin`.

A name that is also a folder in the current directory is read as that folder, so run it elsewhere.

## Install from a folder

A bundle, `<name>.plugin.json`, installs as it is. A source folder holds `plugin.json`, with `types/` and `edge-types/` beside it. The CLI builds the bundle from those files, prints its SHA-256, and installs it at `0.0.0` without `--version`. **A folder names no connector code, so a host can't run that connector:** it's the way to try a plugin's types, or a connector you run yourself.

In a clone of [withmarfa/plugins](https://github.com/withmarfa/plugins), a connector's folder is `connectors/<name>/plugin` and a types plugin's folder is `types/<name>`:

```bash
marfa plugins install ./connectors/rss/plugin --version 0.0.14
marfa plugins install ./tickets.plugin.json
```

A plugin with a connector then says it runs on no host yet and names `marfa plugins assign`; [Run a plugin's connector](/use/run-a-plugin-connector) assigns one. [Plugin format](/reference/plugin-format) says what a folder and a bundle hold.

## Update a plugin

Install it again. The same version answers `tickets 0.0.14 is already installed` and changes nothing. **A newer version may only add,** such as fields, status words, enum values and types. Unchanged guidance needs no new sign-in.

| Answer | Why |
| --- | --- |
| `409 plugin_narrows` | The version would remove or narrow something. `details.changes` names each change. |
| `409 plugin_version_older` | The version is older than the one installed. |
| `409 plugin_child_conflict` | A field on one of your types, beneath a type of the plugin, would clash. Change your type, then install again. |

## When an install is refused

| Answer | Why |
| --- | --- |
| `409 plugin_needs_newer_server` | The plugin needs a later Marfa. [Upgrade](/run/upgrade) first. |
| `409 type_exists` | The instance already holds one of the plugin's types that the plugin didn't install. |
| `409 connector_source_held` | Another plugin, a connector you run yourself, or a key already holds the source the plugin's connector names. |
| `401 insufficient_user_authentication` | Writing its guidance needs [a recent sign-in](/run/sign-in-as-the-owner#confirm-its-you): run `marfa login --fresh-sign-in`. |
| `403 forbidden` | A type sits under `core`, `system`, `marfa`, `app` or `user` (`details.namespace` names it), or a key an app made installs guidance. |

## List and remove plugins

`marfa plugins list` shows every plugin; `marfa plugins get tickets` shows one, with its types and the bundle's fingerprint.

**Removing a plugin deletes no item,** but its connector's settings, secrets and mapping go. Installing it again starts from the default mapping, and you enter every secret again.

<Terminal>

```bash
marfa plugins remove rss
```

```text
removed rss; its 2 types and their items stay; its connector stopped: no key to revoke, 0 registrations removed; source rss keeps no state and 0 agreements
```

</Terminal>

Its types, edge types and items stay, still naming the plugin, and the connector's registrations go. Its source keeps its state and agreements, so installing it again picks up where it stopped. [Change a type](/build/change-a-type) deletes a type you no longer want. Exports and backups carry the plugins installed.

The rules are in the [plugins](https://github.com/withmarfa/marfa/blob/main/conformance/spec/plugins.md) chapter of the contract.
