A **plugin** adds types that every app and agent can share, under `common` or a root of its own, such as `rss`. A type may come with guidance an agent reads. The plugin also brings the edge types those types use and, for some, a connector. Only a plugin adds a `common` type.

The latest release of [withmarfa/plugins](https://github.com/withmarfa/plugins) installs **Tickets** by name. Clone that repository for any other plugin's source folder. Installing the connectors by name, and the steps to install a connector host, are coming. Marfa does not publish a host yet, so a connector you install is recorded and does not run. **You need** the CLI signed in to your instance, as the [Quickstart](/quickstart) leaves you.

## Install by name

<Terminal>

```bash
marfa plugins install tickets
```

```text
installed tickets 0.0.13 with 5 types
```

</Terminal>

The CLI reads the plugin from the latest release. It checks the bundle's SHA-256 against the release's `plugins.json` before it sends the bundle, and your instance fetches nothing. A bundle that doesn't match, or a release the CLI can't read, exits `3` with `plugins_unreachable` and installs nothing. `MARFA_PLUGINS_URL` names another release address.

**Installing is one write:** every type and edge type goes in, or none does. Afterwards `marfa types get common.ticket` shows `provenance.plugin`.

A name that is also a folder in the current directory is read as that folder, so run it elsewhere.

## Install from a folder

A bundle, `<name>.plugin.json`, installs as it is. A source folder holds `plugin.json`, with `types/` and `edge-types/` beside it. The CLI builds the bundle from those files and prints its SHA-256. It does not compile a connector's program. A folder installs at `0.0.0` without `--version`.

In a clone of [withmarfa/plugins](https://github.com/withmarfa/plugins), a connector's folder is `connectors/<name>/plugin` and a types plugin's folder is `types/<name>`:

```bash
marfa plugins install ./connectors/rss/plugin --version 0.0.13
marfa plugins install ./tickets.plugin.json
```

A plugin with a connector then says it runs on no host yet and names `marfa plugins assign`. [Run a plugin's connector](/use/run-a-plugin-connector) links the host. [Plugin format](/reference/plugin-format) says what a folder and a bundle hold.

## Update a plugin

Install it again. The same version answers `tickets 0.0.13 is already installed` and changes nothing. **A newer version may only add,** such as fields, status words, enum values and types.

| Answer | Why |
| --- | --- |
| `409 plugin_narrows` | The version would remove or narrow something. `details.changes` names each change. |
| `409 plugin_version_older` | The version is older than the one installed. |
| `409 plugin_child_conflict` | A field on one of your types, beneath a type of the plugin, would clash. Change your type, then install again. |

## When an install is refused

| Answer | Why |
| --- | --- |
| `409 plugin_needs_newer_server` | The plugin needs a later Marfa. [Upgrade](/run/upgrade) first. |
| `409 type_exists` | The instance already holds one of the plugin's types, and the plugin didn't install it. |
| `409 connector_source_held` | Another plugin, a connector you run yourself, or a key already holds the source the plugin's connector names. |
| `403 forbidden` | A type sits under `core`, `system`, `marfa`, `app` or `user` (`details.namespace` names it), or an app installs types that carry guidance, which only you write. |

A Swift app can also install a plugin ([Swift SDK](/reference/swift-sdk/plugins)).

## List and remove plugins

`marfa plugins list` shows every plugin. `marfa plugins get tickets` shows one, with its types and the fingerprint of the bundle.

**Removing a plugin deletes no item,** but its connector's settings, secrets and mapping go. Installing it again starts from the default mapping, and you enter every secret again.

<Terminal>

```bash
marfa plugins remove rss
```

```text
removed rss; its 2 types and their items stay; its connector stopped: no key to revoke, 0 registrations removed; source rss keeps no state and 0 agreements
```

</Terminal>

Its types, edge types and items stay, and they keep naming the plugin. The connector's registrations go too. Its source keeps its state and agreements, so installing it again picks up where it stopped. [Change a type](/build/change-a-type) deletes a type you no longer want. Exports and backups carry the plugins installed.

The rules are in the [plugins](https://github.com/withmarfa/marfa/blob/main/conformance/spec/plugins.md) chapter of the contract.
