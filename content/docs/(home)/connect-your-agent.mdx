An agent reaches your instance at **your instance's address followed by `/mcp`**, and you sign in in your browser. From the [Quickstart](/quickstart), that's `http://localhost:8600/mcp`, which the commands below use; `marfa whoami` shows it. A `localhost` address works only for an agent on the same computer: Claude needs a public address, and ChatGPT a public one or [OpenAI's Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels).

## Add Marfa to Claude, ChatGPT or another agent

**The Marfa plugin for agents,** `withmarfa/marfa-plugin`, is for Claude Code and Codex. It **isn't a [Marfa plugin](/use/install-a-plugin).** It bundles the [docs MCP server](/reference/docs-mcp-server) as `marfa-docs`, which needs no sign-in and reaches no one's data, and adds four skills:

- **connect** connects the agent to your instance and checks it answers.
- **find-and-save** finds, saves and changes items without duplicates or overwrites.
- **design-a-type** picks the right type for new records and drafts the smallest change.
- **migrate** brings in records from another app, service or folder, with a plan first.

<Tabs items={["Claude", "ChatGPT", "Claude Code", "Codex", "Cursor", "Other agents"]}>
<Tab value="Claude">

Claude connects from Anthropic's servers, so **your instance needs a public `https` address on port 443.** [Give your instance an address](/run/address).

On claude.ai or in Claude Desktop, open **Customize** > **Connectors**, select **+ Add** > **Add custom connector**, name it `Marfa`, enter your address followed by `/mcp` and select **Continue**. Leave **OAuth client** and **Request headers** as they are, select **Continue** again, choose **Sign in now**, then select **Add** and sign in to your instance. Added on the web, it works in the Claude mobile apps too.

On a Team or Enterprise plan, an owner adds it in **Organization settings** > **Connectors** with **Add** > **Custom** > **Web**, and each member selects **Connect**. [Anthropic's help](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) says who may.

</Tab>
<Tab value="ChatGPT">

ChatGPT calls what you make here a plugin. It connects from OpenAI's servers, so your instance needs a public `https` address, or [OpenAI's Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels).

Where your plan and workspace allow it, open **Plugins** at chatgpt.com, select the plus button, then **Add custom MCP server**. Name it `Marfa`, give it a short description, enter your address followed by `/mcp`, then choose OAuth for authentication. Select **I understand and want to continue**, then **Create as a plugin**. Install it, start a new chat, type `@` and choose **Marfa**. [OpenAI's guide](https://developers.openai.com/plugins/deploy/connect-chatgpt) has more.

</Tab>
<Tab value="Claude Code">

Install the plugin:

```bash
claude plugin marketplace add withmarfa/marfa-plugin
claude plugin install marfa@withmarfa
```

In a new session, ask the agent to connect to Marfa. Or add the server yourself:

```bash
claude mcp add --transport http --scope user marfa http://localhost:8600/mcp
```

Then type `/mcp`, choose **marfa** and sign in.

</Tab>
<Tab value="Codex">

Install the plugin:

```bash
codex plugin marketplace add withmarfa/marfa-plugin
codex plugin add marfa@withmarfa
```

In a new session, ask the agent to connect to Marfa. Or add the server yourself:

```bash
codex mcp add marfa --url http://localhost:8600/mcp
codex mcp login marfa
```

</Tab>
<Tab value="Cursor">

Add Marfa to `.cursor/mcp.json` in a project, or to `~/.cursor/mcp.json` for every project:

```json title=".cursor/mcp.json"
{
  "mcpServers": {
    "marfa": { "url": "http://localhost:8600/mcp" }
  }
}
```

Open **Customize** in Cursor's sidebar, enable **marfa** and sign in.

</Tab>

## Approve what it may reach

Your browser opens your instance: sign in with your username and password, or a passkey made at this address. The approval page, headed **Allow** and the agent's name, sums up what it asked for. Select **Allow**, or **Don't Allow** to refuse.

**To give less,** select **Choose…** first. Items and your profile each take **Read and Edit**, **Read Only** or **No Access**. **Settings, keys and more** takes **Full Access**, **No Access** or **Custom…** to choose each power. Where offered, **Read Only** gives server health and the activity log.

- **Marfa marks the agent's name (unverified),** because any program can claim any name. Approve only agents you trust.
- **Allowing with everything new at No Access declines the request.**
- **If you signed in over fifteen minutes ago,** Marfa asks for your password first.
- **If the agent's access changes in another tab,** allowing grants nothing, and the page opens again with what's true now.

An instance with no owner first asks you to create one, with the setup link or code Marfa shows where it runs. [See and revoke access](/use/see-and-revoke-access) ends the sign-in later.

## Other ways in

- **An agent that runs on its own** uses a key instead of a browser: [Work from an agent](/use/from-an-agent#an-agent-that-runs-on-its-own).
- **An agent that runs commands** can use [the `marfa` command](/reference/cli).
- **An agent that edits files** can work in a [synced folder](/use/sync-a-folder).
- **Two more addresses** let an agent change your types or look after the instance: [Marfa MCP server](/reference/marfa-mcp-server).
- **An agent that builds on Marfa** can read the [docs MCP server](/reference/docs-mcp-server).
