title: Changelog

---

Each release of Marfa ships the server, the CLI for macOS on Apple silicon, and the TypeScript SDK on npm. Below is what each one changed that you'd notice when you run an instance or build on it, newest first, with a link to the full list on GitHub.

**Until the first public release, a new build doesn't upgrade a database in place**: it refuses a database another build wrote, and leaves the file as it was. To move your data to a new build, export it with the old build and restore it into the new one, as [Upgrade](/guides/upgrade) shows.

## v0.0.9

Released October 16, 2026. [v0.0.9 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.9)

For running an instance:

- A web page can connect with one approval and no pasted key. The discovery documents and `POST /auth/oauth2/register` answer a request from any origin, and once the owner approves the page, the server lets the origin of its redirect URIs call the API from a browser, with no `CORS_ORIGINS` entry. [Connect a web page](/guides/connect-a-web-page) covers it.
- Because any page can now register, a registration that never receives a grant is removed after 1 day rather than 30 (`MARFA_DCR_CLIENT_RETENTION_DAYS`). A registration takes a body of at most 32,768 bytes and at most 10 redirect URIs.
- Registering a client that authenticates with `private_key_jwt` is refused with `400 invalid_client_metadata`, and the discovery documents list the client authentication methods the instance accepts.
- A connector operation that only the connector's own key can make answers an owner session or the private socket with `403 forbidden`, not `401`.
- Bulk imports no longer delay unrelated outbound webhooks, and listing the owner's connected apps no longer reads every active item, so it stays quick on a large store.

For the API:

- An operation that takes a JSON body refuses a top-level key it doesn't declare with `400 validation_error`, and `details.unknown_body_fields` lists the keys. Before, `POST /items`, `POST /edges` and several others dropped the key and answered success. `PUT /items/{id}/extensions/{namespace}` and `POST /auth/oauth2/register` still accept any key, and the operations that define a type or an edge type refuse one as `invalid_schema`.
- A write can require the exact version you read. `PATCH /items/{id}` takes `version_match: "exact"`, `POST /items/{id}/transition` takes `version`, and `POST /edges` and `DELETE /edges/{id}` take `source_version`. A write whose version no longer matches is refused with `409 version_conflict` and changes nothing.
- A write can name the instance it was made for in `X-Marfa-Instance-Id`. An instance with a different `instance_id` refuses it with `409 instance_changed` and writes nothing, so a write meant for one instance can't land on another that took over the address.
- `POST /items/{id}/tags`, `DELETE /items/{id}/tags/{tag}`, `PUT` and `PATCH /items/{id}/metadata`, and `PUT` and `DELETE /items/{id}/extensions/{namespace}` honor `Idempotency-Key`: a repeat is answered from the record of the first and changes nothing. The matching CLI commands take `--idempotency-key`.
- `GET /edges`, `GET /items/{id}/edges`, `GET /items/{id}/backrefs` and the `edges` and `backrefs` blocks of an item leave out an edge whose source item a key's source filter hides, whatever the source of its target.
- `POST /edge-types` with `evolve_constraints: true` widens the endpoint constraints of a registered edge type in place, keeping its definition and its edges. It answers `200`, or `404` if the type isn't registered.
- The API description types the `version` of an item, an edge, a type and a version snapshot as an integer, so a generated client reads a whole number.

For the CLI:

- `marfa types scaffold <ID>` prints a starting type definition from an id and its fields (`--field`, `--required`, `--parent`, `--description`), without a server or a key.
- `marfa folders watch` with no directory keeps every folder on the machine in step, in one process, and `marfa folders autostart on` runs it from login as a launchd agent on macOS or a systemd user unit on Linux. `off` removes it and `status` reports it. [Keep folders running](/guides/keep-folders-running) covers it.
- A command that works a folder, such as `marfa folders confirm`, asks a running watch for the folder instead of being refused. The watch lets it go and takes it back after the command ends. A watch that doesn't let go within 10 seconds leaves the command refused with `reading_handle`.
- A watch keeps a record of its folders in `folder-watch.json` for other programs on the machine to read. [Folder watch record](/folder-watch-record) covers it.
- `marfa folders add` and `marfa folders watch` warn once on standard error when a folder is in iCloud Drive, a cloud service's synced location or a network file system, and go on. A refused `marfa folders add` leaves behind no directory it made.
- `marfa folders push --send-only` sends what a folder holds and writes or removes no file in it. `marfa folders unmatched <DIR>` lists the files a folder keeps whose items its search no longer matches, and `--remove` takes them away after a confirmation or with `--yes`.
- A Markdown document's file name and its item's title stay in step in a folder: renaming the file sets the title, and a new title renames the file.
- With `OTEL_EXPORTER_OTLP_ENDPOINT` set, the CLI exports one OpenTelemetry trace for each command. With `MARFA_POSTHOG_HOST` and `MARFA_POSTHOG_PROJECT_TOKEN` set as well, a failed command is also sent to PostHog error tracking. With none set, the CLI sends nothing.

For apps and devices:

- A body link keeps naming the item its edge was made to when other links are added to the body or taken out of it, and a link by an item's id always names that item, whatever other items are titled. Before, a new link could move an existing link to another item, and a link by id could land on an item titled with that id.
- An app can forget only the answered writes it names, so an answer recorded between its read and its clear isn't lost unread. Use `forgetAnsweredIds` in the Node module, or `marfa device forget --id <ID>`, which you can repeat. Without ids, `marfa device forget` still clears every answered write.
- A working copy that holds the event stream, such as `marfa device follow`, drains its queue once when the server is reachable again, and reports the result as a `queue.drained` or `queue.not_drained` change, so an app no longer has to drain itself.
- A working copy refuses a write to a `system.*` item before it saves or queues anything, with `403 type_not_permitted`.
- A row that a slice holds in the trash stays in the working copy after a drain reads it back, and a person can discard a create that no read can land, so the queue can empty.
- Moving the source of several edges costs one hydration for the whole batch rather than one for each.

## v0.0.8

Released October 14, 2026. [v0.0.8 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.8)

For running an instance:

- The CLI for macOS is signed and notarized by Apple, so a copy downloaded in a browser runs, as one downloaded in a terminal does.
- One setting, `OTEL_EXPORTER_OTLP_ENDPOINT`, turns on the server's telemetry: with it set, the server sends its traces and logs to that endpoint. `MARFA_OTEL_ENABLED` is gone.
- Replacing a connector's revoked or expired key keeps its inbound webhook addresses and the deliveries waiting for it.

For the API and the CLI:

- An edge write checks the edge's properties against its edge type's `property_schema`, as an item write checks an item's properties against its type, and refuses a wrong value with `400 invalid_properties`.
- `POST /items/bulk-get` takes `X-Marfa-Read-View`, as reading one item does: a view that changed is refused with `409 read_view_changed`, and the answer's `listed` says, for each item, whether listings show it.
- `marfa folders health <folder-id>` reads a folder's sync health from the instance, as each computer that follows the folder reports it.
- An event stream keeps a held change when its key gains read access while the stream opens.

For apps and devices:

- A folder can be added when a directory above it is a symbolic link, as `/tmp` and `/var` are on macOS.
- An edge edit that changes nothing queues no write, so the edge's version stays and no `edge.updated` is announced.
- A working copy reads the items it keeps outside its slice in bulk, so opening one that keeps many sends far fewer requests.
- A catch-up says whether it changed the catalog of types the copy holds, also when it fails.

## v0.0.7

Released October 11, 2026. [v0.0.7 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.7)

For claiming and access:

- A new instance is claimed once, by its owner, with a setup code from the server's log, a single-use link opened in a browser, or `marfa --socket <path> setup claim` on the instance's own machine. The owner and explicit management permissions replace the operator key.
- `--socket` gives the CLI the machine's own authority through a private socket, for `setup`, making keys, restoring an archive, and `owner recover`, which resets a lost owner password.
- Managing an instance takes a named permission, such as `keys.mint`, `audit.read` or `config.manage`, that a key or an app is given on purpose.
- A key can be made with an expiry, and given, changed or cleared one later with `marfa keys create` and `marfa keys update`. An expired key is refused with `401`, as a revoked one is.
- An app the owner connected stays signed in when the owner's browser session ends, and every app is shown as unverified on the consent and sign-in pages.
- An extension namespace is reached only through a key's extension map, never through its label.
- The owner can add passkeys, and list, rename and end apps and keys alongside browser sessions. A browser session ends after a week without use; ending one leaves apps connected.
- A device authorization request must name its scopes. Signed-in owner approval has lookup limits independent of anonymous requests.

For running an instance:

- A Railway template creates a personal instance with persistent storage, HTTPS and daily backups. [Deploy](/guides/deploy) covers it.
- An upload or a restore that would fill the disk is refused with `507 insufficient_storage`, rather than failing later writes.
- Text extraction from office documents is bounded, so a large document can't exhaust the server's memory.
- The server's diagnostics never carry values from the database.
- Only the sign-in routes Marfa uses answer under `/auth/`, and password changes count toward the sign-in limits.
- A restart recovers a stale private socket left by a crash and refuses to disrupt a live listener.
- An archive restores app-written records under `restored:` sources and marks restored app connections revoked, preserving their history without reconnecting them.
- A working copy verifies the same instance at a changed address before sending credentials. Folder sync preserves empty frontmatter properties and defers deletion after an incomplete scan.

For the API and the CLI:

- Moving an item into or out of the trash with `POST /items/{id}/transition` announces `item.deleted` or `item.restored`, as a delete or a restore does.
- The CLI warns once before it sends a credential over plain `http` to a host other than this machine. `--allow-http` says that's intended.
- A device client that can't refresh its token is refused `offline_access`, rather than approved without a refresh token.
- Version history identifies the sign-in that wrote each version and carries a cursor to continue its pages.
- `POST /types/normalize` and `marfa types normalize` compare a candidate with its registered declared and resolved definitions without writing it. Unknown type and edge type schema keys are refused.
- Connector registrations expose persistent problems separately from private state and run results. A connector replaces or clears problems under its hold.

## v0.0.6

Released October 7, 2026. [v0.0.6 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.6)

- `marfa docs` reads this site from a terminal: it searches the pages, lists them, and prints one as Markdown. [Docs as Markdown](/docs-as-markdown) covers it.
- `marfa login` keeps waiting when the server asks it to slow down, and a new instance tells its operator how to create the owner.
- A conflicted copy is linked to its original by a `derived-from` edge, so an app can show the two together on any device.
- A file item carries the size of its bytes in `size_bytes`, set by the server from the blob.
- When the trash or a revoked app's grant is purged by its retention sweep, the purge is announced as an event, so a device learns the item is gone.
- `GET /occurrences` places a whole-day event from local midnight in its time zone, whether it repeats or not.
- A housekeeping run that outlives its deadline is ended and recorded as an error, so the job can run again.
- A working copy, in the Swift SDK or the CLI's device commands, can read the trash and restore or purge from it, hold both tiers in one slice, read and change a folder's settings, and move one end of an edge in a single write. Links and embeds in an item's body become edges when it's written through a copy, as they do in a folder.

## v0.0.4

Released October 5, 2026. [v0.0.4 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.4)

Some of these changes need a change in your code:

- Several operations are renamed so that each verb means one thing, such as `updateType` to `replaceType`, `mergeItemMetadata` to `updateItemMetadata` and `createEdgeType` to `registerEdgeType`. Canceling a bulk action job is `POST /items/bulk-actions/jobs/{id}/cancel`.
- Every frame on the event stream names its event in `event_type`, the same field a webhook delivery uses.
- A request body sent without `Content-Type: application/json` is refused with `400 validation_error`.
- Every operation refuses a query parameter it doesn't recognize, and input the server can't read answers `400` rather than `500`.

For access and files:

- A key holds exactly the permissions it names, and an item of a type the key can't read answers the same on every operation.
- An expired key is no longer found by the key operations.
- An edge or an extension that names a blob lets a credential that reads it fetch the blob.

For running an instance:

- The archive export streams, and a restore brings back items with their dates and history, all or nothing.
- `/health` reports a database, write path or disk that is down as a failure.
- In the container image, a database from another build leaves the container running and unhealthy, with the reason in its log, rather than restarting it.
- The sign-in, consent and device approval pages work as they say, and every HTML page carries a content security policy.

For devices and folders:

- A search matches the same rows on the server and in a working copy.
- An app can read and save to its working copy before its first sync, and declares the types it uses.
- The Swift SDK can add, sync and watch folders as the CLI does.
- A folder's first sync says what it will write and send, and waits for `marfa folders confirm`, or `--yes` on `marfa folders add`.

## v0.0.3

Released October 3, 2026. [v0.0.3 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.3)

Folders arrive: a directory on your machine kept in step with your instance, as Markdown and other files. A folder's settings are a `system.folder` item, shared by every machine bound to it, and a file's frontmatter carries its item's fields and edges. Moving a file from one folder to another on the same machine is a move, not a delete, and a large removal waits for you to confirm it.

For connectors:

- Inbound webhooks: a connector can have an address on the instance where a service such as GitHub posts its changes.
- A connector holds its registration while it runs, and keeps its state on the instance.
- A type can name a link field, unique across its items, and a purge leaves a tombstone, so a connector doesn't bring a purged record back. `POST /items/lookup` finds items and tombstones by link, natural key or ID.

For the API:

- A refused write names the grant the key lacks in `details.grant`, or says the item is in the trash.
- `DELETE /items/{id}` takes the `version` you read.
- An item of a type the key can't read answers `404 item_not_found`, as a missing one does.
- An edge type can declare a reverse name.
- `GET /items/stats` counts the items a listing's filters match.
- An `Idempotency-Key` belongs to the credential that sent it.
- Every blob downloads as a sandboxed file.

For running an instance:

- Every setting is checked when the server starts, and a bad value stops it with a message that names the setting.
- The server refuses a database written by another build, naming what differs.
- With telemetry on, unhandled errors can go to PostHog's error tracking.

For the CLI, `marfa items add` adds a file as an item of its own, and the first run of a new instance is a series of `marfa` commands. Under `--json`, a usage error is a JSON refusal like any other.

## v0.0.2

Released September 27, 2026. [v0.0.2 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.2)

- A key can read its own grants, with `GET /keys/current` or `marfa keys current`.
- The event stream sends `stream_live` once it has replayed what you missed, so a reader can tell it has caught up.
- `marfa keys update --no-permissions` takes every permission and map from a key, so a key made too wide can be emptied without making a new one.
- The TypeScript SDK refuses a credential with characters a bearer token can't hold, without repeating the credential in the error, and sends a body of bytes as the bytes.
