title: Changelog
description: What each release of Marfa changed for someone running an instance or building on it.
---

Each release of Marfa ships the server and its container image, the CLI for macOS on Apple silicon and Intel and for Linux on x86_64 and aarch64 with a checksum file, a Homebrew formula for the CLI, and the TypeScript SDK on npm. This page lists every release, newest first, with what changed and a link to the full list on GitHub. The Swift SDK's own releases are listed after Marfa's.

**Marfa doesn't upgrade a database in place.** A build refuses a database whose schema differs from its own, or that holds retired tables or settings, and leaves the file unchanged; a version change alone doesn't cause a refusal. [Upgrade](/guides/upgrade) shows how to test an export and restore on fresh storage before switching builds.

## v0.0.23

Released October 22, 2026. [v0.0.23 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.23)

**This release renames a database table and breaks the API's operation names.** It refuses an existing v0.0.22 database without changing it, because `blob_locations` is now `blob_copies` and nothing is migrated. To move an instance that holds data, export it with v0.0.22, then restore the export into a fresh v0.0.23 instance. [Upgrade](/guides/upgrade) covers the process.

For apps and the API reference (breaking):

- **The API reference follows the server's 23 groups, in the server's order.** `GET /openapi.json` writes each group's `x-operation-order`, which lists every operation once by its `operationId`, and writes `paths` in the order of each path's earliest operation. The reference shows the groups as the server lists them, and each page is at `/api-reference/<group>/<operationId>`. Trash, Connector state, Inbound webhooks, API keys, Apps, Owner, Sign-ins and passkeys, and Health and maintenance are now groups of their own. The webhook a subscription calls is listed in the Webhooks order as `receiveWebhookEvent`.
- **A blob's recorded stores are its copies.** `GET /blobs/{hash}/locations` is now [`GET /blobs/{hash}/copies`](/api-reference/blobs/listBlobCopies), and `DELETE /blobs/{hash}/locations/{store}` is now [`DELETE /blobs/{hash}/copies/{store}`](/api-reference/blobs/deleteBlobCopy). The operations are `listBlobCopies` and `deleteBlobCopy` where they were `listBlobLocations` and `deleteBlobLocation`. The error code `blob_location_not_found` is now `blob_copy_not_found`.
- **A platform type that the build no longer ships is retired, not drifted.** `GET /platform-types/drift` is now [`GET /platform-types/retired`](/api-reference/health-and-maintenance/listRetiredPlatformTypes), as `listRetiredPlatformTypes` where it was `listPlatformTypeDrift`. `deletePlatformType` is now [`deleteRetiredPlatformType`](/api-reference/health-and-maintenance/deleteRetiredPlatformType), on the same path. The `/health` field `drifted` is now `retired`.
- **Other operations have new `operationId` values,** on the same method and path: `heartbeatConnector` is `sendConnectorHeartbeat`, `holdConnector` is `takeConnectorHold`, `updateSignIn` is `renameSignIn`, `updateOwnerPasskey` is `renameOwnerPasskey`, `removeOwnerPasskey` is `deleteOwnerPasskey`, `exportData` is `exportArchive` and `getServerMetrics` is `getInstanceMetrics`. A generated client names its methods from these, so regenerate it.
- **Schemas follow the names.** `BlobLocation`, `BlobLocationPage` and `BlobLocationNotFoundOrBlobNotFoundRefusal` are now `BlobCopy`, `BlobCopyPage` and `BlobCopyNotFoundOrBlobNotFoundRefusal`. `DriftedPlatformType` and `DriftedPlatformTypePage` are now `RetiredPlatformType` and `RetiredPlatformTypePage`.
- **Summaries say what each operation does on its own.** A connector's webhook endpoint is an inbound endpoint, so the operations are "Create an inbound endpoint", "List inbound endpoints" and "Retire an inbound endpoint". Connector operations name the connector, such as "Release a connector hold" and "Get a connector's state", and the trash operations by summary say so, such as "Trash an item by summary".

For running an instance and using the CLI:

- **`marfa server` runs a server in Docker on the same machine.** `install` asks how the server is reached and prints the link that claims it, and `upgrade`, `status`, `start` and `uninstall` look after it. `upgrade` does not move data, and `uninstall` keeps it unless you pass `--delete-data`. [Deploy](/guides/deploy#install-with-the-command-line) covers it.
- **The CLI comes for Linux and Intel Macs, with checksums.** A release carries four archives, `marfa-<version>-<os>-<arch>.tar.gz`, and one checksum file, `marfa-<version>-checksums.txt`. The release also writes a Homebrew formula to `withmarfa/homebrew-tap`, so `brew install withmarfa/tap/marfa` installs the CLI. [CLI](/cli#install) shows each route.
- **Four CLI commands have new names.** `marfa types drift` is `marfa types retired`, `marfa types prune` is `marfa types delete-retired`, `marfa blobs locations` is `marfa blobs copies` and `marfa blobs delete-location` is `marfa blobs delete-copy`. The old names are gone.
- **An export by a key without `blobs.manage` names the files it could not carry.** The manifest's `missing_blobs` lists a file version whose bytes that key may not read, with a `null` MIME type and size, and `marfa export` then exits 1 and keeps the archive beside the path as `<path>.incomplete`. A script that reads the path never gets an archive that lacks files. [Export and restore](/guides/export-and-restore) covers it.
- **The server refuses to start when its file folder is missing but the database records saved files there.** It names the folder and creates nothing there, so a drive that did not mount cannot become a new, empty store. Where an object store is configured, the bucket serves the copies and the start goes ahead. [Deploy](/guides/deploy) shows the exit status and what to restore.
- **The server image refuses to back up a database that may be older than its bucket's newest copy.** It exits 1 instead of replacing the newer copy. Set `MARFA_REPLACE_NEWER_REPLICA` only when you mean to replace it. A new file, `marfa.db-replica`, sits beside the database, so copy it with a volume backup. [Back up and restore](/guides/back-up-and-restore) lists the files.

For folders, apps and devices:

- **Folder syncing keeps one item when a file moves between folders.** A file item at a `.md`, `.markdown` or `.txt` name that moves keeps its binding until the other folder takes it, and a file found by its identity or its bytes is read as the same item. [Folder safeguards](/guides/folder-safeguards) lists each case.
- **The contract states every owner action that needs a recent sign-in.** That covers making, changing and revoking a key, signing out every browser, the trash operations, removing a custom type and retrying a webhook delivery. [Confirm it's you](/guides/sign-in-as-the-owner#confirm-its-you) lists them.
- **A working copy that an earlier build made is refused with `wrong_schema`.** The copy's folder journal has a new shape, and the build never discards the copy. [Troubleshooting](/guides/troubleshooting#staying-in-step) shows what to do.

## v0.0.22

Released October 21, 2026. [v0.0.22 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.22)

For folders and app builders:

- **A first sync of many files finishes in one run.** A working copy sends waiting new items and their placements in pages of up to 1,000, and reads them back in bulk, instead of using four requests for each file. Pushing 5,000 new notes took 11 pushes because of the request limit and now takes one. Fewer than 50 waiting items are sent one at a time, as before.
- **A write a page cannot settle is sent on its own.** An entry the server skips or refuses goes alone under its key, and a page the server rate-limits is sent again on the next pass.

## v0.0.21

Released October 21, 2026. [v0.0.21 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.21)

**This release changes the database schema.** It refuses an existing v0.0.20 database without changing it. Keep the old build, database and an export made with that build. Test restoring the export into fresh storage before replacing the running instance; cross-build restore is not guaranteed. [Upgrade](/guides/upgrade) covers the process.

For the owner's console:

- **Items and Trash work with summaries.** Items lists and searches names by type without opening item content. Names follow the type's display hints and fallback fields. Trash shows who moved an item there, when, and when it becomes eligible for deletion. You can move items to the trash, restore or permanently delete them, empty the trash in batches, and remove unused custom types. Item actions check the version you saw. These changes ask for a recent sign-in.
- **Connected apps lets you reduce access.** Saving a reduction ends tokens and refresh chains that exceed it; tokens already within the reduced access keep working. Increasing access requires fresh approval. The app-access operations are also published in the API reference.
- **Folders shows reported copies and their problems.** The list and detail pages separate current reports from historical sign-ins. A reported copy does not mean a computer is online.
- **Key and app pages show their webhooks and delivery history.** The owner can retry a retained failed delivery, subject to the subscription's current settings and its maker's access. Creating or changing a subscription still needs its maker's credential.
- **Activity and types retain names.** Audit entries keep the acting sign-in's name at the time of the action. Type details identify the creator where one is recorded; unknown history stays unknown. The CLI's audit command also filters by kind and text.
- **More settings take effect without a restart.** General can change version retention, unused-app retirement, file reading and OCR, error reporting and heartbeat reporting. Receiver addresses and credentials remain machine settings.
- **Home and the CLI share Needs attention.** Health, failed jobs, connector and folder problems, and keys nearing expiry come from one operation. A failed check appears as unavailable alongside any known concerns.
- **Profile accepts a picture address.** The owner can set or clear an HTTP(S) picture URL in Profile or through the CLI's owner update command.

For running an instance and using the CLI:

- **An unresponsive file store no longer holds work indefinitely.** Blob reads try another recorded copy when a store does not begin answering. Integrity and replication jobs report work they could not finish. An unfinished store write or deletion blocks conflicting operations on the same blob, and removing a copy confirms enough other copies still exist.
- **Private-socket access excludes item content.** Item properties, edges, tags, search, counts, events and exports need a key. Summaries and owner trash operations remain available through the socket. A refusal explains which access to use.
- **Sign-in and command errors give the relevant next step.** Login keeps polling through temporary server failures while its code remains valid. Connected apps distinguishes the Marfa CLI from other apps using device authorization. Setup-code refusals, an unreadable keychain, an unreachable server and webhook retry refusals carry more specific errors.

For folders and app builders:

- **A folder push recovers once from a changed key's read view.** It rebuilds the copy and continues waiting writes in the same run, keeping earlier verdicts. A watch preserves the server's requested wait when it hands a folder to a command and takes it back.
- **Folder reports distinguish waiting, unchanged and held files.** First-sync plans count files they leave in place separately from files written beside existing ones. A document the scan refuses is held with its reason, rather than described as waiting to send.
- **A frontmatter type value can belong to another notes app.** A value that is not a Marfa type identifier stays in the item's `type` property and survives writing the file back. A value shaped like a Marfa type identifier still selects the item's type and is refused if it cannot be used.
- **The core's Swift binding accepts a credential renewer.** Apps can provide renewal for working copies and folders when a token is refused, with queued writes retained on failure. This is a binding change in Marfa; the Swift SDK has its own release.

## v0.0.19

Released October 21, 2026. [v0.0.19 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.19)

For running an instance:

- **The owner has a General page.** At `/auth/owner/general`, it shows the instance's name and the five retentions that can change while the server runs, and saves only the ones you change. [Change settings while it runs](/guides/settings#change-settings-while-it-runs) covers it.
- **The owner has a Health page.** At `/auth/owner/health`, it shows whether the database, saving changes, disk, file storage and any attached object store are working, and lists every housekeeping job with its last run, its error if it failed, and Run now. [Housekeeping](/guides/housekeeping) covers the jobs.
- **The owner has a Connected apps page.** At `/auth/owner/apps`, it lists the apps you approved, what each can reach and the keys it made. Disconnecting an app ends its sign-in at once, and its keys keep working unless you revoke them there too ([Revoke access](/guides/authenticate#revoke-access)).
- **The owner has a Browsers page.** At `/auth/owner/browsers`, it lists where you're signed in and signs out one other browser or all of them. [Manage passkeys and sign-ins](/guides/sign-in-as-the-owner#manage-passkeys-and-sign-ins) covers it.
- **Disconnecting an app or signing out another browser needs a recent sign-in.** If yours is more than five minutes old, the page asks you to confirm it's you.
- **The owner has an Activity page.** At `/auth/owner/activity`, it lists the [audit log](/guides/audit-log) newest first and filters it by kind, time and text.
- **The owner has an All settings page.** At `/auth/owner/settings`, it lists every environment setting by group with its variable, whether it can change while the server runs, and its value now; a secret shows only whether it's set. [Every environment setting](/guides/settings#every-environment-setting) lists them.
- **Eight more settings count as secrets.** `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `ERROR_WEBHOOK_URL`, `MARFA_HEARTBEAT_URL`, `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`, `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` and `MARFA_POSTHOG_HOST` can carry a credential in an address, so no page shows their values and no startup message prints them.
- **`MARFA_AUTH_BASE_URL` can't hold a user name, password or query string.** The server refuses one that does; the setting stays readable on the All settings page.
- **The owner has an Export and restore page.** At `/auth/owner/export`, it downloads an archive of everything, or of one type and the types under it, with or without file bytes, and restores one. [Export and restore an archive](/guides/export-and-restore#export-an-archive) covers it.
- **The owner has a Connectors page.** At `/auth/owner/connectors`, it lists each connector as Failing, Problems, Not heard from for over a day, or Running, shows its recent runs, and clears its saved state or removes it after you confirm.
- **The Manage and Restore pages are gone.** `/auth/owner/manage` and `/auth/owner/restore` no longer exist, and nothing redirects from them.

For apps and devices:

- **`PATCH /config` changes only the settings it names.** A setting in the body replaces the stored one, a setting set to `null` goes back to its default, and every other setting stays. `enforcement` is one setting, so naming it replaces all three levers. It takes the same fields and refusals as `PUT /config`. [Update the configuration](/guides/settings#update-the-configuration) covers it.
- **`marfa config update` sends `PATCH /config`**, with `--body` or `--file`.
- **`GET /audit` filters by `kind` and `q`.** `kind` is `access`, `data`, `settings` or `housekeeping`, and `q` keeps the entries that hold every word you give, in any order, ignoring ASCII case. Any other `kind` is refused `400 validation_error`. [Filter it](/guides/audit-log#filter-it) covers both.
- **`GET /export?format=archive&files=false` leaves out file bytes.** The manifest names each file it left out under `missing_blobs`, and a restore reports those the instance doesn't hold in `blobs_missing`. [Leave out the files](/guides/export-and-restore#leave-out-the-files) covers it.

## v0.0.18

Released October 20, 2026. [v0.0.18 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.18)

For running an instance:

- **The owner has a Home page at `/`.** A browser signed in as the owner sees the instance's name and address, what needs attention, a search for pages, and Sign out; a program that requests `/` still gets the description of the instance. [Start from Home](/guides/sign-in-as-the-owner#start-from-home) covers it.
- **Owner pages send a browser with no session to sign in**, and back, or to `/setup` on an unclaimed instance. At `/`, such a browser sees that the instance is running, with a Sign in link.
- **The owner manages API keys in the browser.** The API keys pages list, create, edit and revoke keys; a new key's access starts off, and its secret shows once, until you leave the page. [Use the API keys page](/guides/manage-keys#use-the-api-keys-page) covers it.
- **A key's page refuses a save if the key changed** after the page opened.
- **The owner has Profile and Password and passkeys pages.** Changing a passkey asks you to confirm it's you if your sign-in is more than five minutes old, and changing the password asks for the current one. [Manage passkeys and sign-ins](/guides/sign-in-as-the-owner#manage-passkeys-and-sign-ins) covers them.
- **A passkey name that is empty or too long is refused** `400 validation_error` when the passkey is verified.
- **A folder whose directory is replaced stays listed.** The folder registry records the directory's identity, so the watch resumes when the original directory returns; an entry goes only when its path holds no folder state and isn't known to be another directory. [Folder safeguards](/guides/folder-safeguards#a-missing-or-unreadable-directory) covers it.
- **Sign out stays beside the title on a phone.** On Home, it no longer drops below the title and address.
- **Destructive actions sit in their own card.** Revoking a key and removing a passkey are in a bordered card of their own.
- **Save appears only after a change.** A key's page shows Save and Discard, with a count of the changes, once something has changed.
- **The server needs Node.js 22.14 or later.** The container image runs Node.js 24. [Deploy](/guides/deploy) covers it.

For apps and devices:

- **The owner chooses what an app gets.** The approval screen sets each type to No access, Read only or Read and edit, then the profile, then the powers over Marfa, which start off; three powers that can't be undone are marked. Access the app already holds shows as Already allowed. [What the owner approves](/access#what-the-owner-approves) covers it.
- **The owner can narrow a request for all data to types.** The approval screen shows Choose types, and if the owner picks types, the token names them instead of all data.
- **Turning off all the new access refuses the request.** The app gets `access_denied` and keeps what it held. A request for nothing but `openid` and `offline_access` offers nothing to turn off, so the owner can approve it.
- **A device code is easier to type.** It shows as `XXXX-XXXX`, is accepted in any case with or without the hyphen, and ends after 10 minutes.
- **Confirming it's you happens in a dialog, not a redirect.** `POST /auth/confirm` takes the owner's password or a passkey and replaces the session, so the browser stays on the same page. [What the owner approves](/access#what-the-owner-approves) covers it.
- **A wrong password at `POST /auth/confirm` counts against the sign-in limits.** It answers `401 unauthorized`, then `429 rate_limited` with `Retry-After` once the attempts are spent, and a refused confirmation keeps the session.
- **`POST /auth/confirm` answers `401` without a live owner session**, and to a request that carries a key.
- **A program refused for want of a recent sign-in gets `403 forbidden`**, with "Sign in again to perform this operation". A browser can always end its own sign-in.
- **`narrow_only` keeps a key from gaining access.** `PATCH /keys/{id}` with `narrow_only: true` refuses a change that adds access, and the API keys pages send it. [Narrow a key](/guides/manage-keys#narrow-a-key) covers it.
- **`POST /keys` answers `Cache-Control: no-store`**, so the new secret isn't cached.
- **Marfa keeps a whole number exact, or refuses it.** A `number` or `integer` value that Marfa can't serve back with the same digits, such as `1500000000000000001`, is refused `400 invalid_properties`, and `details.errors` names the field. [Field kinds](/catalog/field-kinds) covers it.
- **A `url` value is judged as the WHATWG URL Standard does.** It's trimmed first, and for a special scheme such as `http`, a non-ASCII host must be valid IDNA and a host with a forbidden code point is refused.
- **A tag of `.` or `..` is refused** with `400 validation_error`, as an empty, blank or over-long tag is. A restore still accepts what an archive holds.
- **Narrowing a webhook cancels the pending deliveries it no longer selects.** They end `canceled`. Changing its `url` or setting `active: false` cancels all of them, and widening revives none. [Change what a webhook sends](/guides/receive-webhooks#change-what-a-webhook-sends) covers it.
- **The CLI prints access in the words the approval page uses.** `marfa login`, `whoami` and `keys list`, `current`, `create` and `update` show No access, Read only or Read and edit for each type, and name powers by their titles; `--json` is unchanged. [CLI](/cli) covers it.
- **A queued write that fails alone is set aside.** When a write keeps failing like an outage while the server answers other writes, a device tests it by sending another write that doesn't depend on it, and blocks it as `failing_alone` only if it fails the same way when sent once more; the writes that depend on it wait as `awaiting_dependency`. [Devices](/devices#verdicts) covers it.
- **`marfa device queue` prints the last answer a write met**, after `last answer:`.
- **A file item's file at a document name is sent as bytes.** A file bound to a file item, at a name ending `.md`, `.markdown` or `.txt`, is sent as bytes whatever they hold, with no frontmatter read. If it's empty it waits, and the rest of the scan goes on. A file at such a name that isn't bound to a file item is still read as a document.
- **A `marfa_id` over 256 bytes isn't read as an item ID.**
- **`--no-keychain` keeps the CLI off the keychain.** It, or `MARFA_NO_KEYCHAIN=1`, makes every command treat the keychain as absent, and `marfa login --print-token` no longer reads or writes it. [CLI](/cli) covers it.
- **A key sent with no server named is refused.** A command that sends a key from `--key` or `MARFA_API_KEY` without naming a server is refused `no_server`.
- **Two types with the same label are told apart on the approval screen.** Each shows its identifier under the label, and the type search matches the identifier.
- **A lock file the CLI can't write is refused with a message.** When the lock file opens read-only, the CLI stops with `<file> cannot be opened for writing, so it cannot be locked: check that it is writable`.
- **A repeat of a write whose first answer was large is refused.** Marfa keeps only the status of a first answer over 1,048,576 bytes, so a repeat under the same `Idempotency-Key` answers `422 idempotency_result_not_retained` with `details.original_status` and writes nothing. [Write safely](/guides/write-safely#retry-with-an-idempotency-key) covers it.
- **A device counts such a repeat's `2xx` status as accepted**, except for a create that names no `id`, which it refuses.
- **A waiting edge edit or delete stays in view through a catch-up.** When a catch-up brings in an item with its edges, the device lays its own waiting writes over them, as hydration does, instead of showing the server's version until the server answers.

## v0.0.17

Released October 20, 2026. [v0.0.17 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.17)

For running an instance:

- **A blob folder that has gone reads as down, not empty.** When the disk store's folder or its `.marfa-store` marker is missing, as on an unmounted drive, `GET /health` reports `blob_storage` as `down` with status `503`. [Deploy](/guides/deploy#keep-it-running) covers the health check.
- **Housekeeping passes over a store it can't reach.** `blob-integrity` strikes none of its copies, counts it in `unreachable` and still checks the stores it can reach, replication carries on past it, and `enrichment-sweep` doesn't count the attempt against the file.
- **A blob read answers `503 blob_store_unavailable` when no store returns the bytes** and a store that holds a copy can't answer, rather than `404 blob_not_found`. A restore that finds the disk store's marker missing, or naming another store, answers the same and writes nothing.
- **The bin purge keeps going through a backlog.** While items past the retention remain, `trash-purge` runs again at once instead of waiting for its interval. [Empty the bin](/guides/housekeeping#empty-the-bin) covers it.
- **A restore keeps an item as the archive holds it.** An item whose type the instance no longer registers, or that lacks a field its type later required, keeps its archived properties and `schema_version`; an item of a `core` or `system` type the build ships is still held to its shape. [Restore an archive](/guides/export-and-restore#restore-an-archive) covers it.
- **A restore keeps an edge whose edge type was force-deleted**, and no longer judges an end of a force-deleted type against the edge type's constraints. Such an edge is still skipped for the other reasons, such as a missing end.
- **An instance that holds such rows can be exported again.** An export no longer refuses them with `409 export_rows_unrestorable`.
- **A restore refuses an archive that lacks one of its four files.** An archive without `manifest.json`, `items.ndjson`, `edges.ndjson` or `types.ndjson` is refused `400 validation_error`, naming each missing entry in the message and in `details.entries`, where before it answered `200` with counts of zero.
- **An upload or a restore has no total time limit.** `MARFA_UPLOAD_IDLE_TIMEOUT_MS`, 60000 milliseconds unless set, ends one that receives no bytes for that long with `408 request_timeout`, and nothing is stored. [Every environment setting](/guides/settings#every-environment-setting) lists the setting.
- **A restore's recent sign-in is judged when it starts.** A restore that starts within five minutes of the owner's sign-in isn't refused for finishing later; an older session is refused `403 forbidden` at once, and one that ends during the upload gets `401 unauthorized`.
- **`marfa export --output` keeps the last whole archive.** When the new archive lacks blobs, the CLI leaves the file at the path, keeps the new archive beside it as `<path>.incomplete`, replacing only an earlier file of that name, and exits `1` with `blobs_missing`. The message says whether the path still holds an earlier file. If the CLI can't write that name, it keeps the archive in a hidden file beside the path and names it. [When an archive lacks a file's bytes](/guides/export-and-restore#when-an-archive-lacks-a-files-bytes) covers it.
- **Claiming in a browser signs the owner in.** A claim that carries the instance's own `Origin` leaves the browser signed in, which counts as a sign-in within the last five minutes, so adding a passkey needs no second prompt; a claim with no `Origin`, such as a script's, or a refused claim sets no session. [Claim the instance](/quickstart#claim-the-instance) covers it.
- **A failed sign-in after a claim leaves the owner claimed**, to sign in at the page that follows.
- **Setup runs as six steps:** the setup code, the owner's details, a passkey, a name for the instance, connecting, and backups.
- **The sign-in page says how long a lockout lasts.** When password sign-in or a device code lookup is refused for too many attempts, the page gives the wait in whole minutes, rounded up, and says that a passkey still signs in. [Troubleshooting](/guides/troubleshooting) covers it.
- **The sign-in page links to Forgot password,** at `/auth/forgot-password`, which gives the command that recovers the owner on the instance's machine. [Recover the owner's password](/guides/sign-in-as-the-owner#recover-the-owners-password) covers the command.

For apps and devices:

- **An export ends with an error when its credential ends.** If the key or app that started `GET /export` is revoked, expires, is disconnected, or is narrowed so it can't read what's left to send, the response ends with an error instead of ending cleanly, in both formats and while an archive sends a blob. A narrowing that takes away nothing left to send changes nothing. [What an export checks](/guides/export-and-restore#what-an-export-checks) covers it.
- **An archive export whose key is revoked before the response begins** gets `401 unauthorized`.

## v0.0.16

Released October 19, 2026. [v0.0.16 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.16)

For running an instance:

- **An archive export is checked against a restore before it's sent.** Marfa checks the whole archive as a restore into an empty instance does, so the archive restores into an empty instance of the same build without skipping an item or an edge. [What an export checks](/guides/export-and-restore#what-an-export-checks) covers it.
- **An export that fails the check is refused.** A row that fails twice without changing answers `409 export_rows_unrestorable`, named in `details.row`; a row or type that changed meanwhile, or a second read that refused a different row, answers `503 export_unrestorable`, so export again.
- **An export's temporary files count against `MARFA_DISK_RESERVE_BYTES`.**
- **Text that isn't well-formed UTF-16 is refused.** A string or property name with a lone surrogate, such as an emoji cut in the middle, is refused `400 validation_error`, and `details.errors[].path` names the text by its JSON pointer. A restore refuses an archive that holds one, and names the row. [Troubleshooting](/guides/troubleshooting) covers the refusal.
- **Text extracted from a file is never cut through a character.** It's cut at `MARFA_ENRICHMENT_MAX_TEXT_CHARS` UTF-16 code units.
- **The body checks apply whatever `Content-Type` a request states.** The UTF-16 check and the limit of 64 nested levels apply to every body except on `POST /blobs`, `POST /restore` and inbound webhooks.

For apps and devices:

- **Approving an app for more than reading needs a recent sign-in.** On the approval screen and the device approval screen, a browser signed in more than five minutes ago can approve reading only; for write access or a permission the app wasn't approved for before, Marfa asks the owner to sign in again and returns them to the screen. [Access](/access#what-the-owner-approves) covers it.
- **Revoking a key or disconnecting an app in a browser needs a recent sign-in** too. A key, an app token and the private socket aren't affected.
- **A write is judged by the key as it stands when it commits.** If a key is narrowed or revoked while one of its item writes waits, the write is refused with `403 type_not_permitted`, `404 item_not_found` when the key can no longer read the type, or `401 unauthorized`. This covers creating, updating, deleting, restoring, transitioning and purging an item. In a bulk write, an atomic page is refused and a best-effort entry is `errored`.
- **A device keeps its working copy when the server sends an answer it can't read.** A hydration, catch-up or follow whose answer or event isn't JSON ends with `decoding` and keeps the copy and its place in the event stream, where before the copy expired.
- **A stream cut in the middle of an event is an interruption.** A catch-up ends `stream_incomplete`, and a follow opens the stream again from its place.

Released October 11, 2026. [v0.0.7 on GitHub](https://github.com/withmarfa/marfa/releases/tag/v0.0.7)

For claiming and access:

- **A new instance is claimed once, by its owner.** Claim it with a setup code from the server's log, a single-use link opened in a browser, or `marfa --socket <path> setup claim` on the instance's own machine. [Claim the instance](/quickstart#claim-the-instance) covers it.

- **`--socket` gives the CLI the machine's own authority** through a private socket, for `setup`, making keys, restoring an archive and `owner recover`, which resets a lost owner password. [CLI](/cli) covers the socket.
- **A key can expire.** `marfa keys create` and `marfa keys update` set, change or clear an expiry, and an expired key is refused `401`, as a revoked one is. [Make a key expire](/guides/manage-keys#make-a-key-expire) covers it.
- **An app the owner connected stays signed in when the owner's browser session ends.**
- **Every app is shown as unverified** on the consent and sign-in pages.
- **An extension namespace is reached only through a key's extension map**, never through its label.
- **The owner can add passkeys**, and list, rename and end apps and keys beside browser sessions.
- **A browser session ends after a week without use**, and ending one leaves apps connected.
- **A device authorization request must name its scopes.**
- **A signed-in owner's approval has its own lookup limits**, apart from anonymous requests.

For running an instance:

- **A Railway template creates a personal instance** with persistent storage, HTTPS and daily backups. [Deploy](/guides/deploy) covers it.
- **An upload or a restore that would fill the disk is refused** with `507 insufficient_storage`, rather than failing later writes.
- **Text extraction from office documents is bounded**, so a large document can't exhaust the server's memory.
- **The server's diagnostics never carry values from the database.**
- **Only the sign-in routes Marfa uses answer under `/auth/`.**
- **Password changes count toward the sign-in limits.**
- **A restart recovers a stale private socket** left by a crash, and refuses to disrupt a live listener.
- **A restore keeps app-written records under `restored:` sources** and marks restored app connections revoked, keeping their history without reconnecting them.
- **A working copy checks that a changed address is the same instance** before it sends credentials.
- **Folder sync keeps empty frontmatter properties**, and defers deletion after an incomplete scan.

For the API and the CLI:

- **A transition into or out of the trash announces `item.deleted` or `item.restored`**, as a delete or a restore does.
- **The CLI warns once before it sends a credential over plain `http`** to a host other than this machine, and `--allow-http` says that's intended.
- **A device client that can't refresh its token is refused `offline_access`**, rather than approved without a refresh token.
- **Version history names the sign-in that wrote each version**, and carries a cursor to continue its pages. [History](/versions#history) covers it.
- **`POST /types/normalize` and `marfa types normalize` compare a candidate with its registered declared and resolved definitions** without writing it. [Change the type](/guides/define-a-type#change-the-type) covers it.
- **Unknown type and edge type schema keys are refused.**
- **A connector registration shows persistent problems apart from its state and runs.** A connector replaces or clears its problems under its hold.

Changes that need a change in your code:

For running an instance:

- **The archive export streams.**
- **A restore brings back items with their dates and history**, all or nothing.
- **`/health` reports a database, write path or disk that is down as a failure.**
- **A database from another build leaves the container running and unhealthy**, with the reason in its log, rather than restarting it.
- **The sign-in, consent and device approval pages work as they say.**
- **Every HTML page carries a content security policy.**

For devices and folders:

- **A search matches the same rows on the server and in a working copy.**

The [Swift SDK](/swift-sdk) is released from its own repository, and each release carries a build of Marfa's core.

### Swift SDK v0.0.24

Released October 21, 2026. [v0.0.24 on GitHub](https://github.com/withmarfa/marfa-swift/releases/tag/v0.0.24)

- **Builds against Marfa's core from after v0.0.20**, with `MarfaTypes` generated again from its API description. The `Marfa` API is unchanged.

### Swift SDK v0.0.23

Released October 20, 2026. [v0.0.23 on GitHub](https://github.com/withmarfa/marfa-swift/releases/tag/v0.0.23)

- **Builds against Marfa v0.0.18.**
- **`BlockedReason.failingAlone` is new.** A write set aside for failing alone is blocked with it, so an exhaustive `switch` over `BlockedReason` needs the case. [Devices](/devices#verdicts) explains the reason.
- **`QueuedWrite.lastFailure` and `environmentalStreak` are new.** `lastFailure` holds the status and the start of the text body of the last failure that wasn't an answer to the write, and `environmentalStreak` counts the drains in a row that met such a failure.
- **`Queue.withdraw(_:)` also takes a write blocked `failingAlone`**, and returns `false` instead of throwing `invalid` when the copy moved while it read the row from the server.
- **`WorkingCopy.open(store:server:)` throws `MarfaError.store` when it can't write the store's lock file.**

### Swift SDK v0.0.22

Released October 20, 2026. [v0.0.22 on GitHub](https://github.com/withmarfa/marfa-swift/releases/tag/v0.0.22)

- **Builds against Marfa's core from after v0.0.17.**
- **`MarfaTesting` is new.** `WorkingCopy.fake(items:itemTypes:)` gives tests and previews a working copy with no store, server or core.

### Swift SDK v0.0.21

Released October 18, 2026. [v0.0.21 on GitHub](https://github.com/withmarfa/marfa-swift/releases/tag/v0.0.21)

- **Builds against Marfa v0.0.13**, including its folder handover repair.
- **The generated types cover owner and delegated profile updates**, and accept the instance's display name as a string.
- **Optional nullable fields tell omission from an explicit `null`**, including profile avatars, key expiry, webhook filters and feed retention.

### Swift SDK v0.0.20

Released October 18, 2026. [v0.0.20 on GitHub](https://github.com/withmarfa/marfa-swift/releases/tag/v0.0.20)

- **Builds against Marfa v0.0.12**, including its working copy repair and owner passkey operations.
- **An app that uses `MemberImportVisibility` can use the SDK's aliased core types with only `import Marfa`.** The package exports those declarations one by one, so the SDK's own names stay unambiguous.
- **The generated wire types keep fields whose only JSON value is `null`.** An optional null-only field tells an absent key from an explicit `null`, and a non-null value is refused when decoded.

### Swift SDK v0.0.19

Released October 18, 2026. [v0.0.19 on GitHub](https://github.com/withmarfa/marfa-swift/releases/tag/v0.0.19)

- **Builds against Marfa v0.0.11**, so an app can read an edge type that no file writes from a server at v0.0.11 or later.
- **`EdgeType.writtenAt` is an `EdgeWrittenAt`**, with the cases `source`, `target` and `none`, in place of `EdgeEnd`. A `switch` over it needs a `.none` case.
- **`MarfaTypes` carries `RetentionPolicy`**, and its `written_at` takes `none`.

### Swift SDK v0.0.18

Released October 18, 2026. [v0.0.18 on GitHub](https://github.com/withmarfa/marfa-swift/releases/tag/v0.0.18)

- **Builds against Marfa v0.0.10.**
- **Properties, bodies and answers are JSON values, not text.** `Edit(properties:replaceProperties:baseVersion:)` replaces `Edit(.merge(_:))` and `Edit(.replace(_:))`, `declareTypes(_:)` takes `[JSONObject]`, and `QueuedWrite.answer` is a `JSONValue?`; the release on GitHub lists every change.
- **`Item.unreadableProperties` and `Edge.unreadableProperties` are new.** A row whose stored properties can't be read comes back with empty `properties` instead of failing the whole read.
- **A value the core can't hold is refused `invalid` before it's queued:** a number that isn't finite, a key that repeats in one object, or nesting deeper than the server reads.
- **`LiveQuery` is new.** It reads from the working copy and reads again when the copy changes, so a SwiftUI view stays current with no refresh code. [Swift SDK](/swift-sdk) covers it.
- **A held `changes()` stream drains after a drain left a write undelivered**, the next time the server is reached, and tells `.queueDrained`.
- **A follow that ends on the server's own answer after an outage tells `.serverReachable` before `.stopped`.**
