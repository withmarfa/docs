---
title: TypeScript SDK
description: Call your instance from TypeScript or JavaScript with a client that knows every operation, its parameters and its answers.
---

The TypeScript SDK is a thin, typed layer over the API for a script, a server or a web app. It's **generated from Marfa's API description**, so a path the API doesn't have, or a required parameter you leave out, doesn't compile.

The SDK keeps nothing between requests. An app that should keep working offline needs a [device](/devices), such as one built on the [Swift SDK](/swift-sdk).

## Install the SDK

The SDK is the npm package `@withmarfa/client`, an ES module:

```bash
npm install @withmarfa/client
```

## Create a client

Pass the URL your instance is served at and a credential: a key ([Manage keys](/run/manage-keys)) or an app's access token ([Authenticate](/build/authenticate)).

```ts title="client.ts"
import { createClient } from "@withmarfa/client";

export const marfa = createClient({
  baseUrl: process.env.MARFA_API_URL ?? "",
  credential: process.env.MARFA_API_KEY ?? "",
});
```

`baseUrl` is an `http` or `https` URL, and can include a path. **The client sends the credential only to URLs under `baseUrl` and never follows a redirect**, so the credential can't reach another server. `createClient` throws a `TypeError` for an empty credential or a `baseUrl` it can't use.

## Call an operation

Name an operation by its method and path, as the [API reference](/api-reference) lists it. Path parameters go in `params.path`, query parameters in `params.query`, and a JSON body in `body`. Each call returns `data` on success, `error` when the server refuses, and the `response`:

```ts
const { data, error } = await marfa.POST("/items", {
  body: { type: "core.note", properties: { title: "Reading list", body: "Start with the essays." } },
});
if (error) throw new Error(error.error.message);

const { data: detail } = await marfa.GET("/items/{id}", {
  params: { path: { id: data.item.id } },
});
```

Once you've checked `error`, TypeScript knows `data` holds the answer's shape.

## Walk every page of a list

A list or a search answers one page at a time, as `{ data, next_cursor }`. `pages` takes a function that fetches the page for a cursor, and yields every row, fetching each page as you reach it:

```ts
import { pages } from "@withmarfa/client";

const notes = pages(async (cursor) => {
  const { data, error } = await marfa.GET("/items", {
    params: { query: { type: "core.note", cursor } },
  });
  if (error) throw new Error(error.error.message);
  return data;
});

for await (const note of notes) {
  if ("id" in note) console.log(note.id, note.properties.title);
}
```

`pages` follows `next_cursor` until it's `null`. **A page can be short, or empty, and still have more after it**, so don't stop a walk early. The `"id" in note` check is there because a listing with `include=metadata` returns each item with its metadata instead.

## Upload a file

[Upload a blob](/api-reference/blobs/uploadBlob) takes a file's bytes, not JSON. Pass a `Blob`, an `ArrayBuffer`, a typed array such as a Node `Buffer`, or a `ReadableStream`, and name the file's type in `Content-Type`, which the instance keeps with the blob. Without it, the client sends a `Blob`'s own type, or `application/octet-stream`. The answer is the blob's hash, type and size:

<Terminal>

```ts
import { readFile } from "node:fs/promises";

const { data: blob, error } = await marfa.POST("/blobs", {
  body: await readFile("photo.png"),
  headers: { "Content-Type": "image/png" },
});
if (error) throw new Error(error.error.message);
console.log(blob);
```

```text
{
  hash: 'sha256:b1ff9c8ea3a780bad09b346c423d2d0e46815926879b18e841d928376a946640',
  mime_type: 'image/png',
  size_bytes: 69
}
```

</Terminal>

[Handle files](/build/handle-files) attaches the blob to an item.

## Handle errors

When the server refuses a request, `error` holds its error envelope, `{ error: { code, message } }`, with `details` where the refusal has them. **Write your logic against `code`**, because the wording of `message` can change. `response` has the status and headers, such as `Retry-After`. Reading an item that doesn't exist prints its status and code:

<Terminal>

```ts
const { error, response } = await marfa.GET("/items/{id}", {
  params: { path: { id: "01a12192-a000-76e3-b129-b55027e21dcb" } },
});
if (error) console.log(response.status, error.error.code);
```

```text
404 item_not_found
```

</Terminal>

[Errors](/api-reference/errors) lists every code. A call throws instead of returning `error` when there's no answer to read: the network failed, the URL is outside `baseUrl`, the server answered with a redirect, or the answer failed the contract check.

## The contract check

The SDK was generated for one version of Marfa's contract, which it exports as `CONTRACT_VERSION`. The server names its version on every answer, in the `X-Marfa-Contract` header. **If an answer names another version, or a success names none, the client throws `ContractMismatchError`** instead of reading a body it may not understand. Against a server on contract 1, it prints:

<Terminal>

```ts
import { ContractMismatchError } from "@withmarfa/client";

try {
  await marfa.GET("/items", { params: { query: { type: "core.note" } } });
} catch (thrown) {
  if (thrown instanceof ContractMismatchError) console.log(thrown.message);
  else throw thrown;
}
```

```text
The server answered with contract "1"; this client was generated for contract 0. Use a client generated for the server's contract.
```

</Terminal>

The fix is the `@withmarfa/client` release that matches your instance. An error answer with no header, such as one from a proxy in front of the server, comes back as `error` like any other.

## What the SDK doesn't do

The SDK sends what the API description declares and returns what the server answered. It doesn't retry a request (even one refused with `Retry-After`), poll a bulk job, read the event stream, verify a webhook's signature or resolve a version conflict. [Write safely](/build/write-safely), [Keep in sync](/build/keep-in-sync) and [Receive webhooks](/build/receive-webhooks) show how to do each with the API.
