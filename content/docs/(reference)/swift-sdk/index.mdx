---
title: Swift SDK
description: Give an iPhone, iPad or Mac app a working copy of an instance that reads offline, queues its writes and keeps itself current.
---

The Swift SDK is the `marfa-swift` package. **An app built on it is a [device](/build/devices)**: it keeps a working copy of part of an instance on the machine, reads it with or without a connection, and sends its writes when it reaches the server.

Use it for an app that must keep working offline. A script or a server needs no working copy: use the [TypeScript SDK](/typescript-sdk) or the [HTTP API](/api-reference). [Build an app with Swift](/build/swift-app) builds a SwiftUI app on the SDK, step by step.

## Install

The SDK supports iOS 27 and macOS 27 and builds with Xcode 27 on a Mac with Apple silicon. In Xcode, choose **File** > **Add Package Dependencies**, enter `https://github.com/withmarfa/marfa-swift`, and set **Dependency Rule** to **Up to Next Major Version**. In a `Package.swift`:

```swift title="Package.swift"
.package(url: "https://github.com/withmarfa/marfa-swift", from: "<latest release>"),
// in your target's dependencies:
.product(name: "Marfa", package: "marfa-swift"),
```

Replace `<latest release>` with the version of the [latest release](https://github.com/withmarfa/marfa-swift/releases/latest). **`from:` takes every later release below 1.0.0.**

- **Every release adds 0.0.1, whatever it changes.** A release can rename a call or add an enum case, so read the [release notes](https://github.com/withmarfa/marfa-swift/releases) before you update.
- **The SDK's enums are exhaustive.** Switch over them without `@unknown default`, so a case a later release adds stops the build where it must be handled.
- **Each release carries the core of one Marfa release,** already built, so the app needs no Rust toolchain. Keep the app and the instance on their newest releases.
- **The core is built for Apple silicon only.** In the app target's build settings, set **Excluded Architectures** for **Any iOS Simulator SDK** to `x86_64`, or some simulator builds fail to link.

## Products

| Product | Holds |
| --- | --- |
| `Marfa` | **The SDK:** the working copy, sign-in, server calls and folders. Add it to the app target. |
| `MarfaAPI` | `Client`, for the [operations the working copy doesn't make](/swift-sdk/server-calls#the-api-client), such as registering a type. It includes `MarfaTypes`. |
| `MarfaTypes` | The server's wire types, generated from the API description, and `marfaContractVersion`. |
| `MarfaTesting` | A [fake working copy](/swift-sdk/errors-and-testing#test-against-a-fake-copy) and a keychain and key store in memory. It compiles empty in a release build, so wrap its uses in `#if DEBUG`. |
| `MarfaIcons` | `TypeIcon`, which [draws a type's icon](/swift-sdk/server-calls#draw-a-types-icon). |
| `MarfaBrandIcons` | The brand marks a type's icon can name. An app that doesn't add it ships none of the artwork. |
| `MarfaTelemetry` | **Fixed-text error reports and log events** sent to a PostHog project the app names. It sends nothing until the app [turns it on](/swift-sdk/errors-and-testing#report-errors). |

## What the SDK decides

- **Marfa decides what things mean:** an item's name and preview, what a link points to, whether an edge is allowed, what a filter matches. The SDK passes on the answers of Marfa's core, so every app agrees.
- **The SDK does what every Swift app needs:** keeping the copy in step, retrying with back-off, sorting errors into kinds, keeping keys, reading dates and drawing icons.
- **The app decides the rest:** its screens, its words, and choices such as what to call an item with no name.
