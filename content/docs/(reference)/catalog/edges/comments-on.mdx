A comment is a **Comment on** one item, and that item lists its **Comments**. Each comment is on exactly one item, which can be another comment: a reply is a `comments-on` edge to the comment it answers.

## When to use it

Use `comments-on` for remarks people add to an item: a comment on a document, a review note on a pull request, a reply in a discussion.

Not for an item that's about another but stands alone, such as a review of a film: that's an [`about`](/catalog/edges/about) edge. Replies hang off comments with `comments-on`, never with [`parent-of`](/catalog/edges/parent-of).

## In the bin

A comment is a **part** of the item it's on, its **host**:

- It goes to the bin with its host, and so do the replies to it, at every depth. They come back when the host comes back, unless you binned them on their own.
- They're purged with the host.
- Removing the edge leaves both items where they are, and archiving a host changes nothing.

A chain of `comments-on` edges can't loop back to where it started: that write is refused with `400 edge_cycle`.

## Example

A reply to a comment:

```json
{
  "edge_type": "comments-on",
  "from_id": "01a1f139-e03c-735c-9ddf-83a546ebebb5",
  "to_id": "01a1f139-e038-76f6-a27c-0508bfc3ed4d"
}
```
