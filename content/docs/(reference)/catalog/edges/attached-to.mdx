An attachment lists what it's **Attached to**, and the item it belongs to lists its **Attachments**. Read from that item, the edge's reverse name is `has-attachment`. An item can be attached to any number of items, and `position` orders an item's attachments.

## When to use it

Use `attached-to` for an item that exists for another and means little without it: a scan for the document it was made for, a photo for the trip it was taken on, a receipt for an expense. Any type can be an attachment, though it's most often a file.

Not for an item that stands on its own. A file that another item only shows is a [`references`](/catalog/edges/references) edge, made by an embed such as `![[map.png]]`, and the file keeps its own life.

## In the bin

An attachment is a **part**, and the items it's attached to are its **hosts**:

- It goes to the bin when its last host does, and comes back when any host comes back. It doesn't come back if you binned it on its own.
- It's purged with its last host.
- Removing the edge leaves both items where they are, and archiving a host changes nothing.

`part eq true` in a [filter](/build/list-filter-search) finds parts.

## In a folder

A file can't hold frontmatter, so the document it's attached to writes the edge under the reverse name:

```yaml
has-attachment:
  - "[[receipt.pdf]]"
```

[Edit notes as files](/use/edit-notes-as-files) covers attachments in a folder.

## Example

A receipt attached to a task, first among its attachments:

```json
{
  "edge_type": "attached-to",
  "from_id": "01a1f139-e006-7509-a3f6-a953e29cdf67",
  "to_id": "01a1f139-dff2-7c08-9f4e-5b6a7d8e9f10",
  "properties": { "position": 1 }
}
```
