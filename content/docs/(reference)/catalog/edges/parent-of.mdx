A parent lists its **Children**, and a child its **Parent**. Read from the child, the edge's reverse name is `child-of`.

## The rules it holds

- **One parent.** A child has at most one parent, and a parent any number of children. A second parent is refused with `400 edge_constraint_violation`.
- **No loops.** An edge that would make an item its own ancestor is refused with `400 edge_cycle`.

## When to use it

Use `parent-of` where one item sits beneath another and belongs there: a subtask under its task, a page under its section, a directory inside a directory, a moved occurrence under its event series.

Use another type when the items stay themselves:

- Members of a reading list or an album are [`in-collection`](/catalog/edges/in-collection).
- Comments and replies are [`comments-on`](/catalog/edges/comments-on).

## In the bin

Moving a parent to the bin moves its children there too, at every depth, even children whose types the key can't read. Restoring the parent brings back the children its trip took, and leaves any child you binned before it. Binning a child leaves its parent.

## In a folder

The child's file writes the edge, under the reverse name:

```yaml
child-of: "[[Move house]]"
```

## Example

A task made a child of another:

```json
{
  "edge_type": "parent-of",
  "from_id": "01a1f139-e055-774a-a8a5-b20cdad1b4a3",
  "to_id": "01a1f139-e05b-7246-94b7-d9ff13926d57"
}
```
