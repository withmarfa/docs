An item lists what it **Supersedes**, and the earlier item what it's **Superseded by**.

## The rules it holds

- **One each way.** An item supersedes at most one item and is superseded by at most one, so versions form a single line. A second edge at either end is refused with `400 edge_constraint_violation`.
- **No loops.** An edge that would lead back to where the line started is refused with `400 edge_cycle`.

## When to use it

Use `supersedes` when a new item takes over from an old one and both are kept: a revised lease and the version it replaced, this year's policy and last year's.

Not for a summary or a copy made from an item, which is [`derived-from`](/catalog/edges/derived-from) it. Not for changes to one item, which Marfa keeps as the item's own [versions](/build/versions).

## In the bin

Either end can go to the bin, or be purged, and the other stays where it is.

## In a folder

The newer item's file writes the edge as a `supersedes` line.

## Example

A revised lease that replaces its draft:

```json
{
  "edge_type": "supersedes",
  "from_id": "01a1f139-e080-70c7-83d3-2a3f48a1eb00",
  "to_id": "01a1f139-e088-76db-afa2-16f1291328f6"
}
```
