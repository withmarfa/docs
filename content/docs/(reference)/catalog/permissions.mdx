A permission opens a group of operations, never items. What a credential reads and writes comes from its maps alone, except a restore: `backups.manage` brings back an archive's items, definitions and settings whatever the credential's maps hold ([`keys-and-oauth/permissions-no-content`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#keys-and-oauthpermissions-no-content)).

Each operation's page in the [API reference](/api-reference) names the permission and the type access it needs. `marfa keys create` gives a key a permission with `--permission`.

## The five maps

Each map names entries at a level. `write` includes `read`, and anything no entry covers is denied.

| Map | Field | CLI flag | Entries | Levels |
| --- | --- | --- | --- | --- |
| Type | `type_permissions` | `--type-permission` | A type ID, a subtree wildcard such as `core.media.*`, or `*` | `read`, `write`, `none` |
| Edge | `edge_permissions` | `--edge-permission` | An edge type, a namespace wildcard such as `user.*`, or `*` | `read`, `write` |
| Extension | `extension_permissions` | `--extension-permission` | An extension namespace, or `*` | `read`, `write` |
| Metadata | `metadata_permissions` | `--metadata-permission` | `types`, `edge_types`, or `*` for both | `read`, `write` |
| Profile | `profile_permissions` | `--profile-permission` | `name`, `email`, `avatar`, or `*` | `read`, `write` |

A flag takes an entry and its level, as `--metadata-permission types=write`.

- **Type map:** an exact entry decides before a wildcard, and a longer wildcard before a shorter. `none` shuts out a type that a wildcard would reach.
- **Metadata map:** registering types and edge types, never an item's tags or extensions.
- **Extension map:** a key's alone; an app reaches none.
- **Profile map:** `*` at `write` changes the name and the avatar, never the email. Only `email` at `write` changes the address that password sign-in matches.

A key made through the [private socket](/run/run-on-a-server#the-private-socket) with [Create a key](/api-reference/api-keys/createKey) naming nothing holds every permission and `*` at `write` in each map. `marfa --socket <path> keys create` refuses to name nothing: `--all-access` makes that key, and `--no-permissions` one that holds nothing.

## OAuth scopes

An app asks for the same reach as scopes. An app naming none is offered `content:read`, `content:write`, `edge.*:read`, `edge.*:write` and `offline_access`.

| Scope | Reach |
| --- | --- |
| `content:read`, `content:write` | Every type except those under `system.` and `marfa.` |
| `<type>:read`, `<type>:write` | A type or a pattern of types, `*` included |
| `edge.<edge type>:read`, `edge.<edge type>:write` | An edge type or a pattern of edge types |
| `metadata:<level>`, `metadata.types:<level>`, `metadata.edge_types:<level>` | The metadata map |
| `profile:<level>`, `profile.<field>:<level>` | Every profile field, or one; `profile:write` changes the name and the avatar |
| A permission, such as `audit.read` | That permission |
| `offline_access` | Refresh tokens |

[Access](/build/access) explains maps and permissions, and [Manage keys](/run/manage-keys) shows how to give a key its access.
