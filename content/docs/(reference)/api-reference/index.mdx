Everything an app, a script or a connector does with an instance goes through its HTTP API, and the CLI, the TypeScript SDK and the Swift SDK all send the same requests. This reference has a page for each operation, generated from the API description, so it always matches the server. Start here for how to send a request and the rules every operation shares, then open the operation you need.

## Operations by area

The operations fall into five areas: **Data** (items and everything attached to them), **Changes** (following what happens to them), **Access** (keys, apps and the owner), **Connectors** (what the instance keeps for each connector) and the **Instance** itself. Each area holds groups, one for each kind of thing an operation acts on, and each group lists its operations by method and path, in the order the sidebar shows them.

## Send a request

Send each request to your instance's address, such as `http://localhost:8600` for one on your own machine. Almost every operation takes a credential in the `Authorization` header: a key, which begins `marfa_k1_`, or an app's access token, which begins `marfa_at_`. [Access](/access) explains both, and [Manage keys](/run/manage-keys) shows how to make a key.

A request body is JSON, sent with `Content-Type: application/json`. This request creates a note:

```http title="Request"
POST /items HTTP/1.1
Host: localhost:8600
Authorization: Bearer <key>
Content-Type: application/json

{ "type": "core.note", "properties": { "title": "Reading list", "body": "Start with the essays." } }
```

Marfa answers `201 Created` with the new item and its metadata:

```json title="Response" status="201"
{
  "item": {
    "id": "01a1231c-986c-7edd-8d1f-235e036b7986",
    "type": "core.note",
    "state": "active",
    "tier": "library",
    "properties": { "body": "Start with the essays.", "title": "Reading list" },
    "created_at": "2026-10-10T00:00:39.021Z",
    "updated_at": "2026-10-10T00:00:39.021Z",
    "occurred_at": "2026-10-10T00:00:39.021Z",
    "version": 1,
    "schema_version": 0,
    "source": "laptop",
    "edges": {}
  },
  "metadata": { "item_id": "01a1231c-986c-7edd-8d1f-235e036b7986", "tags": [], "extensions": {} }
}
```

A refusal answers with an `error` object instead, which [Errors](/api-reference/errors) explains.
