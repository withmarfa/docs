Everything an app, a script or a connector does with an instance goes through its HTTP API, and the CLI, the TypeScript SDK and the Swift SDK all send the same requests. This reference has a page for each operation, generated from the API description, so it always matches the server. Start here for how to send a request and the rules every operation shares, then open the operation you need.

## Send a request

Send each request to your instance's address, such as `http://localhost:8600` for one on your own machine. Almost every operation takes a credential in the `Authorization` header: a key, which begins `marfa_k1_`, or an app's access token, which begins `marfa_at_`. [Access](/access) explains both, and [Manage keys](/run/manage-keys) shows how to make a key.

A request body is JSON, sent with `Content-Type: application/json`. This request creates a note:

```http title="Request"
POST /items HTTP/1.1
Host: localhost:8600
Authorization: Bearer <key>
Content-Type: application/json

{ "type": "core.note", "properties": { "title": "Reading list", "body": "Start with the essays." } }
```

Marfa answers `201 Created` with the new item and its metadata:

```json title="Response" status="201"
{
  "item": {
    "id": "01a1231c-986c-7edd-8d1f-235e036b7986",
    "type": "core.note",
    "state": "active",
    "tier": "library",
    "properties": { "body": "Start with the essays.", "title": "Reading list" },
    "created_at": "2026-10-10T00:00:39.021Z",
    "updated_at": "2026-10-10T00:00:39.021Z",
    "occurred_at": "2026-10-10T00:00:39.021Z",
    "version": 1,
    "schema_version": 0,
    "source": "laptop",
    "edges": {}
  },
  "metadata": { "item_id": "01a1231c-986c-7edd-8d1f-235e036b7986", "tags": [], "extensions": {} }
}
```

A refusal answers with an `error` object instead, which [Errors](/api-reference/errors) explains.

## Groups of operations

The reference groups operations by what they act on. The groups and the operations in each follow the order of the API description, and "Start with" is each group's first operation:

| Group | What it's for | Start with |
| --- | --- | --- |
| Items | The records Marfa stores, each of a type, and the ways to read and change them | [Create an item](/api-reference/items/createItem) |
| Trash | Items in the bin: list them, move an item in, and restore, purge or empty them | [List the trash](/api-reference/trash/listTrash) |
| Bulk actions | One change applied to every item a filter matches, run as a job you can follow and cancel | [Apply a bulk action](/api-reference/bulk-actions/applyBulkAction) |
| Metadata | An item's tags and extensions together, and the tags in use | [Get item metadata](/api-reference/metadata/getItemMetadata) |
| Extensions | JSON objects attached to an item, one per namespace | [Get an extension namespace](/api-reference/extensions/getItemExtension) |
| Edges | Typed, directed relationships between items | [Create an edge](/api-reference/edges/createEdge) |
| Search | Full-text search across items | [Search items](/api-reference/search/searchItems) |
| Types | The types items can have: those Marfa ships and those registered on this instance | [Register a type](/api-reference/types/registerType) |
| Edge types | The types edges can have, each with its labels, cardinality and cascade rule | [Register an edge type](/api-reference/edge-types/registerEdgeType) |
| Blobs | Bytes stored by content hash, and the stores that hold them | [Upload a blob](/api-reference/blobs/uploadBlob) |
| Event stream | Changes to items and edges, streamed as they happen | [Stream change events](/api-reference/event-stream/streamEvents) |
| Webhooks | Changes sent to a URL you choose, and each delivery's record | [Create a webhook](/api-reference/webhooks/createWebhook) |
| Folders | A folder's settings, held as a `system.folder` item | [Create a folder](/api-reference/folders/createFolder) |
| Views | Saved lists of items with their sort and grouping, held as `system.view` items | [Create a view](/api-reference/views/createView) |
| Connectors | Processes outside the server that read and write on your behalf, with their heartbeats and runs | [Register a connector](/api-reference/connectors/registerConnector) |
| Connector state | What the instance keeps for a connector's source: its hold, its state and its agreements | [Take a connector hold](/api-reference/connector-state/takeConnectorHold) |
| Inbound webhooks | Addresses where a service sends requests to a connector, and the deliveries Marfa stores for it | [Create an inbound endpoint](/api-reference/inbound-webhooks/createInboundEndpoint) |
| API keys | The keys that authenticate requests to this instance, and the permissions each holds | [Create an API key](/api-reference/api-keys/createKey) |
| Apps | Apps that register as OAuth clients, and the access the owner grants them | [Register an OAuth client](/api-reference/apps/registerOAuthClient) |
| Owner | The instance's owner and their profile | [Claim the instance](/api-reference/owner/createOwner) |
| Sign-ins and passkeys | The browsers, apps and keys that can reach the instance, and the owner's passkeys | [List sign-ins](/api-reference/sign-ins-and-passkeys/listSignIns) |
| Instance | The instance itself: what it is, how it's configured and what a credential can reach | [Get the instance](/api-reference/instance/getInstance) |
| Health and maintenance | How the instance is doing: what needs attention, its metrics and audit log, its housekeeping jobs and its retired platform types | [List attention items](/api-reference/health-and-maintenance/listAttention) |
| Export and restore | Export the instance's data, and restore it from an archive | [Export an archive](/api-reference/export-and-restore/exportArchive) |
