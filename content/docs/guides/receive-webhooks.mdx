---
title: Receive webhooks
description: Register a webhook, check that each delivery came from your instance, and handle repeats, deliveries that arrive out of order, retries and failed deliveries.
---

A webhook lets a service react to changes in your instance without holding a connection open: you register a URL, and Marfa posts each event you chose to it as it happens. [Events and webhooks](/events) explains when to use a webhook rather than the event stream.

You need a credential with the `webhooks.manage` permission. **The webhook belongs to that key, or to the app that registered it**: Marfa sends it nothing once the key is revoked or expires, and deletes it when the app's access is revoked.

## Register a webhook

[Create a webhook](/api-reference/webhooks/createWebhook) takes the `url` to post to and the `events` you want, such as `item.created`, from the [events](/catalog/events). **There's no wildcard: name each event.** `type_filter` limits item events to one type and its subtypes, and leaves edge events as they are.

```bash tab="CLI" tab-group="client"
marfa webhooks create --to https://example.com/marfa \
  --event item.created --event item.updated --type-filter core.note
```

```http tab="HTTP"
POST /webhooks
Authorization: Bearer <key>
Content-Type: application/json

{
  "url": "https://example.com/marfa",
  "events": ["item.created", "item.updated"],
  "type_filter": "core.note"
}
```

```ts tab="TypeScript"
const { data: webhook, error } = await marfa.POST("/webhooks", {
  body: {
    url: "https://example.com/marfa",
    events: ["item.created", "item.updated"],
    type_filter: "core.note",
  },
});
if (error) throw new Error(error.error.message);
```

Marfa answers with the webhook, its `secret` included:

```json
{
  "id": "01a12329-ce8c-7a1a-868c-a9cc85b6b7b2",
  "url": "https://example.com/marfa",
  "secret": "dfaa1787b11d7e7223ac25bf0951c25b70f3985d5b737d8943eb03d2279d06a7",
  "events": ["item.created", "item.updated"],
  "type_filter": "core.note",
  "active": true,
  "created_at": "2026-10-10T00:15:04.844Z",
  "updated_at": "2026-10-10T00:15:04.844Z"
}
```

**This is the only time Marfa shows the secret.** Every later read shows `****` and its last four characters. Keep it where your receiver can read it and nothing else can, as you would a password.

To use a secret of your own instead, send `secret` with at least 32 characters.

The webhook receives events written after you registered it, and **nothing earlier**.

## Check each delivery

A delivery is a `POST` whose body is the event, as the stream would send it, with three more members: `event_id`, the event's ID in the log; `delivery_id`, which stays the same on every attempt to deliver this event; and `delivered_at`, when Marfa sent this attempt. Here's one, as it arrives:

```http
POST /marfa
Content-Type: application/json
X-Marfa-Event-Type: item.updated
X-Marfa-Signature: t=1791591307,v1=80bc920e57a1e1bee2f839cc2d8eb62841069e5da0e5bc242c39e3c6952ddd2c

{"item":{"id":"01a12329-d2ca-71a2-871d-772152cdb003","type":"core.note","state":"active","tier":"library","properties":{"body":"Start with the essays, then the letters.","title":"Reading list"},"created_at":"2026-10-10T00:15:05.930Z","updated_at":"2026-10-10T00:15:05.957Z","occurred_at":"2026-10-10T00:15:05.930Z","version":2,"source":"laptop","schema_version":0},"metadata":{"item_id":"01a12329-d2ca-71a2-871d-772152cdb003","tags":[],"extensions":{}},"event_type":"item.updated","event_id":"252","delivery_id":"01a12329-d546-703a-8b86-845703c6e005","delivered_at":"2026-10-10T00:15:07.573Z"}
```

Anyone can post to your URL, so **check `X-Marfa-Signature` before you trust a delivery**. It reads `t=<unix seconds>,v1=<hex>`, where `v1` is the HMAC-SHA-256, under your secret, of `t`, a period, and the raw body. **Compute it over the bytes exactly as they arrived**: parsing the JSON and serializing it again changes them.

This receiver uses only Node.js's own modules, and Node.js 22.18 or later runs it as it is. It checks the signature, refuses one older than five minutes so a captured delivery can't be replayed later, and answers before it does any work:

```ts title="receiver.ts"
import { createHmac, timingSafeEqual } from "node:crypto";
import { createServer } from "node:http";

const secret = process.env.MARFA_WEBHOOK_SECRET!;
const handled = new Set<string>(); // keep this in your database

export function verifySignature(
  rawBody: Buffer,
  header: string | undefined,
  secret: string,
  toleranceSeconds = 300,
): boolean {
  if (header === undefined) return false;
  const parts = Object.fromEntries(header.split(",").map((part) => part.trim().split("=", 2)));
  const { t, v1 } = parts;
  if (!/^\d+$/.test(t ?? "") || typeof v1 !== "string") return false;
  if (Math.abs(Date.now() / 1000 - Number(t)) > toleranceSeconds) return false;

  const expected = createHmac("sha256", secret).update(`${t}.`).update(rawBody).digest("hex");
  return v1.length === expected.length && timingSafeEqual(Buffer.from(v1), Buffer.from(expected));
}

createServer((request, response) => {
  const chunks: Buffer[] = [];
  request.on("data", (chunk: Buffer) => chunks.push(chunk));
  request.on("end", () => {
    const rawBody = Buffer.concat(chunks);
    const signature = request.headers["x-marfa-signature"];
    if (!verifySignature(rawBody, typeof signature === "string" ? signature : undefined, secret)) {
      response.writeHead(401).end();
      return;
    }

    const delivery = JSON.parse(rawBody.toString("utf8"));
    response.writeHead(204).end();
    if (handled.has(delivery.delivery_id)) return; // a repeat
    handled.add(delivery.delivery_id);

    console.log(delivery.event_type, delivery.item?.id);
  });
}).listen(3000);
```

```bash
MARFA_WEBHOOK_SECRET=<the secret> node receiver.ts
```

Marfa signs every attempt afresh, with its own `t`, so a retry of an old event still passes the five-minute check.

## Answer, and recognize a repeat

Answer with a `2xx` status, and **answer quickly**: do slow work after you've answered, or in a queue. Marfa can deliver the same event more than once, such as when your answer was lost on the way back, and **every attempt carries the same `delivery_id`**. Record the IDs you've handled, as the receiver above does, and ignore one you've seen.

## Expect deliveries out of order

**Marfa doesn't deliver events in the order they happened.** It sends waiting deliveries at the same time, and it retries a failed one later while newer events go through, so the delivery for an item's second update can arrive before the one for its first.

Each delivery's `event_id` is the event's ID in the log, and IDs rise with every event. It's a string of decimal digits, so compare IDs as numbers: as text, `"99"` sorts after `"252"`. Keep the highest `event_id` you've applied for each item and **ignore a delivery with a lower one**. Alternatively, treat a delivery as a prompt and [get the item](/api-reference/items/getItem) again, which always shows its current state.

## When a delivery fails

Marfa tries a delivery again when your receiver can't be reached, doesn't answer in time, or answers `5xx`, `408` or `429`. It waits longer before each attempt, starting at a second, and **makes eight attempts over about five hours**; a `Retry-After` header asks it to wait longer, up to five minutes. **Any other `4xx`, or a redirect, ends the delivery at once.**

A delivery Marfa gives up on is `dead_letter`. That's why the receiver above answers `401` for a bad signature: if you've configured the wrong secret, Marfa stops at once rather than retrying for hours, and you can send the deliveries again once you've fixed it.

[List webhook deliveries](/api-reference/webhooks/listWebhookDeliveries) shows each delivery, newest first, with its `status` and the last answer your receiver gave:

```bash tab="CLI" tab-group="client"
marfa webhooks deliveries 01a12312-401e-7331-a4dc-9096bb32ac1d --json
```

```http tab="HTTP"
GET /webhooks/01a12312-401e-7331-a4dc-9096bb32ac1d/deliveries
Authorization: Bearer <key>
```

```ts tab="TypeScript"
const { data: deliveries } = await marfa.GET("/webhooks/{id}/deliveries", {
  params: { path: { id: webhook.id } },
});
```

```json
{
  "data": [
    {
      "id": "01a12312-90a8-7828-a95e-475fe680baeb",
      "webhook_id": "01a12312-401e-7331-a4dc-9096bb32ac1d",
      "event_type": "item.updated",
      "status_code": 400,
      "attempt": 1,
      "status": "dead_letter",
      "succeeded": false,
      "error": "HTTP 400",
      "created_at": "2026-10-09T23:49:41.672Z"
    }
  ],
  "next_cursor": null
}
```

[Redeliver a failed delivery](/api-reference/webhooks/redeliverWebhookDelivery) sends a `dead_letter` delivery again, to the webhook's current URL and signed with its current secret, with the same `delivery_id`. It answers the delivery as `pending`, and Marfa sends it shortly after:

```bash tab="CLI" tab-group="client"
marfa webhooks redeliver 01a12312-401e-7331-a4dc-9096bb32ac1d 01a12312-90a8-7828-a95e-475fe680baeb
```

```http tab="HTTP"
POST /webhooks/01a12312-401e-7331-a4dc-9096bb32ac1d/deliveries/01a12312-90a8-7828-a95e-475fe680baeb/redeliver
Authorization: Bearer <key>
```

```ts tab="TypeScript"
await marfa.POST("/webhooks/{id}/deliveries/{delivery_id}/redeliver", {
  params: { path: { id: webhook.id, delivery_id: "01a12312-90a8-7828-a95e-475fe680baeb" } },
});
```

**Only a `dead_letter` delivery can be sent again**; any other answers `409 conflict`. A delivery's record is kept for as long as the instance keeps its audit log.

## Receive deliveries on your own machine

By default, **Marfa posts only to public addresses**, and refuses a webhook whose URL is `localhost` or a private address. To try a receiver on your own machine, start a development instance with `MARFA_WEBHOOK_ALLOW_PRIVATE_ADDRESSES=true`, register `http://localhost:3000/marfa`, and run the receiver above. **Leave the setting off on an instance you keep**, unless its receivers run on a private network: [Settings](/guides/settings) describes it.

The rules behind this guide are in the [events](https://github.com/withmarfa/marfa/blob/main/conformance/spec/events.md) chapter of the contract.
