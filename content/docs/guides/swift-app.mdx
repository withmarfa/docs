This tutorial builds a reading-list app in SwiftUI. It lists notes from an instance, adds and renames them, keeps working with no connection, and follows the instance as other devices change it. [Devices and folders](/get-started/devices-and-folders) explains the working copy and the queue the app uses, and the [Swift package](/tools/swift-package) page is the reference for every call.

You need:

- An instance you can reach, and the owner's sign-in to it. See [Run an instance](/get-started/run-an-instance).
- The [`marfa` command](/tools/marfa-command), to mint a key.
- A Mac with Apple silicon and Xcode 27. The package supports iOS 27 and macOS 27.

## Create the project

1. In Xcode, choose File > New > Project, pick the Multiplatform tab and the App template, and name the app `ReadingList`. If the template sets an older deployment target, set iOS and macOS to 27.
1. Choose File > Add Package Dependencies, and enter `https://github.com/withmarfa/marfa-swift`. Choose Exact Version and enter `0.0.8`. Each release adds 0.0.1 to the version whatever the change, so pin one version and move to a newer one on purpose. Add the `Marfa` product to the app target.
1. The core is built for arm64 only. In the target's build settings, set Excluded Architectures for Any iOS Simulator SDK to `x86_64`.
1. In the macOS target's Signing & Capabilities, turn on Outgoing Connections (Client) under App Sandbox, so the app can reach the instance.

## Mint a key for the app

An app reaches an instance with a key that holds only what the app needs. Sign in as the owner, then mint a key that reads and writes notes and nothing else:

```bash
marfa login --url https://marfa.example
marfa keys create --label "Reading list" --source app.readinglist --type-permission core.note=write --default-tier library
```

The key holds exactly what the flags name. `--source` is the key's own source, which each row written under the key is stamped with, and a source belongs to one key, so a second key needs another. `--default-tier library` lands a write that names no tier in `library`. [Keys and permissions](/get-started/keys-and-permissions) explains what a key can hold.

The answer carries the key. Copy it now: Marfa [shows a key's plaintext only once](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#keys-and-oauthplaintext-once).

## Open the working copy

The app keeps its state in one observable class. Create `ReadingList.swift` and add this. The next four sections add to it, inside the class, so the project builds again after the last one.

```swift
import Foundation
import Marfa
import Observation

@MainActor @Observable
final class ReadingList {
    private(set) var notes: [Item] = []
    private(set) var writes: [QueuedWrite] = []
    private(set) var isOnline = true
    private(set) var needsKey = false
    private(set) var message = ""
    private var copy: WorkingCopy?

    var isConnected: Bool { copy != nil && !needsKey }

    func resume() async {
        guard let address = UserDefaults.standard.string(forKey: "server"), let url = URL(string: address),
            let key = try? Keychain.system.key(service: "app.readinglist", account: address)
        else { return }
        await connect(url: url, key: key)
    }

    func signIn(address: String, key: String) async {
        guard let url = URL(string: address) else {
            message = "That isn't an address."
            return
        }
        do {
            try Keychain.system.save(key: key, service: "app.readinglist", account: address)
            UserDefaults.standard.set(address, forKey: "server")
            if let copy {
                try await copy.useKey(key)
                needsKey = false
                await bringUpToDate()
            } else {
                await connect(url: url, key: key)
            }
        } catch {
            message = error.localizedDescription
        }
    }

    func connect(url: URL, key: String) async {
        do {
            let folder = URL.applicationSupportDirectory.appending(path: "ReadingList", directoryHint: .isDirectory)
            try FileManager.default.createDirectory(at: folder, withIntermediateDirectories: true)
            let copy = try await WorkingCopy.open(
                store: folder.appending(path: "notes.sqlite"), server: Server(url: url, key: key))
            self.copy = copy
            needsKey = false
            await refresh()
            await bringUpToDate()
            follow(copy)
        } catch {
            message = error.localizedDescription
        }
    }
}
```

`WorkingCopy.open(store:server:)` opens the working copy's store, a SQLite file, and makes it if it isn't there. It reads nothing from the instance. `Server(url:key:)` names the instance and the key. The copy holds the key in memory and never writes it to the store, so the app keeps the key in the keychain with `Keychain.system` and the address in `UserDefaults`. `useKey(_:)` gives an open copy a new key.

## Hydrate the copy and read it

A new copy holds nothing. `hydrate(types:tier:)` declares its slice, here every `core.note` in the `library` tier, and fills the copy from the instance. After that, `catchUp()` applies only what changed since. Add these:

```swift
    func refresh() async {
        guard let copy else { return }
        do {
            notes = try await copy.items.list(ListFilters(type: "core.note"))
            writes = try await copy.queue.all()
        } catch {
            message = error.localizedDescription
        }
    }

    func bringUpToDate() async {
        guard let copy else { return }
        do {
            if try await copy.status().hydration == .complete {
                _ = try await copy.catchUp()
            } else {
                _ = try await copy.hydrate(types: ["core.note"], tier: .library)
            }
            await send()
        } catch {
            await handle(error)
        }
    }
```

`status().hydration` says which call to make: `.complete` means the copy holds its slice, and `.never`, `.inProgress` and `.expired` mean it needs a hydration. Nothing runs on its own, so the app decides when to call each.

`refresh()` reads the notes and the queue from the copy and makes no request, so it works with no connection.

## Write a change

Add the calls that write, and the one that sends:

```swift
    func add(title: String) async {
        await write { copy in
            _ = try await copy.items.create(
                Draft(type: "core.note", properties: ["title": .string(title), "body": ""]))
        }
    }

    func rename(_ note: Item, to title: String) async {
        await write { copy in
            _ = try await copy.items.update(
                note.id, Edit(.merge(["title": .string(title)]), baseVersion: note.version))
        }
    }

    private func write(_ work: (WorkingCopy) async throws -> Void) async {
        guard let copy else { return }
        do {
            try await work(copy)
            await refresh()
            await send()
        } catch {
            await handle(error)
        }
    }

    private func send() async {
        guard let copy else { return }
        do {
            let report = try await copy.queue.drain()
            if report.unavailable != nil {
                isOnline = false
            } else if report.answered > 0 {
                isOnline = true
            }
            if report.stopped != nil {
                needsKey = true
                message = "The instance refused the key."
            }
            for answer in report.verdicts {
                switch answer.verdict {
                case .merged(let fields): message = "Merged \(fields.joined(separator: ", ")) with a newer change."
                case .conflicted: message = "Someone else changed the same text. Your version is kept in a copy."
                case .refused(let refusal): message = "Refused: \(refusal.message ?? refusal.reason)"
                default: break
                }
            }
            _ = try await copy.queue.forgetAnswered()
        } catch {
            await handle(error)
        }
        await refresh()
    }
```

`items.create` and `items.update` return at once. The change shows in the copy, and the write waits in the queue. An `Edit` names the `baseVersion` the app read, so the instance can tell whether the note has changed since, and `.merge` replaces only the properties it names.

`queue.drain()` sends the queue in order and reports what the instance answered. If the instance can't be reached, the report says `unavailable` and the writes stay queued. Each answer is a verdict, and the app tells the person about the three that need telling: `merged`, `conflicted` and `refused`. [What a verdict is](/get-started/devices-and-folders#what-a-verdict-is) covers all six. `forgetAnswered()` then clears the writes that were answered. What stays is what hasn't been: writes not sent yet, and writes the instance refused, blocked or gave up on. The screen lists them.

## Keep the copy in step

A held `changes()` stream tells the app about every change to the copy, whether the app wrote it or the instance did. Add the last two functions:

```swift
    private func handle(_ error: Error) async {
        switch error as? MarfaError {
        case .network, .server, .rateLimited, .unnamed:
            isOnline = false
        case .copyExpired:
            _ = try? await copy?.hydrate(types: ["core.note"], tier: .library)
            await send()
        case .unauthorized, .signedOut:
            needsKey = true
            message = "The instance refused the key."
        default:
            message = error.localizedDescription
        }
        await refresh()
    }

    private func follow(_ copy: WorkingCopy) {
        Task { [weak self] in
            for await change in copy.changes() {
                guard let self else { return }
                switch change.origin {
                case .serverUnreachable:
                    isOnline = false
                case .serverReachable:
                    isOnline = true
                    await send()
                case .stopped(let error):
                    await handle(error)
                default:
                    break
                }
                await refresh()
            }
        }
    }
```

`.serverUnreachable` and `.serverReachable` tell the app when the instance goes away and comes back, and a drain on the second sends what waited. `.stopped` means the stream can't go on without the app's help. A `copyExpired` stream needs a new hydration. The log may have moved past the copy, or another instance may answer at the address. `unauthorized` and `signedOut` need a new key. `handle(_:)` gives errors from a call the same treatment. The queue survives all three.

## Build the screens

Replace the contents of `ReadingListApp.swift` with the app and its connect screen:

```swift
import SwiftUI

@main
struct ReadingListApp: App {
    @State private var list = ReadingList()

    var body: some Scene {
        WindowGroup {
            Group {
                if list.isConnected {
                    ContentView(list: list)
                } else {
                    ConnectView(list: list)
                }
            }
            .task { await list.resume() }
        }
    }
}

struct ConnectView: View {
    let list: ReadingList
    @State private var address = ""
    @State private var key = ""

    var body: some View {
        Form {
            TextField("Instance address", text: $address)
            SecureField("Key", text: $key)
            Button("Connect") { Task { await list.signIn(address: address, key: key) } }
            Text(list.message).foregroundStyle(.secondary)
        }
    }
}
```

Then replace the contents of `ContentView.swift` with the list of notes, the queue and the offline notice:

```swift
import Marfa
import SwiftUI

struct ContentView: View {
    @Bindable var list: ReadingList
    @State private var newTitle = ""

    var body: some View {
        NavigationStack {
            List {
                if !list.isOnline {
                    Label("Offline. Changes are saved here and sent later.", systemImage: "wifi.slash")
                }
                Section {
                    TextField("Add a note", text: $newTitle)
                        .onSubmit {
                            let title = newTitle
                            newTitle = ""
                            if !title.isEmpty { Task { await list.add(title: title) } }
                        }
                    ForEach(list.notes) { note in
                        NoteRow(list: list, note: note)
                    }
                }
                if !list.writes.isEmpty {
                    Section("Waiting to send") {
                        ForEach(list.writes, id: \.id) { write in
                            Text("\(String(describing: write.kind)): \(describe(write))")
                        }
                    }
                }
            }
            .navigationTitle("Reading list")
            .refreshable { await list.bringUpToDate() }
            .safeAreaInset(edge: .bottom) {
                Text(list.message).font(.caption).foregroundStyle(.secondary).padding(4)
            }
        }
    }

    private func describe(_ write: QueuedWrite) -> String {
        switch write.verdict {
        case nil: write.waiting ? "waiting for an earlier change" : "not sent yet"
        case .refused(let refusal): "refused, \(refusal.message ?? refusal.reason)"
        case .blocked(let reason, _): "stopped, \(String(describing: reason))"
        default: "gave up"
        }
    }
}

struct NoteRow: View {
    let list: ReadingList
    let note: Item
    @State private var title: String

    init(list: ReadingList, note: Item) {
        self.list = list
        self.note = note
        _title = State(initialValue: note.title ?? "")
    }

    var body: some View {
        TextField("Title", text: $title)
            .onSubmit { Task { await list.rename(note, to: title) } }
            .onChange(of: note.version) { title = note.title ?? "" }
    }
}
```

## Run the app

Run the app on macOS or an iOS simulator. Enter the instance's address and the key, and choose Connect. The list is empty. Add a note: it appears at once. [List items](/api-reference/items/listItems) shows that it reached the instance:

```http
GET /items?type=core.note
Authorization: Bearer <credential>
```

Quit and open the app. It shows the notes from its copy first, then catches up.

## Work with no connection

Stop the instance, or turn off the network. Add a note. It appears in the list, the app says it's offline, and the queue section shows the write as not sent yet. Start the instance again. When the stream reconnects, the app sends the write and the queue section empties.

## See a verdict

1. Stop the instance, rename a note you haven't renamed before, and quit the app. The rename is in the queue, and the queue survives the quit.
1. Start the instance. Change the same note's title as another device would, with [Update an item](/api-reference/items/updateItem). The note is still at version 1, so the request names it:

   ```http
   PATCH /items/{id}
   Authorization: Bearer <credential>
   Content-Type: application/json

   { "version": 1, "properties": { "title": "Changed elsewhere" } }
   ```

1. Open the app. It sends the rename, and the app says "Merged title with a newer change." Both writes changed `title`, and `core.note` keeps the last writer's title, so the instance applies the app's write over the newer version and answers `merged`.
