title: Files in a folder
description: See what a file holds when a folder writes an item as a file, where attached files go, and how an edit on either side reaches the other.
---

A folder writes each item as a file and reads a changed file back as an edit. The examples follow the `Notes` folder made in [Sync a folder](/guides/sync-a-folder).

## How items appear as files

A note is a Markdown file named after its title, or after its ID if it has none. Here's `Reading list.md`:

```markdown title="Notes/Reading list.md"
---
type: core.note
tier: library
title: Reading list
marfa_id: 01a1232d-947e-7399-86e1-97648a87c232
marfa_version: 1
---
Start with the essays, then the letters.
```

The lines between the `---` fences are the frontmatter. The text after them is the body.

- **`type`:** the item's type when the value is a Marfa type identifier. A value that is not a type identifier belongs to the item's `type` property instead and survives writing the file back.
- **`tier`, `tags`, `state` and `occurred_at`:** the item's own fields.
- **A line named after an edge type,** such as `references`: an edge.
- **Every other line:** a property.
- **`marfa_id` and `marfa_version`:** the item and the version the file was written from. Leave them to Marfa.

A new Markdown file needs no frontmatter. It takes its type and tier from the folder's `defaults` or its query, and its title from `defaults` or, without one, its file name. With `query.tier: all`, a new file without an explicit tier uses `defaults.tier` or, without one, `library`. Once the instance creates the item, Marfa writes the frontmatter and `marfa_id` into the file.

A `.txt` file is all body. Any other file the query admits, such as a photo, becomes a file item with its bytes uploaded as a blob, as [Handle files](/guides/handle-files) describes. A file item stays a file item at a `.md`, `.markdown` or `.txt` name, such as after a pull places it there or you rename it: its bytes go to the item as they are, and Marfa doesn't read them as a note.

## Files attached to a note

**Every file attached to a note the folder holds is written with the note**, whether or not the query names its type. A file the note's body embeds, such as `![](photos/map.png)` or `![[map.png]]`, is written where the link says. Every other attached file is written beside the note and listed under its `has-attachment` line:

```markdown title="Notes/Packing for the trip.md"
---
type: core.note
tier: library
title: Packing for the trip
has-attachment:
  - "[[map.png]]"
marfa_id: 01a1232d-94b0-7c1e-9d2a-3f6b8e0c5a71
marfa_version: 2
---
Pack light.
```

- **It follows the note.** Move the note to another directory and the next sync moves the file beside it. A file you move away from its note goes back beside the note; to keep it somewhere else, embed it by its path.
- **One file, one place.** A file attached to notes in two directories is written once, beside the first note in path order, and the sync reports the other note. Two attached files with the same name are told apart by a number.
- **Another folder keeps its own copy.** If another folder on the same Mac holds the file through its own query, each folder keeps a copy, and neither takes the other's. When a note leaves one folder's query for another's, its attached files move with it.
- **It leaves with the note.** When every note it's attached to goes to the bin or leaves the states the query holds, the file goes too, under the same [safeguards](/guides/folder-safeguards) as any other. If the query holds the file itself, it stays.
- **Remove the line, keep the file.** Take a file out of `has-attachment` and the next sync removes the `attached-to` edge. The file stays in the folder as one it no longer holds.

The folder reads attached files with its key, so the key needs read on their types, such as `core.file.*` in [the key you made for the folder](/guides/sync-a-folder#make-a-key-for-the-folder). A file whose bytes the folder can't fetch is reported, and the sync goes on.

## Edit on either side

Edit a file and sync, and the edit reaches its item:

<Terminal>

```bash
marfa folders push Notes
```

```text
0 created, 1 updated, 0 renamed, 2 unchanged, 0 missing, 0 deleted, 0 skipped
the server answered 1 write(s)
1 file(s) written
```

</Terminal>

An edit is a write based on the `marfa_version` the file names. If another app changed the same note meanwhile, the instance settles the two as [Versions](/versions) explains: changes to different fields merge, and a collision the type can't merge leaves a conflicted copy, which appears as a second file.

A note's file name and its title stay in step. Rename the file and the new name, without its extension, becomes the title. Change the title anywhere else and the next sync renames the file, numbering the name if another file has it. The folder leaves a name alone when it can't tell whether you chose it.
