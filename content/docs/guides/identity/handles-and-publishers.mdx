---
title: Handles and publishers
description: Publisher identity for accounts and community-published types.
---

A handle is the public identifier for a Marfa account. The same string serves two roles:

- **Account username.** Every Marfa account has a handle. Required at signup, unique per Marfa instance, used anywhere identity surfaces publicly.
- **Publisher handle.** When the account publishes types, those types live in the handle's namespace: `<publisher>.<type>`. No separate claim — the username is the publisher handle.

Reservation rules apply at signup. They cover the platform's own namespace roots rather than trying to pre-empt every name somebody might squat.

## Username convention

| Rule | Detail |
|---|---|
| Allowed characters | Lowercase alphanumeric and hyphens. |
| Hyphen rules | No leading or trailing hyphens. No consecutive hyphens. |
| Length | 3–32 characters. |
| Case | Stored and compared case-insensitively. `Carla` and `carla` collide. |

Examples that pass: `nadia`, `readwise`, `carla`, `nadia-co`, `acme-co`.
Examples that fail: `-carla`, `carla-`, `carla--co`, `ab` (too short), `MyHandle` (uppercase).

## What's reserved

One category of handle cannot be claimed: the **reserved roots** — `core`, `system`, `app`, `user`, `marfa`, `space`. These root names belong to the platform's namespace tiers, except `space`, which is held clear of the type grammar entirely so the space permissions cannot collide with a type identifier. Claiming any of them as a handle would corrupt the type-identifier grammar.

Nothing else is reserved. A handle is a namespace claim rather than a URL path — no Marfa route is served at `/<handle>` — so an ordinary word like `admin` or `settings` collides with nothing, and a company name claimed by someone unaffiliated is a trademark question rather than a validation one.

Attempting to claim a reserved root returns `400 handle_reserved`. Trademarks and offensive terms are handled via takedown or dispute on demand. The reserved-roots list is maintained in the platform repository.

## Handle change policy

**Handles are practically immutable.** Once claimed, they don't change. Manual support-led rename for genuine exceptions.

Architecturally, the handle is separate from the underlying user-id: internal references (audit trails, admin records) key off the immutable user-id, while the handle is the public-facing label. That decoupling keeps a future rename path open without touching the foreign references.

## One namespace per instance

Handles are unique within a Marfa instance: one flat namespace, the same shape GitHub and npm use, because a flat namespace is what makes a publisher identifier unambiguous. There is no central registry spanning deployments. Schemas are inspectable and portable — a type is just a schema, so you can extract it, modify it, and register it elsewhere — and a local store with no server never touches handles at all.
