`GET /export` streams a space's items, edges, metadata, extensions, and blob references in one pass. Use it for backups, migrations between Marfa instances, and bulk extraction into an external store. The response streams until the filter is exhausted, so a large space exports without buffering the whole dataset in memory.

## Formats

Two output formats, selected with `format`:

- **NDJSON** (default) — one JSON record per line, streamed as `application/x-ndjson`. Item lines come first, each pairing an item with its metadata (`{"item": …, "metadata": …}`); edge lines follow (`{"edge": …}`). A loader that only wants items can filter on the line's top-level key. Suited to piping into a downstream loader.
- **Archive** — `format=archive` returns a gzipped tar (downloaded as `marfa-export-<date>.tar.gz`) carrying `manifest.json` (with `item_count`, `edge_count`, the registration counts, and the blob index), `items.ndjson`, `edges.ndjson`, `types.ndjson`, and the referenced blob bytes under `blobs/`. `types.ndjson` holds the space's own custom type and edge-type registrations, one `{custom_type}` or `{custom_edge_type}` line each, so a restore can write the items that use them. A `{custom_type}` line carries a sibling `provenance` object recording where the type came from, which the restore replays rather than guessing at. This is the format `POST /admin/restore-archive` ingests. See [Archive restore](/guides/querying/bulk-operations#archive-restore).

The full record shape for each format lives in the API reference.

## Scope and filters

Export is space-scoped — it returns only what the calling credential can read, the same visibility rule as [`GET /items`](/guides/querying/search-and-query). The same narrowing parameters apply:

- `type` — a single type identifier (subtypes included via inheritance). An identifier the space does not know is refused with `400 unknown_type`, as on `GET /items`.
- `state` — `active`, `archived`, `trashed`, or `any`. **`any` exports every state in one pass**, which is what an export meaning "everything this space holds" needs, since the archive is what a restore reads back. Omitting the parameter keeps the default every read applies, which excludes trashed rows — so a backup taken without it silently leaves the bin behind.
- `source` — items stamped with a given source credential.
- `timestamp_after` and `timestamp_before` — bound the export by the item's own time (`timestamp`, falling back to `created_at`), inclusive at both ends, as in [Search and query](/guides/querying/search-and-query). These were previously named `since` and `until`; a request still carrying an old name is refused with a `400`. They do not read the modification time, which the reference once said they did.

Edges are included only when both endpoints are in the exported item set, so a filtered export never references an item it does not carry. A full-space export includes every edge; a `type`-filtered one includes only the edges between items of that type.

<Callout type="info">
  The operator key, which is the only credential with no space, passes `target_space_id` to scope the export to one space. Without it the export covers the space-less rows instead — the platform-shipped catalogue and the grant projections rather than anybody's content — and the audit log flags it as unscoped so an accidental extraction is visible.
</Callout>

## Auditing

Every export is recorded in the [audit log](/guides/operations/audit) as an `export.space` action before streaming starts, capturing the format and the resolved space scope. An export by the operator key that runs without a `target_space_id` is flagged in the audit details so operators can spot an accidental unscoped extraction.
