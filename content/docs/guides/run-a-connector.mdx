---
title: Run a connector
description: Build a connector from the marfa-connectors repository, give it a key of its own, and run it once or on a schedule.
---

A connector is **a program you run yourself**, with a key of its own and the vendor's credentials in its environment. [Connectors](/connectors) explains why the server never runs one. These steps run any connector in the [marfa-connectors](https://github.com/withmarfa/marfa-connectors) repository, whether Marfa ships it or you [built it](/guides/connector).

The repository **has no releases and publishes no package**, so build from its `main` branch, and run it against an instance on the latest Marfa release.

## The connectors Marfa ships

Each connector's README lists its settings, such as a vendor token, and the key it needs.

| Connector | What it does |
| --- | --- |
| [GitHub](https://github.com/withmarfa/marfa-connectors/blob/main/connectors/github/README.md) | Reads repositories, issues, comments, pull requests and retained issue and comment files, from a personal token or a GitHub App, and with an App carries issue and comment edits back. |
| [Todoist](https://github.com/withmarfa/marfa-connectors/blob/main/connectors/todoist/README.md) | Reads a Todoist account's tasks, and carries changes back. |
| [Readwise](https://github.com/withmarfa/marfa-connectors/blob/main/connectors/readwise/README.md) | Reads the sources and highlights of one Readwise account, and never writes to Readwise. |
| [Readwise Reader](https://github.com/withmarfa/marfa-connectors/blob/main/connectors/readwise-reader/README.md) | Reads Reader documents and highlights, and carries supported edits back. |
| [RSS](https://github.com/withmarfa/marfa-connectors/blob/main/connectors/rss/README.md) | Reads the entries of the feeds you give it, in Atom, RSS 2.0, RSS 1.0 and JSON Feed, and never writes to a feed. |

## Run one

The steps use the RSS connector. You need a running instance and the CLI, from the [Quickstart](/quickstart), with a key that holds `keys.mint`, such as the Quickstart's. You also need Git, [Node.js](https://nodejs.org) 22.13 or later and [pnpm](https://pnpm.io/installation) 11.

<Steps>
<Step>

### Build the connector

The build compiles every connector in the repository:

```bash
git clone https://github.com/withmarfa/marfa-connectors.git
cd marfa-connectors
pnpm install --frozen-lockfile
pnpm build
```

</Step>
<Step>

### Make its key

Give each connector a key made for it alone. The key's source is the connector's `source`, and it holds write on the connector's own types and nothing else. The RSS connector writes one type, `rss.entry`:

```bash
marfa keys create --label rss --source rss --type-permission rss.entry=write \
  --metadata-permission types=write --default-tier feed
```

`--metadata-permission types=write` lets the connector register its type on the first start. **Copy the key from the answer**, because Marfa shows it once. The connector **refuses a key that holds more, or less**, and names what to change; revoke that key with `marfa keys revoke` and make another. [Manage keys](/guides/manage-keys) explains each flag.

</Step>
<Step>

### Run it once

Set the connector's environment in a terminal of its own, so its key doesn't replace your CLI's, and run it with `--once`. `RSS_FEEDS` holds one feed on each line, as an address or as `name=address`. A feed's address can carry a token, so keep `RSS_FEEDS` and the key out of any file in the checkout:

<Terminal>

```bash
export MARFA_API_URL=https://marfa.example.com
export MARFA_API_KEY=<the connector's key>
export RSS_FEEDS='https://example.org/feed.xml
news=https://example.com/atom.xml'
node connectors/rss/dist/main.js --once
```

```text
2026-10-18T20:48:11.705Z info registered as 01a150c5-a1a9-7db2-840f-4b46cc2facab
2026-10-18T20:48:11.812Z info run succeeded: created 2, updated 0, archived 0, unchanged 0, skipped 0
```

</Terminal>

Give a feed a name when its address may change, so its entries keep their items.

</Step>
<Step>

### Check its runs

With your own key, list the registrations. Each shows its last run and that run's summary or error:

<Terminal>

```bash
marfa connectors list
```

```text
01a150c5-a1a9-7db2-840f-4b46cc2facab  rss  rss  succeeded  2026-10-18T20:48:11.812Z  created 2, updated 0, archived 0, unchanged 0, skipped 0
```

</Terminal>

`marfa connectors runs <connector id>` lists its recent runs, newest first, and `marfa items list --type rss.entry` lists what it wrote.

</Step>
</Steps>

## Exit codes

A run with `--once` ends with one of these codes, for a scheduler to act on:

| Code | Meaning |
| --- | --- |
| `0` | The run succeeded, or the connector was stopped cleanly. |
| `1` | The run failed, or the connector couldn't start, such as on a key it refuses. |
| `2` | A setting is missing or malformed. The log names the setting, never its value. |

A failed run loses nothing the connector wrote before, and the next run reads the vendor again.

## Keep it running

Run a connector in one of two ways:

- **`--every 15m`**: a long-lived process that runs every 15 minutes. Runs never overlap, and after a failed run it waits longer before the next.
- **`--once` from a scheduler**, such as cron, launchd or a scheduled container.

The connector keeps no file: its place at the vendor is on the instance, so a new process or container carries on from the last run. **Run one process for each connector**: a second under the same key waits under `--every` and exits under `--once`, as [Holds and retries](/guides/connector-holds-and-retries) explains. The repository's [template README](https://github.com/withmarfa/marfa-connectors/blob/main/template/README.md#run-it) has a launchd file and a container image.
