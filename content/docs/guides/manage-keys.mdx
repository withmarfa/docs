---
title: Manage keys
description: Give a script or app a key that reaches only what it needs, then narrow, expire, rotate or revoke it, and recover the owner's password.
---

A key is the credential for a script or service you run yourself. **It reaches only what it was made with**: a notes app gets notes and nothing else. An app that people sign in to uses OAuth instead, as [Authenticate](/guides/authenticate) shows. [Access](/access) explains the maps and permissions a key holds.

The owner makes keys in a browser or through the private socket; a key holding `keys.mint` makes keys within its own access. The examples use the socket, so run them on the instance's machine with `MARFA_API_URL` and `MARFA_API_KEY` unset:

```bash
SOCK=/srv/marfa/data/control/marfa.sock
```

## Use the API keys page

Open API keys from [Home](/guides/sign-in-as-the-owner#start-from-home) and choose Create key. Details holds the name and when the key ends. **Access starts with everything off**, so turn on only what the key needs. Advanced holds its sources and where its items land.

**The page shows the key once**, under Copy your key. A saved key can only get less access or an earlier end.

## Make a key

This key reads and writes notes and nothing else:

```bash
marfa --socket "$SOCK" keys create \
  --label "Notes app" --source notes-app --type-permission core.note=write
```

Through the API, [Create an API key](/api-reference/access/createKey) takes the same fields.

The plaintext, which begins `marfa_k1_`, appears **once**. **Copy it to the app now**.

```text
marfa_k1_614e182634b2e78eb69e0a3cda8806b739be5a4917c5765a5420dfe766c63947
key 01a12311-8b01-7c3c-879e-3ff7346ce72f (Notes app); the plaintext is shown once, keep it now
  core.note  Read and edit
```

The source is stamped on every item the key creates. **A source belongs to one live key**: a second key naming it is refused `409 conflict`. With the notes key, a bookmark is refused `403 type_not_permitted`.

These flags work on `keys create` and `keys update` unless noted, and `--help` lists them.

| Flag | What it sets |
| --- | --- |
| `--label`, `--source` | What the key is for, and the source it writes as. Both are required to create, and the source never changes. |
| `--type-permission <pattern=level>` | A type map entry, such as `core.note=write`. Levels are `read` and `write`, and `none` denies a type a wildcard covers. Repeat it. |
| `--edge-permission`, `--extension-permission`, `--metadata-permission`, `--profile-permission` | Entries in the other four maps, as `name=level`. `email` is `read` only. |
| `--permission <name>` | One [permission](/catalog/permissions), such as `audit.read`. |
| `--claim <source>` | Another source the key may write as. |
| `--default-tier <tier>`, `--enforcement-override <json>` | Where its items land when a write names none (`library` or `feed`), and write rules for this key alone. |
| `--expires-in <duration>`, `--expires-at <time>` | When it stops, as a number and `s`, `m`, `h`, `d` or `w` such as `7d`, or as a time such as `2027-01-31T12:00:00Z`. Use one, not both. |
| `--no-permissions` | Hold nothing: no permission and no map. |
| `--no-claims` | Claim no source besides its own. |
| `--no-type-permissions` and four like it | Update only. Empty one map. |
| `--no-expiry` | Update only. Clear the expiry. |

## What a key holds

What a new key holds depends on what the request names:

- **Naming nothing takes everything its maker could give.** For the owner, that is every permission and `write` on all five maps.
- **Naming any permission, map or claim gives exactly what it names.** The notes key holds one map and no permission.
- **A key hands on only what it holds.** Asking for more is refused `403 forbidden`, with the first missing entry in `details.required_scope`.

The rules are [`mint-whole-set`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#keys-and-oauthmint-whole-set), [`mint-names-families`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#keys-and-oauthmint-names-families) and [`mint-ceiling`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#keys-and-oauthmint-ceiling).

## Let keys share a source

A key writes under its own source and any source it claims. Keys that stand for one thing, such as a laptop and a phone, can each use `--claim notes-sync` and update each other's items. An item without a `source` takes the key's own. The owner can grant any claim except one beginning with `oauth:` or `restored:`, which [Marfa refuses](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#keys-and-oauthclaims-reserved). A key holding `keys.mint` can grant only its own source and its claims ([`claims-ceiling`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#keys-and-oauthclaims-ceiling)).

## Make a key expire

Add `--expires-in 7d` to `keys create`, or `"expires_at"` to `POST /keys`. **Once the time passes, the key is gone.** Requests with it are refused `401 unauthorized`, and it leaves the key list. Its source is free for a new key.

A key's life is held to its maker's:

- **A key that expires passes its expiry on.** A key it makes ends when it does, or sooner. A later expiry, or none, is refused `403 forbidden`.
- **A key holding `keys.manage` can only shorten an expiry**, like every other change it makes.
- **Only the owner, or a key with no expiry holding `keys.mint`, lengthens or clears one**, with `--no-expiry` or `"expires_at": null`. Nobody does that for a key an app made.

See [`expiry-inherited`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#keys-and-oauthexpiry-inherited).

## Check what a key holds

**Any key can read itself** with `marfa keys current`, or `GET /keys/current`, so a program can check it holds no more than it should. `marfa keys list` shows each key's access, its last use (recorded at most hourly) and when it ends.

## Narrow a key

Change a key in place by its ID. A map or permission list you name replaces what the key held in that part, and **the parts you leave out stay as they were**. This makes the notes key read-only for 30 days:

```bash
marfa --socket "$SOCK" keys update 01a12311-8b01-7c3c-879e-3ff7346ce72f \
  --type-permission core.note=read --expires-in 30d
```

The same change is `PATCH /keys/{id}`. Who can change which key:

- **The owner** reaches every key and can change anything, but a key an app made can only narrow.
- **A key holding `keys.manage`** reaches every key and can only take access away.
- **A key holding `keys.mint`** reaches keys that hold nothing it doesn't. Any other ID answers `404 api_key_not_found`.

**An update can say it must only narrow.** Add `"narrow_only": true` to `PATCH /keys/{id}`, and Marfa refuses `403 forbidden` any change that gives the key more, whoever sends it. The API keys page sends it with every save. The rules are [`update-narrow-only`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#keys-and-oauthupdate-narrow-only) and [`manage-narrows-only`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#keys-and-oauthmanage-narrows-only).

## Rotate a key

Replace a key when its holder changes. **If a key may have leaked, revoke it first**, then make a new one.

1. Make a key with the same access and a new `--source`, and give it to the app.
2. Check that the new key works. An hour later, `marfa keys list` should show the old key's last use before the switch.
3. Revoke the old key.

**A new source starts new items.** The old key's items keep its source, and an upsert by `source_id` looks only under the new one, adding a second copy. To keep the source, revoke the old key first, or the new key is refused `409 conflict`.

## Revoke a key

**Revoking ends a key at once**: its next request is refused `401 unauthorized`.

```bash
marfa --socket "$SOCK" keys revoke 01a12311-8b01-7c3c-879e-3ff7346ce72f
```

**A browser session that signed in more than five minutes ago is refused `403 forbidden`**, and the key keeps working: the API keys page asks the owner to [confirm it's them](/guides/sign-in-as-the-owner#confirm-its-you). The socket, and a key holding `keys.manage`, aren't held to that ([`revoke-recent`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#keys-and-oauthrevoke-recent)).

## Give a key to a script or agent

The CLI takes a key from `--key`, then `MARFA_API_KEY`, then the keychain, as [the CLI page](/cli#connect-to-a-server) shows.

**On your own machine,** keep the key once in the keychain:

```bash
marfa keys keep --url https://marfa.example.com
```

It reads the key from `MARFA_API_KEY` or standard input and checks it with the server. A key the server refuses is kept nowhere (exit code 5).

**In a script, a CI job or an agent,** set `MARFA_NO_KEYCHAIN=1` and pass the server and the key as variables. With 1Password, store the key as a secret reference, which `op run` replaces with the value:

```bash
export MARFA_API_URL=https://marfa.example.com
export MARFA_API_KEY="op://Private/Marfa/key"
MARFA_NO_KEYCHAIN=1 op run -- marfa items list
```

With Infisical, keep both variables as secrets in the project:

```bash
MARFA_NO_KEYCHAIN=1 infisical run -- marfa items list
```

## Recover the owner's password

Set a lost owner password through the private socket, on the instance's machine:

```bash
marfa --socket "$SOCK" owner recover
```

The CLI asks for the new password without showing it, and `--stdin` reads `{"password": "…"}` instead. **Recovery signs out every browser.** Keys and apps keep working.

It also lifts a password lock: **ten attempts from one address in 15 minutes** answer `429` with `Retry-After`, and a passkey still works. Behind a proxy every client shares one address unless `TRUSTED_PROXY_CIDRS` or `TRUSTED_PROXY_HEADER` is set, as [Deploy](/guides/deploy#the-address) shows.

In a container, run `docker exec -it marfa marfa --socket /data/control/marfa.sock owner recover`. If the server can't start in full, such as when its port is taken, **start it with `MARFA_CONTROL_ONLY=true`** to open the socket alone.

The rules are in the [keys and sign-in](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md) and [instance claim](https://github.com/withmarfa/marfa/blob/main/conformance/spec/instance-claim.md#direct-ownership-and-recovery) chapters of the contract.
