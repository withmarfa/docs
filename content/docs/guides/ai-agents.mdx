---
title: Use Marfa with AI agents
description: Give an AI agent, such as Claude Code or Codex, a key of its own, so it can work with your notes, tasks and files and nothing else.
---

An AI agent works with Marfa the way a script does: it runs the [CLI](/cli), or calls the API, with a key. **Give each agent a key of its own**, made to reach only the kinds of data it needs. You can then see what it wrote, and cut it off at any time.

## Make a key for the agent

Make the key as the owner, through the private socket on the instance's machine. This one lets an agent read and write notes, read tasks and nothing else, and it stops working after 30 days:

```bash
marfa --socket /srv/marfa/data/control/marfa.sock keys create --label claude-code --source claude-code \
  --type-permission core.note=write \
  --type-permission core.task=read \
  --expires-in 30d
```

The CLI prints the key, which begins `marfa_k1_`, once. **The source, `claude-code`, is stamped on every item the agent creates**, so you can always tell its work from yours. [Manage keys](/guides/manage-keys) covers the other things a key can hold.

## Give it to the agent

Set two variables in the environment the agent runs its commands in:

```bash
export MARFA_API_URL=https://marfa.example.com
export MARFA_API_KEY=<the agent's key>
```

Every `marfa` command the agent runs now reaches your instance with its key. Keep the key out of files the agent commits.

## Tell the agent how to use Marfa

Add a few lines to the agent's instructions file, such as `AGENTS.md` or `CLAUDE.md`, that say what Marfa holds and how to reach it:

```markdown title="AGENTS.md"
## Marfa

My notes are in Marfa. Use the `marfa` CLI, with `--json` on every command.

- Find notes: `marfa search "<words>" --type core.note --json`
- Read one: `marfa items get <id> --json`
- Write one: `marfa items create --type core.note --prop title="<title>" --prop body="<text>" --json`
- To change one, read it first, then pass its `version` to `marfa items update`.

Marfa's docs are at https://docs.marfa.so/llms.txt.
```

With `--json`, every answer is JSON, and a refusal is one JSON object with an exit code that says whether to try again. [Exit codes](/cli#exit-codes) lists them.

## What the agent can and can't do

- **It reaches only the types its key names.** A write to another type is refused with `403 type_not_permitted`, and a read of an item it can't see answers `404`, as if the item didn't exist.
- **It can't manage the instance.** Keys, apps, settings and the audit log need permissions, and this key holds none.
- **It can't overwrite a change it hasn't seen.** Every update names the version it read, as [Versions](/versions) explains.
- **You can see what it wrote:** `marfa items list --source claude-code` lists it.
- **You can stop it at once:** `marfa keys revoke <key id>` ends the key, and the agent's next request is refused.

## Let the agent read these docs

An agent that builds on Marfa does better with the current docs than from memory. Connect the [Docs MCP server](/docs-mcp-server) so it can search them, or point it at [`/llms.txt`](/llms.txt), an index of every page as Markdown. [Docs as Markdown](/docs-as-markdown) covers every way to read them.
