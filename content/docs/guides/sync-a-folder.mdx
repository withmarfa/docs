---
title: Sync a folder
description: Keep a directory on your Mac and a set of items in step, so each note is a Markdown file you can edit in any app.
---

A folder lets you work on your items in the tools you already use. A file you add becomes an item, and a change on either side reaches the other. If you stop following the folder, the files stay behind as plain files.

A folder is a [device](/devices) whose working copy is a directory. **Its settings live on the instance** as a `system.folder` item, so every computer that follows the folder shares them, and each keeps its own copy and queue of writes. You run a folder with the CLI's `marfa folders` commands, or in a Mac app with the Swift SDK's `Folders`, which [the Swift SDK](/swift-sdk) covers. [Folder safeguards](/guides/folder-safeguards) says when a folder removes a file or an item, and how to undo it.

## Make a key for the folder

The folder needs a key that reaches what it holds. Make one as the owner, on the instance's machine. This key suits a folder of notes and files:

```bash
marfa --socket /srv/marfa/data/control/marfa.sock keys create \
  --label "Notes folder" --source notes-folder \
  --type-permission system.folder=write \
  --type-permission core.note=write \
  --type-permission 'core.file.*=write' \
  --edge-permission in-folder=write
```

- **`system.folder`:** write creates the settings, and read lets `folders add` bind a directory to them.
- **The types the folder holds:** write on each type the search admits, here `core.note`. `core.file.*` covers `core.file` and every type under it.
- **`in-folder`:** write on this edge, which records where each file sits.

`folders add` is refused without read on `system.folder`, naming `system.folder:read`, and without write on `in-folder`, naming `edge.in-folder:write`. [Manage keys](/guides/manage-keys) explains each flag.

## Set up a folder

<Steps>
<Step>

### Create the folder's settings

The settings say which items the folder holds, through a search, and what a new file becomes. This folder holds every note:

```bash tab="CLI" tab-group="client"
marfa folders create --title Notes --search '{"types":["core.note"]}'
```

```http tab="HTTP"
POST /folders
Authorization: Bearer <key>
Content-Type: application/json

{ "title": "Notes", "search": { "types": ["core.note"] } }
```

```ts tab="TypeScript"
const { data: folder, error } = await marfa.POST("/folders", {
  body: { title: "Notes", search: { types: ["core.note"] } },
});
if (error) throw new Error(error.error.message);
```

```swift tab="Swift"
let folder = try await copy.createFolder(
    FolderSettings(title: "Notes", search: FolderSearch(types: ["core.note"])))
```

The answer is the `system.folder` item. **Keep its ID**, because the next step binds a directory to it.

```text
01a1232d-949d-758c-b244-70057174b96a  system.folder  2026-10-10T00:19:12.157Z  Notes
```

**The search decides every item the folder takes in.** A search that names only a type holds every active and archived item of that type in the library tier, and the first sync writes all of them to disk. With no `types`, it holds every type the key reads except `system.*`. Narrow it with `filter`, `tier`, `state` or `beneath` before you confirm the first sync, as [list, filter and search](/guides/list-filter-search) describes.

</Step>
<Step>

### Add the directory

Bind a directory to the folder. It can be empty or hold files already, and the CLI makes it if it isn't there.

```bash tab="CLI" tab-group="client"
marfa folders add Notes --folder 01a1232d-949d-758c-b244-70057174b96a
```

**Nothing is written into the directory or sent to the instance until you confirm the first sync.** The command says what the sync will do:

```text
Notes follows the folder 01a1232d-949d-758c-b244-70057174b96a
the first sync will write and send nothing until you confirm it: 2 file(s) to write into the directory, 1 to send to the server
`marfa folders confirm Notes` lets it go; `marfa folders remove Notes` drops the folder and leaves the files
```

Here the instance holds two notes and the directory held one file, `Ideas.md`. In a script, pass `--yes` to skip the question the command asks at a terminal. Where an item's file would land on a file already there, one of the two gets a number added to its name, and **neither is written over** ([`folders/placement-collision-number`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/folders.md#foldersplacement-collision-number)).

**Keep the directory out of a location another program syncs**, such as iCloud Drive, a folder a cloud service syncs, or network storage. `marfa folders add` warns on standard error and goes on. Two programs syncing the same files can overwrite each other's changes or leave conflicting copies. On network storage, Marfa may also miss a change made from another computer.

</Step>
<Step>

### Confirm the first sync

Confirm it, then sync once:

```bash tab="CLI" tab-group="client"
marfa folders confirm Notes
marfa folders push Notes
```

`marfa folders push` does everything a folder does, once: it sends what changed in the directory, catches up with the instance, and writes out what changed there. To keep the folder in step, [keep folders running](/guides/keep-folders-running). That watch reads its key from the keychain, so run `marfa keys keep` first, as [the CLI](/cli#connect-to-a-server) shows.

In the Swift SDK, `sync(_:)` returns `.awaitingConfirmation` with the plan until you call `confirmFirstSync(in:)`.

</Step>
</Steps>

The directory now holds a file for each note, and `Ideas.md` is an item:

<Files>
  <Folder name="Notes" defaultOpen>
    <Folder name=".marfa">
      <File name="folder.yaml" />
    </Folder>
    <File name="Ideas.md" />
    <File name="Packing for the trip.md" />
    <File name="Reading list.md" />
  </Folder>
</Files>

## Replace a folder's key

A new key with the same `--source` is refused `409 conflict` while the old key is live. Reuse the `--source` after you revoke the old key.

<Steps>
<Step>

### Revoke the old key and make the new one

[Revoke the old key](/guides/manage-keys#revoke-a-key), run the `keys create` command above again, then run `marfa keys keep` so the folder reads the new key from the keychain.

</Step>
<Step>

### Push again

Run `marfa folders push Notes`. If the new key reads something other than the old one did, the instance refuses the folder's working copy and the push stops with `read_view_changed` ([`device/view-changed`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/device.md#deviceview-changed)). Run the push again: it builds the copy again itself, and its report starts with `hydrated 3 item(s) first`. Writes waiting in the queue are kept.

</Step>
</Steps>

## How items appear as files

A note is a Markdown file named after its title, or after its ID if it has none. Here's `Reading list.md`:

```markdown title="Notes/Reading list.md"
---
type: core.note
tier: library
title: Reading list
marfa_id: 01a1232d-947e-7399-86e1-97648a87c232
marfa_version: 1
---
Start with the essays, then the letters.
```

The lines between the `---` fences are the frontmatter. `type`, `tier`, `tags`, `state` and `occurred_at` are the item's own fields. A line named after an edge type, such as `references`, is an edge, and every other line is a property. The text after the fences is the body. `marfa_id` and `marfa_version` name the item and the version the file was written from: **leave them to Marfa**.

**A new Markdown file needs no frontmatter.** It takes its type and tier from the folder's `defaults` or its search, and its title from `defaults` or, without one, its file name. Once the instance creates the item, Marfa writes the frontmatter and `marfa_id` into the file. A `.txt` file is all body. Any other file the search admits, such as a photo, becomes a file item with its bytes uploaded as a blob, as [Handle files](/guides/handle-files) describes.

## Edits on either side

Edit a file and sync, and the edit reaches its item:

```text
0 created, 1 updated, 0 renamed, 2 unchanged, 0 missing, 0 deleted, 0 skipped
answered 1, held 0
1 file(s) written
```

An edit is a write based on the `marfa_version` the file names. If another app changed the same note meanwhile, the instance settles the two as [Versions](/versions) explains: changes to different fields merge, and a collision the type can't merge leaves a conflicted copy, which appears as a second file.

**A note's file name and its title stay in step.** Rename the file and the new name, without its extension, becomes the title. Change the title anywhere else and the next sync renames the file, numbering the name if another file has it. The folder leaves a name alone when it can't tell whether you chose it ([`folders/title-drift-kept`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/folders.md#folderstitle-drift-kept)).

## Change a folder's settings

Each computer writes the folder's settings out as `.marfa/folder.yaml`:

```yaml title="Notes/.marfa/folder.yaml"
# This folder's settings, the system.folder it follows. An edit here is
# sent through the folder operations by `folders push`, or while watching.
folder: 01a1232d-949d-758c-b244-70057174b96a
version: 1
title: Notes
search:
  types:
    - core.note
```

Edit the file and the next sync sends your change to the instance through [Update a folder](/api-reference/folders/updateFolder), so **it reaches every computer that follows the folder**. `marfa folders change` and the Swift SDK's `changeFolder(_:_:baseVersion:)` change the settings without the file. `folder` and `version` are Marfa's to write. [Folder](/catalog/folder) lists every other setting. This edit leaves a `drafts` directory alone and tags every new note:

```yaml title="Notes/.marfa/folder.yaml"
ignore:
  - drafts/
defaults:
  tags:
    - from-folder
```

To stop following a folder on one computer, run `marfa folders remove Notes`. It is refused while writes wait, apart from a first sync still waiting for confirmation. The folder's own state goes, and **the files stay where they are, as plain files**.

The rules behind this guide are in the [folders](https://github.com/withmarfa/marfa/blob/main/conformance/spec/folders.md) chapter of the contract.
