---
title: Sign in as the owner
description: Sign in to the owner's pages with a password or a passkey, confirm it's you before a sensitive change, and open each page from Home.
---

The owner signs in in a browser at `/auth/sign-in`, with the password chosen when claiming the instance or a registered passkey. A valid passkey works even when password attempts are locked. [Recover the owner's password](/guides/manage-keys#recover-the-owners-password) covers a lost password.

Marfa asks for a recent sign-in before a sensitive change. **No key or app ever gets the owner's authority**, whatever it holds.

## Manage passkeys and sign-ins

The Password and passkeys page, at `/auth/owner/passkeys`, changes the password and manages passkeys. Passkeys need HTTPS, or `localhost` for development. Adding, renaming or removing a passkey **needs a sign-in from the last five minutes**.

On the instance's own machine, the private socket manages passkeys without a browser sign-in:

```bash
marfa --socket <path> owner passkeys list
marfa --socket <path> owner passkeys rename <id> --name "Laptop"
marfa --socket <path> owner passkeys remove <id>
marfa --socket <path> owner passkeys add
```

The add command **issues no sign-in credential**. It opens the sign-in page, where you sign in and register the passkey in the browser. `--no-browser` prints the URL instead.

A sign-in is one of the owner's browsers, apps or keys. The owner's browser and the private local command can list, rename and end sign-ins at `/owner/sign-ins`; keys and app tokens cannot. Renaming a sign-in, or ending one other than your own, needs a sign-in from the last five minutes. To list the local commands, run:

```bash
marfa sign-ins --help
```

## Confirm it's you

When a change needs a sign-in from the last five minutes and yours is older, the page shows a Confirm it's you dialog that asks for the owner's password or a passkey. Then it sends the change again. These changes ask for it:

- Adding, renaming or removing a passkey.
- Changing the owner's name or email on the Profile page.
- Revoking a key, disconnecting an app, or signing out another browser.
- [Approving a write or a permission](/guides/authenticate#when-approval-needs-a-recent-sign-in) the app doesn't already hold.

Confirming replaces your browser session with a new one. A wrong password answers `401 unauthorized`, and after too many attempts `429 rate_limited` with `Retry-After`. A passkey still confirms. A refused confirmation leaves your session as it was.

A program has no dialog, so it gets `403 forbidden` with the message `Sign in again to perform this operation`, and Marfa changes nothing. `POST /auth/confirm` is the operation behind the dialog. It takes the password or a passkey assertion of the signed-in owner, and answers `401 unauthorized` to a request with no live owner session or with a key.

## Start from Home

Open the instance's address in a browser where you are signed in as the owner, and Home lists the owner's pages. A browser that isn't signed in sees a page that says the instance is running, with a Sign in link.

| Group | Page | Address | Covered in |
| --- | --- | --- | --- |
| Access | API keys | `/auth/owner/keys` | [Manage keys](/guides/manage-keys#use-the-api-keys-page) |
| Access | Connected apps | `/auth/owner/apps` | [Revoke access](/guides/authenticate#revoke-access) |
| Access | Browsers | `/auth/owner/browsers` | [Manage passkeys and sign-ins](#manage-passkeys-and-sign-ins) |
| Your data | Export and restore | `/auth/owner/export` | [Back up and restore](/guides/back-up-and-restore) |
| Connections | Connectors | `/auth/owner/connectors` | [Connectors](/connectors) |
| This Marfa | General | `/auth/owner/general` | [Settings](/guides/settings#change-settings-while-it-runs) |
| This Marfa | Health | `/auth/owner/health` | [Housekeeping](/guides/housekeeping) |
| This Marfa | Activity | `/auth/owner/activity` | [Audit log](/guides/audit-log) |
| This Marfa | All settings | `/auth/owner/settings` | [Settings](/guides/settings#every-environment-setting) |

| You | Password and passkeys | `/auth/owner/passkeys` | [Manage passkeys and sign-ins](#manage-passkeys-and-sign-ins) |

Opening an owner page without a session answers `302` to `/auth/sign-in` with the page as `return_to`, and signing in returns you there. On an instance with no owner yet, the redirect goes to `/setup`. A request with an `Authorization` header, or one that doesn't ask for HTML, gets no redirect, and `GET /` answers it with the instance's description.

## Change the owner's email or name

Only the owner changes the sign-in address. On the instance's machine, use the private socket:

```bash
marfa --socket <path> owner update --email owner@example.com --name "Reader"
```

In a browser, the Profile page uses [Update the owner](/api-reference/access/updateOwner), which needs a sign-in from the last five minutes. Keys and app tokens can't use it. The email is stored in lowercase, needs no confirmation, and becomes the address for password sign-in. The owner's password, passkeys, sessions, keys and app grants stay in place.

The rules behind this guide are in the [authentication](https://github.com/withmarfa/marfa/blob/main/conformance/spec/authentication.md) chapter of the contract, with the owner's sign-ins in [keys and sign-in](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#the-owners-sign-ins) and the email in [owner and delegated profile changes](https://github.com/withmarfa/marfa/blob/main/conformance/spec/instance-claim.md#owner-and-delegated-profile-changes).
