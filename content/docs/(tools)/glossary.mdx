Marfa uses each word below in one sense only, in its code, its API and these docs. Each one links to the page that explains it.

## Your data

| Word | What it means |
| --- | --- |
| **item** | One record, such as a note, a task or a photo, with a type, a state and properties. [Items and types](/items-and-types) |
| **type** | What an item is, such as `core.note`, and the properties it holds. Marfa checks every write against it. [Items and types](/items-and-types) |
| **property** | A named value in an item, such as a note's `title`, declared by the item's type. [Properties, metadata and edges](/properties-metadata-and-edges) |
| **tag** | A free-form label on an item, such as `favorite`. [Properties, metadata and edges](/properties-metadata-and-edges) |
| **extension** | An app's own data about an item, stored under a namespace such as `com.example.reader`. [Properties, metadata and edges](/properties-metadata-and-edges) |
| **edge** | A typed link from one item to another, such as a note `about` a book. [Properties, metadata and edges](/properties-metadata-and-edges) |
| **file** | An item that names its bytes, such as a `core.file.image`. [Files](/files) |
| **blob** | A file's bytes, stored once under a hash of their content. [Files](/files) |
| **state** | Where an item is in its life: `active`, `archived` or `trashed`. A `system` item is `active` or `revoked` instead. [Items and types](/items-and-types#an-items-life) |
| **tier** | Whether an item is in the **library**, what a person chose to keep, or the **feed**, what arrived from elsewhere. [Items and types](/items-and-types#library-and-feed) |
| **version** | A count of the changes to an item, which a write names so it can't overwrite a change it hasn't seen. [Versions](/versions) |
| **event** | A record of one change, in the order changes happened. Apps follow events to stay current. [Events and webhooks](/events) |
| **webhook** | A URL Marfa posts events to as they happen. [Events and webhooks](/events) |

## Access

| Word | What it means |
| --- | --- |
| **owner** | The one person an instance belongs to. The owner manages it, and reads and writes data with a key like anyone else. [Access](/access) |
| **credential** | What a request carries to show what it may do: a key or an access token. [Access](/access) |
| **key** | A credential the owner makes for a script, an agent or a connector. It begins `marfa_k1_`. [Manage keys](/guides/manage-keys) |
| **app** | A program that signs in with OAuth and works with the data the owner approved. [Authenticate](/guides/authenticate) |
| **access token** | The credential an app gets when it signs in. It begins `marfa_at_`. [Authenticate](/guides/authenticate) |
| **scope** | One thing an app asks for when it signs in, such as `core.note:read`. [Access](/access) |
| **permission** | The right to use a group of operations, such as reading the audit log. It opens no items. [Access](/access#permissions) |
| **source** | The writer an item came from, stamped by the key that created it, such as `laptop`. [Access](/access#sources) |
| **setup code** | A one-time code the server prints when it starts with no owner, used to claim the instance. [Quickstart](/quickstart) |

## The instance

| Word | What it means |
| --- | --- |
| **instance** | One running Marfa server and the data it keeps, owned by one person. [How Marfa works](/how-marfa-works) |
| **server** | The program that answers for an instance over HTTP. [Deploy](/guides/deploy) |
| **operation** | One thing the API does, such as creating an item. [API reference](/api-reference) |
| **housekeeping** | The work an instance does on itself on a schedule, such as purging what has stayed in the trash too long. [Housekeeping](/guides/housekeeping) |
| **contract** | The written rules Marfa follows, each checked by tests. [The contract](https://github.com/withmarfa/marfa/tree/main/conformance/spec) |

## Devices and folders

| Word | What it means |
| --- | --- |
| **device** | A client that keeps a working copy of part of an instance, such as an iPhone app. [Devices](/devices) |
| **working copy** | The data a device keeps on its own disk, so it reads and writes offline. [Devices](/devices) |
| **verdict** | What a device records for a write it queued, once the instance answers it or once it can't be sent, such as `accepted` or `dead`. [Devices](/devices#verdicts) |
| **folder** | A directory of ordinary files on your computer kept in step with a set of items. [Sync a folder](/guides/sync-a-folder) |

## Connectors

| Word | What it means |
| --- | --- |
| **connector** | A program that brings records in from another service, and can carry changes back. [Connectors](/connectors) |
| **hold** | What lets one copy of a connector write at a time. [Holds and retries](/guides/connector-holds-and-retries) |
| **agreement** | What a connector and its service last agreed about one item. [Connectors](/connectors) |
| **webhook endpoint** | A private address on an instance that a service posts its webhooks to, for a connector to read. [Receive vendor webhooks](/guides/connector-webhooks) |

## The CLI

| Word | What it means |
| --- | --- |
| **CLI** | The `marfa` program, Marfa's command-line tool. [CLI](/cli) |
| **command** | One thing the CLI does, such as `marfa items list`. [CLI](/cli#commands) |

The full vocabulary, with the words Marfa avoids, is the [glossary in the marfa repository](https://github.com/withmarfa/marfa/blob/main/GLOSSARY.md).
