A client is anything that talks to a Marfa server through an SDK — an app, a CLI, an MCP server, a sync agent, a scheduled job. The WithMarfa org maintains a small set of first-party clients that exercise the SDK surface and ship as reference implementations.

## First-party SDKs and clients

| Client | Purpose | Install | Source |
|---|---|---|---|
| [TypeScript SDK](/sdks/typescript) | TypeScript client for Node.js, Bun, Deno, and browsers. | `pnpm add @withmarfa/sdk` | [withmarfa/marfa](https://github.com/withmarfa/marfa/tree/main/packages/sdk) |
| [Swift SDK](/sdks/swift) | Swift client for Apple platforms, in remote mode or local mode. | SwiftPM package | [withmarfa/swift-sdk](https://github.com/withmarfa/swift-sdk) |
| [CLI](/sdks/cli) | Shell tool for inspecting, listing, and mutating items from a terminal. | `npm install -g @withmarfa/cli` | [withmarfa/cli](https://github.com/withmarfa/cli) |
| [MCP server](/sdks/mcp) | Exposes the API as MCP tools for Claude and other MCP hosts. | `npx @withmarfa/mcp` | [withmarfa/mcp](https://github.com/withmarfa/mcp) |
| [Sync agent](/sdks/sync) | Keeps local folders and Marfa in sync; captures markdown notes as `core.note` items you own and edit freely. | `npm install -g @withmarfa/sync` | [withmarfa/sync](https://github.com/withmarfa/sync) |
| [Raycast extension](/sdks/raycast) | Browse, search, capture, and manage keys from Raycast on macOS. | Raycast Store | [withmarfa/raycast](https://github.com/withmarfa/raycast) |

All first-party clients consume the TypeScript SDK or the Swift SDK; none re-implement the wire format.

A client runs in one of two [modes](/guides/identity/deployment-modes). **Remote** means every call crosses the network. **Local** means the app reads from a durable on-device store, which reconciles with a server when one is configured. The Swift SDK offers both; the TypeScript SDK is remote, with a volatile in-process store for one type in the [local replica](/sdks/local-replica) subpath. A client that keeps a durable store holds state the server has not seen, and the rules that keep the two from drifting are the [sync contract](/sdks/sync-contract).

## Integration shapes

A client integrating with Marfa takes one of three shapes. The choice is about *how* the client talks to Marfa, not what runtime it runs in. Pick based on what produces the data and where it lives.

| Shape | What it is | Best for |
|---|---|---|
| **Direct SDK client** | The client uses the TypeScript SDK or the Swift SDK to write items via the API. Authenticates with OAuth or an API key. Runs wherever the app already runs. | Apps with structured data, multi-part outputs, or type-specific semantics. The most common shape. |
| **Sync-mediated** | The client writes files to a folder; the [sync agent](/sdks/sync) watches the folder and writes them into Marfa as typed items the user owns. No SDK code on the client side beyond writing files. | Apps that already produce one-file-per-thing in a user-visible vault — markdown notes apps, image-capture apps producing single files. |
| **Published Integration** | A `system.integration` manifest published to the marketplace, running on Marfa's runtime substrate. See [Integrations](/guides/connections/integrations). | Integrations a user installs and configures — calendar sync, RSS pollers, cron-driven cleanup, scheduled polls of external APIs. |

How to pick:

- **Structured data on the user's own device?** Direct SDK client.
- **Plain files in a vault?** Sync-mediated.
- **Scheduled or event-driven against an external service?** Published Integration.

The shapes aren't exclusive. A Direct SDK app can also publish an Integration manifest if it wants to expose extras — a desktop app that's mostly a direct-SDK client and additionally registers a scheduled-cleanup integration the user can opt into.

## Building your own

The same SDK surface covers third-party clients — apps, integrations, ingest agents, workflow triggers, anything authenticated with a Marfa credential. [Building a client](/sdks/building-a-client) walks through the pattern using the MCP server as the worked example.
