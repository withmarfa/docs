The Raycast extension is the GUI capture surface for Marfa. Same SDK underneath as the [CLI](/sdks/cli), but different ergonomics — Raycast's keyboard launcher, list views, type-aware capture forms. Once registered, every command is one fuzzy-search away from any context.

Source at [`withmarfa/raycast`](https://github.com/withmarfa/raycast). Available via the Raycast Store under the name _Marfa_.

## Install

Install from the Raycast Store — search for _Marfa_ inside Raycast's "Store" tab, or run `Install Extension` from the root and pick it. Set the **Server URL** preference once (e.g. `https://marfa.example.com`); first invocation handles the rest via OAuth.

## Authenticate

Two paths. OAuth is the recommended default; an API key works if you'd rather skip the consent flow.

**OAuth (default)** — leave the API Key preference empty. First invocation against a new server runs OAuth Dynamic Client Registration (DCR) and PKCE consent in one motion; the extension calls `POST /auth/oauth2/register` with a minimal manifest, persists the result keyed by issuer in Raycast's `LocalStorage`, then runs the consent flow. Subsequent calls refresh silently. No operator-side OAuth-app seeding needed — every Marfa server works out of the box.

**API key** — paste an existing key into the API Key preference. The extension skips OAuth entirely and uses the key directly. Useful for self-hosted single-tenant servers or testing.

Changing the Server URL invalidates the stored OAuth state — the next command re-runs DCR + PKCE against the new server.

## Commands

### Browse

Lists items in the tenant with date grouping, tier / type / lifecycle filtering, and inline detail. Default starting view across the tenant; narrow with filter controls in the action panel.

### Search

Full-text search with debounced input. Shares the filter surface with Browse — tier, type, lifecycle, tags. Backed by the same `/items?q=` endpoint the SDK exposes.

### Quick Capture

Single form-shot at any registered type. The most-used command. Picks the type with type-ahead, exposes native fields for core types (`core.note` body / title, `core.bookmark` url + title, `core.task` description + due / priority, `core.event` start / end), and falls back to a generic properties editor for everything else. Atomic edge creation through the same form — Reply writes a `core.note` plus an outbound `in-thread` edge in one transaction.

### Manage Keys

Operator-shaped surface for tenant API keys. Lists, creates, and revokes credentials against the same `client.keys.*` surface the CLI exposes. Non-admin principals see an "admin credentials required" empty state.

### Server Info

Status surface — shows resolved server URL, signed-in user (when OAuth), key role / scope, the type catalog count, and rate-limit headers from the last request.

### Type Registry

Browse the type catalog. Useful for confirming a custom type is registered and inspecting its required fields before Quick Capture against it.

### Clipboard Capture (Text / Image)

Two variants that read the clipboard and create a `core.note` (text) or upload the blob and create a `core.file.image` (image). Both ship `disabledByDefault` — flip on in Raycast Preferences → Extensions → Marfa when you want them on the root launcher.

## Defaults and disabled commands

Three commands are load-bearing — **Browse**, **Search**, **Quick Capture** — and ship enabled on the root launcher. Everything else (key management, server info, type registry, clipboard variants) ships `disabledByDefault` so the root launcher stays uncluttered. Flip individual commands on in Raycast Preferences when you actively use them.

## What this surface deliberately isn't

- **Not the CLI.** The CLI is composition-first — pipelines, scripts, one-shot operations with auto-JSON on non-TTY. Raycast is GUI-flow-first — keyboard launcher, persistent list state, form-shaped capture. Same SDK, different ergonomics; neither replaces the other.
- **Not a full client app.** No detailed multi-pane editing, no rich attachment management, no offline-capable inbox. Items get captured fast or surfaced for triage; deeper work happens in a dedicated app or the CLI.
- **Not a Marfa server admin tool.** Beyond Manage Keys, cross-tenant operations and operator surfaces live in the CLI's `marfa platform`.

## Switching servers

The extension binds to a single Server URL at a time. Changing the URL preference invalidates the stored OAuth state and the next command re-runs DCR + PKCE against the new server. No in-app account switcher — re-login is the model.
