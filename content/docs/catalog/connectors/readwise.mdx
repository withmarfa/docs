---
title: Readwise
description: The sources, highlights, annotations and tags of one Readwise account, read only.
---

The Readwise connector imports the sources and highlights of one Readwise account into the feed. It only sends read requests to Readwise, so nothing goes back.

## What it reads

Readwise's highlights export: every source, such as a book, article, tweet or podcast, and every highlight with its complete passage, annotation and tags. Text and annotations are never shortened.

The first run exports everything. Later runs ask for what changed since the last completed walk, with a five-minute overlap. A full pass repeats every 24 hours, because an incremental export doesn't promise to include a change made only to a source's metadata. A run reads at most 50 pages and leaves the rest for the next run.

## Types it writes

| Type | Parent type | Holds |
| --- | --- | --- |
| `readwise.source` | [Media](/catalog/media) | A book, article, tweet, podcast or other source |
| `readwise.highlight` | [Highlight](/catalog/highlight) | A highlight with its annotation and tags |
| `readwise.file` | [File](/catalog/file) | Content kept for a document that Readwise Reader manages |

Each highlight connects to its source through `references`. A row's `source_id` is `<account>:source:<ID>` or `<account>:highlight:<ID>`, where the account is your `READWISE_ACCOUNT`. Readwise's original timestamps, location kinds and colors are kept as properties.

Each highlight has a `title` and a `body`, which apps show as its title and text. The title is the first line of the passage as plain text, at most 80 characters. A passage that holds only a picture is titled after its source, as in "Picture from Deep Work". The body is the whole passage as Markdown, pictures included.

Dates and times are `datetime` [fields](/catalog/field-kinds), `reader_published_date` is a `date`, and addresses are `url` fields. **A value Readwise sends blank is left out.** A value its field's kind refuses is kept as sent under `original_values`, by field name, so one odd value never stops a row being written.

## What goes back

Nothing. The connector sends no write to Readwise, and trashing or purging a row in Marfa deletes nothing there. An export tombstone archives only the row it names. A missing record, an empty page or a 404 never archives anything.

## Settings

| Setting | What it holds |
| --- | --- |
| `READWISE_ACCESS_TOKEN` | Your Readwise access token. A secret. |
| `READWISE_ACCOUNT` | A stable label for the account that is not secret, such as `primary`. 1 to 64 ASCII letters, digits, dots, underscores or hyphens, starting with a letter or digit. |
| `READWISE_CONTENT_MAX_BYTES` | The largest remote resource to keep, in bytes, from 1 through 1,073,741,824. The default is 268,435,456 (256 MiB). Optional. |

## What to know

- **Keep the account label.** It is part of every row's identity, so keep it the same across token changes and reinstallations. Changing it against saved progress is refused.
- **One Readwise account for each connector.** The label is never worked out from the token.
- **Readwise Reader shares these rows.** If you also run [Readwise Reader](/catalog/connectors/readwise-reader), give both the same label. Reader supplies the canonical passage, and this connector keeps a differing export passage in `readwise_text`.
- **An existing install needs a schema step.** The field kinds change existing fields, so replace both type definitions as the [README](https://github.com/withmarfa/marfa-connectors/blob/main/connectors/readwise/README.md#upgrade-to-highlight-titles-and-field-kinds) describes, then run the connector straight away. Its first run walks everything once and rewrites each row in place, adding titles and dropping blank values. Until then, an edit in Marfa to a row that holds a blank address is refused.
- **Rate limits are honored.** A 429 saves its `Retry-After` deadline across restarts. A failed request or malformed answer fails the run and never becomes an empty import.
- **Requests time out after 30 seconds**, refuse redirects, and read at most 32 MiB of an answer.

## Run it

[Run a connector](/run/run-a-connector) runs any connector. This one's key holds write on `readwise.source`, `readwise.highlight` and `readwise.file`, and on the `references` and `attached-to` connections, and its [README](https://github.com/withmarfa/marfa-connectors/blob/main/connectors/readwise/README.md) has the `marfa keys create` command.
