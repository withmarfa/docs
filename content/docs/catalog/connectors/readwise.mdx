The Readwise connector keeps the sources and highlights of one Readwise account in the feed. **Reader is off by default:** the connector then reads Readwise's export and writes nothing to Readwise. Turn on `readwise_reader` and it also keeps your Reader documents and their content, and carries supported edits back to Reader.

## What it brings in

With Reader off, Readwise's export: every source, such as a book or article, and every highlight with its complete passage, annotation and tags. Text is never shortened.

With Reader on, it also reads Reader's saved library, and the feed if you ask. **A Reader document and its export entry are one item**, so turning Reader on keeps the same items, key and progress. It keeps each document's HTML, any original file and the pictures Readwise hosts, as files attached to the document.

## Types it writes

| Type | Parent type | Holds |
| --- | --- | --- |
| `readwise.source` | [Media](/catalog/media) | A source, or a Reader document |
| `readwise.highlight` | [Highlight](/catalog/highlight) | A highlight with its annotation and tags |
| `readwise.file` | [File](/catalog/file) | Content or a picture kept for a Reader document |

A highlight's `body` is its whole passage as Markdown, and its `title` the passage's first paragraph.

## Edges it writes

| Edge type | From | To |
| --- | --- | --- |
| [`excerpt-of`](/catalog/edges/excerpt-of) | A highlight | Its source |
| [`attached-to`](/catalog/edges/attached-to) | A file | Its source or highlight |

Its key keeps write on `references` only to clear the ones it wrote before.

## What goes back

With Reader off, nothing. With Reader on, for rows Reader manages:

- **Document edits:** title, author, `description`, notes, tags, `reader_location`, category, language, `published_at` and `image_url`.
- **Highlight edits:** `note` and tags.
- **Archive and restore.** Archiving a document moves it to Reader's archive, and restoring it moves it to Later.
- **A new item** with `reader_create: true` is saved to Reader.

The bin never changes Reader, and a row only the export holds, such as a Kindle book, is never sent.

## Settings

Give each as an environment variable named in capitals, such as `READWISE_READER=true`.

| Setting | What it holds |
| --- | --- |
| `readwise_account` | A stable label for the account, such as `primary`. Required. |
| `readwise_access_token` | Your Readwise access token. Secret. Required. |
| `readwise_content_max_bytes` | The largest file to keep. Default 268435456 (256 MiB). |
| `readwise_reader` | `true` turns Reader on. Default `false`. |
| `readwise_reader_include_feed` | `true` also reads Reader's feed. Default `false`. |
| `readwise_reader_pictures` | Pictures from other websites: `addresses` (default) lists them, `save` saves them, `save-in-library` saves them for library documents. |
| `readwise_reader_inbound_only` | `true` sends no edits to Reader. Default `false`. |
| `readwise_reader_propagate_purge` | `true` lets a purge in Marfa delete the Reader record. Default `false`. |
| `readwise_api_url`, `readwise_reader_api_url` | The API addresses, for testing only. |

## What to know

- **Keep the account label.** It is part of every item's identity, so changing it is refused.
- **Turning Reader off keeps what Reader managed.** Those rows are still refreshed from Reader with read requests, and an edit made in Marfa waits until Reader is on.
- **Purges are limited.** With `readwise_reader_propagate_purge` on, more than 20 deletions at once stops the run before anything reaches Reader.

## Make its key

```bash
marfa keys create --label readwise --source readwise \
  --type-permission readwise.source=write \
  --type-permission readwise.highlight=write \
  --type-permission readwise.file=write \
  --edge-permission excerpt-of=write \
  --edge-permission references=write \
  --edge-permission attached-to=write \
  --metadata-permission types=write \
  --default-tier feed
```

## Run it

[Bring in records from another service](/use/connect-a-service) builds and runs any connector, and [Connectors](/build/connectors) explains how they work.

```bash
node connectors/readwise/dist/main.js --once
node connectors/readwise/dist/main.js --every 1h
```
