A connector is a program you run that reads another service and writes what it finds to your instance, under a key made for it alone. Some also carry changes made in Marfa back to the service. [Connectors](/connectors) explains how they work, and [Run a connector](/guides/run-a-connector) runs one.

Marfa ships six, in the [withmarfa/marfa-connectors](https://github.com/withmarfa/marfa-connectors) repository. You build each from that repository and run it yourself.

| Connector | Reads | Goes back to the service |
| --- | --- | --- |
| [GitHub](/catalog/connectors/github) | Repositories, issues, discussions, comments, pull requests and notifications | Issues, discussions and comments, with a GitHub App |
| [Google Calendar](/catalog/connectors/google-calendar) | Calendars and events | Event changes |
| [Todoist](/catalog/connectors/todoist) | Tasks | Task changes |
| [Readwise](/catalog/connectors/readwise) | Sources and highlights | Nothing |
| [Readwise Reader](/catalog/connectors/readwise-reader) | Documents, highlights and saved content | Supported edits to documents and highlights |
| [RSS](/catalog/connectors/rss) | The entries of the feeds you list | Nothing |

## What every connector shares

- **Its own key.** Each connector refuses a key that holds more, or less, than it needs.
- **The feed.** Rows land in the [feed](/items-and-types#library-and-feed), never in a library type. Moving a row to the library is a person's or an app's act.
- **Nothing kept on your machine.** A connector keeps its progress on the instance, and takes its secrets from its environment.
- **Two settings every connector reads.** `MARFA_API_URL` is the address of your instance and `MARFA_API_KEY` is the connector's key. The pages below list only the settings that are specific to a connector.

Each page has the same sections: what the connector reads, the types it writes, what goes back, its settings, what to know and how to run it.
