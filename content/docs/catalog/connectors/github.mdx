## What it brings

It reads repositories a fine-grained personal access token can reach, or that a GitHub App is installed on. `github_repositories` narrows that to `owner/repo` or `owner/*` names, separated by commas. A repository you drop from that list is paused: its rows stay until you name it again.

Issues, discussions, comments and pull requests come in with the relations between them. Issues and pull requests cover what is open and what closed or changed in the last 90 days. An older issue comes in once it changes, or when a synced issue names it.

Stars stay on unless `github_stars` is `false`. `github_notifications_token`, a classic token with only the notifications scope, reads that person's notifications and, with no personal token, their public stars.

`github_files` mirrors Markdown on the default branch under paths you name, as `owner/repo:path`, with paths separated by commas and entries by semicolons or line breaks. A file over 512 KiB, or not UTF-8, is skipped. Images and other files signed into an issue or comment are kept attached to that row. Pull requests and discussions are not.

## What goes back

A personal token never writes. A GitHub App carries changes to issues, discussions and comments, under the App's name. Repositories, pull requests, notifications and files do not. `github_read_only` as `true` stops every write. A comma-separated list of kinds, such as `issue` or `comment`, stops those.

Trashing an open issue closes it as not planned. Trashing a comment the App wrote deletes it on GitHub. Trashing a discussion sends nothing. An issue moved to a repository the App still reads stays the same item. One moved out of what the connector reads is archived.

One instance runs one GitHub connector.

## Settings you decide

Set a value with `marfa plugins settings` and a secret with `marfa plugins secret` ([Give a connector its settings and secrets](/use/connector-settings)). Choose the personal token or the three App settings, never both. Every other setting is named in the plugin's `plugin.json`.

| Setting | What you decide |
| --- | --- |
| `github_personal_token` | Secret. Fine-grained token with read access to Issues, Discussions, Pull requests, Commit statuses, Contents and Starring. |
| `github_app_id`, `github_private_key`, `github_webhook_secret` | The App. The key and webhook secret are secrets. [Register the App](#register-a-github-app) once. |
| `github_notifications_token` | Optional secret beside either choice. |
| `github_public_url` | Public address, so GitHub can deliver changes. Without it, the connector polls. `github_organization` places the App on an organization, and `github_app_name` renames it. |

## Register a GitHub App

Run the built connector once in setup mode. Open the address it logs, create the App, and install it on the repositories to read. Run the lines it prints where `marfa` is signed in as you.

## Install

Install it from its source folder ([Install a plugin](/use/install-a-plugin)). It runs on a connector host ([Run a plugin's connector](/use/run-a-plugin-connector)).

## Limits

A fine-grained token cannot read notifications or check results, so a pull request keeps its last check summary. An installation token names at most 500 repositories, and past that the read covers the whole installation. A clock more than 10 minutes from GitHub's stops every request.
