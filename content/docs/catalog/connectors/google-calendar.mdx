---
title: Google Calendar
description: The calendars and events of a Google account, with changes to events carried back and no invitations sent.
---

The Google Calendar connector keeps the calendars and events of one Google account in the feed, and carries changes you make to events in Marfa back to Google Calendar. It never invites anyone and never has Google email anyone.

## What it reads

- **Calendars.** Every calendar in the account's calendar list that the account owns or can write to, including hidden ones. It skips the Birthdays calendar, and skips a calendar the account can only read unless you name it in `GOOGLE_CALENDAR_READ_ONLY_CALENDARS`.
- **Events.** Every event of those calendars, past and canceled included, because Google reports a deletion as a canceled event. A canceled event archives its row. It skips working-location events, which are not appointments.

After the first read, the connector asks Google only for what changed since the last run.

## Types it writes

| Type | Parent type | Holds |
| --- | --- | --- |
| `google.calendar.calendar` | None | A calendar, read only. Its `access_role` says what the account may do on it. |
| `google.calendar.event` | [Event](/catalog/event) | An event, linked to its calendar by the `google.calendar.in-calendar` connection. |

A recurring event is one row whose `recurrence` holds Google's rules, and Marfa expands the occurrences. A moved or edited occurrence is its own row, with `original_starts_at` set to the time it replaces, and sits beneath its series through `parent-of`. A canceled occurrence is added to the series as an `EXDATE` line.

An event row also holds `calendar_id`, `organizer`, `guests`, and `editable`, which says whether Marfa may change the event, with `uneditable_reason` when it may not.

## What goes back

- **A new event row.** It becomes an event on the calendar its `google.calendar.in-calendar` connection names, or on the primary calendar if it has none. The connector refuses to make an event on a calendar the account can only read.
- **Edits.** The `title`, `description`, `place`, `status` (`confirmed` or `tentative`) and times, and a series' `recurrence`. Connecting the row to another calendar moves the event.
- **Removal.** Trashing a row deletes its event, and restoring the row brings the event back.

Google holds a description as HTML, so the connector reads it as Markdown and sends it back as HTML. It sends bold, italic, links, lists, quotes, code and line breaks. Google has no headings, so a heading becomes bold text, and the row shows the Google form after the next read. Text that looks like a tag, such as `<br>`, stays text. A description Google holds that is longer than 600,000 characters, has more than 25,000 elements, or nests more than 200 levels deep is left out of the row. A description in Marfa nested too deeply to convert is refused, and the run names the event.

Every write sets `sendUpdates=none`, and none names guests.

## Settings

The Google settings are those of every Google connector, and [Create a Google Cloud project for Google connectors](/run/google-project) shows how to get them.

| Setting | What it holds |
| --- | --- |
| `GOOGLE_CLIENT_ID` | The ID of your Desktop app OAuth client. |
| `GOOGLE_CLIENT_SECRET` | That client's secret. A secret. |
| `GOOGLE_REFRESH_TOKEN` | The grant that the connector's setup step writes. A secret. |
| `GOOGLE_CALENDAR_READ_ONLY_CALENDARS` | Calendar IDs, separated by commas or whitespace, of read-only calendars to read, such as a shared holidays calendar. Optional. |
| `GOOGLE_CALENDAR_CONFIRM_DELETES` | Lets one held batch of deletions through. Optional. |

## What to know

- **Marfa does not change an event with other guests.** `editable` is `false` when the account can only read the calendar, someone else organizes the event, Google reserves its kind, or it has guests besides the account, since a change would reach their calendars and Marfa sends no invitation. A change to such a row is put back, and the run raises `declined:<row ID>`.
- **A safety stop holds a large removal.** If one run would remove more than 10 events and more than a quarter of a calendar, nothing is sent and the run fails. Restore the rows in Marfa to keep the events, or set `GOOGLE_CALENDAR_CONFIRM_DELETES` to the value the condition names for one run.
- **Times keep their zone.** A timed event stores UTC instants with its `timezone`. An all-day event stores local midnights in the event's zone, or else the calendar's.
- **A series cannot stop repeating from Marfa.** A `recurrence` with no rules left is refused.
- **One Google account for each instance.** A grant for another account fails the run.
- **It needs the Google Calendar API and two scopes.** Turn the API on in your project. Setup asks for `calendar.events` and `calendar.calendarlist.readonly`; leave both ticked. Without the second, the connector reads nothing.
