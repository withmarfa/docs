title: RSS
description: The entries of the Atom, RSS and JSON feeds you list, read only, and on request the pictures they point to, saved as files.
---

The RSS connector reads the feeds you list and writes one row for each entry into the feed. Nothing goes back to a feed. With `RSS_PICTURES` set, it also saves an entry's pictures as files attached to the entry.

## What it reads

Atom, RSS 2.0, RSS 1.0 (RDF) and JSON Feed, judged by the document rather than its content type. Each run fetches every feed in `RSS_FEEDS` and writes the entries that are new or changed; a feed whose server answers 304 isn't read again. Its `User-Agent` names the connector, so a feed's owner can tell who is reading.

## Types it writes

| Type | Parent type | Holds |
| --- | --- | --- |
| `rss.entry` (RSS Entry) | [Bookmark](/catalog/bookmark) | One entry of a feed |
| `rss.picture` (RSS Picture) | [File image](/catalog/file#core-file-image) | One picture saved from an entry. Declared only when `RSS_PICTURES` is `save` or `save-in-library` |

An entry row holds:

- **`url`, `title` and `description`:** the entry's link, and its title and summary as plain text.
- **`body`:** the entry's content as Markdown. HTML is converted, keeping its structure, links and images and dropping scripts, styles, frames and tracking pixels. Plain text is kept as it is.
- **`author`, `published_at`, `image_url`, `source_url`, `source_title` and `language`**, each where the feed has a value.
- **`entry_id`:** the entry's Atom `id`, RSS `guid`, RSS 1.0 `rdf:about` or JSON Feed `id`, else its link.
- **`feed_origin`:** the scheme, host and port of the feed's address.
- **`feed_hash`:** the same for every entry of one feed.
- **`rss_pictures`:** what became of the entry's pictures ([What an entry records](#what-an-entry-records)).

A row's `source_id` is the feed's hash, a colon and the entry's ID. An entry with no ID and no link is left out. A field longer than 100,000 characters is left out of its entry, and the run names it.

## Saving pictures

With `RSS_PICTURES` set to `save` or `save-in-library`, the connector fetches the pictures an entry points to, after it has read every feed, and saves each as a file. **The entry's text doesn't change:** `body` and `image_url` still hold the feed's addresses.

- **`save`** works on every entry, in the feed or in the library. A picture takes its entry's tier when it's created, and keeps it if the entry moves.
- **`save-in-library`** works only on entries in the library, so a picture arrives up to one run after its entry gets there, and is written in the library. An entry in the feed gets no new pictures.

The connector never moves an entry to the library.

### What is fetched

The connector reads an entry's `image_url`, then the Markdown images in its `body`, each address once, up to 20 for each entry. It fetches only `https` addresses, never a private host unless `RSS_PRIVATE_HOSTS` allows it, and keeps only PNG, JPEG, GIF, WebP, AVIF and HEIC files, judged by their bytes. An `http` address is recorded as not kept, and an SVG file is refused. The [README](https://github.com/withmarfa/marfa-connectors/blob/main/connectors/rss/README.md#what-is-saved) has every fetch rule.

### The picture rows

Each saved picture is an `rss.picture` row with the source `rss`, and an `attached-to` connection runs from it to its entry.

| Field | What it holds |
| --- | --- |
| `source_url` | The address the picture was saved from, in the standard form a URL parser writes |
| `title` | `p-`, 12 characters of a hash of that address and the extension for its type, such as `p-0123456789ab.png` |
| `blob_ref`, `mime_type` | The file and its type, as for every file |

To find an entry's pictures, read the `attached-to` connections that end at the entry, and match each to an address in the entry's text by `source_url`, never by title.

### What an entry records

`rss_pictures` is a read-only field the connector sets. An entry without it has had no picture work done.

| Key | What it holds |
| --- | --- |
| `text` | A hash of the `body` and `image_url` the addresses were read from |
| `saved` | The addresses whose pictures are held |
| `pending` | The addresses still to try, or not reached yet |
| `not_kept` | Each address given up on, with a reason |
| `attempts` | For a pending address, how many runs it has failed in |
| `over` | How many addresses past the first 20 were not read |

A reason is `removed` (a person moved the picture to the bin or purged it), `not_https`, or what the fetch gave: `invalid_address`, `private_address`, `tracker`, `too_many_redirects`, `bad_status`, `too_large`, `timed_out`, `fetch_failed`, `not_a_picture`, `svg`, `one_pixel`, `too_large_dimensions` or `upload_failed`. The addresses aren't secrets, so a feed shouldn't carry signed ones.

### Retries and limits

A failure that may pass, such as a timeout or a busy host, is tried in three runs in all, then recorded as not kept. Any other address in `saved` or `not_kept` isn't fetched again until the entry's text changes.

Each run fetches at most 100 pictures and 200 MiB, and starts no fetch after 10 minutes. Reaching a limit raises `pictures:limit`, and the next run carries on. A failure in the pictures raises `pictures:failed` and doesn't fail the feeds.

### When an entry leaves

When an entry is archived, in the bin or purged, the next run archives its pictures. When the entry is active again, the run after brings back those its text still points to. It brings back only pictures it archived, and never puts a picture in the bin or purges one.

A picture a person moved to the bin or purged is never saved again for that entry. A picture the text stops mentioning is kept.

## What goes back

Nothing. The connector never writes to a feed, and never archives an entry, moves it to the bin or removes it. An entry a feed drops stays as last written, and so do the rows of a feed you take out of `RSS_FEEDS`. A row you move to the bin or purge isn't written back. The only rows it archives are pictures, as above.

## Settings

| Setting | What it holds |
| --- | --- |
| `RSS_FEEDS` | The feeds to read, one for each line or separated by whitespace. A secret. |
| `RSS_PRIVATE_HOSTS` | Host names that may resolve to this machine or a private network, separated by whitespace. Optional. |
| `RSS_PICTURES` | `addresses` (the default), which fetches nothing, `save` or `save-in-library`. Any other value stops the start. Optional. |

A feed in `RSS_FEEDS` is an `http` or `https` address, or `name=address`. **Name a feed whose address or token may change:** the name then identifies the feed, and its rows carry on. Without a name, a changed address or query starts new rows. Credentials in an address go as Basic authorization to that address's origin only.

## What to know

- **A feed's address is a secret,** since a private feed's address carries its token. Logs, reports and rows carry only the feed's origin and hash.
- **It never fetches from a private network** unless `RSS_PRIVATE_HOSTS` names the host, whether a feed lists it or redirects to it. A picture may use a listed host only when it's the host of the entry's own feed.
- **A feed is skipped, and named in the run,** when it's too large, too slow to read or answers with a status other than 200 or 304. A 410 stops it until you change its address. A 301 or 308 is followed, and each run says the feed moved. The [README](https://github.com/withmarfa/marfa-connectors/blob/main/connectors/rss/README.md#limits-and-conditions) has the limits.
- **An entry without a date** is dated by when the connector first stored it, and keeps that date.
- **Treat `body` as untrusted.** The conversion drops what can run, but the text, links and images are still the feed's own.
- **A body too large or too slow to convert is left out,** and the run names the feed. A JSON Feed entry falls back to its `content_text`. A feed that ran out of time is read whole again on the next run.
- **Other feeds carry on.** A run fails only when none of the feeds could be read.

## Run it

[Run a connector](/run/run-a-connector) uses this connector as its example, with `RSS_PICTURES` left at `addresses`. To save pictures, the key also needs write on `rss.picture` and on the `attached-to` connection:

```bash
marfa keys create --label rss --source rss --type-permission rss.entry=write \
  --type-permission rss.picture=write --edge-permission attached-to=write \
  --metadata-permission types=write --default-tier feed
```

**The connector refuses a key that holds more or less than its setting needs,** and names what is wrong. Changing `RSS_PICTURES` therefore means revoking the key with `marfa keys revoke <key-id>` and making one of the other shape.

The connector's [README](https://github.com/withmarfa/marfa-connectors/blob/main/connectors/rss/README.md) has the full setup.
