Nothing is written back to a feed. An entry a feed drops stays as it was last written. A feed you remove from the list stops being read and leaves its rows. Trash or purge a row in Marfa to remove it. The connector does not write it back.

## What it brings

Each entry is an `rss.entry`, a kind of bookmark, read from Atom, RSS or JSON Feed. `title` and `description` are plain text and `body` is Markdown. `body` is text a feed wrote, so treat it as untrusted.

An entry's identity is its feed plus its id, which is its Atom `id`, RSS `guid` or JSON Feed `id`, else its link. An entry with a new title keeps its row, and a changed id makes another. Give a feed a name when its address may change or carries a token: `name=https://example.com/feed.xml`. The name then identifies the feed, and its rows stay when the address moves. Without a name, the address identifies it. Two spellings of one address, such as `http` and `https`, or with and without a trailing slash, are one feed. A different path or query is not.

`rss_feeds` is a secret, because a private feed's address can carry a token. Put one address on each line. An entry that is not an `http` or `https` address stops the run. Credentials in an address are sent only to that address's own origin.

The connector does not fetch this machine or a private network. Name a host in `rss_private_hosts`, one host on each line, to read a feed whose name resolves there. A picture may use that host only when it is the same host as the feed the entry came from.

A feed is skipped when it is larger than 24 MiB, holds more than 5,000 entries or 300,000 elements, redirects more than five times, or is not Atom, RSS or JSON Feed. A feed that answers 410 is not asked again while its address stays the same.

## Pictures

`rss_pictures` is `addresses` or `save`. The default, `addresses`, keeps picture addresses in the entry's text and fetches nothing. `save` fetches each HTTPS picture and stores it as an `rss.picture` attached to the entry. The entry's text is not rewritten. An `http` address is never fetched. Any other value stops the run.

A picture you trash or purge is not saved again for that entry. One the text no longer mentions is kept. Each entry contributes at most 20 pictures. Each run fetches at most 100 pictures, 200 MiB and 10 minutes of fetching, then continues on a later run. With `save`, archiving or trashing an entry archives the pictures this connector saved for it.

## Install

Store the feeds and the other settings as [Give a connector its settings and secrets](/use/connector-settings) describes. The plugin's `plugin.json` lists every setting.

Install the plugin from its source folder, as [Install a plugin](/use/install-a-plugin) describes. Its connector runs on a connector host ([Run a plugin's connector](/use/run-a-plugin-connector)).
