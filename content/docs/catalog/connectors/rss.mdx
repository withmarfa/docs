The RSS connector reads the feeds you list and writes one row for each entry into the feed. It only reads: nothing goes back to a feed.

## What it reads

Atom, RSS 2.0, RSS 1.0 (RDF) and JSON Feed. It reads a feed by what the document is, not by the content type its server names, and skips a document in any other format.

Each run fetches every feed in `RSS_FEEDS` and writes the entries that are new or changed. A feed whose server answers 304 is not read again. Every request carries a `User-Agent` that names the connector, so a feed's owner can tell who is reading.

## Types it writes

| Type | Parent type | Holds |
| --- | --- | --- |
| `rss.entry` | [Bookmark](/catalog/bookmark) | One entry of a feed |

An entry row holds the entry's link as `url`, its `title` and `description` as plain text, and its `body` with the markup the feed gave. It also holds `author`, `published_at`, `image_url`, `source_url`, `source_title` and `language`, each only where the feed has a value. Three fields say where it came from:

- `entry_id`: the entry's ID in its feed, which is an Atom `id`, RSS `guid` or JSON Feed `id`, else its link.
- `feed_origin`: the scheme, host and port of the feed's address.
- `feed_hash`: the same for every entry of one feed.

A row's `source_id` is the feed's hash, a colon and the entry's ID. An entry with no ID and no link is left out. A field longer than 100,000 characters is left out of the entry, and the run names it.

## What goes back

Nothing. The connector never writes to a feed. It also never archives, trashes or removes a row: an entry a feed drops stays in Marfa as last written, and so does a feed you take out of `RSS_FEEDS`. Trash or purge a row in Marfa to remove it, and the connector does not write it back.

## Settings

| Setting | What it holds |
| --- | --- |
| `RSS_FEEDS` | The feeds to read, one for each line or separated by whitespace. A secret. |
| `RSS_PRIVATE_HOSTS` | Host names that may resolve to this machine or a private network, separated by whitespace. Optional. |

An entry in `RSS_FEEDS` is an `http` or `https` address, or `name=address`. A feed with a name keeps its rows when its address or token changes, since the name identifies it. Without a name the address identifies the feed, and a changed address or query starts new rows. An address may carry credentials, which go as Basic authorization to that address's origin only.

## What to know

- **A feed's address is a secret**, since a private feed's address carries its token. The connector keeps it out of every log and report, and entries carry only the feed's origin and hash.
- **It never fetches from a private network** unless you name the host in `RSS_PRIVATE_HOSTS`, whether a feed lists it or redirects to it.
- **A feed is skipped, and named in the run,** if it is larger than 24 MiB, has more than 5,000 entries or 300,000 elements, takes more than 30 seconds to read, redirects more than five times, or answers with a status other than 200 or 304.
- **A 410 stops a feed** until you change its address or remove it.
- **A moved feed is still read.** A permanent redirect (301 or 308) is followed, and each run says the feed moved. Name the feed before you change its address so its rows stay.
- **An entry without a date** is dated by when the connector first stored it, and that date does not move.
- **Treat `body` as untrusted.** The connector does not clean the markup it keeps.
- **Other feeds carry on.** A run fails only when none of the feeds could be read.
