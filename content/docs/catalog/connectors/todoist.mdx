title: Todoist

The Todoist connector keeps the tasks of one Todoist account in the feed, and carries changes you make to them in Marfa back to Todoist.

## What it reads

Every task in the account, through Todoist's Sync API. The first run reads all open tasks, then the tasks completed in the last 12 weeks, and asks about each row still open in Marfa that neither list names. A task deleted in Todoist is archived, and one completed earlier is read as completed.

It also follows the account's projects. When a project is archived or deleted, or the account leaves a shared project, the next run archives the rows of its tasks, completed tasks and subtasks included. An older completed task in a project that is unarchived stays archived.

## Types it writes

| Type | Parent type | Holds |
| --- | --- | --- |
| `todoist.task` | [Task](/catalog/task) | A Todoist task. Title, description, priority, due date and completion are the core task's. |

Beside the core task fields, a `todoist.task` has these:

| Field | What it holds |
| --- | --- |
| `todoist_id` | The Todoist task this row is. A row without one has not been sent to Todoist yet. |
| `project_id` | The project the task sits in. |
| `section_id` | The section of that project, if it has one. |
| `parent_id` | The task this one is a subtask of. Read only. |
| `labels` | The task's labels, by name. |
| `child_order` | Where the task sits among its siblings. Read only. |
| `recurrence` | How the task repeats, in Todoist's own words, such as `every day at 2pm`. Absent for a task that does not repeat. |

## What goes back

Unless the connector is read only, these changes reach Todoist:

- **A new row.** A `todoist.task` made in Marfa becomes a task, in the project and section it names with its labels, or in the Inbox if it names no project.
- **Edits.** The title, description, priority, due date, recurrence, labels, project and section, and completing or reopening the task. Only fields that changed are sent, so an edit never undoes a move made in Todoist.
- **Trash.** Trashing a row deletes the task, and its subtasks, in Todoist. A restore makes the task again if Todoist no longer has it.

The parent and the order among siblings do not travel, and archiving a row sends nothing.

## Settings

| Setting | What it holds |
| --- | --- |
| `TODOIST_API_TOKEN` | The account's API token. A secret. |
| `TODOIST_READ_ONLY` | `true` for a read-only connector. Optional. Nothing goes back, and a change made in Marfa to a synced field is put back and named. |

## What to know

- **Every `todoist.task` syncs.** Whoever made a row and under whatever source, it is sent to Todoist. A task meant to stay in Marfa is a `core.task`.
- **Use one Todoist account for each instance.** A connector for a second account would create, in that account, every row of the type that has no link yet.
- **A Todoist token cannot be narrowed to reading.** `TODOIST_READ_ONLY` is the only guard when you try the connector on a real account.
- **A recurrence needs a date.** Clearing only the date of a row that still has a recurrence is put back, and the run names the row. Clear the recurrence first.
- **Todoist can refuse a change**, such as a label or a move to a project that no longer exists. The run names the row.
