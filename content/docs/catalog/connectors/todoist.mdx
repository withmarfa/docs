## What it brings

Every task in the account comes in through Todoist's Sync API, as `todoist.task`. A full read, which a first run is, lists open tasks, then tasks completed in the last 12 weeks, then asks about each item still open in Marfa that neither list names. A task deleted in Todoist is archived. A task completed earlier is read as completed.

It follows the account's projects. When a project is archived or deleted, or the account leaves a shared project, the next run archives that project's tasks, completed tasks and subtasks included.

`status` is `not_started` while a task is open and `completed` once it is checked. `recurrence_text` holds Todoist's own words, such as `every day at 2pm`. The core `recurrence` field holds the same repeat as calendar rules when those words state it exactly, and is absent otherwise, including a repeat counted from completion. `recurrence` is read only.

The link to the task is `todoist_id`. An item without one has not been sent yet.

## What goes back

Every `todoist.task` on the instance is carried back, whoever made it. A task that should stay in Marfa is a core task, not a `todoist.task`.

Unless `todoist_read_only` is `true`, Marfa sends the title, description, priority, due date, `recurrence_text`, labels, project and section, and completing or reopening. Only fields that changed are sent. A new item is made in the project and section it names, or in the Inbox when it names no project. Trashing an item deletes the task in Todoist, and its subtasks. A restore makes the task again when Todoist no longer has it.

The core `recurrence`, the parent and the order among siblings are not sent. Archiving an item sends nothing. Clearing only the date of an item that still has `recurrence_text` is put back: clear the repeat first. A label or a move Todoist refuses is named on the run.

One Todoist account per instance. A second account's connector would create, in that account, every item of this type that has no link yet. A Todoist token cannot be limited to reading, so `todoist_read_only` is the guard when you try the connector on a real account.

## Settings you decide

| Setting | What you decide |
| --- | --- |
| `todoist_api_token` | Secret. The account's API token. Required. |
| `todoist_read_only` | `true` to send nothing back. A change to a synced field is put back and named. Default is off. |

Store the token with `marfa plugins secret` and the read-only choice with `marfa plugins settings`, as [Give a connector its settings and secrets](/use/connector-settings) describes. The plugin's `plugin.json` lists every setting, including the API address.

## Install

Install the plugin from its source folder, as [Install a plugin](/use/install-a-plugin) describes. Its connector runs on a connector host ([Run a plugin's connector](/use/run-a-plugin-connector)).
