## Identifier

- **Segments:** two or more, separated by dots. Each starts with a lowercase letter and holds lowercase letters, digits, hyphens and underscores. The whole identifier is at most 128 characters ([`types/id-grammar`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesid-grammar)).
- **Root:** `app` followed by exactly two more segments, as in `app.<app name>.<type>`, `user` for your own, as in `user.<type>`, or a publisher name of your own, as in `acme.deal`.
- **Marfa's roots:** you can't register a type under `core`, `system` or `marfa`. Marfa answers `403 forbidden` ([`types/id-reserved-namespace`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesid-reserved-namespace)).
- **Reserved roots:** a publisher name can't be one of the reserved type roots below.

## Fields

- **Kind:** each field has one of the [field kinds](/catalog/field-kinds). An `enum` needs `enum_values`, a list of strings with at least one value. An `array` needs `items_type` ([`types/field-grammar`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesfield-grammar)).
- **Array elements:** a write is refused with `400 invalid_properties` if an element of an `array` field isn't a value of its `items_type`, and `details.errors` names the field and the element's position, as `names.1`. Marfa judges the properties the item would hold after the write, so an item that already stores a wrong element refuses any write that carries `properties` or changes its type and leaves that array in place, and the item stays as it was. The check covers `links` and `attachments`, which every type has, too. An `items_type` that isn't a field kind leaves the elements unchecked ([`types/array-items`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesarray-items), [`types/array-items-refused`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesarray-items-refused), [`types/array-items-unnamed`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesarray-items-unnamed)).
- **Keys:** a field definition takes `type`, `description`, `required`, `enum_values`, `items_type`, `format`, `searchable`, `maxLength` and `maxItems`. Marfa refuses any other key with `400 invalid_schema`, so a field has no `minimum` or `maximum` ([`types/unknown-key`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesunknown-key)).
- **Name:** a field can't take one of the reserved field names below.
- **Thumbnail:** a type holds at most one `thumbnail` field, and it can't be named `title`, `body`, `description` or `name` ([`types/thumbnail-one`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesthumbnail-one), [`types/thumbnail-name`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesthumbnail-name)).
- **Display hints:** `title_field` and `body_field` name a field that the type declares or inherits, and neither names a thumbnail ([`types/field-grammar`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesfield-grammar), [`types/thumbnail-hint`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesthumbnail-hint)).

## Parent and inheritance

- **Parent:** `parent` names a registered type. Types can't form a loop, and no type has more than ten ancestors ([`types/parent-unknown`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesparent-unknown), [`types/parent-chain`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesparent-chain)).
- **What a subtype can do:** it takes every field of its parent. It can add fields, redeclare an inherited field unchanged or with a new `description`, and make an inherited field required ([`types/child-adds`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typeschild-adds)).
- **What it can't do:** change an inherited field's `type`, `format`, `items_type`, `searchable`, `maxLength`, `maxItems` or `enum_values`, or make a required field optional. Marfa answers `400 inheritance_violation` ([`types/child-shape`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typeschild-shape)).
- **Without inheriting:** `compatible_with` names a type that yours is readable as. Yours must require every field that type requires. Each field of that type that yours declares or inherits must be readable as that type's: the same kind, or `url`, `email`, `datetime`, `date`, `thumbnail` or `enum` where that type's is a `string`, or `integer` where it is a `number`; for an `array`, the same `items_type`; for an `enum`, values drawn from that type's; and, where both name a `format`, the same one. Marfa refuses a claim that doesn't hold with `422 compatible_with_violation` ([`types/compatible-with`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typescompatible-with), [`types/compatible-with-refused`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typescompatible-with-refused)).

## Roles

`roles` takes `container` alone. A type with the role can be the target of an [`in-collection`](/catalog/edges#in-collection) edge ([`types/field-grammar`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesfield-grammar)).

## Merge policy

A `merge_policy` names a `default` strategy and, if you want, a strategy for each field. It can name only fields that the type declares or inherits ([`types/merge-policy`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesmerge-policy), [`types/merge-policy-refused`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesmerge-policy-refused)). A strategy is one of two values, which apply when two writers change the same field and the later write asks Marfa to resolve it:

| Strategy           | What happens                                                                                           |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| `last_writer_wins` | The item takes the later writer's value.                                                               |
| `keep_both_copies` | The item keeps its value, and the other writer's value goes to a new item tagged `conflicted-copy`.    |

## Retention policy

A `retention_policy` sets how long Marfa keeps the type's items in the feed. It takes one key, `feed_days` ([`types/retention-policy-values`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesretention-policy-values)):

- **A whole number from 1 to 36500:** the `feed-expiry` [housekeeping job](/guides/housekeeping) moves a feed item of the type to the bin once more than that many days have passed since it arrived.
- **`null`:** the type keeps its feed items, even when a parent type sets a window.
- **Left out:** the type takes its parent's window, so a type that no type in its chain gives a window keeps its items ([`types/retention-policy-merge`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md#typesretention-policy-merge)).

Marfa counts from when the item arrived, and a refresh of the item by its natural key doesn't restart the count. Only active feed items expire. Library items, archived items and items you brought back from the bin stay. Marfa refuses another value or another key in the policy with `400 invalid_schema`. `GET /types/{id}` shows the window the type has after inheritance, and `GET /types` shows only the one the type declares itself.
