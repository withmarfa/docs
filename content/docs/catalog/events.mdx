The table lists every event Marfa sends, where it goes and which writes send it. A write that changes a type, an edge type, a source, a key, the instance's configuration or a webhook subscription sends nothing, and neither does a blob upload ([`events/settings-silent`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/events.md#eventssettings-silent)).

<include cwd>src/generated/event-types.md</include>

- `item.updated` comes with a write that changes the item, and with a patch that only adds or removes an edge, which carries the version the item already held ([`events/update-edges-only-announced`](https://github.com/withmarfa/marfa/blob/v0.0.89/conformance/spec/events.md#eventsupdate-edges-only-announced)). A write that would leave the item as it stands answers `acknowledged: true` and announces nothing ([`versions/unchanged-silent`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/versions.md#versionsunchanged-silent)).
- `edge.updated` comes with an update to an existing edge, a move and a bulk update included ([`edges/update-announced`](https://github.com/withmarfa/marfa/blob/v0.0.89/conformance/spec/edges.md#edgesupdate-announced)). A new edge sends `edge.created`.
- Tags written with an item through `POST /items` or `POST /items/bulk` come in its `item.created` or `item.updated`, with no `metadata.changed`.
- `item.state_changed` comes only for the item a transition names. An item the transition takes to the bin or brings back with it gets `item.trashed` or `item.restored`.
- `attention.raised` goes only to a credential that holds `instance.read`, and never to a stream that names a type or to a copy stream. An entry of kind `fault` sends it at once. While the database fails, a webhook gets it from memory, with no `event_id`, outside the delivery list and with no redelivery.
- The frames whose names start with `stream_`, and `catchup_too_old`, `cursor_ahead` and `reach_changed`, come only on a stream and describe the stream itself.
