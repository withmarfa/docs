description: The keys a field or table column takes, and the values each kind accepts.
job: A builder looks up the kinds a field or table column takes and the values each accepts.

**Marfa refuses a definition that breaks a rule here with `400 invalid_schema`,** naming the key, and **a value a field doesn't accept with `400 invalid_properties`,** naming the field.

## Field keys

A field definition takes these keys and nothing else:

| Key | What it holds |
| --- | --- |
| `type` | Required. One of the [kinds](#kinds). |
| `label` | A name for people, at most 100 characters. Left out, Marfa makes one from the field name: `due_at` is `Due At`. |
| `description` | What the field holds. |
| `required` | `true` when every item must hold it. |
| `enum_values` | For an `enum`, or an `array` of `enum`: at least one string. Refused on any other kind. |
| `status_values` | For a `status`: its words. See [Status words](#status-words). |
| `items_type` | Required for an `array`: the kind of its elements. A name that isn't a kind leaves them unchecked. |
| `items_fields` | For an `array` of `object`, the members of each entry. See [Lists of entries](#lists-of-entries). |
| `format` | A refinement of the kind. See [Formats](#formats). |
| `searchable` | `false` leaves it out of search. |
| `max_length` | For a `string` or `enum`, the most characters, as Unicode code points. At least 1, and not on a `currency` field. |
| `max_items` | For an `array`, the most elements, 10,000 by default. |
| `minimum`, `maximum` | For a `number` or `integer`, the range, each end included. Whole on an `integer`, and a `minimum` above the `maximum` is refused. |

**A type holds at most one `thumbnail` field,** counting inherited ones, never named `title`, `body`, `description` or `name` and never an array's `items_type`.

## Kinds

| Kind | Holds |
| --- | --- |
| `string` | Text of up to `max_length` characters: by default 1,000,000 for the [`body_field`](/catalog/type-definition#display-hints), 100,000 for any other. |
| `number` | A number within the range. A whole number must be written in the shortest digits of its 64-bit float, so `1500000000000000001` and `-0` are refused: send one that must keep every digit as a `string`. |
| `integer` | A whole number from -9007199254740991 to 9007199254740991, written the same way. |
| `boolean` | `true` or `false`. |
| `url` | An absolute URL that the WHATWG URL Standard accepts once whitespace is trimmed from both ends. Marfa stores it without the whitespace. |
| `email` | An email address. |
| `datetime` | `YYYY-MM-DD`, or a date, `T`, a time (`HH:MM`, `HH:MM:SS`, with an optional fraction) and `Z` or a `±HH:MM` offset, such as `2026-03-01T09:30:00Z`. A time with no zone is refused. |
| `date` | `YYYY-MM-DD`, on a day the calendar has. A date with a time is refused. |
| `enum` | One of the field's `enum_values`. |
| `status` | One of the field's status words. |
| `array` | A list of `items_type` elements, or of entries `items_fields` takes. |
| `object` | A JSON object. |
| `thumbnail` | A PNG, JPEG or WebP data URI that decodes to at most 16 KiB. |

The rule on whole numbers holds at any depth, in an edge's `properties` and an extension's data too.

## Status words

A `status` field says where an item stands, in words the type chooses. Each word belongs to one of four groups every type shares: `not_started`, `in_progress`, `completed` and `canceled`. A filter selects by group with `status_group`.

- **`status_values`** is a list of `{ "value": "<word>", "group": "<group>" }`. A word is a lowercase letter, then up to 63 lowercase letters, digits or underscores, and appears once.
- **A type has at most one status field,** and an `array` can't hold status words.
- **A write that sets an undeclared word is refused,** but an item already holding a word its type dropped keeps it.
- **A subtype adds words** by declaring the field with only the new ones, as [Type definition](/catalog/type-definition#parent-and-inheritance) says.

## Lists of entries

`items_fields` gives each entry of an `array` of `object` its members, such as an email and a label. A member is a `string`, `email`, `url`, `enum`, `boolean`, `integer`, `number`, `date` or `datetime`, and takes the field keys `type`, `label`, `description`, `required`, `enum_values`, `format`, `max_length`, `minimum` and `maximum`. An entry holds at least one member, only declared ones and every required one, or is refused with its position and member, as `emails.1.value`.

## Columns

A table a type declares under `tables` takes `columns`, and optionally `label`, `description` and `order`. A [`core.table`](/catalog/table) item holds its own `columns` as a property. **Either way, a column takes these keys and nothing else:**

| Key | What it holds |
| --- | --- |
| `type` | Required: `string`, `email`, `url`, `enum`, `boolean`, `integer`, `number`, `date`, `datetime`, or `item`, which holds another item's ID. |
| `label`, `description`, `required` | As on a field, `required` for every row. |
| `enum_values`, `format`, `max_length`, `minimum`, `maximum` | As on a field of the same kind, and not on an `item` column. |
| `type_constraints` | For an `item` column, the registered types its IDs may name, or the type that declares the column. |
| `adds_up` | `sum`, `average`, `min`, `max` or `count` on a `number` or `integer`; `min`, `max` or `count` on a `date` or `datetime`; `count` on any other kind. |
| `searchable` | `true` puts a `string`, `email` or `url` column in full-text search, on at most 8 columns of a table. |

A table holds at most 64 columns and a type at most 32 tables. A name is a lowercase letter, then up to 63 lowercase letters, digits or underscores. A table a type declares can name in `order` one of its own `datetime`, `number`, `integer` or `string` columns. A `core.table` item can't. A type that breaks a rule is refused `400 invalid_schema`, and a `core.table` item `400 invalid_properties`, naming the path under `columns`.

## Formats

| Format | What Marfa does |
| --- | --- |
| `url`, `email`, `date` or `thumbnail` on a `string` | Stores the field as that kind. An array of strings takes `url`, `email` or `date`. A `datetime` is written as a kind, never a format. |
| The field's own kind, such as `url` on a `url` | Stores the field without the `format`. |
| `currency` on a `string` | Takes three capital letters A to Z, such as `EUR`, whether or not ISO 4217 assigns the code. No `max_length`. |
| `bcp47`, `iso3166` or `phone` on a `string`, not an array | Keeps the format as a label and doesn't check the value. |
| Any other format, or one where the rows above don't allow it | Refuses the type with `400 invalid_schema`. |

The rules behind this page are in the [types](https://github.com/withmarfa/marfa/blob/main/conformance/spec/types.md), [items](https://github.com/withmarfa/marfa/blob/main/conformance/spec/items.md), [search and filters](https://github.com/withmarfa/marfa/blob/main/conformance/spec/search-and-filters.md) and [device](https://github.com/withmarfa/marfa/blob/main/conformance/spec/device.md) chapters of the contract.
