**Marfa refuses a definition that breaks a rule with `400 invalid_schema`** unless the rule names another answer. [Define a type](/build/define-a-type) shows how to register one, and [Field kinds](/catalog/field-kinds) has the rules for its fields.

## Identifier

[Items and types](/items-and-types) explains the namespaces a type can sit in.

- **Grammar:** two or more dot-separated segments, each starting with a lowercase letter and holding only lowercase letters, digits, hyphens and underscores. At most 128 characters, and exactly two segments after `app`, as in `app.readinglist.entry`. Anything else is refused `400 validation_error`.
- **`core`, `system` and `marfa`:** refused `403 forbidden`, whatever the credential.
- **Other reserved roots:** every root in the list below except `app`, `user`, `core`, `system` and `marfa` is refused `400 validation_error`. A root is the whole first segment, so `core-pub` is allowed.

## Label and plural

A type's `label` names one item, such as `Recipe`, and its `plural` names a list of them, such as `Recipes`. Each is optional text of at most 100 characters.

- **A missing label is made** from the identifier's last segment, split into words at each hyphen and underscore, each word capitalized: `user.reading-list` is `Reading List`.
- **A missing plural is made** from the label when the type is read, by the regular English rule, so `Story` makes `Stories`. Name the plural where the rule is wrong, as in `People`. `GET /types` answers only a declared plural.

## Parent and inheritance

| Rule | Marfa allows or refuses |
| --- | --- |
| `parent` | Names a registered type, with no loop and at most ten ancestors. Refused `400 validation_error`. |
| A subtype may | Add fields. Redeclare an inherited field unchanged, or with a new `description` or `label`. Make an inherited field required. Add a range to an inherited `number` or `integer` field, or narrow its range. Add status words. |
| A subtype may not | Change an inherited field's `type`, `format`, `items_type`, `items_fields`, `searchable`, `maxLength`, `maxItems` or `enum_values`. Widen or drop its range. Make a required field optional. Refused `400 inheritance_violation`, naming the field. |
| Write access | A new `parent` that isn't a platform type needs write on that type; keeping one doesn't. Refused `403 type_not_permitted`. |

**A change to a parent that a subtype would break is refused the same way**, such as a new parent field in another shape than a subtype's.

### Status words

A subtype inherits its parent's [status field](/catalog/field-kinds#status-words) and its words. To add words, it declares the same field with only the new ones, such as `blocked` in the `in_progress` group, and `GET /types/{id}` answers them after its parent's. Marfa refuses `400 inheritance_violation` a word a type above already declares, the field under another name, and a parent change that leaves a subtype's field with no words.

### Compatible with

`compatible_with` names a type that yours is readable as, without inheriting from it. A claim that doesn't hold, or that names an unregistered type, is refused `422 compatible_with_violation`. The claim holds when:

- Yours requires every field the target requires.
- Each target field that yours declares or inherits has the same kind. A `string` target field also accepts `url`, `email`, `datetime`, `date`, `thumbnail`, `enum` or `status`, and a `number` accepts `integer`.
- An `array` has the same `items_type`, and the same `items_fields` where either names them. An `enum` takes values from the target's, and a `status` field takes words from the target's, each in the same group.
- A range is no wider than the target's.
- Where both name a `format`, it's the same one. A target's `currency` field needs `currency` on yours, and a `currency` field reads as a plain `string`.

A replacement or deletion that breaks another type's claim is refused the same way, and `details.dependent_type_ids` names the claimants. A new target that isn't a platform type needs write on it, as a `parent` does.

## Display hints

`display_hints` says how an app shows an item of the type. It takes three optional hints:

| Hint | What it holds | Marfa refuses |
| --- | --- | --- |
| `title_field` | The name of the field that names an item. | A field the type and its ancestors don't declare, or a `thumbnail` field. |
| `body_field` | The name of the field that holds the item's text, **in Markdown**. Apps render it, and a device makes [edges](/catalog/edges) from its links. Marfa doesn't check it. | The same as `title_field`. |
| `icon` | An [Iconify](https://iconify.design/) icon ID, `<set>:<name>`, from the `lucide` set (`@iconify-json/lucide` 1.2.149) or, for brand marks, the `simple-icons` set (`@iconify-json/simple-icons` 1.2.101), such as `lucide:star` or `simple-icons:github`. | A bare name such as `star`, another set, a name the set's version lacks, an alias such as `lucide:alert-circle`, an icon the set marks hidden, or a wrong-case or padded ID. Refused `400 invalid_schema`, naming `display_hints.icon`. |

**The icon sets are fixed because apps carry their own copy**, so an icon draws offline and looks the same in every app. The accepted IDs are in [`icon-set-lucide.json`](https://github.com/withmarfa/marfa/blob/main/packages/types/generated/icon-set-lucide.json) and [`icon-set-simple-icons.json`](https://github.com/withmarfa/marfa/blob/main/packages/types/generated/icon-set-simple-icons.json).

**Each hint comes from the nearest type that sets it**, so a type that sets only an `icon` keeps the title and body its parent names. `GET /types` lists only the hints each type declares.

### Names and previews

The server and a device name an item by one rule, so they show the same name, offline included.

- **The name** comes from the first of these fields that holds text: `title_field`, `title`, `name`, `body_field`, `body`, `text`, `filename`, `url` and `address`. Marfa takes the first line, collapses each run of whitespace and keeps at most 120 characters, ending in `…` where it cuts.
- **A name taken from `body_field`, `body` or `text` loses its Markdown**, so a note whose body starts `# Plan` is named `Plan`. A name from any other field keeps every character.
- **An item with no name** is `Untitled` to the server. A device answers that it has none, so each app chooses its own word.
- **A preview** is the body field's text without its Markdown, at most 240 characters, leaving out the line the name came from and every line before it. Only a device makes one.

### The owner's icon

**The owner can choose the icon of any type**, a shipped or connector type included, without replacing it:

```bash
marfa types set-icon user.recipe lucide:chef-hat
marfa types clear-icon user.recipe
```

The same two operations are [set a type's icon](/api-reference/types/setTypeIcon) and [clear a type's icon](/api-reference/types/clearTypeIcon).

- **Reads answer it in place of the author's icon**, and a subtype with no icon of its own shows it. Replacing the type keeps it, and deleting the type discards it.
- **Devices take it at their next catch-up**, or when a follow next opens its stream. No event announces it.
- **Who can change it:** the owner, a local process, or a key with `schema.write` and write on the type. Otherwise it's refused `403 forbidden` or `403 type_not_permitted`.

## Roles

`roles` takes `container` alone. A `container` type can be the target of an [`in-collection`](/catalog/edges#in-collection) edge.

A type also plays its ancestors' roles. [List types](/api-reference/types/listTypes) answers `roles`, every role it plays, and `own_roles`, those it declares. **When you [replace a type](/api-reference/types/replaceType), send its `own_roles` as `roles`.**

## Merge policy

`fields` maps a field the type declares or inherits to a strategy, and `default` covers the rest. Left out, `default` is `last_writer_wins`.

| Strategy | When a later write collides with another on the field |
| --- | --- |
| `last_writer_wins` | The item takes the later writer's value. |
| `keep_both_copies` | The item keeps its value, and the later writer's value goes to a new item tagged `conflicted-copy`. |

## Retention policy

`retention_policy` takes only `feed_days`:

| `feed_days` | Effect |
| --- | --- |
| A whole number from 1 to 36500 | The `feed-expiry` [housekeeping job](/run/housekeeping) moves the type's feed items to the bin once more than that many days have passed since their `created_at`. A natural-key upsert keeps `created_at`, so a refresh doesn't restart the count. |
| `null` | The type keeps its feed items, even when a parent sets a window. |
| Left out | The type takes its parent's window, and keeps its feed items where no type in the chain sets one. |

`GET /types/{id}` shows the window after inheritance, and `GET /types` shows only the window the type declares.
