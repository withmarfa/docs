A permission opens operations and no items. What a credential reads and writes is its maps' alone ([`keys-and-oauth/permissions-no-content`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#keys-and-oauthpermissions-no-content)).

## Access to types and edge types

A key's `type_permissions` and `edge_permissions` name a type or an edge type, a wildcard such as `core.*`, or `*`, each at one level. A name that no entry covers is denied.

| Level   | Lets the credential                                           | Maps       |
| ------- | ------------------------------------------------------------- | ---------- |
| `read`  | Read the type's items, or the edge type's edges.              | Type, edge |
| `write` | Write them. A `write` grant includes `read`.                  | Type, edge |
| `none`  | Nothing: it denies a type that a wildcard entry would grant.  | Type       |

A `write` grant includes `read` ([`keys-and-oauth/type-write-includes-read`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#keys-and-oauthtype-write-includes-read), [`keys-and-oauth/edge-write-includes-read`](https://github.com/withmarfa/marfa/blob/main/conformance/spec/keys-and-oauth.md#keys-and-oauthedge-write-includes-read)).

## Access to profile fields

A key's `profile_permissions` names `name`, `email`, `avatar`, or `*`. The wildcard covers every profile field. A field with neither an entry nor a wildcard is denied.

| Field | Levels | What write access changes |
| --- | --- | --- |
| `name` | `read`, `write` | The owner's display name. |
| `email` | `read` | Nothing. Only the owner can change the sign-in address. |
| `avatar` | `read`, `write` | The owner's picture: uploading a new one and removing it. |
| `*` | `read`, `write` | Name and picture only; email stays read-only. |

Profile write includes read. Read access to `avatar` lets a credential fetch the picture with [`GET /owner/picture`](/api-reference/owner/getOwnerPicture). An explicit key grant for email write is refused, as is the OAuth scope `profile.email:write`. OAuth uses `profile.name:write` and `profile.avatar:write` for individual fields, or `profile:write` for both ([owner and delegated profile changes](https://github.com/withmarfa/marfa/blob/main/conformance/spec/instance-claim.md#instance-claimprofile-grant-closed)).

[Access](/access) explains the maps, and [Manage keys](/run/manage-keys) shows how to give a key its access.
