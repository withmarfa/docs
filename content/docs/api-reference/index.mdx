Everything an app, a script or a connector does with an instance goes through its HTTP API, and the CLI, the TypeScript client and the Swift package all send the same requests. This reference has a page for each operation, generated from the API description, so it always matches the server. Start here for how to send a request and the rules every operation shares, then open the operation you need.

## Send a request

Send each request to your instance's address, such as `http://localhost:8600` for one on your own machine. Almost every operation takes a credential in the `Authorization` header: a key, which begins `marfa_k1_`, or an app's access token, which begins `marfa_at_`. [Access](/access) explains both, and [Manage keys](/guides/manage-keys) shows how to make a key.

A request body is JSON, sent with `Content-Type: application/json`. This request creates a note:

```http
POST /items HTTP/1.1
Host: localhost:8600
Authorization: Bearer <key>
Content-Type: application/json

{ "type": "core.note", "properties": { "title": "Reading list", "body": "Start with the essays." } }
```

Marfa answers `201 Created` with the new item and its metadata:

```json
{
  "item": {
    "id": "01a1231c-986c-7edd-8d1f-235e036b7986",
    "type": "core.note",
    "state": "active",
    "tier": "library",
    "properties": { "body": "Start with the essays.", "title": "Reading list" },
    "created_at": "2026-10-10T00:00:39.021Z",
    "updated_at": "2026-10-10T00:00:39.021Z",
    "occurred_at": "2026-10-10T00:00:39.021Z",
    "version": 1,
    "schema_version": 0,
    "source": "laptop",
    "edges": {}
  },
  "metadata": { "item_id": "01a1231c-986c-7edd-8d1f-235e036b7986", "tags": [], "extensions": {} }
}
```

A refusal answers with an `error` object instead, which [Errors](/api-reference/errors) explains.

## Groups of operations

The reference groups operations by what they act on:

| Group | What it's for | Start with |
| --- | --- | --- |
| Items | The records Marfa stores, each of a type | [Create an item](/api-reference/items/createItem) |
| Bulk actions | One change applied to every item a filter matches, as a job you can follow | [Apply a bulk action](/api-reference/bulk-actions/applyBulkAction) |
| Metadata | An item's tags, and the tags in use | [Get item metadata](/api-reference/metadata/getItemMetadata) |
| Extensions | JSON objects attached to an item, one per namespace | [List extension namespaces](/api-reference/extensions/listItemExtensions) |
| Edges | Typed, directed relationships between items | [List outbound edges](/api-reference/edges/listItemEdges) |
| Types | The types items can have, shipped and registered | [List types](/api-reference/types/listTypes) |
| Edge types | The types edges can have | [Register an edge type](/api-reference/edge-types/registerEdgeType) |
| Blobs | Bytes stored by content hash, and the stores that hold them | [Upload a blob](/api-reference/blobs/uploadBlob) |
| Folders | A folder's settings, held as a `system.folder` item | [Create a folder](/api-reference/folders/createFolder) |
| Search | Full-text search across items | [Search items](/api-reference/search/searchItems) |
| Event stream | Changes to items and edges as they happen | [Stream change events](/api-reference/event-stream/streamEvents) |
| Webhooks | Changes sent to a URL you choose | [Create a webhook](/api-reference/webhooks/createWebhook) |
| Connectors | What the instance keeps for a connector | [Register a connector](/api-reference/connectors/registerConnector) |
| Access | Keys, the owner, and app registration | [Create an API key](/api-reference/access/createKey) |
| Instance | The instance's configuration, housekeeping and audit log | [Describe the instance](/api-reference/instance/getInstance) |
| Export and restore | Archives of the instance's data | [Export items and edges](/api-reference/export-and-restore/exportData) |
