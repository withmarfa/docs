The Marfa API is a single REST surface over the typed data layer. Every endpoint is generated from the OpenAPI spec at `openapi.json` — request and response shapes, status codes, and per-endpoint error sets all live in the resource sections of this reference. This page is the map: what each endpoint group is for, so you know which section to open.

## Base URL

All requests go to one origin, with no version prefix in the path:

```bash
https://your-marfa-instance.example.com
```

Self-hosted instances set their own origin; the hosted service publishes its own. The SDKs and CLI read it from `MARFA_API_URL`.

## Authenticating

Every request carries a bearer token in the `Authorization` header — an API key or an OAuth access token. See [Authentication](/api-reference/authentication) for the token types and [Permissions](/api-reference/permissions) for how access is scoped.

## Endpoint groups

The resource sections below group endpoints by domain. Reach for a group by what you are doing, not by where it sits in the path.

| Group | Use it for |
| --- | --- |
| Items | Reading and writing user content of any type — the atomic four-layer record. |
| Edges, edge types | Typed relationships between items, and registering custom relationship types. |
| Metadata | The universal layer: tags, tier, and lifecycle state, plus tenant-wide tag listing. |
| Extensions | Namespaced sidecar JSON attached to an item, for per-app state with no identity of its own. |
| Blobs | Content-addressed binary storage for images, files, and attachments. |
| Search, export | Full-text retrieval across items, and tenant-scale archive export. |
| Types | Registering, inspecting, and removing item-type schemas at runtime. |
| Keys, auth, credentials | API-key lifecycle and the OAuth 2.1 authorization surface. |
| Profile, tenants | The calling user's own record, and tenant administration. |
| Connections, integrations | Authority grants from third-party apps and installed integrations. |
| Events, webhooks | The live SSE change stream and outbound HTTP event delivery. |
| Audit | The cross-tenant operator audit log. |

The semantics behind each group — the four-layer item, the edge cascade rules, the tier and lifecycle axes — live in the [Guides](/guides). This reference covers the wire.
