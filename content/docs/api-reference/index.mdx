Each operation has its own page, with its parameters, its request body, its responses and the error codes it can return. Send every request to your instance's address, such as `http://localhost:8600` for an instance on your own machine, with a credential in the `Authorization` header. [Rules every operation follows](#rules-every-operation-follows) covers authentication, pagination, errors and the rest of what all operations share.

## Send a request

This request lists the newest note. Replace `<credential>` with a key or an access token; [Keys and permissions](/get-started/keys-and-permissions) explains both.

```http
GET /items?type=core.note&limit=1 HTTP/1.1
Host: localhost:8600
Authorization: Bearer <credential>
```

Marfa answers with one page of items:

```http
HTTP/1.1 200 OK
Content-Type: application/json
X-Marfa-Contract: 0
X-Request-ID: 01a1156b-fda2-7b13-8f6a-2d4c9e0a5b71

{
  "data": [
    {
      "id": "01a10119-55c0-7c4e-9a3d-5e8f1b2c7d40",
      "type": "core.note",
      "state": "active",
      "tier": "library",
      "properties": { "title": "Reading list", "body": "Start with the essays." },
      "created_at": "2026-10-03T09:30:00.000Z",
      "updated_at": "2026-10-03T09:30:00.000Z",
      "occurred_at": "2026-10-03T09:30:00.000Z",
      "version": 1,
      "source": "notes-app",
      "schema_version": 0
    }
  ],
  "next_cursor": "eyJ2IjoiMjAyNi0xMC0wM1QwOTozMDowMC4wMDBaIiwiaWQiOiIwMWExMDExOS01NWMwLTdjNGUtOWEzZC01ZThmMWIyYzdkNDAiLCJrIjoiaXRlbXM6Y3JlYXRlZF9hdDpkZXNjIn0"
}
```

`next_cursor` isn't `null`, so there are more notes: send it back as `cursor` for the next page. The [List items](/api-reference/items/listItems) page describes every filter this operation takes.

## Groups of operations

The reference groups operations by what they act on. Select a group to see what it holds, or open its operations from its name.

<ApiMap />

- **Your data:** [Items](/api-reference/items/createItem) are the records Marfa stores, each of a type. [Bulk actions](/api-reference/bulk-actions/applyBulkAction) apply one change to every item a filter matches. [Metadata](/api-reference/metadata/getItemMetadata) holds an item's tags, [Extensions](/api-reference/extensions/listItemExtensions) the JSON objects attached to it by namespace, and [Edges](/api-reference/edges/listItemEdges) the typed, directed relationships between items.
- **The shape of your data:** [Types](/api-reference/types/listTypes) are the types items can have, and [Edge types](/api-reference/edge-types/registerEdgeType) the types edges can have.
- **Files:** [Blobs](/api-reference/blobs/uploadBlob) are bytes stored by content hash, and [Folders](/api-reference/folders/createFolder) hold a folder's settings.
- **Finding and following changes:** [Search](/api-reference/search/searchItems) finds items by their text. The [Event stream](/api-reference/event-stream/streamEvents) sends changes to items and edges as they happen, and [Webhooks](/api-reference/webhooks/createWebhook) send them to a URL you choose.
- **Running your instance:** [Connectors](/api-reference/connectors/registerConnector) are processes outside the server that read and write on your behalf. [Access](/api-reference/access/createKey) covers keys, the owner and OAuth client registration. [Instance](/api-reference/instance/getInstance) covers the instance's configuration, housekeeping jobs and audit log, and [Export and restore](/api-reference/export-and-restore/exportData) its archives.
