## Why Marfa exists

Building an app has never been easier. Connecting apps is still hard. Each app keeps its data in its own place, in its own shape, behind its own API: your notes in one, your tasks in another, your reading in a third. To search across them, or to see them on one timeline, you glue their APIs together. And the next app you build starts with an empty database.

Marfa is the layer in the middle. It holds one person's data in one place, in shapes that every app can read, and many apps read and write it. A notes app saves notes and a reading app saves articles. An app you write next year can show both on one timeline, without asking either of them.

## One instance, one owner

One running Marfa is an instance. An instance belongs to one person, its owner, and holds that person's data. You run it yourself, on your own machine.

Marfa is open source, under the Apache License 2.0.

## Items, types, edges and files

Everything in an instance is an item: one record, such as a note, a task, a bookmark or a message. Each item has a type, which says what the item is and which properties it carries. Marfa ships core types such as `core.note`, `core.task` and `core.bookmark`, and you can register types of your own.

Edges connect items. An `about` edge says that a note is about a book, and a `parent-of` edge puts one item under another.

A file is an item too. Its type inherits from `core.file`, and it refers to a blob: the file's bytes, addressed by their hash. An item never contains a blob.

The server is the software that answers HTTP for the instance. It is the source of truth: everything else that works with your data reads from it and writes to it.

## Permissions follow the type

If you have built for Apple's HealthKit, the model is familiar. HealthKit defines types of health data, such as steps and heart rate, and an app asks to read or write each type it needs.

Marfa does the same for personal data in general. Every read and write carries a credential, and the credential's permissions name the types it can read and the types it can write. An item of a type a credential can't read answers as if it didn't exist.

## What works with an instance

<InstanceMap />

- **Your instance** holds items, types, edges and files. The server is the source of truth.
- **Apps** read and write over the HTTP API. Every read and write carries a credential: a key, or the access token of an app you signed in to. An app sees only the types its permissions reach.
- **Connectors** are programs outside the server that bring records in from another service or send them out. Each one registers with the instance and reports its runs. The server doesn't run them.
- **Devices** keep a working copy of part of the instance and a queue of writes, through the core: an app built on the Swift package or the Node module, or the `marfa` command. A device reads its copy locally. While offline, it queues writes and sends them when it can reach the server. A folder is a device whose face is a directory, where each file is one item.
- **The `marfa` command** is the reference client. Every published API operation is a command, and the command is a device too.
- **Marfa Cloud** is coming soon. It gives your instance a ready-made public address, and holds none of your data.

## What you can build

The next app you build doesn't start with an empty database. For example:

- A reading app that opens with every article your other apps saved.
- A timeline of your notes, events, messages and photos, whichever app wrote them.
- A personal CRM on the same `core.entity.person` items your other apps use.
- A connector that brings in records from a service you already use.
- A script or an agent that works with your data through a key you give it.

## Where it runs

Marfa runs on your own machine. Today you start the server from a terminal, and [Run an instance](/get-started/run-an-instance) shows how. It keeps your data in one SQLite database file and a directory of blobs, so there is no database server to set up.

You reach your instance in one of three ways:

| Way | What it gives you |
| --- | --- |
| Your local network | Apps and devices on the same network as the machine reach it directly. |
| Tailscale (suggested) | Your own devices reach it from anywhere, over a private network of your own devices. |
| Cloudflare Tunnel | A public address on a domain you own, without opening a port on your network. |

## What Marfa isn't

- **Not shared editing between people.** An instance has one owner, and every app and device works with that one person's data.
- **Not a hosted service that keeps your data.** Your data lives on the machine you run Marfa on, and in any storage you choose to attach. Marfa Cloud, when it comes, is an address, not a store.
- **Not a place where apps run.** Apps, connectors and devices run outside the server and reach it over the API. The server doesn't start, watch or restart any of them.
