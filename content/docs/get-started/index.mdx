## One instance, one owner

Marfa keeps your personal data in one place that you run yourself. One running Marfa is an instance. An instance belongs to one person, its owner, and holds that person's data.

Everything in an instance is an item: one record, such as a note, a task, a bookmark, or a message. Each item has a type, which says what the item is and which properties it carries. Edges connect items to each other, and files are stored as blobs that items refer to.

The server is the software that answers HTTP for the instance. It is the source of truth. Everything else that works with your data reads from it and writes to it.

## What works with an instance

| What | How it works with the instance |
| --- | --- |
| Apps | Read and write items through the HTTP API. Every request carries a credential: a key, or the access token of an app you signed in to. A credential reads and writes only the types its permissions reach. |
| Connectors | Programs outside the server that read or write on your behalf, such as one that brings in records from another service. The server doesn't run them. It gives each one a place to register, report its runs, and keep what it needs to resume. |
| Devices | Keep a working copy of part of the instance, called a slice, on a machine. A device reads its copy locally and queues its writes until it can send them. A folder is a device that shows items as files in a directory. |
| The `marfa` command | The reference client. Every published API operation is a command, and it also runs a device's working copy and folders. |
