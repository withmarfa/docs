title: Your first items
description: Create a note, read it back, change it and watch its version move, and link it to a book, with the marfa command and with the HTTP API.
---

This tutorial writes two items and an edge to your instance. It needs the instance and the key from [Run an instance](/get-started/run-an-instance). Each step shows the `marfa` command and the HTTP API, so follow either one.

The `marfa` command sends the key it kept. An HTTP request sends the key in the `Authorization` header, to `http://localhost:8600`. A key that reads and writes `core.note` and `core.media.book`, and writes the `about` edge type, is enough. Replace `<note id>` and `<book id>` with the `id` that Marfa answers.

## Create an item

A note is an item of the type `core.note`, which requires a `body`.

With the `marfa` command:

```bash
marfa items create --type core.note --prop title="Reading list" --prop body="Start with the essays."
```

```text
01a12192-d471-76a6-abee-797a346d2a64  core.note  2026-10-09T16:50:33.201Z  Reading list
{
  "body": "Start with the essays.",
  "title": "Reading list"
}
```

With the HTTP API, [Create an item](/api-reference/items/createItem):

```http
POST /items
Authorization: Bearer <key>
Content-Type: application/json

{ "type": "core.note", "properties": { "title": "Reading list", "body": "Start with the essays." } }
```

Marfa answers `201` with the item and its metadata record:

```json
{
  "item": {
    "id": "01a12192-a000-76e3-b129-b55027e21dcb",
    "type": "core.note",
    "state": "active",
    "tier": "library",
    "properties": {
      "body": "Start with the essays.",
      "title": "Reading list"
    },
    "created_at": "2026-10-09T16:50:19.776Z",
    "updated_at": "2026-10-09T16:50:19.776Z",
    "occurred_at": "2026-10-09T16:50:19.776Z",
    "version": 1,
    "schema_version": 0,
    "source": "laptop",
    "edges": {}
  },
  "metadata": {
    "item_id": "01a12192-a000-76e3-b129-b55027e21dcb",
    "tags": [],
    "extensions": {}
  }
}
```

Marfa made the `id`, set the item's `state` to `active` and its `tier` to `library`, and started its `version` at 1. `source` is the own source of the key that wrote it. [Items and types](/get-started/items-and-types) explains each part.

## Read it back

With the `marfa` command, add `--json` to see every field, the `version` included:

```bash
marfa items get <note id> --json
```

With the HTTP API, [Get an item](/api-reference/items/getItem):

```http
GET /items/<note id>
Authorization: Bearer <key>
```

Both answer the item you created, at `"version": 1`.

## Change it

An update names the `version` it read, so Marfa can tell whether the item changed since then. An update that names no version is refused `400 missing_required_field`. Change the body, naming version 1.

With the `marfa` command:

```bash
marfa items update <note id> --version 1 --prop body="Start with the essays, then the letters."
```

With the HTTP API, [Update an item](/api-reference/items/updateItem):

```http
PATCH /items/<note id>
Authorization: Bearer <key>
Content-Type: application/json

{ "version": 1, "properties": { "body": "Start with the essays, then the letters." } }
```

The item comes back with the new `body`, a later `updated_at` and `"version": 2`. The properties you send are laid over the ones the item has, so `title` is unchanged.

Now try another change to `body` that still names version 1:

```bash
marfa items update <note id> --version 1 --prop body="Something else."
```

```text
marfa: the server refused (409 version_conflict): Version 1 is stale; current version is 2. Conflicting fields: body.
```

The note is at version 2, so the write is stale, and it changes a property that changed since, so Marfa refuses it. The HTTP API answers `409 version_conflict` too, with the note as it stands now in `current`, so you can combine the two changes and send them at version 2. [Changes over time](/get-started/changes-over-time) explains when a stale write is merged and when it's refused, and [Write safely](/guides/write-safely) shows how to handle each answer.

## Link two items with an edge

An edge joins two items. Make a book to link the note to.

With the `marfa` command:

```bash
marfa items create --type core.media.book --prop title="Letters from a Stoic" --prop author=Seneca
```

With the HTTP API:

```http
POST /items
Authorization: Bearer <key>
Content-Type: application/json

{ "type": "core.media.book", "properties": { "title": "Letters from a Stoic", "author": "Seneca" } }
```

Then say that the note is `about` the book. With the `marfa` command:

```bash
marfa edges create --source <note id> --target <book id> --type about
```

```text
linked 01a12192-d471-76a6-abee-797a346d2a64 -> 01a12192-d4a3-7986-a073-83061eb22e03 with about edge 01a12192-d4b0-7fa8-b9d8-e8f7650734a9
```

With the HTTP API, [Create an edge](/api-reference/edges/createEdge):

```http
POST /edges
Authorization: Bearer <key>
Content-Type: application/json

{ "source_id": "<note id>", "target_id": "<book id>", "edge_type": "about" }
```

Marfa answers `201` with the edge:

```json
{
  "edge": {
    "id": "01a12192-a03b-7aa4-87c0-d9d462ff8bfe",
    "source_id": "01a12192-a000-76e3-b129-b55027e21dcb",
    "target_id": "01a12192-a02c-7dd1-9371-d2c9bafc87a1",
    "edge_type": "about",
    "properties": {},
    "created_at": "2026-10-09T16:50:19.835Z",
    "updated_at": "2026-10-09T16:50:19.835Z",
    "version": 1
  }
}
```

The edge has a version of its own, which starts at 1. Writing it left the note's version at 2. Read the note's edges back with `marfa items edges <note id>`, or [List outbound edges](/api-reference/edges/listItemEdges) with `GET /items/<note id>/edges`.
