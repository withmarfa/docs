These docs are written for developers and the agents working alongside them. The docs MCP serves the whole corpus over the Model Context Protocol, so an agent can search and pull the exact page it needs instead of working from stale training data.

The hosted server is at `https://docs.marfa.so/mcp` — HTTP, JSON-RPC 2.0, and stateless.

<Callout type="info">
  No authentication. The docs are public, so the MCP is too — point a client at the URL and go.
</Callout>

## Connect

In Claude Code:

```bash
claude mcp add --transport http marfa-docs https://docs.marfa.so/mcp
```

In any client that reads an `mcpServers` config (Claude Desktop, Cursor, and others):

```json
{
  "mcpServers": {
    "marfa-docs": {
      "type": "http",
      "url": "https://docs.marfa.so/mcp"
    }
  }
}
```

Clients that only speak stdio can use the stdio shim shipped in the docs repo (`src/lib/mcp/stdio.ts`), which proxies to the same HTTP server.

## Tools

Three tools, mirroring how you would read the docs yourself:

- `docs_list_topics()` returns the hierarchical map of every section and page.
- `docs_search(query, limit?)` runs full-text search and returns ranked markdown chunks.
- `docs_fetch(path)` returns the full markdown for a path, such as `/guides/core-model/items`.

Orient with `docs_list_topics`, narrow with `docs_search`, then read a page in full with `docs_fetch`.

## Without an MCP client

The same surfaces are reachable directly:

- The CLI carries the same three tools as `docs` subcommands — see [CLI](/sdks/cli).
- Append `.md` to any docs URL, or send the `Accept: text/markdown` header, for the raw markdown of a single page.
- [llms.txt](/llms.txt) is a short index of the whole site; `/llms-full.txt` is the entire corpus in one file.

Self-hosting? The MCP ships with your docs deployment at `<your-docs-url>/mcp`. Point a client's URL field, or the CLI's `--docs-url` flag, at it.
