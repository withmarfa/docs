**This is the agent path** — point an MCP client at a Marfa space so it can query and write typed data as tools rather than as scraped text. A couple of minutes, no code.

<Callout type="info">
  Two different MCP servers carry the Marfa name, and it is worth not confusing them. This page connects the **platform** MCP, which reaches your data. The [docs MCP](/introduction/docs-mcp) is a separate, public, unauthenticated server that serves these documentation pages as context. Agents doing real work usually want both.
</Callout>

<Steps>

<Step>

### Get a credential

The MCP server authenticates as one credential against one space. Mint a key scoped to what the agent should actually reach, rather than handing it an admin key.

```bash
marfa keys create --label coding-agent --source coding-agent --role member \
  --type-perm core.note=write \
  --type-perm core.task=write \
  --type-perm core.bookmark=read \
  --edge-perm about=write
```

The plaintext `marfa_k1_...` is printed once. A `member` role with an explicit permission map is the right default: the agent gets exactly the types you named and nothing else. See [Permissions](/api-reference/permissions).

<Callout type="warn">
  Edge access is opt-in. A credential with no `--edge-perm` cannot create any relationship, and edge writes are dual-gated, so the agent needs write on both the source item's type and the edge type.
</Callout>

</Step>

<Step>

### Register the server

No install step. The client runs it through `npx` on demand.

<Tabs items={['Claude Code', 'Config file']}>

<Tab value="Claude Code">

```bash
claude mcp add marfa \
  --env MARFA_API_URL=https://your-marfa-instance.example \
  --env MARFA_API_KEY=marfa_k1_... \
  -- npx -y @withmarfa/mcp
```

</Tab>

<Tab value="Config file">

For any client that reads an `mcpServers` block, such as Claude Desktop or Cursor:

```json
{
  "mcpServers": {
    "marfa": {
      "command": "npx",
      "args": ["-y", "@withmarfa/mcp"],
      "env": {
        "MARFA_API_URL": "https://your-marfa-instance.example",
        "MARFA_API_KEY": "marfa_k1_..."
      }
    }
  }
}
```

</Tab>

</Tabs>

`MARFA_API_URL` is required and the server exits at startup without it. One space per server process: a user with several spaces registers several entries under different names.

</Step>

<Step>

### Pick a toolset

`MARFA_MCP_TOOLSETS` decides how much surface the agent sees. It defaults to `standard`, which is the right choice for most work.

| Value | What it exposes |
| --- | --- |
| `standard` | Items, metadata, edges, and type discovery. The daily driver. |
| `admin` | Key, webhook, and space administration. |
| `all` | Both. |

Tool count is a real cost in an agent's context window, so widen this deliberately rather than by default. An unrecognized name is ignored with a warning and falls back to `standard`.

</Step>

<Step>

### Confirm it works

Restart the client so it spawns the server, then ask the agent for something that can only come from the API:

> List the item types available in my Marfa space, then create a note saying "Hello, Marfa."

A working connection answers with the registered types and returns a created item carrying a server-stamped `id` and `version: 1`. If the agent reports an authentication failure, the key is wrong or revoked; if it reports that a type is not permitted, the key's permission map does not cover what you asked for.

<Callout type="info">
  Picking up a rotated key means fully restarting the client. Reloading a config or a plugin does not restart an already-spawned MCP subprocess.
</Callout>

</Step>

</Steps>

## Why this beats giving an agent the raw API

An agent pointed at the REST API has to hold the wire format in context and can call anything the credential permits. Through MCP it gets one tool per SDK method with validated inputs, and the credential's permission map bounds the blast radius. The tools are stateless between calls, so nothing accumulates across a session.

The type system does the rest of the work. Because items are schema-validated on write, an agent that invents a field gets a `400` naming it rather than quietly writing malformed data.
